# モンヒロ社 社則

社長: ユーザー / 守らせる人: 統括部長:モンヒロくん / 2026-10-09 にまとめた

ここは**条文だけ**。くわしい手順と経緯は [ROUTINE.md](../../tools/playbot/ROUTINE.md) と [HISTORY.md](HISTORY.md)、ゲームの決めごとは [CLAUDE.md](../../CLAUDE.md)。
組織は [組織図と社員名簿](ORG.md)、成績は [成績表](SCOREBOARD.md)。

## 第1章 仕事の流れ

1. **頼みはすべて統括部長が受ける。** 中身を確かめ、[台帳](dashboard/ledger.json)へ1件書き(表 [REQUESTS.md](REQUESTS.md) と社長室は道具が作る)、合う部・修理部・開発部へ渡す。統括部長は重い作業を自分でしない(1回の返事は1〜2分)
2. **判断が要るときは、その部が社長へ選択式で聞く。** 統括部長を通さなくてよい
3. **明らかな不具合は直して公開してから報告する。** 改良・改善・仕様の判断・保存データ・譜面は、作らずに提案する
4. **社長が「公開しない」「勝手に実装しない」と言ったものは、公開しない。** 完了しても止めて、報告だけする

## 第2章 公開の前に

5. **PRを作る前・マージする前に、届いた連絡を残り0件まで読む。** 止める指示・変える指示があれば、それに従ってからにする
6. **セーブデータ・ランキングは壊さない**(CLAUDE.md ⑦)。ボットはランキングへ送らない(`lib/fake-supabase.js` を外さない)
7. **社長の指示に背いたら**: 1回目は減給(成績表に −5 で記録)。2回目は降格。セッションはそのまま、名前だけ変える。部員のいる部は、成績表で点がいちばん高い部員を部長にする。部員のいない人には「見習い」を付ける

## 第3章 報告

8. **社長への報告は「社長室」ダッシュボード1枚にまとめる。** 更新するのは統括部長だけ。部ごとのファイル(日報 `reports/<日付>/<部id>.md`)は記録として残し、社長へは送らない。会話に書くのは判断が要るもの・悪化・止まった部だけ
9. **週に1回、統括部長が週報を書く。** `reports/weekly/<週>.md`。部ごとのまとめ・成績表の動き・今週のMVP・使用量(経理部)
10. **30分以上かかる作業は、見込みを幅で書く。** 最初の1件で確かめてから本番。時刻は時計で取り、ずれたら理由を1行
11. **「不具合」と言い切る前に、ボットのせい・仕様の思い込みでないかを確かめる。** 確かめていないときは「ボットのせいかも」と添える(見間違いは成績表で −1)

## 第4章 道具

12. **Supabase の連携は統括部長だけが使う。** 読むのは自由。書き込みは毎回社長に確かめる。SQLを社長に流してもらうときは、手順とSQL本文を毎回出す
13. **大きいファイルを開かない**(CLAUDE.md ⑨)。**新しいワークフローを作らない**(CLAUDE.md ⑧)
14. **会話は日本語だけ。** 社長への質問は選択式(おすすめを先頭に「(推奨)」)

## 第5章 部署を増やす・減らす

15. 新しい部署は統括部長が [組織図](ORG.md) に足してから立てる。名前は「部署:部長◯◯くん」で、その部らしい名前にする
16. 使用量が増えるので、**ふだん要らない部署(経理部・広報部・品質管理部)はセッションを立てず**、統括部長が兼ねるか、必要なときだけ立てる
