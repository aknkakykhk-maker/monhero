# HELL: 空中の光「奥まで」を、空中の判定線から道の奥の端まで(2026-10-13・iPhone の報告)

社長の iPhone(縦 390×844)「空中の柱の光は手前までしか出ていない」「判定ラインより低い位置から出てる」(Grievous Lady HELL の待機中のスクショ)。

## 原因

スクショの光(空中の判定線の少し下から上へ・下が青く上が白い・1レーン幅)は、押している間の空中の光(`drawSkyPress`)だった。
この光は空中の判定線の上 0.22・下 0.06(道の高さに対する割合)だけを描く作りで、「奥まで」の設定を見ていなかった。
2026-10-11 に、道の奥まで伸ばすと左右のはしのレーンで道のふちの外へはみ出したため短くしていた。
叩いたときの柱(`drawFarBeam`)は奥まで描いていたが、下の端が判定ラインの下の縁を持ち上げた位置で、空中の判定線より数 px 下から出ていた。
(この環境に WebKit は入っていないので、Safari そのものでは撮れていない。描き方は WebKit でも同じ結果になる単純な形にした)

## 直したこと

- 「奥まで」(既定)のとき、押している間の空中の光を、空中の判定線から道の奥の端まで描く。色の段は地上の押した光と同じ。判定線より下には出さない
- 叩いたときの柱も同じ形(`skyFarColumn`)で、空中の判定線から奥の端まで、1枚の多角形で塗る
- 形は描くたびにその場の道の形(判定ラインの高さ・道の幅・画面の大きさ)から作る。横の位置は道のふちの内側へ収めてから奥へ細める(はみ出さない)
- 「短い」「出さない」のときの形は変えていない
- 見張り: `tools/mode/rhythm-sky-far-reach-check.js`(横 844×390・縦 390×844 画素密度3 × 2D/WebGL × 標準/最小/軽量 × 3レーン = 72通り。直す前は押した光の36通りが NG)

## 絵(Sheriruth HELL・通常の曲えらび)

- `compare.webp` … 縦 390×844。左から 待機中の前・後、叩いた直後の前・後
- `before-iphone-*` / `after-iphone-*` … 縦。`wait` は画素密度3、`hit` は画素密度1(画面写しに時間がかかると柱が消えてしまうため)。`webgl` は描画方式「軽い」
- `after-landscape-*` … 横 844×390 の後(既定・最小)
