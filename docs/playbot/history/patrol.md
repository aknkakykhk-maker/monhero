班のセッションが毎晩いちばん上へ1日ぶんを足す(手順は [`tools/playbot/ROUTINE.md`](../../../tools/playbot/ROUTINE.md) の手順8・9)。
書くこと: 結果のひとこと / 不具合と PR の番号(マージ待ちか) / 出した提案と、ユーザーの返事(**却下・保留もそのまま残す**) / 作り手へ回したいこと / 決まったこと

## 2026-10-09(試しの点検。日・水の定期とは別。この部の初回)

- 結果: 4人の部員が約9.5分で遊び切った(見た画面62・押した743回)。新人は設定16手、ストーリーは時刻の前後と回想6本が通った、探検150手、案内は入口11か所。不具合候補3件・改善のヒント4件
- 直した不具合: なし(「明らか」と言えるものが無かった)
- 見間違い: デザインくんの「モンヒロバトル59%変化」は、入口を作り直した見た目が前回の基準(旧い絵)と違うだけで、崩れではない。基準が古いままなので、次の定期の前に取り直したい
- 小さい画面の演奏(CPU4倍遅い)で「指が帯の上なのにMISS」2件・「HOLDが途中で切れた」1件。直近の遅れすぎたタップの変更(2044e2a)の影響の可能性があるが、遅い端末の再現でゲームの判定の不具合とは言い切れず、ビート部へ回す
- 出した提案: 長いお話(26回押す)に読み飛ばし、幅が32px未満のページ送りの点は既知のまま、基準の取り直し(ボットの小さな直し)
- ユーザーの返事: 3つとも実装。①基準の取り直し=実施(look の基準を新しい見た目へ)。②読み飛ばしの追加=**実装せず**。ゲームの回想・お話には「スキップ」がすでにあり、ボットが数えた「26回」はスキップが見えない重なり(お知らせ・ログインボーナス等)の連続を足していた見間違いだった。ボットの数え方を「スキップの見えない『次へ』」だけに直した。③小さい画面のMISS=ビート部へ調査を依頼(同じ小さい画面で別の曲でも「指が帯の中なのにMISS」が出るので、遅い端末の再現そのものの傾きかもしれない)

## 2026-10-07
