## 2026-10-09(見回り部からの依頼・小さい画面の3件)

- 依頼: 見回り部 8:05 の小さい画面(幅320・CPU 4倍遅い・EXPERT 476ノーツ・種 726642)で「指が帯の上なのにMISS」2件・「HOLDが途中で切れた」1件。2044e2a(遅れすぎたタップを本当の遅れで選び直す)を疑う
- 結果: **2044e2a は原因ではない。ボットの見間違い**。同じ種で、いまの main と、選び直しを止めた写しを交互に3回ずつ回した: MISS は main 23・27・32 / 止めた写し 28・28・29、指の不具合候補はどちらも 0件。
  選び直しが実際に働いたのは main で1曲 0〜2回だけ(止めた写しは 0回)。種が同じでも、CPU を遅くした演奏は毎回ゆれる(直す前の main の1回目は候補10件・MISS 34)
- 正体: CPU 4倍遅いと、ボット自身の1コマが100ms以上止まるのが1曲で300〜400回ある。止まっているあいだに押す予定の時刻が来ると、ボットは予定より遅れて押すのに、候補の条件は「予定の時刻のずれ」で見ていた。
  ホールドも、止まったあとボットが1コマ遅れて指を動かす(実機なら止まっていた間の指の動きはまとめて届く)
- 直したこと(ボット側・`scenarios/rhythm.js`): 実際に押した時刻のずれ(`sentDelta`)と予定からの遅れ(`lag`)を記録し、タップは予定より50ms以上遅れて押したもの、ホールドは切れる直前400ms以内にボットが止まっていたものを、候補でなく「その巻き添え」に数える。
  要約に「ボットの1コマが100ms以上止まった回数・その巻き添え」と、ゲームの数え(遅れすぎて抑えた・本当の遅れで選び直した)を出す。直したあとの main: 巻き添え7・候補0件
