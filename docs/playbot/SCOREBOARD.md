# モンヒロ社 成績表

つけるのは統括部長:モンヒロくん。部の日報(`reports/<日付>/<部id>.md`)を読んだあと、**下の「できごとの記録」へ1行足すだけ**。2026-10-09 からつけ始めた。
部員ごとの表と社長室の `scores.json` は、記録の足し算で `node tools/playbot/scoreboard.js` が作る(**手で数えない・表を手で直さない**。2026-10-09 改善部の提案 C2)。
記録の「種類」は 本物 / 公開 / ボット直し / 見込み / 見間違い / 違反 のどれか(空なら点から決める)。何件かをまとめた行は点を件数ぶん書く(例 本物9件 = +27)。
週の終わりに週報(`reports/weekly/<週>.md`)で今週のMVPを決め、下の「表彰」に残す。

## 点の数え方

| できごと | 点 | 例 |
| --- | --- | --- |
| 本物の不具合を見つけた(直して公開まで) | +3 | 文字の折り返しの崩れを見つけて直した |
| 社長が選んだ改良を公開した | +2 | 難易度えらびの色の強弱 |
| ボット側の漏れを自分で見つけて直した | +1 | レイドで止まった押し方の漏れ |
| 30分以上の作業の見込みが当たった(±30%) | +1 | — |
| 見間違い(ボットの誤り・仕様の思い込みを不具合として報告) | −1 | 範囲の中なのにMISS(ボットの遅らせたタッチ) |
| 30分以上の作業の見込みが外れた | −1 | — |
| 社長の指示に背いた(公開するなと言われて公開など) | −5 | 減給と同時に記録 |

- 見間違いは**報告すること自体は悪くない**。確かめずに「不具合」と言い切ったときだけ数える。確かめて「ボットのせいかも」と添えたものは数えない
- 部長の点は部長自身の仕事だけ。部員の点は部員に付く
- 降格のとき(社則7)、部の中で点のいちばん高い部員を次の部長にする
