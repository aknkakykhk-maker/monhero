# 刻みも「ノーツ」として数える見積もり(v2・2026-10-17・作らずに調べただけ)

社長の判断が変わった: 「刻みもノーツとして数える(他の音ゲーと同じく判定を付け、ノーツ数・判定の数・コンボを増やす)」
「刻みの位置は難易度・曲で変える」「帯の折れ点には必ず刻み」。フルコンボは刻みも落とさないことが条件・取得済みの称号は下げない・
コンボが切れたプレイのスコアが動くのは許す(ここまでは前回のまま)。作: ビート部:部長テンポくん。
前回の見積もり: [`combo-estimate.md`](combo-estimate.md)。案②の作りかけはブランチ `claude/tempo-combo-tick` に残してある(マージしていない)。
データベースは読むだけ(1回)。

## 0. 数の目安(配信中の40曲・全難易度を実際に数えた)

| 難易度 | 8分音符の刻み ÷ ノーツ数(中央 / 最大) | 帯の折れ点 ÷ ノーツ数(中央 / 最大) |
| --- | --- | --- |
| EASY・NORMAL | 0.29 / 0.55 | 0 / 0(曲がる帯が無い) |
| HARD | 0.32 / 0.91 | 0.14 / 0.45 |
| EXPERT | 0.34 / 1.00 | 0.15 / 0.71 |
| MASTER | 0.36 / 0.99 | 0.15 / 0.58 |
| HELL(4曲) | 0.62 / 0.86 | 0.31 / **1.32**(Sheriruth HELL は折れ点847か所) |

8分音符で刻むと、MASTER でノーツ数がふつう1.4倍、帯の多い曲(Grievous Lady MASTER)で2倍になる。折れ点をそのまま全部足すと HELL が膨らみすぎる。

## 1. 刻みの置き方の決まり(案)

- **間隔(難易度ごと・曲のテンポで自動調整)**: EASY・NORMAL・HARD は4分音符(1拍)、EXPERT・MASTER・HELL は8分音符。
  ただし刻みどうしが **150ms より詰まる速い曲は1段粗く**する(8分→4分)。テンポは曲の拍の表(`RHYTHM_SONG_BEATS`・40曲すべてにある)から取る。
  拍の表が無い曲(試験用・チュートリアル)は 250ms ごと
- **折れ点**: 帯の曲がる点には必ず置く。ただし前後の刻みと **100ms 以内なら1つにまとめる**(拍の刻みを折れ点へ寄せる)。
  1本の帯で「刻みは100ms に1つまで」を上限にする(Sheriruth HELL の847か所は、まとめると約半分になる見込み)
- **始まりと終わり**: 帯の始まり(押した瞬間)と終わり(離す瞬間)は今までどおり帯そのものの1ノーツで判定する。その前後40ms には刻みを置かない(二重に数えない)
- **刻みの判定**: 押さえて通れば MARVELOUS 扱い、外れて通れば MISS(時刻のずれは無い)。外れの一瞬(120ms 未満)では落とさない(今の判定の線と同じ)
- **譜面のデータは変えない**: 刻みは演奏を始めるときに、帯の点と曲の拍の表から作る(どの端末でも同じ数になる)。公開中の譜面の指紋の見張り(`rhythm-released-chart-lock-check.js`)にも触れない

## 2. スコア

| 問い | 答え |
| --- | --- |
| 満点を保つ正規化はできるか | **できる**。判定の点 = Σ(判定の割合) ÷ (ノーツ数+刻みの数)、コンボの点 = 最大コンボ ÷ (ノーツ数+刻みの数)。全部 MARVELOUS でつなげば満点は今と同じ(MASTER まで 1,000,000・HELL 1,050,000) |
| 刻みが楽に取れる分、平均点が上がるか | **上がる**。押さえていれば MARVELOUS なので、判定の割合が上がる。例: ノーツの判定の割合が 85% の人は、MASTER(刻み+36%)で約 +3.6万点、HELL(+62%)で約 +5万点。長い帯の多い曲ほど上がる。**古い記録とは比べられない**(1位の入れ替わりが起きる) |
| ランキングを版で分ける必要があるか | **ある**。同じ表に新旧が混ざると、新しい版で遊んだ人がほぼ必ず上になる |
| ⑦を守れるか | **守れる(足すだけ)**: 表 `rhythm_scores`(1,851件)・`rhythm_song_bests`(254件)に **`score_version` の列を足す(既定値 1)**。新しい版は 2 を送る。**古い版のままの端末は列を送らないので自動で 1(旧の物差し)に入る**(混ざらない)。順位の見方(合計・曲ごと・週間・相棒ランク)は版ごとに分けて読む。古い行は消さない・書き換えない。端末の自己ベストは **新しいキー `mh_rhythm_best_v2`** を足す(`mh_rhythm_best_v1` はそのまま残し「旧記録」として見せる)。取った FC・AE・AM の実績(`mh_rhythm_achievements_v1`)は下げない |

参考: 刻みの重みを軽くする(刻み1つ = ノーツの 1/4 など)と、平均点の上がり方は 1/4 程度に抑えられるが、それでも同じ表には混ぜられない。

## 3. 曲えらび・結果画面・譜面の Lv.

- **ノーツ数の表示**: 譜面のノーツ数(今の数)は変えずに出し、刻みの数を「+刻み 477」のように分けて出す。更新履歴に書いた曲のノーツ数(`song-numbers-check.js` が見張る)と食い違わない
- **譜面の Lv.**: 公開中の表示は固定(`LEVEL_OVERRIDES`)なので変わらない。刻みは押さえていれば取れるので、Lv. の式(`rhythm-chart-level.js`)には入れないのがよい(入れると帯の多い曲だけ Lv. が上がる)
- **実行時に帯から作れるか**: できる(上の1)。譜面のデータ・指紋は1つも変えない

## 4. レイド(大王ジャック)の釣り合い

今の式: `Σ(判定の数 × 1つあたりのダメージ) × (1 + 最大コンボ × 0.0005) × 称号の倍率(なし 0.35 / FC 0.7 / AE 0.9 / AM 1.0)`

- 刻みを判定の数に入れると、土台が MASTER で +36%(HELL +62%)、コンボの上乗せも増え(642コンボ→1,119コンボで ×1.32→×1.56)、うまい人ほど **1回のダメージが約1.6〜2.2倍**になる。
  一方で FC は刻みも条件になるので取りにくくなり、FC を逃した人は 0.7→0.35 で半分になる → 上手い人と惜しい人の差が大きく開く
- **直し方(ダメージを今と同じにしたい場合)**: レイドには **ノーツだけの判定の数・ノーツだけの最大コンボ**を渡す(刻みは数えない)。称号の倍率は「ノーツだけで FC」を使う。これでダメージは今と同じ
- **みんなの合計の進み**: 上のとおりノーツだけで数えれば変わらない。刻みを入れる場合は、段階の体力(`RAID_JACK_A_TIERS` の hp)を同じ倍率で上げ直す必要があり、**開催中のイベントの途中では変えない**

**危ないところ**

- **データベースの変更**(列を足す・順位の見方を作り直す)。列の既定値を 1 にすれば古い版の端末は旧の表へ入るので混ざらないが、見方(ビュー・関数)の作り直しで今の順位を壊さないよう、当てる前に今の順位と突き合わせる検査が要る
- **切り替えの時期**: 週の区切りに合わせる。モンヒロビートのイベント・大王ジャックの開催中は避ける
- **元に戻しにくい**: 新しい物差しの記録が貯まったあとで戻すと、新しい記録の行き場が無くなる(消さずに凍結はできる)
- 刻みの数が端末ごとにずれないこと(譜面と拍の表だけで決まる作りにし、検査で全曲の数を固定して見張る)

**おすすめ**

社長の決定どおり作るなら、**上の 1〜7 を2段に分ける**:

- **第1段(データベースを変えない・約3)**: 1・2・3 と 6 のうちレイド・遊んだ記録・異変の報告の分。ただし**ランキングへの送信は旧の物差しのスコアを並べて計算して送る**(新しいスコアは画面と端末の自己ベスト v2 にだけ)。ランキングを壊さずに、遊ぶ人は新しい数え方をすぐ体験できる
- **第2段(データベース・約4)**: 4・5・7。新しい物差しのランキングを開き、旧の表は「旧記録」として凍結。週の区切りで切り替える

先に社長に決めてほしいこと:

1. 刻みの間隔(案: EASY〜HARD 4分・EXPERT 以上 8分・150ms より詰まる速い曲は1段粗く)と折れ点の上限(案: 100ms に1つ)
2. 刻みの重み(1ノーツと同じ / 軽くする)
3. レイド: 社長の考え(大きくなってよい)どおり刻みも数えて係数は直さないか(4-2 のとおり MASTER で中央 ×1.5・帯の多い曲で最大 ×2.9)、刻みを数えない(今と同じ)か。あわせて HELL の補正を足すか
4. 第1段と第2段に分けるか(第1段のあいだ、ランキングは旧の物差しのまま)

## 7. 追加の前提: 刻みは「押さえて通ればジャストマーベラス・外せば MISS」の2つだけ(社長)

### スコア

ジャストかどうかはスコアの点に効かない(点は判定ごと: MARVELOUS 1・EXCELLENT 0.98・GREAT 0.9・GOOD 0.7・BAD 0.3・MISS 0。ジャストは MARVELOUS の中の数)。
刻みは取れば1点・落とせば0点で、ノーツ+刻みの数で割る(満点はそのまま)。上がり方は **その人のノーツの判定の割合しだい**:

- うまい人(判定の割合 94〜99%)は **+1千〜8千点**。判定の割合が低い人ほど大きく上がる(85%の人で MASTER 約 +3.6万点・HELL 約 +5万点。2 の数字)。AM は満点のまま
- 上位の差は数千点で、今の順位の差(同じ曲の上位どうし)と同じくらいの大きさなので、**同じ表に混ぜると順位が入れ替わる**。版で分ける必要があるのは変わらない
- 同点のときの並べ替え(「JUST MARVELOUS の数」・#3030 と `RHYTHM_JM_TIEBREAK_APPLY.sql` の4つの関数)は、刻みもジャストとして数えると **刻みの多い曲・帯を落とさなかった人ほど多くなる**。
  同じ曲の同点なら、両方とも刻みを全部取っていることがほとんどなので順番は今と同じ。総合・週間の合計では、帯の多い曲を遊んだ人が有利になる → 並べ替えには **ノーツだけのジャストの数**を使い続けるのがよい(記録の `party` の先頭に、ノーツだけの数と刻みの数を分けて入れる)

### 称号

| 称号 | 数え方 |
| --- | --- |
| フルコンボ | ノーツの BAD・MISS が0 **かつ** 刻みの MISS が0(社長の決定どおり今より厳しい) |
| オールエクセレント | ノーツが EXCELLENT 以上 かつ 刻みの MISS が0 |
| オールマーベラス | ノーツが全部 MARVELOUS かつ 刻みの MISS が0(刻みは取れば MARVELOUS なので、刻みを全部取ることと同じ) |
| ALL JUST | **今は無い**。作るなら「ノーツが全部ジャスト かつ 刻みを全部取る」。刻みはジャストとして数えるので、刻みが増えても取りにくさはノーツの数で決まる |

取った称号は下げない(`mergeRhythmBestRecord` は「前に取った or 今回取った」)。新しい数え方では取りにくくなるので、**曲えらびの印は「新しい数え方で取ったか」を別に持つ**(`mh_rhythm_best_v2` 側)と、旧の印と見分けられる。

### 遊んだ記録の学習・判定の異変の報告

| もの | 刻みを混ぜた場合 | どうするか |
| --- | --- | --- |
| 遊んだ記録(`rhythm_play_logs` の `deltas`・`judge_offset_ms`) | 刻みは「ずれ0ms のジャスト」になる。混ぜると、ずれの平均が0へ引っ張られ、「この端末は早め/遅め」の学び(タイミングの自動の合わせ方・譜面の重さの学び)が鈍る | **刻みは入れない**。`note_count` は譜面のノーツ数のまま。刻みの数と取れた数は別の項目(足すだけ)に |
| 判定の異変の報告(MISS 率 = `stats.misses ÷ note_count`、前の7日と比べる) | 刻みの MISS(帯を外した)が入ると、帯の多い曲だけ MISS 率が上がり、切り替えた週に「急に MISS が増えた」と誤って引っかかる | **ノーツだけの MISS を今の項目に入れ続け**、刻みの MISS は新しい項目に分ける。報告の式は今のまま |
| ジャストの割合(端末の記録の precise) | 刻みは全部ジャストなので、混ぜるとジャストの割合が見かけ上上がる | 同じく、刻みは別の項目に |

まとめ: 「刻みは2つの判定だけ」にすると、**スコアの上がり方は小さく(うまい人で数千点)、レイドは2〜3倍**になる。
記録・学習・異変の報告は、刻みを別の項目へ分ければ今の物差しのまま使える。
