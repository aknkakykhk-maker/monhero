# タクティクスのヘイト・モンスターのタイプ: 公開のときに出す文(下書き)

2026-10-17 バトル部:ブレイブくん。社長「公開時に出すストーリーと説明も作っといて」「これを機にモンスターごとのタイプ作る？」への下書き。
**いまはゲームの更新履歴・ヘルプには入れていない**(試作が公開と決まったら、下のコードをそのまま貼る)。
試作の中身: [tactics-hate-proto/README.md](tactics-hate-proto/README.md)。数字の根拠: [tactics-hate-numbers.md](tactics-hate-numbers.md)

決まりごと(changelog-help-update スキル)に合わせたこと:
- 告知の種別は `content`(新しい遊び)。`mode` は新モード・新難易度だけなので使わない
- 敵の数字・まだ出ていない敵は書かない。ヘイトの数字も出さない(炎の段だけで伝える)
- 画面に出す名前は正式名称(タクティクスバトル・モンスター図鑑)
- 時刻は貼るときに `TZ=Asia/Tokyo date '+%Y-%m-%d %H:%M'` で取り直す(下の `date` は仮)

### 案B: はじめてヘイトのあるバトルに入ったときの案内(画面のなかの案内)

大きい追加は「画面のなかでの使い方案内」もセット(スキル §6)。タクティクスバトルで、だれかに初めて🔥が付いたターンに、助手の吹き出しで1回だけ出す。
一度きりの印は**新しいキー** `mh_tactics_hate_intro_seen_v1`(既存のキーは触らない)。

```js
addAssistantLinePack({ id: 'tactics_hate_intro_v1', lines: {
  tacticsHateIntro: [
    { e:'surprise', t:'あっ、{who}に🔥が付いた！ 目立った子は、敵に狙われやすくなるよ' },
    { e:'normal',   t:'🔥が多いほど狙われやすいの。守りたい子がいたら、タンクにガードやかばうで🔥を集めてもらおう！' },
  ],
}});
```

### 案C: 短いお話(ストーリーの1場面・いちばん手間がかかる)

お話の仕組みで出す場合の台本。**モノリスはしゃべらない**(今までどおり)。地の文と助手の会話で進める。

> ――タクティクスバトルの戦場。敵の目が、さっきから一体ばかりを追っている。
>
> **みゅあ**「ねえ、気づいた？ 敵、いちばん暴れてる子ばっかり見てるよ！」
> **もも**「ほんとだ……ハムくん、張り切りすぎて🔥がいっぱいになってる！」
> **みゅあ**「このままじゃ狙われちゃう……！」
>
> ――そのとき、重たい足音とともに、黒い石の柱が前へ出た。モノリスだ。
> 体の前で光がはじけ、敵の目がいっせいにモノリスへ向く。
>
> **もも**「モノリス、みんなをかばってくれたんだ……！ 🔥🔥🔥になってる！」
> **みゅあ**「目立つ子が狙われるなら、いちばん硬い子が、いちばん目立てばいいんだね！」
> **みゅあ**「{name}、🔥を見ながら、だれに引き受けてもらうか決めよう！」

おすすめは **案A + 案B**(今の作りのまま出せて、遊んでいる最中にも気づける)。案Cはお話の枠を作るときに。

## 4. 公開するときにすること(覚え書き)

1. 確認待ちの試作の2行(`tactics_hate` / `monster_type`)を一覧から消し、`tacticsHateProtoOn()` / `monsterTypeProtoOn()` を公開の印(`RELEASE_FLAGS`)へ置き換える(保存キーはそのまま残す。SAVE_DATA.md)
2. 上の更新履歴・ヘルプ・告知の台本を貼る(時刻は貼るときの実時刻)
3. 案Bにするなら、`mh_tactics_hate_intro_seen_v1` を SAVE_DATA.md に足す
4. `node tools/run-checks.js --area required` と `node tools/changelog/player-words-check.js` を通す
