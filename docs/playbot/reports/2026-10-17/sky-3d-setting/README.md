# 空中のノーツの見た目を設定で選べるように(2026-10-17)

社長の判断「空中を本物の3D(段階A・#3136)が1番見やすかった。これと今のを設定で選べるようにする」。作: ビート部:部長テンポくん。

## 見方(本番)

曲えらびの「設定」→「表示」タブ →「空中のノーツの見た目」(HELL が出ているときだけ)で「いつもの」か「立体」を選んで「変更を保存」。次の演奏から効く。

## 何をしたか

- 普通の設定に「空中のノーツの見た目」(いつもの/立体)を足した。既定は「いつもの」
- 保存は新しいキー `mh_rhythm_sky_note_look_v1`(「立体」のときだけ `'3d'` を置く)。古い値・壊れた値は「いつもの」
- 段階Aの試作(`mh_rhythm_floor3d_proto_v1='a3d'`)を入れていた端末は、そのまま「立体」に見える。設定で選び直すと試作の `a3d` だけを消す(ほかの試作の値は残す)
- 段階Aの中身・地上のノーツ・道は今のまま。ノーツを WebGL で描いていないとき(描画方式「Canvas」・WebGL が作れない端末)は「いつもの」で描く
- 段階Aの試作のスイッチは「確認待ちの試作」の一覧から外した(ほかの試作は残してある)
- 検査: `tools/mode/rhythm-sky-note-look-check.js`(既定・壊れた値・試作からの引き継ぎ・試作の値の消し方・WebGL のときだけ)

## 写しと動画

- `settings-before.jpg` / `settings-after.jpg`: 設定の「表示」タブ(縦持ち)。前は項目なし、後は「空中の道の見え方」の下に「空中のノーツの見た目」(立体を選んだところ)
- `sky-3d-setting-play.mp4`: 「立体」を選んで Sheriruth HELL を自動演奏した12秒(46〜58秒・横持ち・ノーツを WebGL で描く)。`play-3d-50s.jpg` はその1コマ

## 重さ(前回と同じ物差し: CPU を4倍遅くした条件・Sheriruth HELL 70〜90秒・横持ち・ノーツを WebGL で描く・ほかの処理を止めて交互に2回)

| | 1回目 平均 / 95% / 最長 | 2回目 平均 / 95% / 最長 |
| --- | --- | --- |
| いつもの | 124.4 / 167 / 217ms | 118.5 / 167 / 233ms |
| 立体 | 116.7 / 167 / 250ms | 102.0 / 150 / 167ms |

関数ごと(1秒あたり ms): 箱 `drawSkyCube3d` 5.0・管 `drawSkyTube3d` 8.4(合わせて全体の約1.3%)。毎コマの処理 `tick` 247.8 → 254.3(ゆれの中)。

⚠️ 手元のブラウザには GPU が無く、WebGL を CPU で肩代わりしている(とても遅い)ので数字はどちらも大きい。「立体」で悪くなっていないことだけを見ている。
iPhone の本物の GPU での重さはここでは測れない。立体は WebGL の層を増やさず、今のノーツの層の中で描き、準備(シェーダーの組み立て)も演奏前に済ませているので、
増えるのは空中のノーツの数ぶんの小さな形だけの見込み。実機で重く感じたら知らせてほしい。
