  - 案の効き目は、シミュレーターでモンスターの数字をメモリの中だけ変えて測る(`sim.MONS` の baseHp などを書き換えて simulateRun。ゲームのファイルは変えない)

- 案の候補(実戦・机上・シミュレーターがそろって弱め): ハム・スエゾー・エイキ・ウンディーネ。強め: モッチー・ミタラシ(回数の偏りに注意。モッチーは前の不具合で勇者の回が多い)

## 依頼(社長 → 統括部長 → 研究所)

- 味方モンスター全員の Tier 表とバランス調整の案。**案だけ。ゲームの数字は変えない**。更新履歴・ヘルプに載せない
- Tier はステータスだけで決めない。勇者特性・固有技・EX・間合い適性まで総合する
- 「机上の計算(ゲームの式)」と「実戦(ブラウザでボットが戦う)」の2本立てで、理由に「机上ではこう、実戦ではこう、だからこの Tier」と書く
- 社長の感覚とのずれ(例: 「ゴーレムはかなり上のはず」)は精度の目安。点を合わせに行かない。ずれが大きい子ほど、先にボットの取りこぼしを疑う
- 置き場所: `docs/playbot/reports/tier/monster-tier.md`(1枚を育てる)。更新したら統括部長へ2〜3行

## ボットで直したこと(Tier の精度に効いたもの)

1. 勇者モンの画面で「供モン選び」が割り込み、モッチーを押し続けていた(2026-10-09 まで。モッチーの勇者の回数が多いのはこのため)
2. EX の使い方の表に無い子は全部「火力」扱いだった → 名簿の effect から決める(ゴーレム・ハム・オボロゲソウ・エイキなどを直した)
3. ガッツの少ない子(元のガッツ 90 以下)は最初から猛勉強・ガッツのアシストカード
4. 間合いの数え方: 適性は「立っている枠」のもの、距離の倍率は「枠と敵の距離の差」(60-app.jsx の getDmg)

## 残っている不具合

- ヤオビクニの EX「悠久の刻」(時間停止)のあと「進行停止」と出ていたのは、**ボットの見誤り**(EX の説明どおり、そのターンはターンの数字が進まない。ボットは数字だけで「動いたか」を見ていた)。手札が配り直されたことでも見るように直した。ヤオビクニを勇者モンにした対戦で確かめ済み(2回使って進行停止0回)。時間停止は重い攻撃まで取っておくようにした

- 勇者モンの画面が「編成 | ベースモン」(最初の8体だけの一覧)で開くことがあり、そこでは押しても選べない。その回は「入れなかった」で終わる(成績は汚れない)

## 簡易シミュレーター(2026-10-10 最初の版。`sim/battle.js` → `sim.md`)

- `node tools/playbot/sim/battle.js --diff Hard,Expert,Master --runs 300 --md docs/playbot/reports/tier/sim.md`(26体×3難易度×300回で約5分)。`SIM_TRACE=1` で1ターンずつの経過
- 入れていないもの: トレーニング・アシストカード・EX・魂格・WAVE 報酬・固有技の長く続く効果。だから**実戦より弱く出る**(Hard +4.6 / Expert +1.9 / Master +1.6 WAVE、実戦のほうが先まで届く)
- 使い道: 素の性能の並び(序盤を越えやすい子)。次はトレーニング・EX・アシカを足して、実戦との差を縮める
- `load-game.js` は `isTacticsMode` が無くクラシックの敵が出ていた → 直した。desk.md も作り直した

## 簡易シミュレーターの作り方(元の計画)

ブラウザなしで 10 WAVE を回し、1体あたり数百回。式はゲームのコードから写す(作り変えない)。

- そのまま使える(load-game.js): `createBattleEnemy`・`chooseEnemyAction`(random を渡せる)・`enemyActionProbabilities`・`chooseTacticsTarget`・`tacticsIntentTargets`・`resolveTacticsGuardedHit`・`tacticsEnemyPowerMultiplier`・`createTacticsUnit`・`buildAttackHits`・EX の状態の関数(32 の 970〜2408 行)
- 写す必要がある(60-app.jsx。React の中):
  - 与ダメージ `getDmg`(10967)・見込み `getAttackPredictedDmg`(11025)・即時補正 `localBoostFromCard`(10935)
  - 被ダメージ `getIncomingDamageBeforeTurnReduction`(10272)
  - カードのガッツ `getCardGuts`(9175)・1ターンの枚数 `baseCardLimit`(9129)・`slotMaxUses`
  - ガード量 `guardValueOf` / `guardDefFor`(10900 付近。`GUARD_EVOLUTION` は data/skills.js)
  - ターン終わりの回復(11689。ガッツ 5%・ライフ autoHpRecovery 10%)・捨てる(12830。1枚 5%)
  - 敵を出すとき `spawnEnemy`(13532。`tacticsEnemyPowerMultiplier(start, now)`)
  - ターンの流れ processTurn(12233〜)・敵の番(11257〜11560)
- 最初の版は「勇者モン1体で戦う WAVE 1〜2」から(勇者特性がいちばん効くところ)。ガード・捨てる・固有技までの単純な戦い方で回し、ブラウザの同じ条件の結果と合うかを確かめてから広げる
- 合わせ方: 同じ勇者・同じ難易度で、ブラウザの「届いた WAVE・倒すまでのターン・受けたダメージ」と比べる

## 2026-10-09 夜までの実戦(すべて解放・Hard と Expert を交互)

- Tier 表は 26/26 体・84 回。Hard は全員を勇者モンで1回以上。Hard の WAVE 10(覚醒ムー)は編成の総合力でライフが約2.6倍(52,500 → 138,522)になり、多くの回がここで負ける
- Hard をクリアした勇者モン: 剣士モッチー(2回)・スプーキー(2回)・ゴーレム・オボロゲソウ
- 追加で直したボットの取りこぼし: リザルトの見誤り(打ち切り)/ 難易度の札の送りすぎ(Hard のつもりが Expert)/ 供モンの記録の重なり / スプーキーの EX を回復待ちにして一度も使わなかった
- 次: 簡易シミュレーター(上)。Master の全種集め。5回以上そろった子から調整の案
