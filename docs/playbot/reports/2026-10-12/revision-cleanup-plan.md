## 2. 外せるもの/外せないもの

**外せる(段階的に)**
- 生成器・splice・tempo-warp などの **Rev.2〜20 の分かれ道**: 公開曲は Rev.1 か Rev.21 以上なので、2〜20 の区別は誰も使っていない
  (Rev.21 以上の曲には全部「入」、Rev.1 の曲には全部「切」)。まずは「Rev.1 か、それ以外か」の1本にまとめられる
- リビジョンの検査19本の大半(rev8〜rev20): その版の改良が「1つ前の版を変えない」ことを見るもので、古い版を作らなくなれば役目が終わる。
  かわりに「公開曲が使う7つのリビジョンの出力の指紋」を見る検査1本にまとめる(下の 3.)
- さらに先(段階4・判断が要る): Rev.1・21〜26 の道も外し、生成器は最新リビジョンだけ作る形にする

**外せない**
- 曲の一覧と譜面の JSON の `chartRevision` の欄と数字(データ。曲ごとにどの作り方で作ったかの記録。消すと遊んだ記録・感想と結び付かなくなる)
- `rhythm-chart-v3-revision.js` の番号の決め方(作り方・作法の重み・遊んだ記録の調整値の最大+1)。学び直し(`rhythm-chart-learn.js`)と遊んだ記録(`rhythm-play-log.js`・`rhythm-chart-feel-report.js`)が番号で引く
- 作法の重み(`rhythm-chart-knowledge.js`・Rev.7〜)と遊んだ記録の調整値(Rev.27・30): 番号ごとの値を持つデータ。値は残す
- 6レーン化の境目(Rev.5)と手のモデルの読み方(Rev.8・14): 公開中の Rev.1 の3曲が5レーン時代のものなら、検査や手のモデルが読むときに要る(段階1で確かめる)
- 公開中の譜面そのもの(`rhythm-mode.js`)と、その指紋の控え

## 3. 外しても「配信中の譜面が1音も変わらない」ことの確かめ方

1. **公開中の譜面は生成器を通らない**: ゲームが読むのは `rhythm-mode.js` に書き出した譜面だけ。`rhythm-released-chart-lock-check.js` が公開中の全譜面の指紋を見張る(CI でも回る)。
   整理の各段階で、この検査が控えを書き直さずに通ること(`--update` を使わない)
2. **作り直したら同じものができることの指紋を、外す前に取っておく**: 新しい道具 `rhythm-chart-revision-freeze.js`(段階0で作る)が、曲の一覧の43曲を
   それぞれのリビジョンで作り、出力(EASY〜MASTER の JSON)の sha256 を `authoring/revision-freeze.json` に書く。整理の各段階のあとに同じ道具で作り直して
   **指紋が1つも変わらない**ことを見る(段階1〜3)。段階4で古い道を外したあとは、その曲は「凍結」として指紋の表だけを残す
3. **古い作り方は git の記録から取り出せる**: 凍結の表に「最後に古い道を持っていたコミット」を書く。取り出し方は
   `git worktree add /tmp/old <コミット>` → `node tools/mode/rhythm-chart-v3-generate.js --track <曲> --chart-revision <N> --output-dir ...`。
   段階0で、そのコミットから実際に1曲作り直して指紋が一致することを確かめておく(リポジトリは浅い取り込みのことがあるので、必要なら `git fetch --deepen`)
4. 生成器の出力に頼る検査(39本)は、段階ごとに「最新リビジョンで作る」形へ寄せる。既存曲を作り直して比べている検査は、凍結の指紋の比べに置き換える
