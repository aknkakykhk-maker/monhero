# 染めたマスモンのアイコンの色ずれ(2026-10-13 ビート部 テンポくん)

社長の報告: マスモンとのセッション(モンヒロビートのマルチ)のチャットで、発言の左の丸いアイコンの染色がずれて見える(Android の折りたたみ・Chrome 系)。
スクショでは、剣士モッチー系が全身ひと色、カマキリ系が灰色の影だけ、白い花の子が白っぽく崩れていた。

## 原因
染めた絵は、元の絵の上に「部位ごとに染めた絵」を重ね、CSS の切り抜きの型(`mask-image`・その場で作った data URL の PNG)で部位の形に切り抜いていた。
この型が効かない端末では、部位ごとの染め絵がまるごと重なり、いちばん上の部位の色が全身を覆う。
- 型を無効にして直す前の版を撮ると、社長のスクショと同じ崩れ方になる(`before-after-nomask.webp` の上の段: 剣士モッチー・花の子・カマキリ)
- 手元のヘッドレス Chromium では型が効くので、ふつうに撮るとずれない(`before-widths-h7h8.webp`: 390@3・673@2.2・884@2.6・412@1.75 の4通りで全部合っていた)

## 直したこと
`DyedMonsterImage`(`src/parts/15-dye-and-art.jsx`)で、型の重ね合わせを CSS ではなく canvas で1枚の絵に焼き、`<img>` 1枚で出す。
重ね方は前と同じ(型のアルファで切り抜く・同じ縦横比で全面に重ねる・部位ごとの濃さ)。端末の型の描き方に左右されない。
- 焼き上がるまでは元の絵を出す。焼けなかったときだけ前の CSS の重ね方に戻る
- 焼いた絵は blob: のURLで出す(書き出しを画面の処理と分けるため。data URL だと染色40体で画面が合計2秒止まった→ blob で 0.11秒)。
  控えは64組まで・同じ種類と色なら使い回す。片づけは染め絵と同じ仕組み(表示中は片づけない)。長い辺は 768px まで
- 型の調整画面(デバッグ)は、動かしながら見るので今までどおり CSS で重ねる
- 染めの保存データ(`mh_*`)は触っていない

## 効く所(この部品を使う所は全部)
染めた絵を出す部品 `DyedMonsterImage` は 75か所で使われていて、部位で染め分ける子(`MASU_COLOR_REGION_HUES` のある子)は全部この直しで1枚に焼かれる。
主な画面: モンヒロビートのマルチ(チャット・部屋・シャッフル・結果・ランキング)・相棒のシート・マスモンの一覧と詳細・プロフィール・
マスモンの供え・ランキングの詳細・図鑑・バトルの切り込みの絵・染色の画面のプレビュー。
