# 場面のBGMを軽く持つ(#3083)の聞き比べ(2026-10-16)

どの動画も、**同じ曲の同じ所を「切(今まで)」→「入(軽く持つ)」の順に続けて流します**(場面ごとに 切12秒 → 入12秒。継ぎ目は10秒ずつ)。
音は、ゲームと同じ処理で作りました(Chromium で曲を 48kHz で解く → 入はそれを 24kHz に描き直す(14-audio.jsx の lightenBuffer と同じ OfflineAudioContext)→ 鳴らすときの 48kHz に戻す)。

| ファイル | 場面 | 曲 |
| --- | --- | --- |
| `bgm-light-title.mp4` | タイトル | bgm-title-theme.mp3 の 6〜18秒 |
| `bgm-light-home.mp4` | ホーム | bgm-monster-hero-theme.mp3 の 30〜42秒 |
| `bgm-light-battle.mp4` | バトル | bgm-battle.mp3 の 25〜37秒 |
| `bgm-light-loop.mp4` | ループの継ぎ目 | bgm-battle.mp3 の 終わり5秒 → 頭5秒(一周して戻るところ) |

## 数字(手元の Chromium)
- 持つ大きさ: タイトル 8→4MB / ホーム 56→28MB / バトル 23→11MB(入でちょうど半分)
- 入で消える音(12kHz より上): 曲全体の音より タイトル 28dB・ホーム 26dB・バトル 36dB 小さい音だけ(シンバルのいちばん上の響きなど。ほとんどの音は残る)
- 場面の切り替えで増える待ち時間(描き直し): タイトル 11ms / ホーム 68ms / バトル 27ms(曲を解く時間 105 / 677 / 274ms の約1割。iPhone ではこの数倍の見込み)

- ループの継ぎ目で、入のときにプツッ・途切れが増えていないか
