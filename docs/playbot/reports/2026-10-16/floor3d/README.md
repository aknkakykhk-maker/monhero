## 新しい参考動画(社長が撮影・2026-10-16 16:20)で確かめたこと

明るい白い道の画面(640×360・12fps)。見せ方は上の表と同じ方向だった。
- 地上: 床に平たく寝た細い板。奥ほど細く薄い。光らない(0:33 ごろ)
- 空中のタップ: 空中の線へ縦に下りる細い導線の上の、小さな平たい板(0:44 ごろ)。道が明るいので濃い色、10/11 の動画(暗い道)では白 → **道の明るさの反対の色で目立たせている**。こちらは色を今のまま(赤)にする(社長の決定)
- 空中スライド: 左手=水色・右手=桃色の半透明の幅広い帯。床から空中の線へ上がる
- 影・厚みの細かい量は、画質が粗くて読み取れなかった
- 譜面の作り方は [`CHART_FROM_REF.md`](CHART_FROM_REF.md)

## 色は今のまま・見せ方だけ(2026-10-16 社長「今の色の置き方は悪くないから、見せ方を変えるのがいいと思う」)

地上の種類ごとの色(タップの水色・フリックの桃など)も、空中の赤い箱・影の色も、今の決まり(`RHYTHM_NOTE_COLORS`・`RHYTHM_SKY_LOOK`)のまま。
変えたのは形と陰影だけ(床に寝た台形・手前の側面・光らせない/空中は上の面・手前の厚み・側面のある箱・床に寝た影)。

## 重さの比べ(CPU を4倍遅くした条件・Sheriruth HELL 70〜90秒)

1コマの時間(プロファイラなし・2回ずつ):

| | 平均 | 95% | 最長 | 50ms 超 |
| --- | --- | --- | --- | --- |
| 今の見た目 | 39.4 / 38.3ms | 83 / 67ms | 133 / 183ms | 77 / 81コマ |
| 試作 | 34.2 / 38.7ms | 67 / 67ms | 117 / 133ms | 68 / 79コマ |

関数ごとの時間(1秒あたり ms・1回ずつ): 毎コマの処理 `tick` 328.5 → 355.3(約8%増)。地上の粒 `drawHead` 30.6 → 18.7(光を描かないぶん減る)。
空中の箱 `drawGlassBox`+`drawGlassBox3d` 2.6 → 9.1、床の台形の計算 `floorQuad` 0.8。
コマの数字では悪くなっていない(差は測るたびのゆれの中)。実機(GPU のある iPhone)では、ゲームの処理は1コマ 1ms 前後なので、この差は見えない見込み。
