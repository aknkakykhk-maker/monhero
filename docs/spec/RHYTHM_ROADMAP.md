## 1-B. 基盤固定ライン（自動検査で確認した断面）

正式譜面の制作へ入るにあたり、**譜面制作中に「なんとなく」で動かさない値・構造**をここに固定する。
下の項目を変えると遠近・落下速度・判定・入力位置のいずれかが必ず動く。変更したくなった場合は
譜面側の都合で触らず、先に理由をユーザーへ確認する。

| 固定する対象 | 現在の値・構造 | 置き場所 |
| --- | --- | --- |
| レーンの収束率 | `RHYTHM_PROJECTION_TOP_SCALE = .18` | `data/rhythm-mode.js` |
| 奥行きの曲線 | `TOP + (1-TOP) * pow(clamp01(y), 1.24)` | `data/rhythm-mode.js` |
| メインレーン / サブレーン | 5 / 10 | `data/rhythm-mode.js` |
| プレイ画面のHUD | プレイエリアへ重ねる絶対配置。レイアウトの高さを取らない | `src/game-system.jsx` |
| HUDの背景 | 背景色・背景画像・影・ぼかしを一切持たない（JSX側・`index.html` 側の両方） | `src/game-system.jsx` / `index.html` |
| プレイエリアの高さ | 画面の上端から下端まで。上端側の inset 影は置かない | `index.html` |
| ノーツの落下時間 | `rhythmTravelMsForSpeed(noteSpeed)` のみ。**画面の向きで分岐させない** | `src/game-system.jsx` |
| 判定窓 | モンスターノーツでも共通（能力用に甘くしない） | `data/rhythm-mode.js` |
| スコアの重み | 判定90% / コンボ10% | `data/rhythm-mode.js` |
| ライフ | 最大1000。元気 `+500` / 根性の復活 `50` | `data/rhythm-mode.js` |
| 保存キー | 音ゲーで増やすのはマスモンの枠のみ。既存 `mh_*` は触らない | — |

### 固定時点で通した自動検査

`tools/mode/rhythm-*.js` の全47件、`check-syntax` / `undefined-reference-check` /
`jsx-text-brace-check` / `render-error-check` / `build.js --check`、
ヘルプ・助手・起動系の各検査をすべて成功させた状態を基準断面とする。

とくに次の3つは、過去に実際に壊して気づけなかった箇所を機械的に見張るためのもの。
譜面制作中も落ちたら必ず直す。

- `rhythm-hud-wedge-check.js` / `rhythm-landscape-hud-check.js`
  … HUDが背景を持たず、プレイエリアが画面上端から始まることを実ブラウザで計測する
  （`index.html` 側のグローバルCSSも読み込む）
- `rhythm-orientation-check.js`
  … 譜面・判定窓・スコア式を画面の向きで分けていないことを見る
- `rhythm-monster-notes-check.js`
  … 4能力の効果・重ねがけ・DOWN/復活・枠なし中央表示をまとめて見る

### 毎フレームの余裕（headless Chromiumでの実測）

ノーツは毎フレーム全件を走査する。ノーツ数を変えて1フレームあたりの走査コストを測った結果:

| ノーツ数 | 1フレーム | 16.7msに対して |
| --- | --- | --- |
| 52（DEBUG 60s の実数） | 0.03ms | 0.2% |
| 400 | 0.22ms | 1.3% |
| 800 | 0.45ms | 2.7% |
| 1600 | 0.89ms | 5.3% |

正式譜面が想定する規模では余裕があるため、**性能目的の作り替えは行わない**。
実機でのカクつきはiPhoneのDEBUG計測UIで確認する（STEP 2）。

## 3. 譜面制作ルールの追加方針

今後の正式譜面では、同時刻に横へ隣接し、見た目として1つに繋がるTAPを複数の別ノーツとして置かない。

例:

- 隣接する幅1 TAPが2個 → 幅2相当の1つの可変幅TAPとして制作
- 隣接する幅1 TAPが3個 → 幅3相当の1つの可変幅TAPとして制作
- 幅2 + 幅1が隙間なく連続する場合 → 可能なら連続範囲を1つの可変幅TAPとして制作

間に空白がある本当の同時押しは別ノーツのままにする。

この方針はruntimeで自動結合する仕様ではなく、**譜面を作るときの制作ルール**とする。
既存のデバッグ譜面を今すぐ一括修正する必要はなく、正式譜面の制作・調整時に適用する。

# 4. 先行公開する「音ゲー体験版」

正式版の完成を待たず、基礎がある程度固まった段階で、**1曲だけ遊べる音ゲー体験版を先行公開する**。

## 4.1 体験版の曲

先行公開曲は **Monster Hero** とする。

既存BGM登録:

- trackId: `monster_hero_theme`
- 表示名: `MonsterHero`
- 音源: `monster-hero/audio/bgm-monster-hero-theme.mp3`

既存音源を再利用し、体験版のために同じ音源を複製しない。

`あつ杯テーマ DEBUG 60s` は引き続き開発・総合回帰確認用とし、先行公開曲にはしない。

## 4.2 体験版の難易度

体験版では **3難易度** を遊べるようにする。

1. EASY
2. NORMAL
3. HARD

EXPERT / MASTER は体験版のプレイ対象外。
体験版UIで非表示にするか、将来難易度として非活性表示するかは現時点では未確定なので、実装時に勝手に決めない。

## 4.3 3難易度の役割

### EASY

- 初めて音ゲーへ触る人向け
- TAP中心
- HOLDは少なめ
- 激しい左右移動や複雑な同時押しを避ける
- モンスターノーツは意識して狙える位置へ置く

### NORMAL

- 標準的な遊び方を見せる
- TAP / HOLD / FLICK
- 可変幅ノーツを自然に使用
- EASYより密度・左右移動を増やす

### HARD

- 現在の音ゲーシステムの広さをある程度体験できる難易度
- TAP / HOLD / FLICK / SLIDE
- 0.5レーンや可変幅SLIDE、複合操作を必要な範囲で使用
- DEBUG譜面のような機能詰め込みではなく、曲として気持ちよく遊べることを優先する

## 5. Monster Hero 体験版譜面の制作順

### STEP 3〜5: Monster Hero EASY / NORMAL / HARD

**自動で作れるところまで完了（2026-09-03）。** 3難易度の正式候補v1をデバッグ導線で
全尺プレイできる状態にした。詳細は `docs/spec/RHYTHM_MODE.md` の
「12.5 体験版の先行公開曲『Monster Hero』」を参照。

| | EASY | NORMAL | HARD |
| --- | --- | --- | --- |
| ノーツ数 | 176 | 212 | 266 |
| 密度 | 1.22/秒 | 1.45/秒 | 1.80/秒 |
| 種別 | TAP / HOLD | ＋FLICK | ＋SLIDE |
| 置き場所 | 8分のみ | 8分のみ | 16分裏も |
| レーン移動 | 1つまで | 2つまで | 3つまで |
| 同時押し | なし | なし | 長押し中の別TAPのみ |

済んだこと:

- 実音源の解析でBPM 173.153 / `beatZeroMs` 206ms / 16分グリッド86.63msを確定
- 3難易度とも±30ms以内の候補だけを採用し、超えたものは `earReviewGrids` へ保留
- 隣接同時TAPを作らないので、可変幅1ノーツ化の制作ルールに自動的に従う
- モンスターノーツ4体を各難易度の 20 / 40 / 60 / 80% 付近へ配置
- `songId: monster_hero_theme_candidate` としてデバッグ画面から全尺プレイ可能に
- 109項目の検査で、配置の規則・難易度の並び・runtimeとの一致を機械的に確認

残っていること（ここから先は実機の耳が要る）:

- iPhoneで3難易度を全尺プレイし、拍・小節・フレーズ・キメに合っているかを確認
- `earReviewGrids`（EASY 25 / NORMAL 37 / HARD 78点）の採用・移動・不採用を決める
- 密度・レーンの流れ・HOLD/FLICK/SLIDEの位置を曲に合わせて手直し
- 難易度差が自然か、押しにくいだけの配置になっていないかの確認
- 正式runtime・BESTへの接続

自動生成した配置は出発点であり、これで完成扱いにはしない。

以下は当初からの方針（変更なし）。

#### EASY

- 初めて音ゲーへ触る人向け / TAP中心 / HOLDは少なめ
- 激しい左右移動や複雑な同時押しを避ける
- モンスターノーツは意識して狙える位置へ置く

#### NORMAL

- 標準的な遊び方を見せる / TAP・HOLD・FLICK / 可変幅ノーツを自然に使用
- EASYより密度・左右移動を増やす

#### HARD

- 現在の音ゲーシステムの広さをある程度体験できる難易度
- 0.5レーンや可変幅SLIDE、複合操作を必要な範囲で使用
- 機能詰め込みではなく、曲として気持ちよく遊べることを優先する

# 10. 体験版後の正式版ロードマップ

### STEP 10: Monster Heroを5難易度へ拡張

体験版の3難易度を土台に、EXPERT / MASTERを制作する。

### STEP 11: 正式HOMEを完成

- 楽曲選択
- 5難易度選択
- 自己ハイスコア
- クリア / 達成状況
- オプション
- マスモン設定
- プレイ / リザルト導線

を正式版として整理する。

### STEP 12: マスモン連携の残りを検討・実装

現行設計で残っている候補:

- 曲 / BPMに合わせたマスモン演出
- 音ゲープレイでマスモンへ経験値を入れる仕組み

経験値量は本編育成バランスへ影響するため、実装前に最新mainの育成効率と比較して決める。

### STEP 13: 2曲目・3曲目の正式譜面を制作

Monster Heroで確立した譜面制作ルールを再利用し、正式曲を増やす。
各曲は公開対象にする難易度を完成させ、デバッグ譜面を正式譜面扱いにしない。

### STEP 14: 永続全国ランキング

既存設計に従い正式ランキングを実装する。
モンスターノーツ能力込みのプレイは正式攻略要素として扱い、能力使用有無で別部門には分けない方針を維持する。

### STEP 15: 正式曲3曲以上で週間システム

週間システムは**正式譜面が完成している曲が3曲以上揃ってから**進める。

想定:

- 毎週3曲
- 各曲ランキング3部門
- 週間総合1部門
- 週間ミッション
- 順位報酬
- 参加報酬
- リセット / 受取 / 同点処理

3曲揃う前に週間システムを一般公開しない。

### STEP 16: 最終仕上げ

- 演出
- SE
- コンボ演出
- マスモン演出
- 横画面
- 軽量モード
- 長時間プレイ
- 各種端末回帰
- ヘルプ / 更新履歴

### STEP 17: 音ゲー正式公開

正式公開は、必要な正式曲・HOME・ランキング・保存・実機回帰が揃ったあと、ユーザーの明示許可を受けて行う。
