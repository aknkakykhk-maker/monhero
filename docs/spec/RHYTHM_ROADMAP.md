## 1-B. 基盤固定ライン（自動検査で確認した断面）

正式譜面の制作へ入るにあたり、**譜面制作中に「なんとなく」で動かさない値・構造**をここに固定する。
下の項目を変えると遠近・落下速度・判定・入力位置のいずれかが必ず動く。変更したくなった場合は
譜面側の都合で触らず、先に理由をユーザーへ確認する。

| 固定する対象 | 現在の値・構造 | 置き場所 |
| --- | --- | --- |
| レーンの収束率 | `RHYTHM_PROJECTION_TOP_SCALE = .18` | `data/rhythm-mode.js` |
| 奥行きの曲線 | `TOP + (1-TOP) * pow(clamp01(y), 1.24)` | `data/rhythm-mode.js` |
| メインレーン / サブレーン | 5 / 10 | `data/rhythm-mode.js` |
| プレイ画面のHUD | プレイエリアへ重ねる絶対配置。レイアウトの高さを取らない | `src/game-system.jsx` |
| HUDの背景 | 背景色・背景画像・影・ぼかしを一切持たない（JSX側・`index.html` 側の両方） | `src/game-system.jsx` / `index.html` |
| プレイエリアの高さ | 画面の上端から下端まで。上端側の inset 影は置かない | `index.html` |
| ノーツの落下時間 | `rhythmTravelMsForSpeed(noteSpeed)` のみ。**画面の向きで分岐させない** | `src/game-system.jsx` |
| 判定窓 | モンスターノーツでも共通（能力用に甘くしない） | `data/rhythm-mode.js` |
| スコアの重み | 判定90% / コンボ10% | `data/rhythm-mode.js` |
| ライフ | 最大1000。元気 `+500` / 根性の復活 `50` | `data/rhythm-mode.js` |
| 保存キー | 音ゲーで増やすのはマスモンの枠のみ。既存 `mh_*` は触らない | — |

### 固定時点で通した自動検査

`tools/mode/rhythm-*.js` の全47件、`check-syntax` / `undefined-reference-check` /
`jsx-text-brace-check` / `render-error-check` / `build.js --check`、
ヘルプ・助手・起動系の各検査をすべて成功させた状態を基準断面とする。

とくに次の3つは、過去に実際に壊して気づけなかった箇所を機械的に見張るためのもの。
譜面制作中も落ちたら必ず直す。

- `rhythm-hud-wedge-check.js` / `rhythm-landscape-hud-check.js`
  … HUDが背景を持たず、プレイエリアが画面上端から始まることを実ブラウザで計測する
  （`index.html` 側のグローバルCSSも読み込む）
- `rhythm-orientation-check.js`
  … 譜面・判定窓・スコア式を画面の向きで分けていないことを見る
- `rhythm-monster-notes-check.js`
  … 4能力の効果・重ねがけ・DOWN/復活・枠なし中央表示をまとめて見る

## 1-C. STEP 0: 現行HUD最終修正＋基盤固定準備（完了・2026-09-04）

STEP 1（iPhone実機での基盤固定）へ進む前に、公開直後にCodexレビューで指摘された
ランクゲージの表示不具合だけを先に直した。**レーンgeometry・projection曲線・判定窓・
入力座標・ノーツ落下時間には一切触れていない**（HUD/表示ロジックのみの変更）。

修正内容:

- `rhythmNextRankId(score, maxScore)` に第2引数`maxScore`（難易度ごとの満点、
  `RHYTHM_DIFFICULTIES`の`maxScore`）を追加。次ランクのしきい値が今の難易度の満点を
  超える場合は「次は無い(★MAX)」として扱うようにし、EASY(満点60万=A上限)なのに
  「→S」のような絶対に届かない次ランクを表示してしまう不具合を直した。
- ランク自体の判定・しきい値（`RHYTHM_RANKS`）、スコア計算、`rhythmRankForScore`、
  `rhythmRankProgress`は変更していない。

難易度ごとの満点における期待挙動（確認済み）:

| 難易度 | 満点 | 満点時のランク | 満点到達時の次ランク表示 |
| --- | --- | --- | --- |
| EASY | 600,000 | A | ★MAX |
| NORMAL | 700,000 | S | ★MAX |
| HARD | 800,000 | SS | ★MAX |
| EXPERT | 900,000 | M | ★MAX |
| MASTER | 1,000,000 | M | ★MAX |

※この表の「満点時のランク」はSTEP 0のこの修正を行った時点のもの。直後の「1-D」で
ランクのしきい値自体を1段ずつシフトしたため、現在の対応は1-Dを参照
（EASY→B / NORMAL→A / HARD→S / EXPERT→SS / MASTER→M）。

回帰確認（`tools/mode/rhythm-*.js`含む自動検査で確認、実機確認は別途iPhoneで実施）:

- ランクゲージ本体・目盛り表示
- 100コンボごとの演出が200 / 300 / 400 / 500以降も毎回出ること
- 500以降は最大段階(stage 5)を再利用すること
- FULL COMBO / ALL EXCELLENT / ALL MARVELOUSのcelebrate画面
- celebrate → result遷移
- 軽量モード / 演出量MINIMALでcelebrate・派手な演出をスキップすること

## 1-D. ランクしきい値を1段シフト（2026-09-04、STEP 0の続き）

ユーザー指示で `RHYTHM_RANKS` の各しきい値を1段ずつ上へずらした
（＝同じ点数で付くランクは1段ずつ下がる）。これもHUD/表示ロジックのみの変更で、
レーンgeometry・判定窓・入力座標・ノーツ落下時間・スコア計算式には触れていない。

理由: 旧しきい値ではEXPERTの満点(90万点)もMASTERの満点(100万点)と同じM評価に届いてしまい、
「MASTERの満点だけがMへ届く」という当初の設計意図と実際の挙動が食い違っていた。

| 難易度 | 満点 | 旧: 満点時のランク | 新: 満点時のランク |
| --- | --- | --- | --- |
| EASY | 600,000 | A | B |
| NORMAL | 700,000 | S | A |
| HARD | 800,000 | SS | S |
| EXPERT | 900,000 | M | SS |
| MASTER | 1,000,000 | M | M（ここだけ変わらず、唯一Mへ届く） |

`RHYTHM_RANKS`のG(0点)以外の9段のしきい値をすべて100,000ずつ引き上げた
（G→F→E→D→C→B→A→S→SS→Mの並び自体・段数・`rhythmRankForScore`/`rhythmRankProgress`/
`rhythmNextRankId`のロジックは変更していない。しきい値の定数だけを変えている）。
最新の値は本書ではなく`docs/spec/RHYTHM_MODE.md`「3.5. スコアランク」を正本とする。

## 1-E. 全国ランキング「モンビー」の先行実装（2026-09-04）

「10. 体験版後の正式版ロードマップ」のSTEP14（永続全国ランキング）は、本来STEP8の
体験版公開よりあとに予定していたが、ユーザーから「本実装で細かい実装はするが、
先行公開時にも全国ランキングがほしい」と明示の指示があり、Monster Hero 1曲分を
先行実装した。

要点（詳細設計は`docs/spec/RHYTHM_MODE.md`「9.5 全国ランキング『モンビー』」を正本とする）:

- 新テーブル・新列は増やさず、既存`rankings`テーブルの`difficulty`列へ
  `Rhythm-<songId>-<難易度id>`という専用キーを入れるだけで区別する
  （種族チャレンジの`Species-<血統>-<難易度>`と同じ考え方）
- EASY/NORMAL/HARDを1本にまとめた「難易度合算」方式。難易度が高いほど満点も高いため、
  高い難易度で挑むほど上位に近づく
- 自分のスコアは、これまでの中でいちばん高い1件だけが表示される
  （書き込みは1プレイ＝1行のまま、表示のときにユーザー名ごとの最高得点へ畳む）
- 各行に「詳細」ボタンを付け、判定内訳・最大コンボ・達成称号を確認できる
  （既存の`party`列へJSONで持たせる。新しい列は増やしていない）
- 体験版ホームから始めたプレイだけを送信し、デバッグ画面からのプレイは送信しない
- 送信に失敗したときだけ、新規キー`mh_rhythm_rank_pending_v1`(直近20件)へ退避する
  （既存のBEST記録`mh_rhythm_best_v1`には影響しない）
- 識別・不正対策は通常バトル等の既存ランキングと同じ水準
  （ブリーダー名ベース、クライアントからの送信をそのまま信頼）

STEP14で残っているのは、2曲目以降を追加したときの接続確認と、モンスターノーツ能力込みの
プレイを正式攻略要素として扱う方針の最終確認だけ（キー設計自体はsongIdを含むため、
曲を増やすだけで対応できる見込み）。

## 1-F. STEP1実機確認: タップ感度（隣接サブレーン重なり閾値）を調整（2026-09-04）

STEP1のiPhone実機確認中、ユーザーから「1つの指で3個（サブレーン）まで押すのが難しい」
という指摘があった。原因は`RHYTHM_TOUCH_MIN_SUBLANE_COVERAGE`（隣接サブレーンへどれだけ
重なったら接触扱いにするかの閾値）が25%と厳しめだったこと。

- `RHYTHM_TOUCH_MIN_SUBLANE_COVERAGE`を`.25`→`.20`へ緩和し、指腹の接触判定を少し広くした
- 判定窓・スコア計算・接触半径縮小(`RHYTHM_TOUCH_RADIUS_SCALE=.70`)・固定3上限なしの方針・
  異常値guardは変更していない（`docs/spec/RHYTHM_MODE.md`「入力: iPhone Touch接触幅」参照）
- 広すぎる誤爆（意図しない隣接サブレーンの誤検出）が起きていないか、引き続き実機で確認する

これはSTEP1の実機確認の中で見つかった調整であり、STEP1自体はこの後も続く。

## 3. 譜面制作ルールの追加方針

今後の正式譜面では、同時刻に横へ隣接し、見た目として1つに繋がるTAPを複数の別ノーツとして置かない。

例:

- 隣接する幅1 TAPが2個 → 幅2相当の1つの可変幅TAPとして制作
- 隣接する幅1 TAPが3個 → 幅3相当の1つの可変幅TAPとして制作
- 幅2 + 幅1が隙間なく連続する場合 → 可能なら連続範囲を1つの可変幅TAPとして制作

間に空白がある本当の同時押しは別ノーツのままにする。

この方針はruntimeで自動結合する仕様ではなく、**譜面を作るときの制作ルール**とする。
既存のデバッグ譜面を今すぐ一括修正する必要はなく、正式譜面の制作・調整時に適用する。

# 4. 先行公開する「音ゲー体験版」

正式版の完成を待たず、基礎がある程度固まった段階で、**1曲だけ遊べる音ゲー体験版を先行公開する**。

## 4.1 体験版の曲

先行公開曲は **Monster Hero** とする。

既存BGM登録:

- trackId: `monster_hero_theme`
- 表示名: `MonsterHero`
- 音源: `monster-hero/audio/bgm-monster-hero-theme.mp3`

既存音源を再利用し、体験版のために同じ音源を複製しない。

`あつ杯テーマ DEBUG 60s` は引き続き開発・総合回帰確認用とし、先行公開曲にはしない。

## 4.2 体験版の難易度

体験版では **3難易度** を遊べるようにする。

1. EASY
2. NORMAL
3. HARD

EXPERT / MASTER は体験版のプレイ対象外。
体験版UIで非表示にするか、将来難易度として非活性表示するかは現時点では未確定なので、実装時に勝手に決めない。

## 4.3 3難易度の役割

### EASY

- 初めて音ゲーへ触る人向け
- TAP中心
- HOLDは少なめ
- 激しい左右移動や複雑な同時押しを避ける
- モンスターノーツは意識して狙える位置へ置く

### NORMAL

- 標準的な遊び方を見せる
- TAP / HOLD / FLICK
- 可変幅ノーツを自然に使用
- EASYより密度・左右移動を増やす

### HARD

- 現在の音ゲーシステムの広さをある程度体験できる難易度
- TAP / HOLD / FLICK / SLIDE
- 0.5レーンや可変幅SLIDE、複合操作を必要な範囲で使用
- DEBUG譜面のような機能詰め込みではなく、曲として気持ちよく遊べることを優先する
