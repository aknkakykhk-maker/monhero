# モンヒロビートの実績の仕組み（2026-10-05）

**ユーザー指示**「モンビーの曲でフルコンボ、オールエクセレント、オールマーベラスの実績の仕組みを作って。今後そこに報酬をいれたい。
報酬内容はまだ決まってないから仕組みだけ作っといてほしい」

**いまは報酬が無い。** 実績を台帳に記録し、後から報酬を足せる受け口だけを作った。プレイヤーに見える変化は無い
（プロフィールの「モンヒロビートの実績」表は、これまでどおりBESTから数えている）。

## 実績とは

「曲 × 難易度 × 称号」ごとに1つ。称号は3つで、**上の称号を取れば下の称号も取ったことになる**（AM ⊃ AE ⊃ FC。プロフィールの実績表と同じ数え方）。

| 称号 | id | 条件（`rhythmResultAchievements`） |
| --- | --- | --- |
| FC フルコンボ | `fullCombo` | BAD と MISS が 0 |
| AE オールエクセレント | `allExcellent` | GREAT・GOOD・BAD・MISS が 0 |
| AM オールマーベラス | `allMarvelous` | 全ノーツが MARVELOUS |

実績のidは `曲のid:難易度:称号`（例 `mf_ichika_mix:EXPERT:fullCombo`）。

## 取れたかの正本は、BEST記録のまま

`mh_rhythm_best_v1` の各記録に、`fullCombo`・`allExcellent`・`allMarvelous` が**一度取れたら残る形**で入っている（`mergeRhythmBestRecord`）。
実績はこの印を読むだけで、**BESTには何も足さない・書き換えない**。したがって、次の扱いはBESTと同じになる。

- アシストモード・練習・タイミング合わせのプレイはBESTに残らない → 実績にもならない
- 一度取った実績は下がらない（BESTが下がらない）
- 実績の仕組みより前に取っていた称号も、BESTに残っていれば実績になる

## 台帳（`mh_rhythm_achievements_v1`）

BESTだけでは分からない「いつ取ったか」と「報酬を受け取ったか」を持つ、**新しい保存キー**。

```
{ v:1,
  items:   { '曲:難易度:称号': { at: 取った時刻(ms) } },     // at=0 は「仕組みより前から取っていた（時刻は不明）」
  claimed: { '実績のid#報酬ルールのid': 受け取った時刻(ms) } }
```

- 壊れた項目は読まずに捨てるだけで、ほかの項目は残す（`normalizeRhythmAchievementLedger`）。曲の一覧は見ずに整えるので、
  曲が増減しても・一覧を読み込む前でも台帳は減らない。件数に上限（4000）
- **受け取り済みの印は、時刻が読めなくても消さない**（二重に渡さないため）
- BESTと同期するのは「足す」ことだけ（`syncRhythmAchievementLedger`）。消さない。何度走らせても同じ結果になる

### いつ同期するか（`recordRhythmAchievements`）

| 場面 | 呼び方 | 結果 |
| --- | --- | --- |
| モンヒロビートを開いたとき（通常・デバッグ） | `recordRhythmAchievements(BEST)` | 台帳が無ければ、すでに取れていたぶんを**時刻不明（0）**で取り込む。あれば足りないぶんを足す |
| 曲を遊び終えてBESTを保存した直後 | `recordRhythmAchievements(新BEST, { initialRecords: 保存前のBEST })` | 台帳が無ければ保存前のBESTを時刻0で取り込み、保存前との差を**いま取れた**（時刻あり）として足す |

後者の `initialRecords` があるので、**初めて遊ぶ人の最初のフルコンボも「いま取れた」になる**（「すでに取っていたぶん」に混ざらない）。
返り値の `added` が、今回新しく取れた実績のid。報酬や「達成」の表示を出すときの種になる（いまは使っていない）。

台帳に触る処理は順番待ちにしてある（`rhythmAchievementEnqueue`）。「読む → 待つ → 書く」を同時に走らせると、あとから書いたほうだけが残るため
（ビートPで一度踏んだ。`addRhythmEventPoints` と同じ理由）。保存を読めなくても例外は外へ出さず、BESTの保存や遊びを止めない。

## 報酬の受け口（いまは空）

### 報酬ルール（`RHYTHM_ACHIEVEMENT_REWARDS`・`13-bgm-and-rhythm-settings.jsx`）

報酬が決まったら、ここへルールを足すだけで始められる。

```js
{ id: 'fc-expert-beat-p',            // ルールの名前。英数字と _ - の40字まで。**後から変えない**（受け取り済みの印に使うため）
  kinds: ['fullCombo'],              // 称号の絞り込み。null ならすべて
  difficulties: ['EXPERT', 'MASTER'],// 難易度の絞り込み。null ならすべて
  songs: null,                       // 曲の絞り込み。null ならすべて
  since: 0,                          // 取った時刻(ms)の下限。省略または 0 なら、すでに取っていた実績にも遡って配る
  reward: { type: 'beatP', amount: 100 } }  // 報酬の種類と中身
```

- 形が正しくないルール（名前の綴り・報酬の形・知らない称号・同じ名前の2つ目）は捨てる（`normalizeRhythmAchievementRules`）
- **`since` を書かないと、すでに取っていた実績にも遡って配る。** 「これから取る分だけ」にしたいときは、公開の時刻を `since` に書く
  （時刻不明の 0 は `since` を書くと対象外になる）
- 同じ実績へ後から別のルールを足しても、別々に受け取れる（受け取り済みの印は「実績のid#ルールのid」）

### 渡す処理（`RHYTHM_ACHIEVEMENT_GRANTERS`・`25-storage.jsx`）

報酬の種類ごとに、`async (reward, info) => 渡せたら true` を足す。`info` は `{achievementId, songId, difficultyId, kind, ruleId}`。

- **渡す処理が無い種類・false を返す・例外を投げるときは、渡さず受け取り待ちのまま残す**（受け取り済みの印は付けない）
- 渡せた**直後に1件ずつ**「受け取り済み」を書く。途中で落ちても、渡し済みのぶんは二重に渡さない
  （渡してから書くまでの一瞬に落ちると二重に渡る余地はあるが、渡し損ねるよりよいと判断した）
- 公開していない曲・難易度（デバッグ用）で取れた実績には渡さない（`rhythmAchievementEligible`）
- **ルールが空のあいだは、受け取りの処理は読み書きを一切しない**

### 報酬を足す手順

1. `RHYTHM_ACHIEVEMENT_REWARDS` にルールを足す
2. 報酬の種類の渡す処理を `RHYTHM_ACHIEVEMENT_GRANTERS` に足す（ビートP・ダイヤ・アイテムなど。**増えた分が二重に入らない**書き方で）
3. `node tools/mode/rhythm-achievement-check.js` を通す。出荷しているルールが正しい形か、渡す処理があるかは、この検査が見る
4. 更新履歴・ヘルプに書く（報酬はプレイヤーに見える）。受け取りの通知を出すなら、`recordRhythmAchievements` の返り値 `added` を使う

## 検査

- `tools/mode/rhythm-achievement-check.js` … 実装を取り出して偽の保存で動かす。称号の数え方・壊れた保存値・BESTとの同期・報酬ルールの検証・
  受け取り待ちの絞り込み・一度だけ渡す・渡せなかったら待つ・1件ずつ書く・順番待ち・保存が読めなくても落ちない・画面側の配線
- `tools/mode/rhythm-achievement-browser-check.js` … 本物のゲームを開いて、開いたときの取り込み・BESTの保存値が書き換わらないこと・
  公開している曲だけが報酬の対象になることを見る

## 決めていないこと（報酬を決めるときに）

- 報酬の中身（種類・個数）と、称号・難易度ごとの差
- すでに取っていた実績にも配るか（既定は遡って配る）
- 受け取りの通知の出し方（結果画面・実績の一覧画面など）。いまは画面を作っていない
- 「難易度ごとに○曲」のような**数を達成条件にする報酬**（いまのルールは、1つの実績ごと）
