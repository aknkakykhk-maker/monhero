# クイック∞周回 × モンヒロビート 連携 — 設計書

2026-09-06 にユーザーと決めた内容をまとめたもの。**まだ実装していない**（この文書だけが先行している）。
着手するときは、まず [`docs/refactor/REGRESSION_RISK_MAP.md`](../refactor/REGRESSION_RISK_MAP.md) を読むこと。

## 1. 何をしたいか

クイックモードの∞周回は「放置していても経験値・ダイヤ・絆が貯まる」のが値打ち。
一方モンヒロビート（以下モンビー）は1曲2分ほどの別モードで、遊んでいる間は周回が完全に止まる。

**モンビーを開いているあいだも∞周回が進むようにする。**
「演奏していなくても、モンビーのページにいるだけで意味がある」状態を作るのが目的
（2026-09-06 ユーザー指示）。

## 2. 決めたこと

| 項目 | 決定 | 備考 |
| --- | --- | --- |
| 実装方式 | **モンビーの非演奏画面では本物のバトルを裏で回す。演奏中だけ止め、曲が終わってから追いつかせる** | 演奏中に負荷をかけない。§4 |
| 対象モード | **クイックのみ** | チャレンジ・プロ・極限・種族は全国ランキング対象なので裏で回さない |
| 報酬 | **等倍** | 通常の∞周回と同じ。ヘッドレス分も同じ計算を使うので根拠がぶれない |
| 演奏中の扱い | **止めたうえで、曲が終わった時点でその時間ぶんを追いつかせる** | §4.3 |
| 周回中のバトル音 | **消す**（BGM・SEとも） | モンビー側の試聴・曲と重ならないように。超省エネの仕組みを流用 |
| 動線 | ①∞周回中にモンビーへ飛ぶ ②モンビーから周回を始める ③モンビー中に周回の進捗を出す | §5 |

### 3.1 `gameState` が2つの役目を兼ねている

`gameState` は「いま描いている画面」と「ランの進行段階」を同時に表している。
モンビーを開くと前者が変わるので、後者まで巻き添えで止まる。**この2つを分けるのが今回の核心**。

`RUN_PHASE_STATES`（`60-app.jsx:2031`）という似た名前の定数が既にあるが、
これはBGMの切り替え用で進行の管理はしていない。混同しないよう別の名前を使う。

## 4. 設計

### 4.1 ランの進行段階を画面から分ける

`runStage`（ランが無いときは `null`）を新しく持ち、ランの進行はこれで進める。
画面は `gameState` のまま。バトルUIは描かれないだけで、ランは生きている。

```
これまで: gameState === 'BATTLE'      → ターンを進める
これから: runStage  === 'BATTLE' かつ 周回が止まっていない → ターンを進める
```

- `gameState` は画面の正本、`runStage` はランの正本にする
- バトル画面を描いているあいだは `gameState` と `runStage` が同じ値で並走する（既存の挙動と一致する）
- ランが無いときは `runStage=null`。既存の全モードは何も変わらない

**これは案A・案Bどちらへ進んでも必要な土台**なので、最初のPRで入れる。

### 4.2 モンビーの2つの状態

| モンビーの状態 | `gameState` | 周回 |
| --- | --- | --- |
| ホーム・曲えらび・遊びかた・マスモン枠・ランキング | `RHYTHM_DEMO_HOME` / `RHYTHM_DEMO_HELP` / `RHYTHM_DEMO_MONSTERS` / `RHYTHM_RANKING` | **本物のバトルが裏で回る** |
| 演奏中 | `RHYTHM_PLAY` | **止める**（ターンの切れ目で自然に停止） |

非演奏画面は60fpsも精密入力も要らないので、既存のバトル処理をそのまま回してよい。
止め方は、既存ループの `blocked` 条件へ「演奏中か」を足すだけ。
ループは「状態が変わったら次のターンを予約する」形なので、**ターンの切れ目で止まり、
フラグが下りれば再開する**。ランの状態は保持されるので、途中から続けられる。

### 4.3 演奏中ぶんの追いつき（ヘッドレス周回）

演奏中は計算も描画も保存もしない。**曲が終わった時点で「この時間ぶんに進むはずだった量」を
まとめて計算して反映する。**

- 反映は演奏リザルトが出たあと1回だけ。演奏中に `storeSet` を走らせない
- 計算はSTEP 5で一本化した `buildAttackHits` / `ATTACK_COMBO_RULES` を使い、
  **本物のバトルと同じ正本から出す**（数値を二重に持たない）
- 追いつきの上限を決める（例: 1曲ぶん = 演奏時間まで）。
  タブを閉じていた時間まで遡って配ることは**しない**（∞周回の既存方針と揃える）

> ⚠ シミュレータと本物が食い違うと、静かにバランスが壊れる。
> `tools/battle/damage-parity-check.js` と同じ手で、
> **同じ乱数列で本物の周回とシミュレータの結果が一致する検査を先に書いてから**実装する。

### 4.4 音

モンビーにいるあいだはバトルのBGMとSEを止め、モンビー側の音（試聴・曲）だけを鳴らす。
超省エネ（`ultraEcoSession`、`60-app.jsx:516`・`2122`）が既に
「SE音量を0にする／ミュートして戻す」を持っているので、同じ仕組みを流用する。
**ユーザーが手で変えた音量設定は上書きしない**（超省エネと同じ約束）。

## 5. 画面と動線

1. **∞周回中にモンビーへ飛ぶ** — クイックのバトル画面・リザルトから「🎵 モンビーへ」を出す。
   `returnToHome` を通さず `openRhythmDemo` 相当へ直接移る（§3の1行目・2行目が理由）
2. **モンビーから周回を始める** — モンビーのホームに「裏でクイックを回す」トグルを置く。
   編成・難易度は `repeatRunTemplateRef` の周回テンプレートを使う。
   テンプレートが無い（まだ1度も周回していない）ときはトグルを押せないようにし、
   「クイックで∞周回を1度始めてください」と出す
3. **モンビー中に周回の進捗を出す** — モンビーのホーム／曲えらびに
   「◯周目・獲得ダイヤ・獲得経験値」を小さく出し、クイック画面へ戻るボタンを置く

> リザルトに「この1曲で◯周」を出す案は、今回は入れない（2026-09-06 ユーザー判断）。
> 3の進捗表示で足りるか確かめてから決める。

## 6. 守ること

- **新しい保存キーを作らない。** 周回の記録は既存の `mh_quick_*` のまま。
  進捗表示はメモリ上の値だけで作り、保存しない（リロードで消えてよい）
- **ランキングへ送らない。** クイックは元から全国ランキング対象外・チャレンジの自己ベストも
  上書きしない設計なので、その性質をそのまま使う。新しい送信経路を作らない
- **本当のバックグラウンド（タブ非表示）では止める。** 既存の `visibilityState` の見張りは残す
- **音ゲーの曲時刻・判定窓・投影の数式を触らない**（`REGRESSION_RISK_MAP.md` §4-1）
- **演奏中に `storeSet` を呼ばない**（同期のlocalStorage書き込みでノーツを落とす）
- 既存モード（チャレンジ・プロ・極限・種族）の挙動を1つも変えない

## 7-1. PR2で入ったもの（2026-09-06）

`60-app.jsx` に次の3つを置き、ランの進行を回す3つのループがこれだけを見るようにした。
バトル画面を描いている間は `runStage === gameState` で、**挙動は何も変わっていない**。

```js
const RUN_STAGE_SCREENS = [...RUN_PHASE_STATES,'BATTLE'];  // 画面の表は既存の定数を再利用
const runStage = RUN_STAGE_SCREENS.includes(gameState) ? gameState : null;
const runProgressAllowed = runStage !== null;              // ← PR3で変えるのはこの行
```

寄せたループは、ターン進行・WAVE後の各段・次周開始の3つ。
**PR3では `runProgressAllowed` に「モンビーの非演奏画面ならtrue」を足し、
`runStage` を画面から離れても保つようにする。**
