# モンヒロビート イベントP・交換所システム設計書

> **ステータス: 暫定仕様 / 商品基準の一部確定**
>
> 本書は、モンヒロビートの「イベントP」と、それを使用する交換所システムについて、2026-09-14 時点で決まっている内容をまとめる。
> イベントPの骨格、交換所の基本運用、初期商品の一部と価格基準は合意済み。
> 勇者の証系・虹の超越の実・アイコン・将来の円盤石やアシスト等は未確定であり、実装側が推測で補完しない。

## 1. 目的

モンヒロビートの期間限定イベントに、ランキングとは別の継続報酬として「イベントP」を追加する。

イベントPは以下によって獲得量が変化する。

- イベントを遊んだ回数
- そのプレイで出したスコア
- イベント対象曲を遊んだか

ランキングだけでは上位入賞できないプレイヤーにもイベントを遊ぶ目的を持たせつつ、高スコアを出す価値も残す。
獲得したイベントPは常設の交換所で使用する。

## 2. 基本方針

イベントPシステムはランキングとは独立させる。

- ランキング: プレイヤー同士でスコア・順位を競う
- イベントP: イベント期間中にプレイした量とスコアに応じて蓄積する
- イベント対象曲: イベントP獲得量にボーナスを与える
- イベントP交換所: 貯めたイベントPを任意の商品へ交換する

ランキング用スコアとイベントP計算を混同しない。

## 3. イベントPの種類

### 3.1 共通イベントP

通常の期間限定イベントでは、共通のイベントPを使用する。

- イベント終了時にリセットしない
- 次回以降のイベントへ持ち越せる
- イベントをまたいで同じ残高を使用する

### 3.2 特殊イベント専用P

将来的に、特殊イベントだけ専用イベントPを使用できる拡張性を持たせる。

ただし通常運用では共通イベントPを使用する。
専用Pが必要になった時点で、以下を個別に仕様追加する。

- 持ち越し有無
- 有効期間
- 専用交換所の扱い
- イベント終了後の処理

現時点では専用イベントPを実運用しない。

## 4. イベントP獲得期間

イベントPを獲得できるのは、モンヒロビートの期間限定イベント開催中のみ。
イベント期間外はモンヒロビートをプレイしてもイベントPを獲得しない。

開催判定には既存の期間限定イベント設定を利用する。

## 5. イベントP獲得対象曲

イベント開催期間中は、公開されている通常のモンヒロビート楽曲すべてでイベントPを獲得できる。
イベント対象曲だけに限定しない。

曲倍率は暫定で以下とする。

- 通常曲: 1.0倍
- イベント対象曲: 1.5倍

対象曲以外をプレイする自由を残しつつ、イベント対象曲を遊ぶメリットを設ける。

## 6. イベントP基本計算

主なプレイヤースコア帯として、以下を想定する。

- 約80万点: 下位側
- 約95万点以上: 主要帯
- 95万〜100万点付近: 特に差を付けたい帯

そのため、95万点までは緩やかに増加し、95万点を超えてからイベントPの伸びが大きくなる計算を採用する。

### 6.1 基本式

```text
基本イベントP =
floor(
  スコア ÷ 10,000
  + max(0, スコア - 950,000) ÷ 500
)
```

### 6.2 計算例

| スコア | 基本イベントP |
| ---: | ---: |
| 800,000 | 80P |
| 850,000 | 85P |
| 900,000 | 90P |
| 950,000 | 95P |
| 960,000 | 116P |
| 970,000 | 137P |
| 980,000 | 158P |
| 990,000 | 179P |
| 1,000,000 | 200P |

95万点を超えると、約1万点のスコア差で約21Pの差が生まれる。

## 7. イベント対象曲倍率

基本イベントPを計算した後、そのプレイ曲に応じて倍率を適用する。

```text
通常曲倍率 = 1.0
イベント対象曲倍率 = 1.5

最終イベントP = floor(基本イベントP × 曲倍率)
```

例:

- 980,000点: 通常曲158P / イベント対象曲237P
- 1,000,000点: 通常曲200P / イベント対象曲300P

## 8. ランキングとの分離

イベント対象曲1.5倍はイベントPにのみ使用する。
以下には影響させない。

- 通常リザルトスコア
- ベストスコア
- 週間ランキング
- イベントランキング
- 総合ランキング
- 既存ランキング用ボーナス計算

また、イベントランキング側の回数ボーナス等をイベントPへ流用しない。
イベントPは、その1プレイで実際に出したリザルトスコアから独立して計算する。

## 9. イベントP付与タイミング

イベント期間中は、正常に完了したプレイごとにイベントPを付与する。
ベストスコア更新の有無は問わない。

同じ曲を何度プレイしても、その都度イベントPを獲得できる。
プレイ回数とスコアの両方がイベントP獲得効率へ影響する。

## 10. 付与対象外

少なくとも以下はイベントP獲得対象外とする。

- イベント開催期間外
- プレイ途中で終了した場合
- ギブアップ等で正常リザルトまで到達していない場合
- DEBUG専用曲
- スコアや記録を残さないテスト・練習用途

具体的な既存プレイモード判定は実装時に最新mainを確認する。

## 11. 二重付与防止

1回のプレイ結果に対してイベントPを複数回付与してはならない。

リザルト画面の再描画、画面遷移、Reactの再実行等によって同一結果が重複処理されないようにする。
既存のスコア確定・保存処理との境界を実装時に確認し、イベントP付与は1プレイにつき1回のみとする。

## 12. イベントP保存

イベントPは既存セーブとの後方互換を維持した新規保存項目として追加する。

- 既存の `mh_*` キーを変更・削除・意味変更しない
- 既存ユーザーに新しい保存項目が存在しない場合は0Pとして正規化する
- イベント終了時に削除・リセットしない

具体的な保存キー名は実装時に既存保存設計と照合して確定する。

## 13. マーケット構造再編

イベントP交換所追加に伴い、マーケットの横並びタブ増加を避けるため、マーケット全体を階層型へ変更する。

マーケットTOPは「通常ショップ / 交換所」の2分類にはせず、プレイヤーが何を使って商品を入手する場所なのかが分かる入口構成とする。

### 13.1 マーケットTOP

マーケットへ入ると、最初に以下の4種類をカード形式で選択する。

1. ダイヤショップ
2. ブリーダーP交換所
3. アイテム交換所
4. イベントP交換所

### 13.2 TOPカードのレイアウト

スマートフォン縦画面を基準として、カードは横2列のグリッドで配置する。

現時点の4種類では2列×2段となるが、カードそのものを大きくしすぎない。
将来カテゴリが増えた場合も同じサイズ感のまま縦方向へ追加できる構造とし、少なくとも横2列×縦4段程度（最大8入口程度）までは大きな再設計なしで扱えることを目安とする。

- 横方向へ小さいタブを追加し続けない
- 入口カードはコンパクトな中サイズを基本とする
- タップ領域はスマートフォン操作に十分な大きさを確保する
- 入口追加時は縦方向へ自然に増える構造にする

### 13.3 TOPカードの所持数表示

マーケットTOPでは以下のみ所持数を表示する。

- ダイヤショップ: 現在のダイヤ所持数
- ブリーダーP交換所: 現在のブリーダーP所持数
- イベントP交換所: 現在のイベントP所持数

アイテム交換所は交換素材が複数存在するため、TOPカードでは個別所持数を表示しない。
虹のプシュケー、勇者の証片、勇者の証などの所持数はアイテム交換所へ入った後に表示する。

## 14. ダイヤショップ

ダイヤを消費して入手する既存商品を配置する。

現行の商品種別を踏まえ、円盤石・アシスト・アイテム等を扱う。
商品数が多い場合は、ダイヤショップへ入った後に既存の商品種別に応じたタブ・カテゴリ切り替えを使用できる。

マーケットTOP再編によって既存商品の価格、購入結果、所持判定、販売状態を変更しない。
既存の商品購入処理・商品カード・詳細表示は可能な限り再利用する。

## 15. ブリーダーP交換所

ブリーダーPを使用する商品を配置する。

現行では主にブリーダーアイコン等のブリーダーP商品を扱う想定とする。
マーケットTOP再編によって既存商品の価格、購入結果、所持判定を変更しない。

## 16. アイテム交換所

ダイヤやブリーダーPではなく、所持アイテムを交換素材として使用する既存・将来の交換をまとめる。

想定する交換素材の例:

- 虹のプシュケー
- 勇者の証片
- 勇者の証
- 今後追加される交換用アイテム

アイテム交換所へ入った後は、交換に関係する各アイテムの所持数を確認できるようにする。

既存の「証片から勇者の証へ交換」等の処理は、UI再編によって交換条件・必要数・結果を変更しない。
具体的にどの既存商品・交換をこの画面へ移すかは、実装時に最新mainの通貨・交換条件を確認して決定する。

## 17. イベントP交換所

イベントP交換所は常設する。
イベント非開催期間でも利用可能。

- イベント中: P獲得可能 / 交換可能
- イベント外: P獲得不可 / 交換可能

イベントPを獲得できる期間と、交換できる期間は分離する。

イベントP交換所では複数種類の商品を取り扱える。

想定:

- 通常アイテム
- 育成アイテム
- スキップチケット
- 円盤石
- アシストカード
- アイコン等のコレクション商品
- その他将来追加商品

初期段階では商品種類ごとに別画面へ分ける必要はない。
商品数が増え、一覧性が悪化した場合にのみイベントP交換所内部へ追加カテゴリを設けられる構造とする。

## 18. 交換回数制限

現時点の基本運用では、イベントP交換所の商品は**すべて交換回数無制限**とする。

- 消耗品も無制限
- 育成アイテムも無制限
- スキップチケットも無制限
- 常設のコレクション商品についても、商品そのものが重複所持できない既存仕様を持つ場合を除き、イベントP側では回数制限を設けない

将来どうしても個別上限が必要な商品が生じた場合に備えて、商品データ側は交換上限を持てる拡張性を残してよい。
ただし、現時点で1回・3回・5回等のイベントごとの交換制限は使用しない。

## 19. 商品ラインナップ方式

イベントP交換所の商品は、**基本的にすべて常設**とする。

イベント終了後も商品を消さず、イベントPを持ち越して好きなタイミングで交換できることを基本運用とする。
商品が増えた場合も、既存商品を期間終了で削除するのではなく、常設商品として積み上げていく。

将来的に特別な理由がある商品だけ期間限定販売へ拡張できる構造は残してよいが、現時点では通常運用として期間限定商品を前提にしない。

## 20. 初期商品と価格基準

### 20.1 現時点の合意商品

以下をイベントP交換所の初期商品・価格基準として扱う。

| 商品 | 1回の交換内容 | 必要イベントP | 備考 |
| --- | ---: | ---: | --- |
| ダイヤ | 300 | 1P | クイック周回で集めやすいため低単価枠 |
| トレーニングチケット | 3枚 | 1P | 1枚あたり絆EXP15。低単価枠 |
| 重トレーニングチケット | 1枚 | 3P | 通常トレーニングチケット10枚ぶんの育成量 |
| 虹のプシュケー | 1個 | 1P | 1個単位で交換 |
| スキップチケット・序 | 1枚 | 10P | Normal用 |
| スキップチケット・破 | 1枚 | 16P | Hard用 |
| スキップチケット・急 | 1枚 | 23P | Expert用 |
| スキップチケット・極 | 1枚 | 50P | Master用。新規追加予定 |
| スキップチケット・覇 | 1枚 | 100P | Grand Master用。新規追加予定 |

ダイヤ・トレーニングチケットは、現在のゲーム環境ではクイック周回で比較的集めやすく実質価値が低いため、イベントP交換では意図的に低単価へ置く。
イベントP全体の価値をこの2商品だけで決めず、今後追加する入手困難商品・コレクション商品を交換所の中長期的な目標にする。

### 20.2 スキップチケットの対応難易度とダイヤ価格

既存3種のダイヤ販売価格を見直し、新たに上位2種を追加する方針とする。

| チケット | 対応難易度 | 難易度の経験値倍率 | ダイヤ価格 | イベントP |
| --- | --- | ---: | ---: | ---: |
| 序 | Normal | ×1 | 3,000 | 10P |
| 破 | Hard | ×2 | 5,000 | 16P |
| 急 | Expert | ×3 | 7,000 | 23P |
| 極 | Master | ×5 | 15,000 | 50P |
| 覇 | Grand Master | ×8 | 30,000 | 100P |

上位2種の名称は「極」「覇」とする。
Hell / Legend用スキップチケットは今回の対象外とする。

イベントP価格は、経験値倍率だけの単純換算ではなく、以下を含むスキップチケット全体の実用価値を見て設定する。

- 10WAVEクリア相当のブリーダー経験値
- 難易度倍率に応じた絆経験値
- クリア相当のダイヤ
- 勇者モン・参加マスモン・控えへの絆経験値配布
- 周回時間を省略できる利便性

そのため、トレーニングチケットの絆EXPだけから算出した価格より高く設定する。
序10P / 破16P / 急23P / 極50P / 覇100Pを現時点の採用値とする。

### 20.3 今後追加する商品の考え方

イベントP交換所は、安い日用品だけで完結させない。

今後は以下のような商品を常設追加する想定とする。

- 勇者の証片
- 勇者の証
- 虹の超越の実
- アイコン
- 円盤石
- アシストカード
- その他の入手困難品・コレクション商品

これらの必要イベントPはまだ決定しない。
既存経済との相対価値を確認してから本書へ追記する。

## 21. UI表示

### 21.1 モンヒロビートのリザルト

イベント期間中は今回獲得したイベントPを表示する。

例:

```text
イベントP +158P
```

イベント対象曲の場合は、1.5倍ボーナスが適用されたことが分かる表示を行う。

### 21.2 曲選択画面

イベント開催期間中は現在の共通イベントP所持数を表示する。
イベント期間外の表示要否は現時点では必須としない。

### 21.3 イベントP交換所

現在の所持イベントPを常時確認できるようにする。

交換回数は無制限のため、複数個・複数枚を交換する商品についてはスマートフォンで連打を強制しないUIを優先する。
数量指定、増減ボタン、まとめ交換等の具体方式は実装時に既存マーケットUIと合わせて決定する。

### 21.4 HOME

HOMEへイベントPを常時表示しない。
通貨表示の乱立を避ける。

## 22. モバイルUI

既存方針どおりスマートフォン縦画面を最優先する。

特にマーケット再編では以下を優先する。

- マーケットTOPは横2列のカードグリッドとする
- 2列×2段を前提にカードを巨大化せず、将来は2列×4段程度まで自然に増やせるサイズ感とする
- 小さいタブをTOPへ大量に横並びにしない
- タップ領域を十分確保する
- iPhone Safariで見切れない
- Safe Areaを考慮する
- 商品一覧へ入った後の既存操作性を不必要に変えない

## 23. 既存システムとの互換性

本機能追加によって以下を意図せず変更しない。

- 既存ランキング
- 既存イベントランキング
- 既存スコア
- モンヒロビートBEST
- セーブデータ
- 既存マーケット商品の所持状態
- 円盤石購入処理
- アシスト購入処理
- アイテム購入処理
- ブリーダーアイコン購入処理
- 既存のアイテム交換条件・交換結果

マーケットUIを再編しても、既存の商品・価格・購入結果・交換結果・所持状態を変えない。
今回のマーケット再編は原則として「商品や交換をどの入口から見るか」の変更として扱う。

ただし本仕様で明示したスキップチケットの価格改定と、新規スキップチケット・極 / 覇の追加は別途実装対象とする。

## 25. バランス調整方針

現在のイベントP計算式およびイベント曲1.5倍は暫定値とする。
実際のイベント運用、プレイ回数、交換商品の価格帯を確認したうえで調整可能とする。

特にダイヤ・トレーニングチケットはクイック周回で集めやすいため、その既存入手性を基準に低単価へ置く。
逆に、今後の入手困難品・コレクション商品はイベントPを貯める中長期目標として価格を設定する。

ただし計算式を変更しても、過去に獲得済みのイベントPを遡って再計算しない。
商品価格を変更した場合も、過去の交換を遡って差額補填・差額回収しない。
