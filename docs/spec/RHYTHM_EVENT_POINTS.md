# モンヒロビート ビートP・交換所システム設計書

> **ステータス: STEP4 正式公開済み**
>
> 実装状況（2026-09-15）: プレイヤー向け名称を「ビートP」とし、STEP4で正式公開済み。ビートP交換所はイベントの開催有無や残高にかかわらず常設し、STEP3の固定12商品・数量選択・原子的保存をそのまま利用する。イベント非開催中は新規ビートPを獲得しない。対象アイコン未決定の「アイコン 2,000P」は未実装のまま残す。
>
> 本書は、モンヒロビートの「ビートP」と、それを使用する交換所システムについて、2026-09-15 時点の正式仕様をまとめる。
> ビートPの骨格、初期獲得式、イベント対象曲倍率、交換所の基本運用、初期商品の価格基準は実装済み。
> 将来追加する円盤石・アシストカード・その他追加商品や、個別の販売対象選定が必要な商品は、実装側が推測で補完しない。

### 用語と内部互換

- プレイヤー向け正式名称は「ビートP」「ビートP交換所」「所持ビートP」とする。
- 旧称「イベントP」はSTEP3までの開発履歴を説明する場合に限って使用する。
- 内部識別子の `eventPoints`、`rhythmEventPoints`、`RHYTHM_EVENT_POINTS_*`、`RHYTHM_EVENT_POINT_SHOP_OFFERS` は互換性と変更範囲最小化のため維持する。
- 保存キー `mh_rhythm_event_points_v1` は変更・削除せず、既存残高をそのまま引き継ぐ。名称変更に伴う初期配布・補填・残高リセットは行わない。

## 1. 目的

モンヒロビートの期間限定イベントに、ランキングとは別の継続報酬として「ビートP」を追加する。

ビートPは以下によって獲得量が変化する。

- イベントを遊んだ回数
- そのプレイで出したスコア
- イベント対象曲を遊んだか

ランキングだけでは上位入賞できないプレイヤーにもイベントを遊ぶ目的を持たせつつ、高スコアを出す価値も残す。
獲得したビートPは常設の交換所で使用する。

## 2. 基本方針

ビートPシステムはランキングとは独立させる。

- ランキング: プレイヤー同士でスコア・順位を競う
- ビートP: イベント期間中にプレイした量とスコアに応じて蓄積する
- イベント対象曲: ビートP獲得量にボーナスを与える
- ビートP交換所: 貯めたビートPを任意の商品へ交換する

ランキング用スコアとビートP計算を混同しない。

## 3. ビートPの種類

### 3.1 共通ビートP

通常の期間限定イベントでは、共通のビートPを使用する。

- イベント終了時にリセットしない
- 次回以降のイベントへ持ち越せる
- イベントをまたいで同じ残高を使用する

### 3.2 特殊イベント専用P

将来的に、特殊イベントだけ専用ビートPを使用できる拡張性を持たせる。

ただし通常運用では共通ビートPを使用する。
専用Pが必要になった時点で、以下を個別に仕様追加する。

- 持ち越し有無
- 有効期間
- 専用交換所の扱い
- イベント終了後の処理

現時点では専用ビートPを実運用しない。

## 4. ビートP獲得期間

ビートPを獲得できるのは、モンヒロビートの期間限定イベント開催中のみ。
イベント期間外はモンヒロビートをプレイしてもビートPを獲得しない。

開催判定には既存の期間限定イベント設定を利用する。

## 5. ビートP獲得対象曲

イベント開催期間中は、公開されている通常のモンヒロビート楽曲すべてでビートPを獲得できる。
イベント対象曲だけに限定しない。

曲倍率は初期正式値として以下を採用する。

- 通常曲: 1.0倍
- イベント対象曲: 1.5倍

対象曲以外をプレイする自由を残しつつ、イベント対象曲を遊ぶメリットを設ける。

## 6. ビートP基本計算

主なプレイヤースコア帯として、以下を想定する。

- 約80万点: 下位側
- 約95万点以上: 主要帯
- 95万〜100万点付近: 特に差を付けたい帯

そのため、95万点までは緩やかに増加し、95万点を超えてからビートPの伸びが大きくなる計算を採用する。
以下の式を初回実装の正式値とする。

### 6.1 基本式

```text
基本ビートP =
floor(
  スコア ÷ 10,000
  + max(0, スコア - 950,000) ÷ 500
)
```

### 6.2 計算例

| スコア | 基本ビートP |
| ---: | ---: |
| 800,000 | 80P |
| 850,000 | 85P |
| 900,000 | 90P |
| 950,000 | 95P |
| 960,000 | 116P |
| 970,000 | 137P |
| 980,000 | 158P |
| 990,000 | 179P |
| 1,000,000 | 200P |

95万点を超えると、約1万点のスコア差で約21Pの差が生まれる。

## 7. イベント対象曲倍率

基本ビートPを計算した後、そのプレイ曲に応じて倍率を適用する。

```text
通常曲倍率 = 1.0
イベント対象曲倍率 = 1.5

最終ビートP = floor(基本ビートP × 曲倍率)
```

例:

- 980,000点: 通常曲158P / イベント対象曲237P
- 1,000,000点: 通常曲200P / イベント対象曲300P

## 8. ランキングとの分離

イベント対象曲1.5倍はビートPにのみ使用する。
以下には影響させない。

- 通常リザルトスコア
- ベストスコア
- 週間ランキング
- イベントランキング
- 総合ランキング
- 既存ランキング用ボーナス計算

また、イベントランキング側の回数ボーナス等をビートPへ流用しない。
ビートPは、その1プレイで実際に出したリザルトスコアから独立して計算する。

## 9. ビートP付与タイミング

イベント期間中は、正常に完了したプレイごとにビートPを付与する。
ベストスコア更新の有無は問わない。

同じ曲を何度プレイしても、その都度ビートPを獲得できる。
プレイ回数とスコアの両方がビートP獲得効率へ影響する。

## 10. 付与対象外

少なくとも以下はビートP獲得対象外とする。

- イベント開催期間外
- プレイ途中で終了した場合
- ギブアップ等で正常リザルトまで到達していない場合
- DEBUG専用曲
- スコアや記録を残さないテスト・練習用途

具体的な既存プレイモード判定は実装時に最新mainを確認する。

## 11. 二重付与防止

1回のプレイ結果に対してビートPを複数回付与してはならない。

リザルト画面の再描画、画面遷移、Reactの再実行等によって同一結果が重複処理されないようにする。
既存のスコア確定・保存処理との境界を実装時に確認し、ビートP付与は1プレイにつき1回のみとする。

## 12. ビートP保存

ビートPは既存セーブとの後方互換を維持した保存項目として扱う。

- 既存の `mh_*` キーを変更・削除・意味変更しない
- 既存ユーザーに新しい保存項目が存在しない場合は0Pとして正規化する
- イベント終了時に削除・リセットしない

初期実装の保存キーは `mh_rhythm_event_points_v1` とする。値は0以上の整数へ正規化し、欠損・不正値は0として扱う。
STEP4正式公開では公開フラグ `RHYTHM_EVENT_POINTS_PUBLIC_RELEASE` を `true` とする。公開フラグONは交換所の常設公開を示すが、獲得可否は既存のイベント期間判定を必ず通し、イベント非開催中は付与しない。

## 13. マーケット構造再編

ビートP交換所追加に伴い、マーケットの横並びタブ増加を避けるため、マーケット全体を階層型へ変更する。

マーケットTOPは「通常ショップ / 交換所」の2分類にはせず、プレイヤーが何を使って商品を入手する場所なのかが分かる入口構成とする。

### 13.1 マーケットTOP

マーケットへ入ると、最初に以下の4種類をカード形式で選択する。

1. ダイヤショップ
2. ブリーダーP交換所
3. アイテム交換所
4. ビートP交換所

### 13.2 TOPカードのレイアウト

スマートフォン縦画面を基準として、カードは横2列のグリッドで配置する。

現時点の4種類では2列×2段となるが、カードそのものを大きくしすぎない。
将来カテゴリが増えた場合も同じサイズ感のまま縦方向へ追加できる構造とし、少なくとも横2列×縦4段程度（最大8入口程度）までは大きな再設計なしで扱えることを目安とする。

- 横方向へ小さいタブを追加し続けない
- 入口カードはコンパクトな中サイズを基本とする
- タップ領域はスマートフォン操作に十分な大きさを確保する
- 入口追加時は縦方向へ自然に増える構造にする

### 13.3 TOPカードの所持数表示

マーケットTOPでは以下のみ所持数を表示する。

- ダイヤショップ: 現在のダイヤ所持数
- ブリーダーP交換所: 現在のブリーダーP所持数
- ビートP交換所: 現在のビートP所持数

アイテム交換所は交換素材が複数存在するため、TOPカードでは個別所持数を表示しない。
虹のプシュケー、勇者の証片、勇者の証などの所持数はアイテム交換所へ入った後に表示する。

## 14. ダイヤショップ

ダイヤを消費して入手する既存商品を配置する。

現行の商品種別を踏まえ、円盤石・アシスト・アイテム等を扱う。
商品数が多い場合は、ダイヤショップへ入った後に既存の商品種別に応じたタブ・カテゴリ切り替えを使用できる。

マーケットTOP再編によって既存商品の価格、購入結果、所持判定、販売状態を変更しない。
既存の商品購入処理・商品カード・詳細表示は可能な限り再利用する。

## 15. ブリーダーP交換所

ブリーダーPを使用する商品を配置する。

現行では主にブリーダーアイコン等のブリーダーP商品を扱う想定とする。
マーケットTOP再編によって既存商品の価格、購入結果、所持判定を変更しない。

## 16. アイテム交換所

ダイヤやブリーダーPではなく、所持アイテムを交換素材として使用する既存・将来の交換をまとめる。

想定する交換素材の例:

- 虹のプシュケー
- 勇者の証片
- 勇者の証
- 今後追加される交換用アイテム

アイテム交換所へ入った後は、交換に関係する各アイテムの所持数を確認できるようにする。

既存の「証片から勇者の証へ交換」等の処理は、UI再編によって交換条件・必要数・結果を変更しない。
具体的にどの既存商品・交換をこの画面へ移すかは、実装時に最新mainの通貨・交換条件を確認して決定する。

## 17. ビートP交換所

ビートP交換所は常設する。
イベント非開催期間でも利用可能。

- イベント中: P獲得可能 / 交換可能
- イベント外: P獲得不可 / 交換可能

ビートPを獲得できる期間と、交換できる期間は分離する。残高が0Pでも入口・所持残高・12商品を表示し、交換ボタンだけを無効にする。

ビートP交換所では複数種類の商品を取り扱える。

想定:

- 通常アイテム
- 育成アイテム
- スキップチケット
- 円盤石
- アシストカード
- アイコン等のコレクション商品
- その他将来追加商品

初期段階では商品種類ごとに別画面へ分ける必要はない。
商品数が増え、一覧性が悪化した場合にのみビートP交換所内部へ追加カテゴリを設けられる構造とする。

## 18. 交換回数制限

現時点の基本運用では、ビートP交換所の商品は**すべて交換回数無制限**とする。

- 消耗品も無制限
- 育成アイテムも無制限
- スキップチケットも無制限
- 常設のコレクション商品についても、商品そのものが重複所持できない既存仕様を持つ場合を除き、ビートP側では回数制限を設けない

将来どうしても個別上限が必要な商品が生じた場合に備えて、商品データ側は交換上限を持てる拡張性を残してよい。
ただし、現時点で1回・3回・5回等のイベントごとの交換制限は使用しない。

## 19. 商品ラインナップ方式

ビートP交換所の商品は、**基本的にすべて常設**とする。

イベント終了後も商品を消さず、ビートPを持ち越して好きなタイミングで交換できることを基本運用とする。
商品が増えた場合も、既存商品を期間終了で削除するのではなく、常設商品として積み上げていく。

将来的に特別な理由がある商品だけ期間限定販売へ拡張できる構造は残してよいが、現時点では通常運用として期間限定商品を前提にしない。

## 20. 初期商品と価格基準

### 20.1 初期実装商品・価格

以下をビートP交換所の初期実装における商品価格として採用する。正式公開時は対象未決定のアイコンを除く固定12商品を実装する。

| 商品 | 1回の交換内容 | 必要ビートP | 備考 |
| --- | ---: | ---: | --- |
| ダイヤ | 300 | 5P | クイック周回で集めやすいため低単価枠 |
| トレーニングチケット | 3枚 | 5P | 1枚あたり絆EXP15。低単価枠 |
| 重トレーニングチケット | 1枚 | 15P | 通常トレーニングチケット10枚ぶんの育成量 |
| 虹のプシュケー | 1個 | 5P | 1個単位で交換 |
| スキップチケット・序 | 1枚 | 50P | Normal用 |
| スキップチケット・破 | 1枚 | 80P | Hard用 |
| スキップチケット・急 | 1枚 | 115P | Expert用 |
| スキップチケット・極 | 1枚 | 250P | Master用 |
| スキップチケット・覇 | 1枚 | 500P | Grand Master用 |
| 勇者の証片 | 1個 | 500P | 20個で勇者の証1個へ交換できる既存仕様との整合を取る |
| アイコン | 1個 | 2,000P | コレクション枠。具体的な対象アイコンは実装側で推測せず、既存商品を確認して選定する |
| 虹の超越の実 | 1個 | 5,000P | 中長期目標の育成枠 |
| 勇者の証 | 1個 | 10,000P | 高価値の常設目標枠 |

> **2026-09-17の改定（ユーザー指示）**: 勇者の証片・虹の超越の実・勇者の証の**3つを据え置き**、
> それ以外の9商品を**5倍**にした。ビートPの入手量に対して低単価枠が安すぎたため、
> 高額の目標（証片・虹の超越の実・勇者の証）との差を広げるのが狙い。
> 据え置いた3つの関係は変わらないので、下の「証片×20個＝勇者の証1個」の対応もそのまま成り立つ。

勇者の証片は500P×20個＝10,000Pとなり、勇者の証を直接10,000Pで交換する場合とビートP価値を一致させる。
証片経由と直接交換のどちらを選んでも、ビートP上の有利不利を作らない。

ダイヤ・トレーニングチケットは、現在のゲーム環境ではクイック周回で比較的集めやすく実質価値が低いため、ビートP交換では意図的に低単価へ置く。
ビートP全体の価値をこの2商品だけで決めず、勇者の証片・虹の超越の実・勇者の証・アイコン等を交換所の中長期的な目標にする。

アイコンは1個2,000Pを初期価格基準とする。
初回実装でどの既存アイコンをビートP交換対象へ並べるかは、最新mainの商品構成を確認して別途選定する。実装側が独自判断で全アイコンを対象化しない。

### 20.2 スキップチケットの対応難易度とダイヤ価格

スキップチケット5種のダイヤ販売価格とビートP価格は以下とする。

| チケット | 対応難易度 | 難易度の経験値倍率 | ダイヤ価格 | ビートP |
| --- | --- | ---: | ---: | ---: |
| 序 | Normal | ×1 | 3,000 | 50P |
| 破 | Hard | ×2 | 5,000 | 80P |
| 急 | Expert | ×3 | 7,000 | 115P |
| 極 | Master | ×5 | 15,000 | 250P |
| 覇 | Grand Master | ×8 | 30,000 | 500P |

上位2種の名称は「極」「覇」とする。
Hell / Legend用スキップチケットは今回の対象外とする。

ビートP価格は、経験値倍率だけの単純換算ではなく、以下を含むスキップチケット全体の実用価値を見て設定する。

- 10WAVEクリア相当のブリーダー経験値
- 難易度倍率に応じた絆経験値
- クリア相当のダイヤ
- 勇者モン・参加マスモン・控えへの絆経験値配布
- 周回時間を省略できる利便性

そのため、トレーニングチケットの絆EXPだけから算出した価格より高く設定する。
序50P / 破80P / 急115P / 極250P / 覇500Pを正式値とする（2026-09-17に5倍へ改定）。

### 20.3 今後追加する商品の考え方

ビートP交換所は、安い日用品だけで完結させない。

初期実装後は、必要に応じて以下のような商品を常設追加できる。

- 円盤石
- アシストカード
- 追加アイコン
- その他の入手困難品・コレクション商品

これらのうち、円盤石・アシストカード・その他新規商品の必要ビートPはまだ決定しない。
追加アイコンは原則2,000Pを価格基準とし、別価格にする場合は個別に仕様変更する。
既存経済との相対価値を確認してから本書へ追記する。

## 21. UI表示

### 21.1 モンヒロビートのリザルト

イベント期間中は今回獲得したビートPを表示する。

例:

```text
ビートP +158P
```

イベント対象曲の場合は、1.5倍ボーナスが適用されたことが分かる表示を行う。

### 21.2 曲選択画面

イベント開催期間中はビートPを獲得できることを曲選択画面に表示する。イベント期間外は獲得案内を出さない。

### 21.3 ビートP交換所

現在の所持ビートPを常時確認できるようにする。

交換回数は無制限のため、複数個・複数枚を交換する商品についてはスマートフォンで連打を強制しないUIを優先する。
数量指定、増減ボタン、まとめ交換等の具体方式は実装時に既存マーケットUIと合わせて決定する。

### 21.4 HOME

HOMEへビートPを常時表示しない。
通貨表示の乱立を避ける。

## 22. モバイルUI

既存方針どおりスマートフォン縦画面を最優先する。

特にマーケット再編では以下を優先する。

- マーケットTOPは横2列のカードグリッドとする
- 2列×2段を前提にカードを巨大化せず、将来は2列×4段程度まで自然に増やせるサイズ感とする
- 小さいタブをTOPへ大量に横並びにしない
- タップ領域を十分確保する
- iPhone Safariで見切れない
- Safe Areaを考慮する
- 商品一覧へ入った後の既存操作性を不必要に変えない

## 23. 既存システムとの互換性

本機能追加によって以下を意図せず変更しない。

- 既存ランキング
- 既存イベントランキング
- 既存スコア

## 25. バランス調整方針

初期実装では、本書のビートP計算式とイベント対象曲1.5倍を正式値として採用する。
実際のイベント運用、プレイ回数、交換商品の利用状況を確認したうえで、将来のアップデートで調整することは可能とする。

特にダイヤ・トレーニングチケットはクイック周回で集めやすいため、その既存入手性を基準に低単価へ置く。
逆に、勇者の証片・虹の超越の実・勇者の証・アイコン等はビートPを貯める中長期目標として扱う。

ただし計算式を変更しても、過去に獲得済みのビートPを遡って再計算しない。
商品価格を変更した場合も、過去の交換を遡って差額補填・差額回収しない。
