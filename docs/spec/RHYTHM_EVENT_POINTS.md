# モンヒロビート イベントP・交換所システム設計書

> **ステータス: 暫定仕様 / 今後変更・追加あり**
>
> 本書は、モンヒロビートの「イベントP」と、それを使用する交換所システムについて、2026-09-14 時点で決まっている骨格をまとめる。
> 交換所の商品ラインナップ、価格、正式名称などは未確定であり、今後ユーザーと決定した内容を追記・変更する。
> 未確定事項を実装側が推測で補完しない。

## 1. 目的

モンヒロビートの期間限定イベントに、ランキングとは別の継続報酬として「イベントP」を追加する。

イベントPは以下によって獲得量が変化する。

- イベントを遊んだ回数
- そのプレイで出したスコア
- イベント対象曲を遊んだか

ランキングだけでは上位入賞できないプレイヤーにもイベントを遊ぶ目的を持たせつつ、高スコアを出す価値も残す。
獲得したイベントPは常設の交換所で使用する。

## 2. 基本方針

イベントPシステムはランキングとは独立させる。

- ランキング: プレイヤー同士でスコア・順位を競う
- イベントP: イベント期間中にプレイした量とスコアに応じて蓄積する
- イベント対象曲: イベントP獲得量にボーナスを与える
- イベントP交換所: 貯めたイベントPを任意の商品へ交換する

ランキング用スコアとイベントP計算を混同しない。

## 3. イベントPの種類

### 3.1 共通イベントP

通常の期間限定イベントでは、共通のイベントPを使用する。

- イベント終了時にリセットしない
- 次回以降のイベントへ持ち越せる
- イベントをまたいで同じ残高を使用する

### 3.2 特殊イベント専用P

将来的に、特殊イベントだけ専用イベントPを使用できる拡張性を持たせる。

ただし通常運用では共通イベントPを使用する。
専用Pが必要になった時点で、以下を個別に仕様追加する。

- 持ち越し有無
- 有効期間
- 専用交換所の扱い
- イベント終了後の処理

現時点では専用イベントPを実運用しない。

## 4. イベントP獲得期間

イベントPを獲得できるのは、モンヒロビートの期間限定イベント開催中のみ。
イベント期間外はモンヒロビートをプレイしてもイベントPを獲得しない。

開催判定には既存の期間限定イベント設定を利用する。

## 5. イベントP獲得対象曲

イベント開催期間中は、公開されている通常のモンヒロビート楽曲すべてでイベントPを獲得できる。
イベント対象曲だけに限定しない。

曲倍率は暫定で以下とする。

- 通常曲: 1.0倍
- イベント対象曲: 1.5倍

対象曲以外をプレイする自由を残しつつ、イベント対象曲を遊ぶメリットを設ける。

## 6. イベントP基本計算

主なプレイヤースコア帯として、以下を想定する。

- 約80万点: 下位側
- 約95万点以上: 主要帯
- 95万〜100万点付近: 特に差を付けたい帯

そのため、95万点までは緩やかに増加し、95万点を超えてからイベントPの伸びが大きくなる計算を採用する。

### 6.1 基本式

```text
基本イベントP =
floor(
  スコア ÷ 10,000
  + max(0, スコア - 950,000) ÷ 500
)
```

### 6.2 計算例

| スコア | 基本イベントP |
| ---: | ---: |
| 800,000 | 80P |
| 850,000 | 85P |
| 900,000 | 90P |
| 950,000 | 95P |
| 960,000 | 116P |
| 970,000 | 137P |
| 980,000 | 158P |
| 990,000 | 179P |
| 1,000,000 | 200P |

95万点を超えると、約1万点のスコア差で約21Pの差が生まれる。

## 7. イベント対象曲倍率

基本イベントPを計算した後、そのプレイ曲に応じて倍率を適用する。

```text
通常曲倍率 = 1.0
イベント対象曲倍率 = 1.5

最終イベントP = floor(基本イベントP × 曲倍率)
```

例:

- 980,000点: 通常曲158P / イベント対象曲237P
- 1,000,000点: 通常曲200P / イベント対象曲300P

## 8. ランキングとの分離

イベント対象曲1.5倍はイベントPにのみ使用する。
以下には影響させない。

- 通常リザルトスコア
- ベストスコア
- 週間ランキング
- イベントランキング
- 総合ランキング
- 既存ランキング用ボーナス計算

また、イベントランキング側の回数ボーナス等をイベントPへ流用しない。
イベントPは、その1プレイで実際に出したリザルトスコアから独立して計算する。

## 9. イベントP付与タイミング

イベント期間中は、正常に完了したプレイごとにイベントPを付与する。
ベストスコア更新の有無は問わない。

同じ曲を何度プレイしても、その都度イベントPを獲得できる。
プレイ回数とスコアの両方がイベントP獲得効率へ影響する。

## 10. 付与対象外

少なくとも以下はイベントP獲得対象外とする。

- イベント開催期間外
- プレイ途中で終了した場合
- ギブアップ等で正常リザルトまで到達していない場合
- DEBUG専用曲
- スコアや記録を残さないテスト・練習用途

具体的な既存プレイモード判定は実装時に最新mainを確認する。

## 11. 二重付与防止

1回のプレイ結果に対してイベントPを複数回付与してはならない。

リザルト画面の再描画、画面遷移、Reactの再実行等によって同一結果が重複処理されないようにする。
既存のスコア確定・保存処理との境界を実装時に確認し、イベントP付与は1プレイにつき1回のみとする。

## 12. イベントP保存

イベントPは既存セーブとの後方互換を維持した新規保存項目として追加する。

- 既存の `mh_*` キーを変更・削除・意味変更しない
- 既存ユーザーに新しい保存項目が存在しない場合は0Pとして正規化する
- イベント終了時に削除・リセットしない

具体的な保存キー名は実装時に既存保存設計と照合して確定する。

## 13. マーケット構造再編

イベントP交換所追加に伴い、マーケットの横並びタブ増加を避けるため、マーケット全体を階層型へ変更する。

マーケットTOPは「通常ショップ / 交換所」の2分類にはせず、プレイヤーが何を使って商品を入手する場所なのかが分かる入口構成とする。

### 13.1 マーケットTOP

マーケットへ入ると、最初に以下の4種類をカード形式で選択する。

1. ダイヤショップ
2. ブリーダーP交換所
3. アイテム交換所
4. イベントP交換所

### 13.2 TOPカードのレイアウト

スマートフォン縦画面を基準として、カードは横2列のグリッドで配置する。

現時点の4種類では2列×2段となるが、カードそのものを大きくしすぎない。
将来カテゴリが増えた場合も同じサイズ感のまま縦方向へ追加できる構造とし、少なくとも横2列×縦4段程度（最大8入口程度）までは大きな再設計なしで扱えることを目安とする。

- 横方向へ小さいタブを追加し続けない
- 入口カードはコンパクトな中サイズを基本とする
- タップ領域はスマートフォン操作に十分な大きさを確保する
- 入口追加時は縦方向へ自然に増える構造にする

### 13.3 TOPカードの所持数表示

マーケットTOPでは以下のみ所持数を表示する。

- ダイヤショップ: 現在のダイヤ所持数
- ブリーダーP交換所: 現在のブリーダーP所持数
- イベントP交換所: 現在のイベントP所持数

アイテム交換所は交換素材が複数存在するため、TOPカードでは個別所持数を表示しない。
虹のプシュケー、勇者の証片、勇者の証などの所持数はアイテム交換所へ入った後に表示する。

## 14. ダイヤショップ

ダイヤを消費して入手する既存商品を配置する。

現行の商品種別を踏まえ、円盤石・アシスト・アイテム等を扱う。
商品数が多い場合は、ダイヤショップへ入った後に既存の商品種別に応じたタブ・カテゴリ切り替えを使用できる。

マーケットTOP再編によって既存商品の価格、購入結果、所持判定、販売状態を変更しない。
既存の商品購入処理・商品カード・詳細表示は可能な限り再利用する。

## 15. ブリーダーP交換所

ブリーダーPを使用する商品を配置する。

現行では主にブリーダーアイコン等のブリーダーP商品を扱う想定とする。
マーケットTOP再編によって既存商品の価格、購入結果、所持判定を変更しない。

## 16. アイテム交換所

ダイヤやブリーダーPではなく、所持アイテムを交換素材として使用する既存・将来の交換をまとめる。

想定する交換素材の例:

- 虹のプシュケー
- 勇者の証片
- 勇者の証
- 今後追加される交換用アイテム

アイテム交換所へ入った後は、交換に関係する各アイテムの所持数を確認できるようにする。

既存の「証片から勇者の証へ交換」等の処理は、UI再編によって交換条件・必要数・結果を変更しない。
具体的にどの既存商品・交換をこの画面へ移すかは、実装時に最新mainの通貨・交換条件を確認して決定する。

## 17. イベントP交換所

イベントP交換所は常設する。
イベント非開催期間でも利用可能。

- イベント中: P獲得可能 / 交換可能
- イベント外: P獲得不可 / 交換可能

イベントPを獲得できる期間と、交換できる期間は分離する。

イベントP交換所では複数種類の商品を取り扱える。

想定:

- 通常アイテム
- 育成アイテム
- 円盤石
- アシストカード
- イベント限定商品
- その他将来追加商品

初期段階では商品種類ごとに別画面へ分ける必要はない。
商品数が増え、一覧性が悪化した場合にのみイベントP交換所内部へ追加カテゴリを設けられる構造とする。

## 18. 交換回数制限

交換可能回数は商品ごとに設定可能とする。

例:

- 無制限
- 1回
- 3回
- 5回
- 10回

すべての商品へ同一ルールを強制しない。
消耗品、限定品、円盤石、アシストカード等の価値に合わせて個別設定できるようにする。

## 19. 商品ラインナップ方式

イベントP交換所では「常設商品 + 期間限定商品」を混在できる。

### 19.1 常設商品

期間に関係なく交換可能。

### 19.2 期間限定商品

指定期間のみ交換可能。
イベント限定の円盤石・アシストカード等にも使用できる。

期間限定商品の販売終了後も、共通イベントP自体は消滅しない。

## 20. 商品データの拡張性

交換商品は、後からデータ追加・変更しやすい構造にする。

最低限、将来的に以下を設定可能とする。

- 商品ID
- 商品種別
- 必要イベントP
- 表示状態
- 表示順
- 交換上限
- 常設 / 期間限定
- 販売開始日時
- 販売終了日時

必要になった項目は今後追加可能とする。
商品ラインナップそのものは本仕様書ではまだ決定しない。

## 21. UI表示

### 21.1 モンヒロビートのリザルト

イベント期間中は今回獲得したイベントPを表示する。

例:

```text
イベントP +158P
```

イベント対象曲の場合は、1.5倍ボーナスが適用されたことが分かる表示を行う。

### 21.2 曲選択画面

イベント開催期間中は現在の共通イベントP所持数を表示する。
イベント期間外の表示要否は現時点では必須としない。

### 21.3 イベントP交換所

現在の所持イベントPを常時確認できるようにする。

### 21.4 HOME

HOMEへイベントPを常時表示しない。
通貨表示の乱立を避ける。

## 22. モバイルUI

既存方針どおりスマートフォン縦画面を最優先する。

特にマーケット再編では以下を優先する。

- マーケットTOPは横2列のカードグリッドとする
- 2列×2段を前提にカードを巨大化せず、将来は2列×4段程度まで自然に増やせるサイズ感とする
- 小さいタブをTOPへ大量に横並びにしない
- タップ領域を十分確保する
- iPhone Safariで見切れない
- Safe Areaを考慮する
- 商品一覧へ入った後の既存操作性を不必要に変えない

## 23. 既存システムとの互換性

本機能追加によって以下を意図せず変更しない。

- 既存ランキング
- 既存イベントランキング
- 既存スコア
- モンヒロビートBEST
- セーブデータ
- 既存マーケット商品の所持状態
- 円盤石購入処理
- アシスト購入処理
- アイテム購入処理
- ブリーダーアイコン購入処理
- 既存のアイテム交換条件・交換結果

マーケットUIを再編しても、既存の商品・価格・購入結果・交換結果・所持状態を変えない。
今回のマーケット再編は原則として「商品や交換をどの入口から見るか」の変更として扱う。

## 25. バランス調整方針

現在のイベントP計算式およびイベント曲1.5倍は暫定値とする。
実際のイベント運用、プレイ回数、交換商品の価格帯を確認したうえで調整可能とする。

ただし計算式を変更しても、過去に獲得済みのイベントPを遡って再計算しない。
