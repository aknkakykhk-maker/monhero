# バトル新モード 設計（2026-09-19）

## 0. この文書の位置づけ

新モード（id `tactics`）の設計の正本。**まだ公開していない**（`TACTICS_MODE_PUBLIC_RELEASE` は `false`）。
ユーザーと決めた事項と、コードを読んで確かめた現状だけを書く。

> ⚠️ **2026-09-19 に設計を大きく変えた。** 当初は「既存のバトルをそのまま使い、敵の行動を増やして
> 供モン加入の効きを抑える」案で進め、段階1・2まで入れた。そのあとユーザーから
> **「ステータスを合算式ではなくモンスターごとに個別にする」「1体が狙われて倒れたら選択できなくする」
> 「敵がどの距離のモンスターを狙うか、全体攻撃がある」** という方針が出たため、
> 戦闘の形そのものを作り直す。合算を前提にしていた段階3の実装は取り消した。

## 1. なぜ作るか（2026-09-19 ユーザー）

- プレイヤーの1人が最高難易度 RAGNAROK（敵強度×200）をクリアした
- **「ただ強いだけの難易度」をさらに足しても面白くない**
- ほしいのは「めちゃめちゃ強い人でも苦戦し、それより弱い人でも多少はやれる可能性がある」遊び
- そのために**バトルシステム自体を変える**

## 2. いまのバトルの形（コードが正本・ここを変える）

| いま | 新モード |
| --- | --- |
| ライフ・ちから・丈夫さ・ガッツを**パーティで1セット**持つ | **モンスターごとに個別に持つ** |
| 敵の攻撃は**パーティのライフ**を削る。「誰が狙われたか」が存在しない | **狙われた子のライフ**を削る |
| 与ダメは「共通のちから × 距離差倍率 × 技倍率」 | **攻撃した子のちから**を使う |
| 供モンが合流すると `plusStats` を**合算**する | 合算しない。**戦力が1体増える** |
| 誰も「倒れない」（パーティのライフが0で敗北） | **1体ずつ倒れる。倒れた子はカードを使えない** |

そのほか、いまのバトルで動いているもの（新モードでも土台にする）。

- 4スロット（零・近・中・遠）へ配置する。**配置はラン中に変えられない**
- 敵は1体。距離を移動し、こちらの与ダメは「スロットと敵の距離差」で変わる（差0:1.5 … 差3:0.9）
- 各WAVEは**20ターン制限**（21ターン目で敗北）。新モードでも変えない
- 敵の行動は1ターン前に予告する（`enemyIntent` が次、`enemyNextIntent` がその次）

## 3. 決まっていること（2026-09-19 ユーザーが選択）

| 項目 | 決定 |
| --- | --- |
| 位置づけ | **常設モード（6つ目）**。期間限定イベントではない |
| ステータス | **モンスターごとに個別**（ライフ・ちから・丈夫さ・**ガッツも個別**） |
| 倒れたとき | **回復カードで戻せる**。全員倒れたら敗北 |
| 勇者モン | **ほかの子と同じ扱い**。倒れても他の子が生きていれば続行。**固有技は使えなくなる**（倒れた子はカードを選べない）が、**勇者特性は倒れても効き続ける**（2026-09-20 ユーザーが実装どおりで確定。`mainHero` は編成で決まり、倒れても入れ替わらない）。ただし**効く相手は勇者モン本人だけ**（4.9） |
| 敵の狙い | **どの距離のモンスターを狙うか選ぶ**。**全体攻撃もある** |
| アシストカード | **使う子を選んで**、その子のガッツで払う |
| ガード | **カードを使った子自身**を守る |
| トレーニング | **モンスターごとに選ぶ**。倒れた子を**生き返せる**が、選ぶとそのWAVEは誰も強化できない |
| ターン制限 | **現状の20ターンのまま** |
| スコア式 | 現状の式のまま。**新モードだけ 1/1000 ほどへ縮める**（0にしない） |
| モードの名前 | **あとで決める**。idは `tactics` で固定済み |

### 3.1 idは決定済み（あとから変えられない）

モードのidは**保存キー（`mh_tactics_*`）と全国ランキングの `difficulty`（`TacticsHard` など）へ焼き付く**。
画面に出す名前とidは一致していなくてよいので、**名前だけあとから差し替える**。

## 4. 個別ステータスの設計

### 4.0 効き先の早見表（2026-09-22 に整理）

タクティクスは**1体ずつステータスを持つ**ので、「誰に効くのか」を取り違えるとバランスが丸ごと変わる。
2026-09-22 に食い違いが4つ見つかった（みゃるの薬・固有技の効果・ガードの軽減量・連撃系の勇者特性）ので、
**結論だけをここへ全部並べる**。なぜそうなったかは各節にある。

#### ① カードは誰に効くか

決めるのは `cardGenreLabel` / `cardScopeLabel` の**1か所**。カードの説明にもこの2つが出る。

| ジャンル | カード | 効く先 |
| --- | --- | --- |
| 攻撃 | バースト・距離撃・固有技・あつの挑発 | **敵へ**（威力は置いた子のちから） |
| 守り | ガード・弱ガード | **単体**（置いた子だけ。置き方で④へ変わる） |
| 回復 | 回復カード・みゅあの愛・メロソの解析 | **全体**（立っている味方ぜんぶ） |
| 支援 | **みゃるの薬** | **単体** |
| 支援 | ニコラオの力・ドラの緑膝・かどみうむの計算・ききの応援・ポルツの弁当 | **全体** |

> ⚠️ **単体に効くのはガードとみゃるの薬だけ**（2026-09-19 ユーザーの整理「単体に効くのは
> ガードの余りとドレインと吸収だけ」＋ みゃるの薬を 2026-09-22 に単体へ直した）。
> 回復カードも、永続バフを積む支援カードも、全部が味方ぜんぶへ入る。
> → 4.4「カードの説明に『ジャンル』と『誰に効くか』を出す」

#### ② 次のターンへ残る効果（ターンバフ）

| 出どころ | 効果 | 鍵 | 効く先 |
| --- | --- | --- | --- |
| みゃるの薬 | 次ターン攻撃 ×2.0〜3.0（自傷あり） | `atkMult` | **枠ごと**（飲んだ子） |
| ピクシー／ミーア | 次ターン、攻撃カードの消費0 | `zeroGuts` | **枠ごと** |
| タイガー | 次ターン、会心確定 | `guaranteedCrit` | **枠ごと** |
| アーク／イブリース（贖罪） | 次ターン、被ダメ50%減 | `takenDamageMult` | **枠ごと**（下と組） |
| アーク／イブリース（贖罪） | 次ターン、消費ガッツ+15% | `gutsCostMult` | **枠ごと**（上と組） |
| パンドラ（共鳴） | 2ターン、消費ガッツ半減 | `pandoraResonanceTurns` | **枠ごと** |
| モノリス | 次ターン、反射 | `reflect` | **味方全体** |
| メロソの解析 | 次ターン、被ダメ減／ライフ・ガッツ全回復 | `takenDamageMult` / `melosoFullRecoveryMult` | **味方全体** |
| 永続バフ（ATK+x%・丈夫さ+x% など） | | `permaBuffs` | **味方全体**（倍率は1体ずつの上限へ掛かる） |

置き場所は **枠ごと＝`nextTurnBuffs.bySlot`**、**全体＝`nextTurnBuffs` のまま**。
同じターンに両方が乗ったら**掛け合わせる**（メロソの全体 × アークの枠ごと）。
→ 4.4「みゃるの薬は『飲んだ子だけ』」「固有技の効果も『使った子だけ』」

#### ③ 勇者特性は誰のものか

原則は「**持っている子**」（`traitOwnerOf`）。**連撃系だけ例外がある。**

| 種類 | 特性 | 効き方 |
| --- | --- | --- |
| 攻撃 | 怪力・魔力開放・禁忌解錠の「引き継いだ固有技+50%」 | **持っている子**（札を出した子） |
| 被弾 | 俊足・反射・吸収・もち肌・中二病 | **持っている子**（狙われた子） |
| 枚数 | ハム「連続攻撃」・剣士モッチー「二刀流」の枚数+1 | **持っている子** |
| 敵へ | スエゾー「眼力」 | **持っている子**（攻撃したターンに1回） |
| 回復 | 氷海の支配者 | **持っている子** |
| **連撃** | **ザン「連撃」** | **持っている子**（供モンでも出る） |
| **連撃** | エイキ「桜花連舞」／パンドラ「禁忌解錠」の連撃ぶん／剣士モッチー「二刀流」の連撃ぶん | **勇者モンにしたときだけ** |

> ⚠️ **固有技そのものに付いている連撃は別**。ザンの「連斬」・エイキの「緋桜連華」・
> 剣士モッチーの「ソードスキル」は**技の出自**で決まるので、誰が使っても出る。
> → 4.9「連撃系は『勇者モンにしたからこそ強い』を残す」

#### ④ ガードの置き方

| 置き方 | なるもの | 受け止める量 | 画面 |
| --- | --- | --- | --- |
| 1体に1枚 | ふつうのガード | 構えた子の丈夫さ×倍率 | 札に `-71` |
| 同じ子へ2枚以上 | **連撃ガード** | 合計値で**連撃の全部**を受け止める | 札に `[連撃]` ＋ 枠に `🛡 連撃ガード ◯◯` |
| 2体以上が別々に | **全体ガード** | 構えた子は自分のぶん。構えていない子は**その子の丈夫さ×倍率×半減** | 札に `[全体]` ＋ 立っている子**全員**の枠に `🛡 全体 ◯◯` |

- **この2つは同時に成り立つ**（Aに2枚・Bに1枚 → Aは連撃ガード、Bは自分のぶん、残りは半減ぶん）
- **ガードカードは「1体につき何枚まで」の外**。どの子にも何枚でも構えられる
- **空き枠・倒れた子には付かない**
- 軽減量は必ず**構えた子の丈夫さ**（パーティの平均ではない）
- → 4.5-2「ガードの数え方」

#### よくある取り違え

- 4.4 の「**全体で見てよいのは7つだけ**」は **値**（ライフの合計・ガード段階など）の話。
  **効果**が誰に効くかは①②③④で決める。ターンバフはその7つに入っていない
- 「勇者特性は持っている子に効く」は**原則**。③のとおり連撃系に例外がある
- 「回復は全体・ガードは単体」。逆に覚えると、回復カードを倒れた子へ向けたくなる（その必要はない）

### 4.1 1体ぶんが持つもの

ラン中の各モンスターは、次を自分の値として持つ。

| 値 | もとになるもの |
| --- | --- |
| ライフ（現在／最大） | その子の `baseHp` ＋ 育成（マスモンなら個体の強化ぶん） |
| ちから | その子の `baseAtk` ＋ 育成 |
| 丈夫さ | その子の `baseDef` ＋ 育成 |
| ガッツ（現在／最大） | その子の `baseGuts` ＋ 育成 |
| 生存フラグ | 倒れているかどうか |

合流した供モンは、**合算されず自分の値のまま**盤面に加わる。これがこの作り直しの中心。

### 4.2 ガッツも個別（ユーザーが選択）

- その子のカードは、**その子のガッツ**で払う
- 自動回復もその子ごとに進む
- 「ガッツの高い子を休ませながら回す」という遷移が生まれる

### 4.3 倒れたとき（2026-09-19 ユーザーが決めた形）

**ライフが全快になってはじめて復活する。**

- 倒れても**ライフは回復で貯まっていく**。0から上限未満のあいだは「ライフを持ったまま倒れている」
- **回復で貯まる。** 回復カード・緊急回復（§10「段階7で決めた形」の表でいう「全体回復」。
  **配るのではなく1体ずつ「その子の上限 × 率」**）はもちろん、
  単体回復（ガードの余り・ドレイン）がその子に入ることもある
- ⚠️ **倒れている子は、毎ターン「その子の上限の10%」ずつ戻る**（2026-09-21 ユーザー指示
  「死んだら毎ターン10%は回復する仕様に変更 何もしなくても10ターンで生き返れる」）。
  **何もしなくても10ターンで満タンに戻り、そこで立ち上がる。** 率は
  `TACTICS_DOWNED_REGEN_RATE`、処理は `regenDownedTacticsBoard`（`32-tactics-units.jsx`）。
  - **立っている子の自動再生とは別に数える。** 倒れている子は行動していないので、
    バフの乗り方で戻る速さが変わると「強い編成ほど早く起きる」になってしまう
  - **ガッツは戻さない**（倒れている子はカードを使えないので、戻しても行き場がない）
  - 回復カード・緊急回復で早められるのは今までどおり
  - `tactics-units-check.js` が**実際に10ターン回して**数えている
  > これは 2026-09-20 の「**勝手に起きる回復では復活しない**」を覆した決めごと。
  > 当時は「オート回復も乗る」で作ったところ、**何もしなくても毎ターン勝手に貯まって復活し、
  > 誰も倒れたままにならない**（＝一生死ななくなる）と分かって止めた。
  > 今回は**10ターンという長さ**でその心配を受け止めている（20ターンの半分）。
- ⚠️ **それ以外の「勝手に起きる回復」では、いまも復活しない。**
  - **自動再生（毎ターンのライフ回復%）・ポルツの弁当** … 立っている子を1体ずつ、その子の上限の率で回す
  - **吸収** … 狙われた子だけに入る（§10「段階7で決めた形」）。狙いは立っている子にしか向かないので、起き上がらない
- 早く起こす手段は **回復カード・緊急回復・トレーニング**
- **上限まで届いた瞬間に立ち上がる**（`normalizeTacticsUnit` が見る決まりはこれ1つだけ）
- WAVE後のトレーニングで「起こす」を選ぶと、**満タンまで戻って**その場で立つ（`reviveTacticsUnit`）。
  ただし**そのWAVEは誰も強化できない**

> ⚠️ `downed` は「ライフが0かどうか」では決まらない。ここが作り直す前との違い。
> ⚠️ **パーティのライフ（合計）へ数えるのは立っている子だけ。** 倒れた子のライフは
> 復活までの貯めなので、合計へ入れると「全員倒れているのに敗北しない」が起きる。

### 4.4 全体で見るもの／個別で見るもの（2026-09-20 に棚卸し）

**ここは「値」の話**（ライフの合計・ガード段階・パーティのちからなど）。
**効果が誰に効くか**は 4.0 の早見表にまとめてある。

**全体で見てよい値はこの7つだけ。** ほかはすべて1体ずつ。

| 全体で見るもの | なぜ |
| --- | --- |
| 敗北判定（立っている子の合計ライフが0） | 全滅の定義そのもの |
| **ガード段階**（手札に出るガードカードの段階と枚数） | 手札は編成で1組。**いちばん硬い子**で決める（`tacticsMaxDef`。平均だと1体だけ壁役を育てても段階が上がらない） |
| 攻撃段階（`computeAtkTier`） | 手札のカードの段階。⚠️ **合算ではない。** `distTotalBonus` 経由で **その間合いに立っている子の適性だけ**を見る（`tacticsSlotApt`）。2026-09-22 に読み直して分かった（それまで「編成全員の合計」と書いてあった） |
| スコア・WAVE合計ダメージ | 記録そのもの |
| 永続バフの倍率（ATK+x% など） | 全員に同じ倍率が乗る（倍率は1体ずつの上限へ掛かる） |
| パーティのちから・丈夫さ（`atk` / `def`） | **既存5モードと共通の `state` が残っているだけ**で、持っているのは盤面の**平均**（合計ではない。`tacticsPartyStat`）。ダメージは攻撃した子の `atk`、受ける量は狙われた子の `def`、ガード段階はいちばん硬い子の `def` で決まる（2026-09-21 ユーザー指摘「パーティーのステータスって何？ ステータスは個別扱いだよ」）。⚠️ **2026-09-22 まで1か所だけ残っていた**（下） |
| パーティのガッツ（`guts` / `maxGuts`） | **画面と歯止めのためだけに持つ**。リザルトの「ガッツ ◯◯/◯◯」、バトル中の確認パネル、現在値が上限を超えないようにする歯止め。**判断に使う場所はもう無い**（払えるか＝`canTacticsSlotPay`、枚数＝人数、回復ボタン＝`tacticsHasGutsRoom`。どれも1体ずつ）。バトル画面には合計の帯を出さない |

#### カードの説明に「ジャンル」と「誰に効くか」を出す（2026-09-22 ユーザー指示）

ユーザー指示「単体効果と全体効果が分かるようにカード説明に表示するようにしたい」
「攻撃や回復や支援とかそれに単体や全体など効果のジャンルが分かるようにしたい」。

タクティクスは1体ずつステータスを持つので、**置いた子だけに効くのか・味方ぜんぶに効くのか**で
置き方がまるごと変わる。カードをタップしたときの説明の先頭へ、2つの札を並べる。

| ジャンル | あたるもの |
| --- | --- |
| 攻撃 | バースト・距離撃・固有技・あつの挑発（`isAttackCard`） |
| 守り | ガード・弱ガード |
| 回復 | 回復カード・みゅあの愛・メロソの解析 |
| 支援 | ニコラオの力・ドラの緑膝・かどみうむの計算・ききの応援・ポルツの弁当・みゃるの薬 |

| 効く先 | あたるもの |
| --- | --- |
| **単体**（置いた子だけ） | ガード・弱ガード・**みゃるの薬** |
| **全体**（立っている味方ぜんぶ） | 回復カードも、永続バフを積む支援カードも全部こちら |
| **敵へ** | 攻撃カード（味方には効かない。威力は置いた子のちから） |

⚠️ **単体に効くのはガードとみゃるの薬だけ**（2026-09-19 ユーザーの整理「単体に効くのは
ガードの余りとドレインと吸収だけ」。みゃるの薬は 2026-09-22 に単体へ直した）。
決め方は `cardGenreLabel` / `cardScopeLabel` の**1か所**に置く。
⚠️ **既存5モードには出さない**（ステータスがパーティ共通なので「単体」に意味が無い）。
`cardScopeLabel` がタクティクス以外では `null` を返し、札ごと出さない。

#### ガードが連撃・全体に変わったときの名前（2026-09-22 ユーザーが選択）

ユーザー選択「名前＋印に分ける」。**カードの名前は変えず、となりへ `連撃` `全体` の印を出す。**

- ガードの段階は9つあり、**後半は名前に「ガード」が付かない**
  （ガード／ハイガード／鉄壁ガード／金剛不壊／絶対防御／聖域展開／因果遮断／不変の真理／万象拒絶）。
  頭へ足すと「全体万象拒絶」「連撃金剛不壊」になり、言葉として読みにくい
- 名前をそのまま残すので、**どの段階のガードを置いたのか**も同時に読める
- 印は枠の札（`data-tactics-guard-mark`）。枠の下のまとめ（`🛡 連撃ガード 1987` ／ `🛡 全体 71`）は
  今までどおり

#### みゃるの薬は「飲んだ子だけ」（2026-09-22 ユーザー指摘で見つけた食い違い）

### 4.5 供モンの加入（2026-09-20 ユーザー指示）

- **加入ボーナス（`plusStats`）は使わない。** その子の**素のステータスをそのまま**盤面へ入れる
  （距離適性も合算せず、その子のぶんだけ）
- ただし供モンは **WAVE 2 / 4 / 6** で加わるので、勇者モンがそこまでに受けたトレーニング
  （1WAVEにつき2択）のぶんだけ見劣りする。WAVE6加入なら**10択ぶん**の差
- そこで **追いつき補正** を入れる。**WAVEを1つ抜けるたびに、そのWAVEの残りターン×1%** を
  掛け算で積む（`addTacticsJoinCatchUp`）。積んだ倍率を、あとから加わる子の
  ライフ上限・ガッツ上限・ATK・DEF へまとめて掛ける（`applyTacticsJoinCatchUp`）

  | そのWAVEにかけたターン | 残りターン | そのWAVEぶんの上がり |
  | ---: | ---: | ---: |
  | 1 | 20 | +20% |
  | 11（持ち時間の半分） | 10 | +10% |
  | 20 | 1 | +1% |
  | 21（時間切れ） | 0 | 0% |

- **速く抜けるほど厚くなる。** 掛け算で積むので、5WAVEぶんなら最速 ×2.49 / 最遅 ×1.05。
  「バトルの展開次第であとのほうが強くなる」をターン数で表す形（2026-09-20 ユーザー指示）
- 残りターンは**スコアの倍率と同じ数え方**（`21 - turnCount`）を使う。別の数え方を増やさない
- 積み上げは**1周ごとに数え直す**（周回の入口で1へ戻す）。加入した子は**満タンで**盤面に入る
- 供モン選択の「合流ボーナス」欄も、新モードでは**素のステのまま入ることと追いつき補正**を出す
  - ⚠️ **ここは2026-09-21まで実装が追いついていなかった。** 加入の処理そのものは
    `applyTacticsJoinCatchUp` を通していたのに、**画面だけがクラシックのまま**で
    「合流後 480 ／ 実際 +130」と**パーティが増える形**を出していた
    （ユーザー指摘「タクティクスは個別のステータスだからそもそも増えるって言うのがおかしい」）。
  - いまは `allyJoinPreview` がタクティクスのとき **素の値 → 盤面に入る値**を返す
    （`before` が素の値、`after` が追いつき補正込み、`tactics:true`、`catchUp` が率）。
    カードは「600 → 720」と並べ、下に「**追いつき +87%（57ターン残して勝ったぶん）**」を出す
    （2026-09-21 ユーザー選択「素の値と追いつき分を分けて出す」）。
    ⚠️ 「速く抜けたぶん」という書き方はやめた（2026-09-21 ユーザー指示「速く抜けた分とか
    言う表示ダサすぎる ターン数でボーナス値決まってるんだからそれでわかるようにして」）。
    **率は「残りターン×1%」で決まる**ので、積んだ残りターンの合計（`tacticsJoinCatchUpTurnsRef`）
    をそのまま出す。率と一緒に積み、**1周ごとに両方とも数え直す**。
  - **距離適性も合算しない。** `before` は 0 から始め、その子のぶんだけを出す。
  - 盤面へ入れるときと**同じ `applyTacticsJoinCatchUp` を通す**（別に計算すると画面と実際がずれる）。
    `tools/run/ally-join-view-check.js` が本体の `allyJoinPreview` を実際に動かして確かめている。

#### 間合いのボーナスも追いつかせる（2026-09-21 ユーザー指示）

ステータスだけをそろえても、**火力が置いていかれる**ことが分かった。

- 間合いのボーナス（`distDmgBonus`）は **その間合いで与えたダメージ**で伸びる
  （`与えたダメージ × DIST_BONUS_PER_DAMAGE`。WAVEを抜けるたびに積む）
- タクティクスは各間合いに1体ずつ立つので、**あとから埋まった間合いは 0 から始まる**。
  WAVE1から立っている勇者モンの間合いには永久に追いつけない
- ユーザー指摘「そうしたら追いつき補正で距離ボーナスも乗せないとだね」

そこで、**加入した枠の間合いのボーナスを引き上げる**（`catchUpTacticsDistBonus`）。
ステータス側とは3つだけ違う。

| | ステータス側 | 間合いのボーナス側 |
| --- | --- | --- |
| ベース値 | その子の素の値 | **これまでの合計ダメージ**（`totalAllDamage`） |
| 率 | 残りターン×1%（基準なし） | **（残りターン − 10）×1%**（残り10ターンがベース値どおり） |
| 積み方 | WAVEごとに掛け算 | 同じ（WAVEごとに掛け算） |

- **残りターン10がベース値どおりになる基準**（`TACTICS_JOIN_DIST_BASE_TURNS`、
  2026-09-21 ユーザー指示）。残り20ターン（1ターンで抜けた）ならベース値の1.1倍、
  残り10ターンならベース値どおり、時間切れ（残り0）でもベース値の0.9倍
- ⚠️ **上下するのは「ベース値より上か下か」であって、もらえるボーナスがマイナスへ
  なるわけではない**（2026-09-21 ユーザー指摘「プラスマイナスの話はボーナスが
  マイナスになるわけじゃなくて、ベースボーナスが基準値より上か下かっていう意味」）。
  手間取った周でも倍率が1を割るだけで、引き上げる値そのものは必ず0以上。
  `tools/mode/tactics-units-check.js` ㉚が、いちばん遅い抜け方でも引き上げが
  残ること・それがベース値より下に収まることを実際に計算して確かめている
- ベース値を合計ダメージで見るのは、**その子も最初から立っていたらこれくらい積んでいたはず**
  を表すため（ユーザー指示「ただしベース値は合計ダメージで見る」）
- 難易度の距離強化（`applyDistanceEnhancement`）も**既存の子と同じように通す**。
  通さないと NIGHTMARE / INFINITY で追いつきだけが厚くなる
- **すでに積み上がっている枠は下げない**（`Math.max`）。間合いのボーナスは
  4距離ぶんの配列をパーティで共有しているので、下げるとそこへ立っていた子のぶんまで削れる
- 合計ダメージは **ref から読む**（`totalAllDamageRef`）。周回のはじめは
  「0へ戻す」のと「編成を入れる」のが同じ処理の中で続くため、state を読むと
  **前の周回の合計ダメージで勇者モンの間合いにボーナスを配ってしまう**
- 「今回あたらしく入った枠」の判定は `isSameTacticsUnit` ひとつだけにする
  （`tacticsJoinedSlots`）。盤面を作り直す側と数える側が別々の判定を持つと
  「入れ替えたのに追いつかない」になる
- 供モン選択のカードにも**同じ値**を出す（`tacticsJoinDistCatchUpBonus`）。
  「立つ間合いのボーナスを +12.3% まで引き上げ」

⚠️ **周回のはじめのリセットが漏れていた。** 追いつき補正（`tacticsJoinCatchUpRef`）は
デバッグの入口でしか1へ戻していなかったため、本番の周回では**前の周回ぶんが残っていた**。
2026-09-21 に `applyResetAllState`（本番・繰り返し・リザルトからの再戦がすべて通る入口）へ
3つまとめて移した。

### 4.5-2 ガードの数え方（2026-09-22 ユーザー指示の新仕様）

ユーザー指示「ガードを2枚以上使ったときの挙動」。決めごとは3つで、
**どれも「枚数をどう配ったか」で変わる**。正本は `32-tactics-units.jsx`。

#### ① ガードは「1ヒットごと」に効く

構えた値は、受け止めるヒットそれぞれへ**まるごと**当たる。合計同士で引き算しない。

- 3連撃300（各100）をガード合計150で受け止める → 1ヒットずつ150が当たって**全部止まる**
- 1ヒットぶんに足りなければ、その足りないぶんだけ通る（ガード60なら 40×3 = 120 受ける）

#### ② 同じ子へ2枚以上 → 連撃ガード

その子は連撃の**全ヒット**を、構えた値の合計で受け止める（`TACTICS_RUSH_GUARD_CARDS = 2`）。

- 1枚のままなら今までどおり**1ヒットぶん**。厚さをいくら積んでも増えない
- 数えるのは**枚数**（`cards`）。厚さ（`flat`/`mult`）や重み（`weight`）では増えない。
  弱ガードも厚さは半分だが**1枚**と数える

#### ③ 2体以上へ別々に → 全体ガード

構えていない子にも、**その子の丈夫さをベースにしたガード**が付く
（`TACTICS_SPREAD_GUARD_SLOTS = 2`）。2026-09-22 ユーザー指示「あくまでも個別での丈夫さを
ベースとしてだよ。かつ2枚目以降は半分になるからその補正値」。

- 式は `(GUARD_EVOLUTION[段階].flat + その子の丈夫さ × GUARD_EVOLUTION[段階].mult) × 半減`。
  計算の形はクラシックと同じで、**固定値も同じように通す**
- ⚠️ **2枚目以降のカードと同じ半減（×0.5）がかかる。** 構えた子のちょうど半分になる。
  半減の率は本体の `cardEffectMultiplier` をそのまま通す（`0.5` を書き写さない）。
  2026-09-22 に一度「1枚ぶん満額」で入れてしまい、ユーザー指摘で直した
- ⚠️ **`flat` はいま9段階とも 0**（`guts` も0で、そちらはコードから1回も参照されていない）。
  だから実際は「丈夫さ × 倍率」だけで決まる。ここで `0` を直に書くと、
  将来 `flat` に値を入れたときだけ全体ガードが置いていかれるので、必ず `flat` を通す
- 構えていない子が受け止めるのは**1ヒットぶん**（連撃ガードにはならない）

> 固定値が0になった経緯は、このリポジトリの履歴では追えない（残っている最古のコミット
> `78c32834`＝PR #1456 の時点ですでに全段階0）。

#### ②と③は同時に成り立つ

ユーザー確認済み。「Aに2枚入れたら600+300で900の連撃ガード。これに更に別のやつに1枚
いれたら900の連撃ガードと600の全体ガードになる」。

| | Ａ（2枚） | Ｂ（1枚） | 残り2体 |
| --- | --- | --- | --- |
| ガード値 | 600＋300＝**900** | **600** | 丈夫さ×倍率 |
| 受け止めるヒット | **全ヒット** | 1ヒット | 1ヒット |

「1枚目600・2枚目300」は、既存の**2枚目以降は効果半減**（`cardEffectMultiplier`）が
そのまま出た値。半減の数えは枠ごと（`makeCardHalveCounter` にスロットを渡す）。

#### 間合い攻撃をずらしたとき（2026-09-22 ユーザー指摘で2つ直した）

ユーザー指摘「近距離にいる場合は1.2倍攻撃だけど敵を移動させて中距離とかにさせたら
狙われてるモンスターが0.4倍攻撃に変わるイメージ」。**そのとおりに直した。**

**決まりは2段階**（2026-09-22 ユーザー指示「誰に攻撃するかが大事で、それに対して
敵がどの距離で狙われた味方がどの距離かを見るんだよ」）。

1. **誰を狙うか**を決める（`withTacticsTarget`）。ほかの技とまったく同じ扱いで `targetSlot` が付き、
   予告に 🎯 で名前が出る。予告した間合い（`sweepDist`＝敵がいまいる間合い）に
   立っている子がいればその子。いなければ、ほかの技と同じ決め方（ライフの少ない子を狙いやすい）で1体
2. **威力は距離を見比べて決まる**（`isTacticsSweepOnSpot`）。
   **敵がいる距離** と **狙われた子の距離（＝その子の枠）** が同じなら ×1.2、違えば ×0.4

- ⚠️ **当たり外れの材料は `sweepDist` ではない。** `sweepDist` は「敵がどこから薙ぐか」の
  見出しであって、判定に使うのは `enemyDist` と `targetSlot` の2つだけ。
  ここを `sweepDist` で見ていたころは、その間合いに誰も立っていないと**狙いが空になり、
  ダメージそのものが起きなかった**（2026-09-22 ユーザー指摘「敵が狙った距離にこっちが
  いない場合はダメージ喰らわないままになってた」）。盤面が1体しかいないWAVE1では
  「敵の間合いに誰もいない」が当たり前に起きるので、敵のターンが丸ごと無駄になっていた
- ⚠️ **合わないと0になる、ではない。** 「合えば1.2倍・合わなければ0.4倍」
- ⚠️ **狙いは決まったら動かない。** 距離撃で敵を動かしても狙われる子は同じで、威力だけが落ちる。
  威力を落とすのは `tacticsSweepIntent` の1か所で、**予告（画面）も実行（processTurn）も
  ここを通る**ので「予定より減った・増えた」が起きない
- ⚠️ 外れたときの文は「**間合いが外れた！ 威力ダウン**」。「かわした」は嘘になる（0.4倍は当たる）
- 予告のあとに倒れていた子を起こしても、狙いは変わらない（`targetSlot` は予告のときに決まる）
- ⚠️ **威力は `actingIntent`（`missValue` ＝ ×`TACTICS_SWEEP_MISS_MULT`）で出す。**
  タクティクスの枠ごとの計算・反射・吸収の**4か所とも元の `intent` を見ていた**ため、
  距離撃でずらしてもフルダメージが入っていた。`tactics-units-check.js` が
  「`getIncomingDamageBeforeTurnReduction(intent,` が1つも残っていないこと」を見張る

#### 連撃は「発ごとの通る量」で出す（2026-09-22 ユーザー指摘）

ユーザー指摘「ガード1枚でしたけど連撃分全部のダメージが同じだった」。

⚠️ **合計を均等に割っていた**ので、ガードが効いた発も効いていない発も同じ数字で出ていた。
ガードが仕事をしたことが画面から読めない。

- `splitTacticsGuardedAmounts` が**発ごとの通る量**を返す。ガードが当たった発は
  `max(0, 1発ぶん − ガード値)`、当たらなかった発はそのまま。端数は最後の発へ
- `scaleTacticsHitAmounts` が、ターン軽減のあとの合計へ割り直す（足すと必ずその合計に戻る）
- 予告も受けたあとも**この2つを通す**ので、割り方がそろう
- 止まった発（0）は数字を出さない。**数字の数＝実際に食らう回数**

**連撃の予定ダメージは「1発ずつ」出す**（2026-09-22 ユーザー指示「連撃ダメージ予測が
合算分だから分かりにくい ガード入れても合算計算だし うまくバラバラでわかるようにしたい」）。

- 予告の帯も枠の 🎯 も `129・129・130` の形。**数字の数＝これから食らう回数**
- ガードで止めた発は数に入れない（1枚構えれば `129・130` の2つに減る）。
  連撃ガードで全部止まれば数字そのものが消える
- 割り方は受けたあとの表示と**同じ `splitTacticsHitAmounts`** を通す。
  予告と実際で割り方がずれない（端数はどちらも最後の発へ寄る）
- 1発の技（通常攻撃・必殺技・貫通撃・全体攻撃）は今までどおり数字ひとつ
- ⚠️ **1発ずつにしたら、合計がどこにも出なくなった**（2026-09-22 ユーザー指摘
  「連撃ダメージで合計ダメージと軽減後の合計ダメージがないといくつくらうかわからない」）。
  帯は `合計 639→573 ＝ 147・213・213`、枠の 🎯 は上の行が合計・下の行が内訳。
  **ガードやターン軽減が効いていれば「軽減前→軽減後」**で出すので、効き目もその場で読める
  （`plannedHitFor` が `raw`（軽減前の合計）も返す）

**ガードも攻撃と同じく、枠ごとに「この子へ置いたらいくら受け止められるか」を出す**
（2026-09-22 ユーザー指摘「ダメージは個別に見えるのにガード値は個別に分からない
カード詳細も誰の数値をもとにしてるかもわからないし、ダメージと同じような仕様にして」）。

- 置き場所を選んでいるあいだ、枠へ `GUARD:233`（緑）。攻撃の `DMG:368`（赤）と同じ場所・同じ形
- 2枚目以降になる置き先では `½ GUARD:116` と出る
- ⚠️ **カードの説明（`focusedCard`）でパーティの平均から1つの数字を出さない。**
  タクティクスでは「`0 ＋ その子の丈夫さ×2.85`」と決まり方だけを書き、
  「置く子で変わります。盤面の枠に出る GUARD の数字で確かめられます」と添える

枠の左下へ「ガードのまとめ」を出す。

| その枠 | 出るもの |
| --- | --- |
| 2枚以上（連撃ガード） | 「🛡 連撃ガード **合計値**」（琥珀） |
| 全体ガードのとき（構えた子も構えていない子も） | 「🛡 全体 ◯◯」（水色） |
| 全体ガードでない1枚だけ | **出さない**（カードの札と同じ数字になり二重になる） |
| 空き枠・倒れた子 | **出さない** |

⚠️ **全体ガードになったら、立っている子は全員の枠に軽減値が出る**（2026-09-22 ユーザー指示
「全体ガードになったときは全味方モンスターに軽減値を出して」）。構えた子も構えていない子も
**その子の丈夫さ**で軽減量が違うので、1つの数字では誰がどれだけ受け止めるのか分からない。

⚠️ **空き枠と倒れた子には出ない。** `tacticsSlotGuardValue` が `canTacticsSlotAct` を通す。
以前は誰もいない枠にまで「🛡 全体 131」が出ていた（`guardDefFor` が unit の無い枠で
**パーティ平均の丈夫さ**を返すため、そこに居ない子ぶんの数字まで作られていた）。

カードごとの単体値は、いままでどおり枠の上のカードの札に出したまま
（2026-09-22 ユーザー指示「ガードタップ時は単体数値がいくつかはわかるようにして」）。
ただし**全体ガードになった枠の札は「全体ハイガード」と名乗り、数字は出さない**
（2026-09-22 ユーザー指示「ハイガード-71みたいになってるとこを全体ハイガードみたいに変えて」）。
軽減量はその枠の 🛡 に出るので、同じ数字を2つ並べない。連撃ガードの枠だけは
1枚ずつの値が要る（合計は 🛡 に出る）ので、札の数字をそのまま残す。

⚠️ 画面と実際で別々に書くと必ずずれる（2026-09-22 に、ガードの軽減量が
「実際はその子・画面はパーティの平均」になっていた前例がある）。
全体ガードかどうかは**全枠を見ないと決まらない**ので、枠ごとにまとめてから数える
（`plannedGuardBySlot`）。`tools/mode/tactics-units-check.js` ㉕㉜が実際に計算して確かめる。

### 4.6 ガッツと行動回数（2026-09-20 に棚卸し）

1ターンに何回動けるかは3つで決まる。

| | 決まり方 | 新モードでの扱い |
| --- | --- | --- |
| **1ターンに選べる総数**（`cardLimit`） | ガッツ上限120＋味方2体で2枚／180＋3体で3枚。勇者特性（ハム）・きき・魂格の連携で **+1** ずつ、上限5枚 | **ガッツのしきいを見ない。立っている人数だけで決める**（2人で2枚／3人以上で3枚）。4体編成なら1体倒れても3体残るので枚数は変わらないが、2体まで減れば2枚。**+1 は人数と関係なく足すので倒れても減らない** |
| **1体が出せるカードの枚数**（`slotMaxUses`） | ふつう1枚。ハム本人・きき・連携持ちだけ増える | 同じ。**ガードとアシストカード以外のすべて**に効く（数えるかは `countsTowardTacticsSlotLimit` が1か所で決める。下記） |
| **払えるか** | その子のガッツ（`canTacticsSlotPay`） | もともと1体ずつ |

> ⚠️ **ガッツのしきい（120/180）は新モードでは外した**（2026-09-20 ユーザー指示）。
> `effectiveMaxGuts` は新モードでは**全員ぶんの上限の合計**なので、しきいは人数の条件と
> ほとんど二重になっていた。そのうえ**ガッツ上限の低い子だけで組むと、人数がそろっても
> 枚数が増えなかった**（素の上限は最小40・中央70なので、40が2人だと合計80で120に届かない）。

> ⚠️ **「1体につき何枚まで」は、アシストカード以外のすべてに効く**（2026-09-21 ユーザー指摘
> 「パンドラに2枚カード使えるのはおかしい」）。作り始めたころは**攻撃カードだけ**数えていて、
> 守り・回復は何枚でも同じ子へ置けた。そのため 👑（ハム・剣士モッチー）を持たない子にも
> 「攻撃1枚＋ガード1枚」が乗り、`slotMaxUses` の決めごと（**持っている子だけが1枚多く使える**）が
> 効いていなかった。
> 当時は「守り・回復まで数えると、供モンが居ないWAVE1で1ターン1枚しか使えなくなる」と考えたが、
> **全体の枚数（`baseCardLimit`）も「立っている人数＋👑」で決まる**ので、1体1枚に絞っても
> 配り切れる（盤面1体なら全体も1枚、👑持ちなら全体2枚でその子が2枚使える）。**減らない。**
> アシストカード（助手の教え）は全体の枚数にも数えないので、ここでも数えない。
> 払えるかどうかは `canTacticsSlotPay` が1体ずつ見るので、ここで合計を見る必要がない。

> ⚠️ **ガードカードだけは、2026-09-22 に「1体につき何枚まで」から外した**（ユーザー指示
> 「ガードは個別にも枚数制限ないようにして 連撃ガードがほとんどのモンスターができない」）。
> 同じ子へ2枚構えると**連撃ガード**になる決めごとを入れたのに、1体1枚のままでは
> 👑（ハム・剣士モッチー）を持つ子しか連撃ガードにできなかった。
> 守りを何枚重ねても、そのターンの総数（`cardLimit`）とその子のガッツで頭打ちになる。
> 数えるかどうかは **`countsTowardTacticsSlotLimit` の1か所**で決め、
> 手動（`tacticsUsableSlots`・`tacticsCardBlock`）もAUTO（`chooseAutoTurn` の
> `countsTowardSlotLimit`）も同じ答えを通す。別々に持っていたころは、
> **AUTOだけ回復もバフも何枚でも同じ子へ置けて**、手動では作れない盤面をAUTOが作れていた。
> ⚠️ **ガッツの合計（現在値・上限とも）は「立っている子だけ」**（`tacticsAliveSlots` 経由）。
> ライフと同じ扱いにそろえてある。

### 4.7 カードの払い主

ガッツを個別に持つので、「誰が払うか」を必ず決める。

- **モンスターのカード**（通常技・距離技・固有技）… そのカードの持ち主が払う。**倒れていたら使えない**
- **アシストカード**（ブリーダーの教え）… **使う子を選んで**その子のガッツで払う（2026-09-19 ユーザーが選択）。
  生きている子の中から選ぶので、全員のガッツが足りなければ打てない。
  ガッツに余裕のある子へ肩代わりさせる判断が生まれる
- **ガード**… **使った子自身**を守る（2026-09-19 ユーザーが選択）。
  敵が「次は近距離の子を狙う」と予告したら、その子にガードを持たせる。
  **予告を読んで守る子を選ぶ**、がこのモードの読み合いの中心になる

### 4.8 WAVEクリア後のトレーニング（2026-09-19 ユーザーが決めた形）

いまは「4種類から2回選び、パーティ共通の値へ効かせる」。新モードでは**モンスターごと**にする。

- 盤面にいる子それぞれについて選ぶ。**2体いれば2体ぶん、それぞれ2回**
- 倒れている子は、強化のかわりに **「生き返す」を選べる**
- ただし**生き返すを選ぶと、そのWAVEでは誰も強化できない**。仲間を戻すか、全員を伸ばすかのどちらか

強化を諦めて戻すか、バトル中にガッツを払って回復カードで戻すか、という選び方になる。

#### 選び終わったあとも、その子を指したままにする（2026-09-22 ユーザー指摘）

画面は「まだ選び終わっていない子」へ自動で進む形にしてある（タブを押させないため）。
⚠️ **全員ぶん選び終わると指す先が `null` へ落ち、ステータスの欄が
`baseStats` のフォールバック（`maxHp` / `maxGuts` ＝ パーティ合計）へ戻っていた。**
ユーザー指摘「タクティクスのトレーニングを2回め選ぶとステがもとに戻る」。
1体しか立っていないときは2つ目を選んだ瞬間に起きるので、いちばん目につく。

- `pendingSlot`（まだ選び終わっていない子）と `currentSlot`（いま出している子）を分ける。
  全員ぶん終わったら **最後の子を指したまま**留まる
- カードを押せるかどうかは `pendingSlot` で決める（指す先を残しても3つ目を積ませない）
- 全員ぶん終わったら見出しを「全員ぶん決まりました」にする
- タクティクスで指す先が無いとき（全員倒れている）は、**パーティ合計の欄そのものを出さない**。
  1体ずつのモードで合計を出しても何の数字か読み取れない
- `tools/run/training-reward-check.js` が実際に描いて、選び終わったあとも
  増えた値（500 → 600 → 720）が残ることを確かめる

実際に入る強化量（`handleTraining`）はこの間もずっと正しかった。**表示だけの不具合。**

### 4.9 勇者特性は「その子の能力」（2026-09-20 ユーザー指示 → 同日ユーザー提案で供モンへ拡張）

**タクティクスバトルでは、勇者特性は「持っているモンスター本人」に効く。**
最初は「勇者モン本人にだけ」と決めたが（「勇者モン特有のものだから、誰かではなく決められた
モンスターのみ」）、同じ日にユーザーから「とももんも勇者特性がかかるようにしてもいいかと思うけど
どう思う？」と提案があり、**供モンにも広げた**。効き目は勇者モンと同じ**等倍**（ユーザーが選択）。

理由: このモードはステータスを1体ずつ持つのに特性だけ勇者モンのもの、というのがちぐはぐだった。
供モンを選ぶ意味も「ステータスの足し算」から「**どの特性を連れていくか**」に変わる。

**既存5モードは今までどおり勇者モンのものをパーティ全体へ効かせる**
（ステータスがパーティ共通なので、分ける意味がない。仕様 8.触らないもの）。

| 種類 | 特性 | タクティクスバトルでの効き方 |
| --- | --- | --- |
| **被弾** | ライガー「俊足」回避50／モノリス「反射」30／オボロ・プラント「吸収」30 | **先に受ける子を1体決め**（`defenseSlot`）、**その子の特性で表を作って**引く（`defenseTable`）。避ける／返す／吸うのも同じその子 |
| | モッチー・ミタラシ「もち肌」被ダメ20%軽減 | **狙われた子が持っていたときだけ**（`traitHeroId`） |
| | アーク・イブリース「中二病」被ダメ50%カット2回 | 同上。**持っている子が狙われていないターンは回数も減らさない**（`chuuniAimed`） |
| **攻撃** | ゴーレム「怪力」与ダメ20%増 | **その札を出した子が持っていたときだけ**（`attackHeroId`） |
| | ピクシー・ミーア「魔力開放」固有技2倍 | 同上 |
| | パンドラ「禁忌解錠」引き継いだ固有技+50% | 同上（技の出自は `card.monId` で見るのは今までどおり） |
| **連撃** | **ザン「連斬」** | **持っている子**（`traitOwnerId===‘Zan’ && attackerId===‘Zan’`）。供モンでも出る |
| | エイキ「桜花連舞」／パンドラ（自身の固有技の連撃100%・通常攻撃の50%+50%）／剣士モッチー「二刀流」 | **勇者モンにしたときだけ**（`heroId===… && attackerId===…`）。下記 |
| **回復** | 氷海の支配者（スネグーラチカ・ウンディーネ・ヤオビクニ） | **持っている子が敵と同じ距離にいるとき、その子のガッツ回復だけ**+50%（`iceExtraRateAt`）。全員へ配る率には混ぜない |
| **枚数** | ハム「連続攻撃」1ターンの枚数+1 | **持っているモンスターだけ**が1枚多く使える（`bonusOwner`）。盤面にいる持ち主の人数を `heroCardBonus` に数える |
| **敵へ** | スエゾー「眼力」敵を行動不能40% | **持っている子が攻撃したターン**に引く（`TACTICS_INTIMIDATE_RATE`）。1ターンに何枚使っても判定は1回。敵ターン頭の `battleIntimidate` からは新モードぶんを外す |

#### 連撃系は「勇者モンにしたからこそ強い」を残す（2026-09-22 ユーザー判断）

ユーザー指摘「パンドラが弱く感じた　勇者特性がきいてないとか」。調べたら**連撃系は4体とも
`heroId`（＝勇者モン）を見ていて、勇者モンにしないと1つも効いていなかった**。
この文書に書いてあった「連撃系はもともと本人限定」という記述のほうが誤りだった。

ユーザーの判断は「**ザンのみ持ち主へ。エイキ・パンドラ・剣士モッチーは勇者モンだからこそ強い
設定なので、供モンでは発動しない**」。効き方は元ダメージ1000で次のとおり（`buildAttackHits` を実際に回した値）。

| | 勇者モン | 供モン |
| --- | --- | --- |
| ザン 固有技／通常 | 1500／1300 | **1500／1300**（直した） |
| エイキ 固有技／通常 | 1800／1200 | 1300／1000 |
| パンドラ 固有技／通常 | 2000／1000 | 1000／1000 |
| 剣士モッチー 固有技／通常 | 1700／1000 | 1400／1000 |

> ⚠️ **供モンでも出るぶん（固有技の出自で決まるもの）は別**。ザンの「連斬」（技の出自がザン）、
> エイキの「緋桜連華」、剣士モッチーの「ソードスキル」は**誰が使っても出る**ので、上の表の
> 供モンの値にも入っている。勇者モン限定なのは**勇者特性ぶんの追撃だけ**。

実装は `buildAttackHits` が **`heroId`（勇者モン）と `traitOwnerId`（特性の持ち主）の2つ**を受け取る形。
`traitOwnerId` を渡さなければ `heroId` と同じに倒れるので、既存5モードの呼び出しは何も変わらない。
持ち主は `traitOwnerOf(mon)` の1か所で決め、攻撃側の特性（怪力・魔力開放・禁忌解錠の+50%）と同じものを通す。

> ⚠️ **ここがちぐはぐだったのが元の姿。**
> 被弾側と攻撃側は `mainHero` を見るだけ＝**誰が狙われても／誰が攻撃しても効いていた**。
> ⚠️ **4体いても、発動するのは狙われた子／攻撃した子の1体ぶん**なので重ねがけにはならない。
> ⚠️ **魂格（ソウルランク）由来の回避・反射・吸収は編成全体のもの**なので、誰が受けても乗る。
> `defenseTable` は魂格ぶん＋受ける子の勇者特性ぶん、で毎回その場で作る。
> ⚠️ **表を引いてから避ける子を選んではいけない。** 俊足を持っていない子が俊足ぶんの確率で
> 避けてしまう。**先に受ける子を決めてから、その子の表を引く**（`pickDefenseSlot()` は
> 決めた1体を返すだけ）。

## 5. 敵の攻撃（狙いと全体攻撃）

### 5.1 狙いは1ターン前に予告する

既存の予告のしくみへそのまま乗せる。「次は**近距離の子**を狙う」と出してから実行するので、
守る・回復する・間合いをずらす、のどれで受けるかを決められる。

### 5.2 敵の技と倍率（2026-09-20 にユーザーが1つずつ決め直した）

正本は `22-enemy-and-bond-entries.jsx` の `TACTICS_*_MULT` と `TACTICS_ACTION_DEFINITIONS`。
下は読むための写しなので、数字を変えるときは**必ずそちらを直す**。

| 技 | 倍率 | 重み | 当たり方・受け方 |
| --- | ---: | ---: | --- |
| 通常攻撃 | ×1.0 | 30 | 狙った1体へ。ガードが効く。**ここが基準** |
| ためる → 必殺技 | ×2.5 | 12 → 確定 | 「ためる」の次のターンに必ず来る。2ターン前から読める |
| 行動なし | — | 10 | 何もしない。**回復や立て直しに使える休み** |
| 移動 | — | 10 | いまと違う間合いへ。距離差で与ダメが変わる |
| 間合い攻撃 | ×1.2（外し **×0.4**） | 14 | **予告した間合いにいる子**へ。距離撃でずらしても狙いは変わらず、威力だけ落ちる |
| 連撃 | ×1.2（**0.4×3ヒット**） | 14 | 狙った1体へ。**ガード1枚につき1ヒット**を受け止める（3枚構えれば止めきれる） |
| 貫通技準備 → 貫通撃 | ×0.8 | 12 → 確定 | 「構え」の次のターンに必ず来る。狙った1体へ、**ガードが効かない** |
| 攻撃力アップ | — | 10 | 次のターンから敵の攻撃 ×1.5（**2回まで＝最大 ×2.25**、WAVE中ずっと） |
| 再生 | 最大ライフの **50%** 回復 | 10 | 敵自身。ライフが90%を下回ったときだけ |
| **全体攻撃** | ×0.4／体 | 10 | 立っている**全員**へ同時。ガードは構えた子しか守れない |

**決め直したときの考え方**（2026-09-20）。

- **攻める側（敵）の倍率は全体に下げた。** それまでは受けるダメージが重く、
  とくに次の2つが歪んでいた。
  - **人数が増えるほど全体攻撃だけが強くなっていた**（1体あたり×0.9＝4体で合計×3.6）。
    ガードは構えた子しか守れず回復も1体ずつなので、**供モンを連れて人数を増やすほど不利**だった
  - **連撃（×1.8）が貫通撃（×1.8）を絶対に上回れなかった。** 同じ倍率なのに連撃だけ
    ガードで減るため、技が2つある意味が薄かった
- **そのぶん敵は落としにくくした。** 再生を 8% → **50%** へ。与ダメは変えていないので、
  下げたのは「こちらが受ける量」だけになる
- **「行動なし」を戻した。** 作り始めた当初は「新モードに何もしないターンは作らない」だったが、
  立て直しに使える休みが要るので戻した（既存5モードは重み20、新モードは**重み10**）
- **単体狙い（×2.2）は廃止した。** 必殺技（ためる → ×2.5）と役割がかぶるため。
  通常攻撃も連撃も貫通撃も「狙った1体」へ当たるので、**誰が狙われるかを読む遊びは残る**

> ⚠️ **全体攻撃の1体あたりの威力は、通常攻撃より必ず低くする。**
> 同じか上にすると「全員を殴るほうが得」になり、狙いを読む意味も供モンを連れる意味も消える
> （`tactics-enemy-actions-check.js` が見張る。4体ぶんの合計が必殺技より軽いことも見る）。

> ⚠️ **連撃のガードは「枚数」で受け止める**（2026-09-21 ユーザー指示「連撃はガード1個で
> 1個めのガードが出来て、2個使えば2個目までも出来る とかそういう感じだよ」）。
> **ガード1枚につき1ヒット。**厚さでは止まらない（どれだけ厚い1枚でも1ヒットぶん）。
> 3ヒットすべてを止めるにはガード3枚が要るので、そのターンは攻めに回せる手が無くなる。
> 止めるか、通して攻めるかがそのまま読み合いになる。
> 弱ガードは0.5枚ぶんなので、2枚でようやく1ヒットになる。
> 数え方は `tacticsGuardHits`、受け方は `resolveTacticsGuardedHit`（どちらも
> `32-tactics-units.jsx`）。**予告の「予定」も同じ関数を通る**ので、
> 構えた枚数がそのまま予定ダメージに出る。
> `tactics-units-check.js` が**実際に計算して**確かめている（厚いガード1枚では止まらないこと、
> 受け止めたぶんと通ったぶんの合計が元の値に戻ることまで）。
>
> 連撃は**予告の時点で「3連撃」と分かる**ようにしてある（2026-09-21 ユーザー指摘
> 「敵の連撃技が連撃表示になってない」）。当たったときも「連撃 3ヒット！ ガードは◯ヒットぶん」を
> 必ず出す（前はガードして貫通したときだけ出ていたので、ガードしないと連撃だと分からなかった）。

> ⚠️ **ラスボスの見せ方は、ムーと覚醒ムーでそろえる**（2026-09-21 ユーザー指摘
> 「覚醒ムーがしょぼすぎる クラシックのムーの描写を参照してって言ったじゃん」）。
> `ENEMY_ART_LAYOUT` だけムーとそろえてあったが、**演出の分岐（8か所）からは漏れていた**。
> ラスボスの見せ方は `enemy?.id==='Moo'` を画面のあちこちへ直に書いて出し分けていたので、
> 覚醒ムーは丸枠の中に小さく出るだけになっていた。
> いまは `MOO_BOSS_IDS` / `isMooBoss(id)`（`22-enemy-and-bond-entries.jsx`）に一覧を置き、
> 次の7つがまとめて効く。
>
> | 見せ方 | 中身 |
> | --- | --- |
> | 丸枠の外に巨大な立ち絵 | 560px。浮遊（`mooFloat`）・突進・ためこみ・移動のアニメ |
> | 丸枠の中は空 | 本体は枠外に出すため |
> | 丸枠の中に台座のオーラ | 紫のグラデーションと輪 |

>
> **ラスボスを足すときは `MOO_BOSS_IDS` へ1行足すだけ**にする。id を画面へ直に書くと、
> また片方だけ抜ける。`tools/battle/moo-boss-presentation-check.js` が
> 「直書きが戻っていないか」まで見張る。

> ⚠️ **このターン、誰に何が起きたかは枠ごとに出す**（2026-09-21 ユーザー指摘
> 「個別ダメージと全体ダメージで誰に何が起きてるか分かりにくい」「ダメージや回復表示は
> 個別で分かるようになった？」）。合計の数字を画面のまんなかへ出すだけでは、
> 4体のうち誰が減って誰が戻ったのかが読めない。
> 入れ物は `tacticsSlotFx = { [枠]: { dmg, heal, guts, guard, evade, reflect, revive } }`。
>
> | 出るもの | どこから |
> | --- | --- |
> | `-242`（減ったぶん） | 敵の攻撃。狙われた枠ごと |
> | `-20` `-20` `-20` | **連撃は1ヒットずつ**。240ms おきに1つずつ増える（2026-09-21 ユーザー指示「敵の3連撃なら3回ダメージ表記が出るようにして 60なら20、20，20みたいな」）。割り方は `splitTacticsHitAmounts`（端数はいちばん最後のヒットへ寄せ、足すと必ず元の合計へ戻る）。**ガードで受け止めたヒットは数えない**ので、1枚構えて1ヒット止めたなら数字は2つ |
> | 🛡（受け止めた） | ガードを構えていた枠 |
> | `💚 +120` / `⚡ +12` | ガードの余り・回復カード・緊急回復・メロソ・ポルツ・吸収 |
> | 回避！ / 反射！ | その子だけ |
> | `💤 +60` | 倒れている子が毎ターン戻るぶん |
>
> ⚠️ **合計はまんなかへ重ねない**（2026-09-21 ユーザー指示「個別をみんなに出してるなら
> ただ見にくいだけだから出さないで ただし連撃は最後に合計を出すようにして」）。
> 枠ごとに出しているもの（受けたダメージ・ガードで戻ったぶん・回復カード・緊急回復・
> 自動再生・吸収）は、**画面まんなかの合計をやめた**。既存5モードは今までどおり合計で出す。
> **例外は連撃だけ。** 1ヒットずつ見せたあとに「合計 60」を出す
> （**味方が敵へ連撃したときと同じ見せ方**＝`合計 ${totalDmg}`）。
> 「無傷！」は残す（枠に数字が出ないだけでは、何も起きなかったのか分からないため）。
> 表示は**2.6秒で消える**（`showTacticsSlotFx` が時計を張る）。自分がカードを切ったときは
> その場で消す（`clearTacticsSlotFx`）。
> ⚠️ 作った当初は「次に自分がカードを切るまで残す」だったが、**敵が何もしないターン
> （様子を見ている）を挟むと前のターンの数字が居座っていた**

> （回復を足すたびに書き足さなくてよい）。重ねて足すので、同じターンのガードぶんと
> 回復カードぶんが両方残る。

> ⚠️ **全体攻撃の予定ダメージは、枠ごとに出す**（2026-09-21 ユーザー依頼「全体攻撃は
> モンスターごとにダメージが変わるはずだからそれを分かるようにして」）。全体攻撃は立っている
> 全員に当たり、**受ける量はその子の丈夫さで1体ずつ変わる**のに、予告の吹き出しは
> 1つの数字しか出していなかった。ガードも枠ごとなのに全部まとめて数えていた。
> いまは `plannedDamageFor(slotIdx)` に数え方を**1か所だけ**置き、吹き出しと枠の両方が通る。
> 全体攻撃のときは吹き出しに数字を出さず（`showPlannedInBubble`）、狙われた枠の 🎯 に
> `-242` のようにその子のぶんを出す。

### 5.2-1 種別の呼び名は「何をする技か」が分かる言い方にする（2026-09-21 ユーザー指示）

画面に出る技名は**敵ごとのもの**（羅刹・ドラゴンパンチ…）で、SCANとヘルプにはその**種別名**が出る。
種別名が分かりにくいと、SCANを見ても何が来るのか分からない。

| 変更前 | 変更後 | 理由 |
| --- | --- | --- |
| 薙ぎ払い | **間合い攻撃** | 「薙ぎ払い」では何のことか分からない（ユーザー指摘） |
| 咆哮 | **攻撃力アップ** | 何が起きるかがそのまま名前になる |

ほかの種別名（通常攻撃・ためる・必殺技・特殊行動・移動・連撃・貫通の構え・貫通撃・再生・全体攻撃）
はそのまま。**倍率も当たり方も出やすさも変えていない。名前だけ。**

> ⚠️ 古い呼び名へ戻すと `tactics-enemy-actions-check.js` の
> 「種別の呼び名に、分かりにくい古い言い方が残っていない」が落ちる。

#### 何をする技かを、敵の右上へ出す（2026-09-22 ユーザー指示）

ユーザー指示「他の技も効果が名前だけだと覚えられないから全部吹き出しで効果出しても良さそう」
「右上に必殺技！みたいに吹き出し出せばいい。3連撃！とか」。

- タクティクスの敵は技に**固有の名前**が付いている（「かえるのうた」「しこ踏み」）ので、
  **名前だけでは連撃なのか回復なのか分からない**
- `TACTICS_ACTION_DEFINITIONS` の各技へ **`noticeLabel`** を持たせ、予告（`intent.notice`）へ
  そのまま積む。敵の絵の**右上**に「3連撃！」「回復！」「攻撃力アップ！」と出しっぱなしにする
- 分類名（`category`）をそのまま出さない。「再生」→ **回復**、「特殊行動」→ **様子見**、
  「連撃」→ **3連撃**（ヒット数まで）。プレイヤーが覚えるための言葉にする

> ⚠️ **ラスボス（ムー・覚醒ムー）だけは置き場所が違う**（2026-09-22 ユーザー指摘
> 「ムー戦の吹き出しが見えない」）。ラスボスの本体は丸枠の外へ `position:fixed`・
> `z-index:30` で画面いっぱいに描くので、**丸枠の右上へ置くと絵の下に隠れて1文字も見えない**。
> ラスボスのときは吹き出しも `position:fixed` にし、画面の右上（敵のライフ帯のすぐ下、
> `top:max(112px,16dvh)`）へ立ち絵より上の重なり順で出す。ラスボスは画面を覆うので、
> **画面の右上＝そのまま敵の右上**になる。
>
> ⚠️ **根っこは丸枠の `transform`。** ラスボスのときだけ丸枠を `transform:translateY(3dvh)` で
> ずらしていた。`transform` は**新しいスタッキング文脈**を作るので、その中の `z-index:9000` は
> 外から見ると `z-index:auto` の一員でしかなく、`z-index:30` の立ち絵に負ける。
> さらに中の `position:fixed` も**画面ではなく丸枠が基準**になるため、必殺技予告の
> 「全画面の危険ビネット」も丸枠の中だけに縮んでいた。同じだけずらすなら
> **スタッキング文脈を作らない `top:'3dvh'`** を使う（丸枠はもともと `position:relative`）。
>
> ⚠️ **これで2回目**。1回目は移動の吹き出しで、同じく「丸枠の中に置いたため、枠外へ巨大に描く
> ムーの裏へ回っていた」（`tools/battle/move-hint-layout-check.js` の頭）。
> `tools/battle/moo-notice-visibility-check.js` が実際のブラウザで
> `document.elementFromPoint` を使い、吹き出しの真ん中に何がいるかを測る。
> **昔の置き方なら隠れること**も同じページで確かめ、測り方そのものが不具合を拾えることを示す。
- 出すのは**タクティクスだけ**。既存5モードは今までどおり「❗」1つ
- **中央に大きく出ている技には重ねない**（いまは貫通技準備だけ）
- **色・動き・光り方・アイコンを効果ごとに変える**（2026-09-22 ユーザー指示「吹き出しを
  効果によって変えると見た目がいい」）。文字を読む前に、攻めてくるのか回復するのかが
  見分けられるようにする

  | 効果 | 色 | 動き |
  | --- | --- | --- |
  | 殴ってくる技（通常攻撃・連撃・間合い攻撃・全体攻撃・貫通撃） | 赤 | `noticeHit`（小刻みに震える） |
  | 必殺技 | フクシア | 同上 |
  | 必殺技準備（ためる） | 琥珀 | `noticeCharge`（膨らむ） |
  | 攻撃力アップ | 橙 | `noticeShout`（左右に揺れる） |
  | 回復 | 緑 | `noticeHeal`（ふわっと浮く） |
  | 間合い移動・様子見 | シアン / 灰 | `noticeCalm`（静かに明滅） |

  ⚠️ 動きの名前（`@keyframes`）は `70-bootstrap.jsx` にある。**書いた名前が実在しないと
  札が止まったままになる**ので、`tactics-enemy-actions-check.js` が突き合わせる
- 「ためる」も準備の技なので **「必殺技準備」** と出す（貫通技準備と対にする。
  2026-09-22 ユーザー指示）

⚠️ **「貫通の構え」という呼び名はやめた**（2026-09-22 ユーザー指摘「貫通のときに予告は
固有技で出て吹き出しで貫通の構えって出る…矛盾が感じるから出し方を変えたほうがいい」）。
予告の帯には敵ごとの技名（「上手投げの構え」）が出るので、そこへ種別の「構え」を重ねると
同じ言葉が2つ並ぶ。**`category` も画面の大きな警告も「貫通技準備」へそろえた。**
ヘルプの表は `category` から作っているので、そこも一緒に変わる。

### 5.2-2 貫通撃は「構え」を挟む（2026-09-21 ユーザー指示）

ユーザーの言葉は「**貫通は必殺級の技だからこれもためると同じように1ターン経由したほうがいい**」。

ガードが効かない＝**受け方が無い**技なので、来ると分かってから距離を取る・回避を用意する、という
備えができるようにした。形は「ためる → 必殺技」とまったく同じ。

- 抽選に出るのは **`pierceCharge`（貫通技準備・重み12）** のほうで、`pierce` 自身は **重み0**
- 構えた次のターンは **貫通撃で確定**（ほかの行動では上書きされない）
- 構えを止めた（スタン等で行動を潰した）ら、予約していた貫通撃は捨てて引き直す
- 構えの見出しは、その敵の貫通撃の名前から作る（「**チャージラッシュの構え**」）。
  何が来るかが名前で分かる
- 画面には「ためる」と同じ大きさの警告を出す。色は貫通撃と同じ赤系にして、ためる（琥珀）と分ける

#### 倍率は ×0.8 のまま。上げない（2026-09-21 ユーザー判断）

構えを挟んだぶん1ターンあたりの威力が落ちるので、こちらから **×1.8 へ上げる案**を出したが、
**ユーザーが却下した。** 理由はそのままの言葉で残す。

> 基本相手の攻撃はガードで防げるけど貫通はおならとか反射で対策しないとだから強くするのはない

**この技だけ、備え方の種類が少ない。** ほかの技は全員がいつでも使えるガードで受けられるが、
貫通撃にガードは効かないので、次のどれかを用意しておくしかない。

| 備え方 | 貫通撃に効くか | 誰でもできるか |
| --- | --- | --- |
| ガード | **効かない** | 誰でも |
| 距離を取る | **効かない**（貫通撃は全間合い。間合い攻撃と違って間合いで外せない） | 誰でも |
| スタン（ハムの固有技「おなら」／アシストカード「あつの挑発」） | 構えのターンを止めれば**不発**（予約を捨てて引き直す） | その札を持っていれば |
| 回避 | 避けられる | 特性・札しだい |
| 反射 | 返せる | 特性・札しだい |

備えが要る技の倍率を上げると、**備えを持っていない編成には手の打ちようがなくなる**。
**この理由を忘れて「1ターン使うのに弱い」だけを見て上げ直さないこと。**

### 5.2-3 難易度が上がると使える技が増える（2026-09-21 ユーザー指示）

ユーザーの言葉は「**難易度が上がるにつれて使える技も増やそうか**」。

それまでは、どの難易度でも敵の技は `TACTICS_ENEMY_ACTION_IDS` の基本構成で固定だった。

- **基本構成（Normal / Hard）を 0 として、難易度ごとに増減する**（`TACTICS_DIFFICULTY_ACTION_DELTA`）。
  Beginner −2 / Easy −1 / Expert・Master +1 / GrandMaster・Hell +2 / Legend +3 /
  EXTREME・NIGHTMARE +4 / CHAOS +5 / ULTIMATE 以上 +6
- **増やす順は共通**（`TACTICS_EXTRA_ACTION_ORDER`）: 連撃 → 間合い攻撃 → 攻撃力アップ → 再生 → 貫通撃 → 全体攻撃。
  **全体攻撃がいちばん後ろ**なのは、早い段階で全員攻撃が来ると受け方を1つずつ覚えられないため
- **減らすときは、殴ってこない技（攻撃力アップ・再生）から先に落とす**（`TACTICS_SUPPORT_ACTION_IDS`）。
  前から順に切ると、ニャルラトホテプが再生だけ・ドクドクが咆哮だけになり、
  易しい難易度ほど「敵が何もしてこない」ように見えてしまう
- **最低1本は残す。** 0にすると通常攻撃とためるだけになり、このモードの読み合いが消える
- **難易度は敵そのものが持ち歩く**（`createBattleEnemy` が `difficulty` を返り値へ入れる）。
  行動表を引くたびに「いまの難易度」を別経路で探すと、実戦とSCANでずれる

難易度ごとの本数（基本構成が1本のカワズモー 〜 6本の覚醒ムー）:

| 難易度 | カワズモー | イナリ | スプラッター | 覚醒ムー |
| --- | ---: | ---: | ---: | ---: |
| Beginner | 1 | 1 | 2 | 4 |
| Normal | 1 | 2 | 4 | 6 |
| Legend | 4 | 5 | 6 | 6 |
| 極限（CHAOS以上） | 6 | 6 | 6 | 6 |

> ⚠️ **難易度の並びを検査へ書き写さない。** `tactics-enemy-actions-check.js` は
> `DIFFICULTY_SETTINGS` / `QUICK_EXTREME_SETTINGS` の**定義順を本体から読む**。
> 増減の値でソートして単調性を見ると、どんな値でも単調に見えてしまい、
> 「難易度が上がると減る」を素通りさせる（2026-09-21に実際そうなっていた）。

### 5.3 狙いの決まり方

狙いは `withTacticsTarget` が決める。**ライフの割合が低い子ほど狙われやすい**（`TACTICS_TARGET_LOW_HP_BIAS`）。
完全なランダムだと「誰を守るか」の判断が立たないため。

全体攻撃だけは `targetsAll` を持ち、立っている全員が対象になる（狙いをかわせない）。

## 5.5 BGM は3枠とも専用（2026-09-21 ユーザー指示）

曲は3回に分けて決まった。
「**曲数が足りないからボス戦だけいれよう**」→「**中ボス戦は一旦これで**」→
「**通常曲とボス曲の変更 / 戦場→通常曲 / 魔窟→ボス曲**」。

| WAVE | 場面 | 枠 | 曲 |
| --- | --- | --- | --- |
| 1〜8 | 通常戦 | `tacticsBattle` | **戦場の疾風**（`senjou_no_shippuu`） |
| 9 | 中ボス戦 | `tacticsMidBoss` | **The City Beneath the Comets**（**すでにある曲を指すだけ**） |
| 10 | ボス戦 | `tacticsBoss` | **魔窟の旋律**（`makutsu_no_senritsu`） |

- **中ボス戦は音源を増やさない。** すでに入っている曲の id を指すだけにする
  （CLAUDE.md ⑥-2「すでにゲームに入っている音源が使えるなら、コピーを作らない」）
- **ジャケットは預かっているだけ。** 2枚とも `tools/art-sources/song-art/` にあり、
  `monster-hero/images/song-art/` へは置かない（「今後モンビー実装用にジャケットも送っとく」）。
  先に置くと `image-asset-check` が「どこからも参照されていない絵」として落とす
- BGMアレンジのタブはモードを公開するまで出さない
  （`TACTICS_MODE_PUBLIC_RELEASE || TACTICS_BETA_PRO_RELEASE`。種族チャレンジと同じ扱い）
- **枠の呼び名は「中ボス戦」。** WAVE9はデュラハンではなくスプラッターなので、
  画面に「デュラハン戦」と出すと敵と食い違う（内部の `modeBgm.dullahan` はそのまま）

**判定はタクティクスをいちばん先に見る。**

```js
const modeBgm = isTacticsMode(runMode)
  ? { normal:'tacticsBattle', dullahan:'tacticsMidBoss', moo:'tacticsBoss' }
  : isSpeciesChallengeMode(runMode) ? …
```

> ⚠️ タクティクスの種族チャレンジ・プロは `isSpeciesChallengeMode` / `isProMode` にも当たる。
> **後ろに置くとそちらの枠へ落ちて、専用曲が一度も鳴らない。**

> ⚠️ **`tacticsBoss` / `tacticsMidBoss` を `BGM_ARRANGEMENT_LEGACY_FALLBACK` へ入れない。**
> 入れると、チャレンジのボス曲・デュラハン曲を自分で選んでいる人にはその曲が引き継がれ、
> 決めた曲が鳴らない。
> 入れなければ `normalizeBgmArrangement` が既定値（専用曲）で埋めるので、
> 既存プレイヤーにもそのまま届く（CLAUDE.md ⑦ の「新しいキーを足す」に沿う）。

> ⚠️ **曲の名前にモード名を入れない。** BGMアレンジの**選択肢は公開前でも全曲出る**ので、
> 「タクティクス ボステーマ」にすると、まだ見せていないモードの名前がそこから見えてしまう。
> いまは仮に「決戦テーマ」。ユーザーから正式な曲名をもらったら差し替える。

音源の形はBGMの流儀（**96kbps / 44100Hz ステレオ**）にそろえてある。
受け取った原本はどれも 180〜192kbps・48kHz でジャケット画像が埋まっていたので、
`-map_metadata -1 -vn` で落とし、倍率をかけて **-14.4 LUFS** にそろえた
（戦場の疾風 +1.6dB / 2.22MB・3分14秒、魔窟の旋律 +1.8dB / 1.70MB・2分29秒）。

> ⚠️ **中ボス戦の曲だけ 32kHz。** モンヒロビートの曲を流用しているため（あちらの流儀は
> 32kHz / 96kbps）。すでに配信している曲なので作り直さない。
> 検査も、**このモードのために入れた曲だけ**形を見る。
起動時の読み込み（`index.html` の `SIZES`）には入れない（開いたときに初めて読む側が正しい）。

### 公開するとBGMアレンジのタブが6つになる

チャレンジ・クイック・プロ・極限・種族・**タクティクス**。5つまでは1行（5列）に収まっていたが、
6つを1行に押し込むと375pxで「チャレン**/**ジ」「タクティ**/**クス」と割れて読めない。
**6つ以上は3列×2行**にする（`battleModes.length>=6?'grid-cols-3':…`）。

> ⚠️ 検査(`bgm-arrangement-layout-check.js`)は、**列数の決め方を本体の式から読む**。
> 検査へ書き写していたため、タブが6つになったのに5列のまま測って落ちていた（2026-09-21）。
> あわせて「**文字が折り返されない**」も見るようにした。はみ出しの検査だけでは、
> 6列に押し込んで文字が2行に割れた状態を拾えなかった。

検査は `tools/audio/tactics-bgm-check.js`（曲と結線）と
`tools/audio/bgm-arrangement-layout-check.js`（タブの並び）。

> `TacticsProBeta*` から `TacticsPro*` へ変わる。**行は消さない**ので、本番の順位は空から始まる

> ⚠️ 検査は**公開の状態で見るものが変わる**。`tactics-modes-check.js`（遊べるモード・ランキング）、
> `tactics-browser-check.js`（入口の枠が押せるか）、`tactics-intro-story-check.js`（導線）の

## 6. 供モンの加入

合算しないので、加入は「**盤面に1体増える**」ことそのものになる。

- 加入した子は**自分のライフ・ちから・丈夫さ・ガッツ**を持って空きスロットへ入る
- 倒れた子の代わりにはならない（スロットは埋まったまま）
- **加入すると敵も強くなる**（当初案から引き継ぐ。強く育てた子を連れていくほど敵も手ごわい）
  - 強化量は「連れてきた供モンの**総合力**（`monsterPowerOf`）」で決める
  - 人数ごとの固定倍率にすると弱い編成ほど苦しくなるため、総合力で決める（2026-09-19 ユーザーが選択）

## 7. 作りながら当てた数字（全部決着済み）

設計の骨を決めたあと、作りながら当てる宿題が4つあった。**4つとも済んでいる。**

| 当時の宿題 | 決まった形 |
| --- | --- |
| **戻したときのライフ** | どちらも**満タン**。回復カード・緊急回復は率で貯まり、**上限に届いた瞬間に立つ**（割合を別に決めていない）。トレーニングの「起こす」は `reviveTacticsUnit` が `hp = maxHp` にする |
| **距離適性の扱い** | 新モードは**「その子の適性が、その子の攻撃に効く」**。既存モードは今までどおり編成全員ぶんの合算（`distAptPct`）。合流しても合算しない。枠ごとの表示（`distTotalBonus`）も、その枠に立っている子の適性を出す。カードの攻撃段階（`ATK_TIER_THRESHOLDS`）は編成から決まるのでこれまでどおり |
| **全体攻撃の威力** | 1体あたり ×0.9（単体狙いは ×2.2）。**単体狙いより必ず低くする**を `tactics-enemy-actions-check.js` が見張る（5.3） |
| **敵の狙い方の偏り** | **ライフの割合が低い子ほど狙われやすい**（`TACTICS_TARGET_LOW_HP_BIAS`）。完全ランダムだと「誰を守るか」の判断が立たないため（5.3） |

## 10. 段階ごとに決めた形（あとから読む人向け）

9の表の各段階について、そのとき決めた形と理由を残す。

### 段階4で決めた形

- 盤面 `tacticsUnits` は `slots` と同じ並び。更新の入口は **`applySlots` ひとつだけ**にした。
  `setSlots` を直に呼ぶ場所を作ると、盤面だけ古いまま狙いを決めてしまう
- 盤面は **ref でも持つ**。敵の行動を抽選するのは再描画より先なので、state だけでは間に合わない
- 狙いは「**予告として出す直前**」に決める（`aimTacticsIntent`）。予約した時点で固定すると、
  そのあいだに倒れた子を狙ったまま予告してしまう
- 予告の吹き出しは `enemyIntent.targetName` を出すだけにした。画面側はモードを知らない
  - ⚠️ **それだけでは足りなかった**（2026-09-21 ユーザー指摘「誰に攻撃か分からない」）。
    **間合い攻撃は相手を1体決めない**（`withTacticsTarget` が `sweep` を素通りさせる）ので
    `targetName` を持たず、予告が「突進: 中 (予定: 186)」で終わっていた。
    いまは画面側で `tacticsIntentTargets`（**本番と同じ関数**）を通し、
    その間合いに立っている子の名前を出す。距離撃でずらして誰もいなくなったときは
    「だれもいない」と出す。全体攻撃は今までどおり「全員」
  - **名前だけでは4つの枠から自分で探すことになる**ので、盤面の枠そのものにも印を出す
    （`data-tactics-aimed` ＋ 枠の内側の赤い線と 🎯）。カードを置ける黄色の輪・
    ドラッグ中の緑の輪と重ねないよう、**輪ではなく内側の線**で出している

### 段階5で決めた形

- パーティのライフ（`hp`）＝**盤面の合計**、`maxHp`＝**素の上限の合計**。
  みゅあ補正は既存モードと同じく `effectiveMaxHp` が掛け、**1体ずつの上限にも同じ倍率**を入れる
  （`scaleTacticsUnits`）。どちらか片方だけにすると、ゲージの満タンと盤面の合計がずれる
- 盤面を書き換えるのは `commitTacticsUnits` **ひとつだけ**。ref・state・`hp`・`maxHp` を必ず同時に動かす
- **1体もいない盤面ではライフに触らない。** ここで0にすると、編成前の画面が
  いきなり敗北扱い（`hp<=0` で GAME OVER）になる
- ライフの増減は `tacticsDamage` / `tacticsHeal` / `tacticsWipe` を通し、
  **新モード以外では `null` を返す**。呼び出し側は `null` のときだけ今までどおりの1行を通すので、
  既存5モードの分岐（ガード・反射・吸収・回避）を1行も書き換えずに済む
- 供モン合流のライフ**合算はやめた**。合流した子は自分のライフを持って盤面へ加わる
- ~~トレーニングで伸びた上限は素の上限に比例して配る~~ → **段階11で「1体ずつ選ぶ」形になった**（4.8 / 段階11で決めた形）
- 自傷（みゅあの札）では誰も倒れない。1体ずつ最低1を残す

### 段階6で決めた形

- ガッツも盤面の合計。**ただし払えるかは合計では決まらない。** その子のガッツで払う
  （`canTacticsSlotPay`）。合計で足りていても1体に寄っていれば使えない
- `cardNeedsMonster` が**どのカードでも true** になる。守りも回復もアシストも「使う子」を選ぶ
- **「1体につき何枚まで」に数えるのは攻撃カードだけ。** 守り・回復まで数えると、
  供モンが居ないWAVE1で1ターン1枚しか使えなくなる
- 使える子が1体しかいないときは、選ぶ手間を省いて自動で割り当てる（WAVE1は毎回これ）
- 倒れた子は `canTacticsSlotAct` が false なので、手札にカードが残っていても選べない
- ガッツを増やすのは `gainGuts` 1か所へまとめた（新モードは立っている子へ配る）
- AUTOには「倒れた子を空スロットにした `slots`」と `gutsForSlot` を渡す。
  ★`isAttackCardFn` も渡すこと。新モードは `cardNeedsMonster` がどのカードでも true になるため、
  渡さないと「守りだけのターン」を防ぐ仕掛け（`needsAttack`）が効かなくなる

### 段階7で決めた形

- 新モードの被弾は**専用の経路**を通る（`handleEnemyTurn` の `isTacticsMode` 分岐）。
  既存モードのガード処理はそのまま残してあり、新モードはそこを通らない
- ガードは**構えた子のぶんだけ**で受ける。誰が構えたかは `guardBySlot` に集める。
  貫通撃はガードが効かない
- **連撃は 0.6×3 の3ヒットに分かれ、ガードが届くのは1ヒットぶんだけ**（2026-09-20 ユーザー指示）。
  残りの2ヒットは必ず通り、**1ヒットに使い切れなかったガードは余らない**
  （ライフ・ガッツにもならない）。ここを「合計から引く」に戻すと、
  厚いガード1枚で連撃を完全に止められてしまう。
  つまり連撃は **最低でも ×1.2 ぶんが必ず通る**
- 振り分けは純関数に集める。`splitTacticsGuardedHit(incoming, hits)` が
  「ガードが届くぶん／通るぶん」を分け（端数は通るぶんへ寄せて合計を合わせる）、
  `resolveTacticsGuardedHit(incoming, hits, guard)` が**実際に受ける量と余り**を返す。
  **予告（予定ダメージ）と実行の両方が同じ関数を通る**。別々に数えると
  「ガードしたのに予定より減った」になる
- 数字の例（1ヒット60×3＝180ダメージ）。`tools/mode/tactics-units-check.js` が実際に動かして見る

  | ガード | 受ける | 余り（ライフ・ガッツへ） |
  | ---: | ---: | --- |
  | 0 | 180 | 0 |
  | 40 | 140 | 0 |
  | 60 | **120** | 0 |
  | 100 | **120** | **0**（余らせない） |
  | 999 | **120** | **0** |
- ガードの余りは**その子の**ライフとガッツになる
- **回復には全体回復と単体回復がある**（2026-09-19 ユーザーの整理）。
  「その効果が誰に起きたことか」で決まり、カードの持ち主では決まらない

  | 種類 | どれ | 入り先 |
  | --- | --- | --- |
  | **全体回復** | 回復カード（みゅあ・メロソほか）・緊急回復・メロソの次ターン全回復 | **1体ずつ「その子の上限 × 率」**（`rateHealTacticsBoard(..., true)`）。倒れた子にも入る |
  | **自動再生** | 毎ターンのライフ回復%・ガッツ回復%・ポルツの弁当 | 同じく1体ずつだが**倒れた子には入れない**（`includeDowned` なし） |
  | **単体回復** | ガードの余り（構えた子）・ドレイン（殴った子）・**吸収（狙われた子）**・固有技（使った子） | その子だけ（`healTacticsAt` / `rateHealTacticsAt`） |

- ⚠️ **量はどれも「その子の上限 × 率」**（2026-09-20 ユーザー指示）。合計の上限から量を出して
  配る形が残っていると、そこだけ「1体だけ傷ついているとパーティ全員ぶんがその子へ入る」になる。
  入口は `tacticsRateHeal` / `tacticsRateHealAt` / `gainGutsByRate` の3つに集約してある
- **ガッツは倒れた子へ入れない**（カードを使えないので貯める意味がない）

- 回復カードで「使う子」を選ぶのは**ガッツを払うため**。効き先は上の表のとおりで、
  使った子だけに寄るわけではない（倒れた子にも入る）
- **自動再生を1体ずつにした理由**（2026-09-20 ユーザー指摘）。
  合計の上限から量を出して配る形だと、①1体だけ傷ついているとき**パーティ全員ぶんの回復が
  その子へ丸ごと入る**、②**倒れている子の上限も量の計算に入る**ので倒れている子が多いほど
  残った子がよけいに回復する（逆になっている）、の2つが起きる。
  例：上限 1440 / 518 / 1328 / 1420 で回復率38%なら、前は合計 4706 の38%＝**1788**を
  減っている子へ配っていた。いまは **547 / 196 / 504 / 539** と1体ずつ
- **吸収は「狙われた子に起きたこと」**（2026-09-20 ユーザー指示）。回避・反射と同じ抽選から出るが、
  効くのは**その子だけ**。受けるはずだったダメージ（**その子の丈夫さ**で計算し直した値）ぶんだけ、
  その子のライフへ入り、その10%がその子のガッツへ入る。
  全体攻撃なら狙われた全員がそれぞれ自分のぶんを吸う
- **「2枚目以降は効果半減」は同じ子の2枚目だけ**（2026-09-20 ユーザー指示）。
  ステータスが1体ずつになったので、パーティ全体で数えると**ほかの子が1枚使っただけで
  自分の1枚目が半分になる**。ハム・ききでカードの枚数が増えて**同じ子が2回動くとき**だけ半減する
- 数え方は `cardHalveGroup(slotIdx)` の1か所で決める（新モードは枠ごとの箱、既存5モードは
  いつも同じ箱）。器は純関数 `makeCardHalveCounter(groupOf, isExempt)`。
  **実処理・カード選択中の予測・合計軽減の表示がすべてここを通る**。
  別々に数えると「予測より実際が弱い」が起きる
- 立ち上がった知らせ（「◯◯が起き上がった！」）は `commitTacticsUnits` が**1か所**で出す。
  どの回復から戻っても同じ扱いにするため
- 自傷・ドレイン・カードで増えるガッツも「使った子」へ
- **反射・回避・吸収の効く範囲は全部決まっている**（2026-09-20 ユーザー指示）。
  分け方は **「確定バフ（固有技）は味方全体、確率で出るものは狙われた子だけ」** の1本。

  | | 出どころ | 効く範囲 | 返す／入る量 |
  | --- | --- | --- | --- |
  | **反射（確定）** | **モノリスの固有技**（`setNextTurnBuff('reflect',true)`。抽選を飛ばす） | **味方全体。** 発動したターンは**誰もダメージを受けない**（ガードも要らない） | 狙われた子が受けるはずだった量。全体攻撃なら**狙われた全員ぶんの合計**を返す |
  | **反射（確率）** | 勇者モンがモノリス（30）・魂格 | **狙われた子だけ。** 全体攻撃なら狙われた中の**1体**が返し、残りはそれぞれ受ける | その子が受けるはずだった量 |
  | **回避** | 勇者モンがライガー（50）・魂格 | **狙われた子だけ。** 全体攻撃なら狙われた中の**1体**が避ける | — |
  | **吸収** | 勇者モンがオボロ／プラント（30）・魂格 | **狙われた子だけ** | その子が受けるはずだった量。その10%がその子のガッツへ |

  ⚠️ **同じ「反射」でも出どころで範囲が変わる**のがここの要点。
  実装は `forcedReflect`（＝`getTurnBuff('reflect')`）で枝を分けている。
  確定のほうは味方全体の枝、確率のほうは新モードの被弾処理の中で1体だけ返す。
  ⚠️ **確率で出るものは同時に起きない**（`rollUnifiedSpecialDefense` が回避／反射／吸収を排他で選ぶ）

### 段階8で決めた形

- **盤面はどのモードでも作る**（`syncTacticsUnits` はモードで分けない）。画面へ渡すときだけ
  新モード以外を `null` にする。ここを間違えると、ほかのモードにも帯が出てしまう
- 「このカードをこの子へ置けるか」も画面へ渡す（`tacticsCanAssign`）。
  **`null` のときだけ今までどおりの判定**を使うので、既存モードの置き方は変わらない
- 帯には検査の手がかり（`data-tactics-party-slot` / `data-tactics-hp` / `data-tactics-guts` /
  `data-tactics-downed`）を付けてある。実ブラウザの検査はここから合計を数える
- **合計のライフ・ガッツの帯（`data-ally-life` / `data-ally-guts`）は新モードでは出さない**
  （2026-09-19 ユーザー依頼）。スロットの中に入れた小さい帯は字が小さすぎて読めず、
  合計だけでは「どの子が瀕死か」が分からなかった。**合計の帯があった場所に、距離枠と同じ4列で
  1体ずつのライフ・ガッツを出す**。空いている枠は「空き」。倒れた子は枠ごと緑にして「ダウン」
- **1体ずつのちから・丈夫さ・距離適性はステータス画面（Hero Scan）で見る**。
  ここは元から「いまの自分の数値」を見る場所なので、新モードでは1体ずつに割って出す
- **強化の札（バフ欄）はいくつ付いても高さを変えない**（2026-09-20 ユーザー指摘）。
  もとは `flex-wrap` で何行にも伸び、強化が10個を超えると**敵の絵・「緊急」のボタン・
  与ダメの数字が押し出されて読めなくなっていた**。ふだんは**アイコン1行**（横に溢れたら横スクロール）、
  数値は「詳細」を押したときだけ出す（開いた側も `maxHeight:92px` で中スクロール）。
  この帯はどのモードでも共通なので、直せば既存5モードにも効く
- **帯は必ずアニメーションさせる**（ライフ `duration-1000` / ガッツ `duration-500`）。
  合計の帯にはもともと付いていたので、付け忘れると**回復もダメージも瞬間で増減して見える**
  （2026-09-20 ユーザー指摘）。`data-tactics-hp-bar` / `data-tactics-guts-bar` を手がかりに、
  実ブラウザで効いている時間そのものを見張る
- **手札の「使えない（灰色）」も合計では決まらない**（2026-09-19 ユーザー指摘）。
  ⚡242 持っていても 125 と 117 に分かれていたら ⚡128 のカードは誰も払えない。
  合計で見ていたころは灰色にならず、**枠に合わせてはじめて使えないと分かり、理由も出なかった**。
  画面は `tacticsCardBlock(card, cardIndex)` に聞く（**新モード以外は `null`** を返すので、
  そのときだけ今までどおり合計で見る）
- 使えない理由は `kind` で分ける。`guts`（ガッツ不足）／`down`（全員ダウン）／
  `uses`（攻撃カードを出せる子が残っていない）／`none`（その技を使える子がいない）／
  `limit`（1ターンに選べる枚数の上限）。**`limit` だけは帯を出さず、灰色だけ**にする
  （いままでの5モードと同じ見え方。全部のカードに赤い帯が出るとうるさい）
- 理由の帯（`data-tactics-card-block`）は**`grayscale` の外**、カードの枠の `div` へ置く。
  中へ入れると赤も灰色になる。全文（いちばん近い子の名前と ⚡いくつ足りないか）は
  カード詳細のパネル（`data-tactics-card-why`）に出す

### 段階9で決めた形

- 強化の基準は「**バトルを始めた時点（勇者モン1体）の総合力**」。いまの総合力が何倍になったかで決める。
  絶対値で決めないので、育ちきった人にも育っていない人にも同じ手ざわりになる
- **そのまま倍率にせず指数（0.7）で緩める。** 4倍の編成でも敵は約2.7倍まで。
  「めちゃめちゃ強い人でも苦戦して、それより弱くても多少はやれる」を残すため
- 上限は6倍

### 段階10で決めた形

- 与ダメージは**攻撃したその子のちから**。被ダメージは**狙われた子の丈夫さ**
- `getIncomingDamageBeforeTurnReduction(intent, targetSlot)` の **`targetSlot` を渡したときだけ**
  1体ずつの丈夫さになる。渡さない既存モードの呼び出しは何も変わらない
- ガードの軽減量も、その子の丈夫さから出す
- **パーティの `atk` / `def` は残す。** ガードの段階（カードの枚数）と攻撃段階を決めるのに使い続ける。
  ダメージそのものだけを1体ずつの値にした
- トレーニングで伸びたちから・丈夫さは、いまの値に比例して盤面へ配る（段階11で1体ずつ選ぶ形にする）

### 段階11で決めた形

- `trainingPicks` は新モードだけ **`{slot, id}` の並び**になる。立っている子ごとに2回ずつ選ぶ
- **タブは作らない。** まだ選び終わっていない子へ自動で進む（押す回数を増やさないため）
- **倒れた子はここで起こせる。起こすとそのWAVEは誰も強化できない**（ユーザーが決めた形）。
  戻るライフは**満タン**（`reviveTacticsUnit` が `hp = maxHp` にする）。
  ⚠️ 割合の定数は持っていない。回復カードのほうも割合で戻すのではなく、
  **率で貯めた結果が上限に届いた瞬間に立つ**（4.3）
- パーティの `atk` / `def` は**1体ずつの平均**を盤面から入れ直す（`commitTacticsUnits`）。
  合計にすると、人数が増えただけでガードの段階が跳ね上がる

### 段階12で決めた形

- **式は今までどおり。桁だけ 1/1000 へ縮める**（`shrinkTacticsScore`）
- **0にしない。** 1点でも入ったWAVEは1点残す（「何もしていない」と区別が付かなくなる）
- 記録もランキングも新モード専用の名前空間（`mh_tactics_*` / `Tactics*`）なので、
  ほかのモードのスコアとは混ざらない

## 11. 踏んだ落とし穴（繰り返さない）

### 11.1 「ルールを持っているか」の truthy 判定に新モードを巻き込まない

モードそのものに `specialRules` を持たせたところ、WAVE 1で
`showExtremeRule = w === 1 && !!specialRuleDifficultyForRun(...)` が真になり、
**極限チャレンジ用の「ルール発動」テロップが中身のないまま開いて `isBusy` が下りず、
敵の行動予告も出ず操作もできなくなった。**

極限の演出（テロップ・専用の帯・ルール詳細）は極限のもの。新モードが同じ取り出し口を使うときは、
**演出側で明示的に新モードを外す**こと。実行時エラーが出ず画面も壊れないので、遊んでみるまで気付けない。

### 11.2 実ブラウザの検査で「押せるものを押す」フォールバックを書かない

バトルまで進める検査で、押すものが見つからないときに「とりあえず押せるボタン」を押していたため、
戻るボタンや「全WAVE詳細」を踏んで難易度選択まで戻り、何が起きたのか分からないまま落ちていた。
**見つからなければその場で止めて画面を報告する**。

### 11.3 サンドボックスへ新しい定数を足すのを忘れない

`19-difficulties-and-rules.jsx` を切り出して動かす検査が7本ある。
新モードの定数（`BATTLE_MODE_TACTICS` / `isTacticsMode`）は `10-core.jsx` 側にあるため、
切り出し範囲から参照すると `ReferenceError` で一斉に落ちる。足すときはサンドボックスも合わせる。

## 12. 段階5に入る前に立てた計画（当時のもの）

> ⚠️ **ここは着手前の計画で、そのとおりにならなかったところがある。**
> **いまの形は §4（個別ステータスの設計）と §10（段階ごとに決めた形）が正本。**
> 残しているのは「なぜそう決めたか」の出発点を辿れるようにするため。
> ここを読んで実装を直さないこと。

### 12.1 いちばん大事な決めごと（いまも生きている）

**新モードでは、パーティのライフ（`hp` / `maxHp`）を「盤面の合計」にする。**

こうすると、いまある「ライフが0になったら敗北」「ライフバー」「20ターン経過で `setHp(0)`」などの
仕組みをそのまま使える。**全滅＝合計0** が自動的に成り立つ。

> ⚠️ 逆に言うと、**盤面と `hp` が食い違うと即座に壊れる**。「合計は残っているのに全員倒れている」
> 「誰も倒れていないのに敗北」が起きる。だから盤面を書き換える場所は1つだけにする。

```
commitTacticsUnits(next)   盤面を書き換える唯一の入口。
                           ref・state・hp・maxHp を必ず同時に更新して、合計を返す
```

### 12.2 計画と違ったところ

| 当時の計画 | いまの形 | なぜ変わったか |
| --- | --- | --- |
| 自動再生・ガード余剰・吸収で増えるぶんは**立っている子へ配る**（足りない量に比例・端数は先頭の子へ） | **配らない。** 自動再生＝1体ずつ「その子の上限 × 率」／ガードの余り＝**構えた子**／吸収＝**狙われた子** | 配る形だと「1体だけ傷ついているとパーティ全員ぶんがその子へ丸ごと入る」「倒れている子の上限まで量の計算に入る」が起きた（2026-09-20 ユーザー指摘。§10「段階7で決めた形」） |
| **回復カードのガッツも全体へ** | ライフは `tacticsRateHeal` で盤面ぜんぶへ入っていたのに、**ガッツだけ「使った子」へ入れていた**（2026-09-21 ユーザー指摘「みゅあの回復は全体なのに1体にしかきいてなかった」）。回復カード（助手の教え）は全体回復で、使う子を選ぶのは**ガッツを払うためだけ**。いまは `gainGutsByRateAll(率)` を通す。**その子だけ**へ入るのは固有技（スエゾー＝そのモンスターの技）と氷海の支配者（持っている子だけ・4.9）の2つ |
| **回復は倒れた子へ配らない** | 回復カード・緊急回復は**倒れた子にも入る**（`includeDowned`）。**勝手に起きる回復だけ**入れない | 「倒れた子のライフは復活までの貯め」にしたため（4.3）。勝手に復活してしまう自動回復のほうだけ止めた（2026-09-20 ユーザー指示） |
| **ガード・反射・吸収・回避は段階6まで今のまま**（パーティ単位） | ガード＝**構えた子自身**、吸収＝**狙われた子**。反射・回避はパーティ単位のまま | 段階6・7で個別化した |
| **WAVEクリアの全回復**で立っている子を満タンへ | **WAVEクリアの全回復はない**（クイックモード専用の仕組みで、新モードは通らない）。戻すのはトレーニングの「起こす」か回復カード | 段階11でトレーニングを1体ずつ選ぶ形にしたため（4.8） |
| 倒れた子のカードを使えなくするのは段階6 | 済み（`canTacticsSlotAct`） | — |

計画どおりに入ったものは次のとおり。

- 敵の攻撃は `tacticsIntentTargets` が返した子**だけ**が減り、0になったその子が倒れる
- 20ターン経過は全員を0にする（`tacticsWipe`。敗北の見え方をそろえる）
- `effectiveMaxHp` の二重がけを避け、**みゅあ補正は1体ずつの `maxHp` へ入れる**
- 供モン合流のライフ合算はやめた（合流した子は自分のライフを持って盤面へ加わる）
- 既存5モードは `isTacticsMode` の外なので何も変わらない（**既存の分岐を書き換えず、足す**）

### 12.3 検査で押さえたこと

- 盤面の合計と `hp` が必ず一致する（書き換えの入口が1つであること）
- 狙われた子だけが減り、ほかの子は減らない
- 全体攻撃は立っている全員が減る
- 1体倒れても敗北しない。全員倒れたときだけ敗北
- **勝手に起きる回復は倒れた子へ入れない**（回復カード・緊急回復は入れる）

## 13. 公開は2段階（β版 → 本公開）

中身は全部できている。公開は**β版（タクティクスプロだけ）→ 本公開（3モード）**の2段階で、
どちらも**いまはOFF**。

| | フラグ | 遊べるもの | ランキングの行 |
| --- | --- | --- | --- |
| いま | どちらも `false` | デバッグからだけ（記録もランキングも残らない） | 送らない |
| β版 | `TACTICS_BETA_PRO_RELEASE = true` | **タクティクスプロだけ**。ほかの2つは「準備中」のカード | `TacticsProBeta<難易度>` |
| 本公開 | `TACTICS_MODE_PUBLIC_RELEASE = true` | 3モードすべて | `TacticsPro<難易度>` / `Tactics<難易度>` |

### 13.1 β版を出すとき（2026-09-20 ユーザー指示）

「公開の前にβ版としてプロモードだけ出来るようにして」。やることは**フラグ1つ**。

1. `TACTICS_BETA_PRO_RELEASE` を `true` にする
2. `changelog-help-update` スキルを開いて、更新履歴1件＋助手の告知
   （`assistantNotice: { id:'update_notice_◯◯_v1', type:'mode' }`）。
   **「まだプロだけ」「ほかは準備中」であることを本文に書く**

画面はフラグだけで切り替わる。

- 仕組みのカードに **「β版」**の印と「いまはタクティクスプロだけ遊べます。ほかのモードは準備中です」が出る
- 中のカードは**3枚とも並び**、タクティクスチャレンジと種族チャレンジは押せない「準備中」になる
  （ユーザー指示「3つ並べてプロ以外は準備中」）
- 記録欄も「準備中／遊べません／遊べるようになったらお知らせします」に差し替わる

### 13.2 β版のスコアの区切り方（消さずにキーを変える）

**β版のあいだは `TacticsProBeta<難易度>` へ送り、本公開で `TacticsPro<難易度>` へ切り替える。**
本番の順位は空から始まり、**削除作業が要らない**。

> ⚠️ **ランキングの行はゲームから消せない。** `rankings` テーブルは `revoke delete` と RLS で
> 止めてあり、消すには Supabase の管理接続で SQL を流すしかない
> （手順は `docs/sql/rankings/MASTER_RANKING_INCIDENT_AUDIT.sql`）。消しすぎても戻せない。
> モンヒロビートの週間ランキングが週IDで区切っているのと同じで、**キーを変えるだけにする**。

β版の行は残るが、本公開後はどこからも読まないので画面には出ない。

### 13.3 本公開するとき

1. `TACTICS_MODE_PUBLIC_RELEASE` を `true` にする（β版のフラグはそのままでよい。
   本公開が立つと `battleModePlayable` が3モードすべてを `true` にする）
2. `changelog-help-update` スキルを開いて、更新履歴1件＋助手の告知
   （`type:'mode'`）と、画面のなかでの使い方案内（新しい `mh_◯◯_seen_v1`、公開フラグと同じ出し入れ）
3. **ヘルプの「👑+1」の説明を直す。** いまは「供モンとして合流しているだけでは増えません」と
   書いてあるが、タクティクスバトルでは**持っているモンスター本人が1枚多く使える**（4.9）。
   クラシックバトルの話であることが分かるように書き分ける
   （`tools/battle/hero-marker-check.js` がこの文を見張っているので、直したら期待値も合わせる）

### 13.4 公開フラグの見方は1か所（`battleModePlayable`）

画面・ランキング・プロフィールが**それぞれフラグを見ない**。どれも `battleModePlayable(id)` を
通すので、段階を増やしてもここ1つを直せば全部そろう。

| 関数 | 何を決めるか |
| --- | --- |
| `battleModePlayable(id, {debugBattle})` | そのモードをいま遊べるか |
| `battleModeComingSoon(id, {debugBattle})` | 遊べないが「準備中」のカードとして並べるか |
| `battleSystemComingSoon(systemId, …)` | 仕組みごと「準備中」にするか（β版が立つと外れる） |
| `battleSystemBeta(systemId, …)` | 仕組みのカードへ「β版」の印を出すか |
| `modeHasRanking(mode)` | 全国ランキングへ送るか（`battleModePlayable` を見る） |

> ⚠️ 一度 `true` にしたフラグを、実装側から勝手に `false` へ戻さない。
> 戻すと、すでに遊んだ人の全国ランキングだけが止まる。

## 14. モンヒロバトルの入口（2026-09-20 ユーザー指示・土台まで）

「モンヒロバトルに入ったらすぐモード選択ページにいかずに、チャレンジモードと新バトルモードと
クイックモードを選べるようにして、そこの中で各種モードがあるようにしたい」「クイックのみそのまま
入れる」「現状の仕様はクイックだけ外してほかはそのまま」「1画面増やしてそこで現状のモードと
新モード選べるようにすればいい」「通常/極限、種族とかはどっちのモードにもあるように」。

### 14.1 画面の並び

```
HOME「モンヒロバトル」
  └ BATTLE_SYSTEM_SELECT   どのバトルで遊ぶか ← ここを増やした
      ├ クラシックバトル   → BATTLE_MODE_SELECT（チャレンジ／プロ／種族チャレンジ）→ 難易度
      ├ タクティクスバトル → BATTLE_MODE_SELECT（いまはタクティクスチャレンジだけ）→ 難易度
      └ クイックモード     → そのまま難易度（中のモードが1つだけなので飛ばす）
```

- **仕組み（`BATTLE_SYSTEMS`）は保存しない。** 画面を分けるためだけの値で、記録もランキングも
  今までどおりモードのid（`mh_hs_*` / `mh_tactics_*` など）で分かれる。**保存キーは1つも増えていない**
- **クイックはモード選択のカルーセルから外した**（入口で選ぶ）。ほかは今までどおり並ぶ
- **「そのまま難易度へ」で入ったときは、戻る先もモード選択ではなく入口**。モード選択へ戻すと
  そのモード1つだけが並ぶ画面が出てしまう（`battleSystemOf(battleMode).direct` で分ける）
- **名前は2026-09-20にユーザーが決めた。** 仕組みが **クラシックバトル / タクティクスバトル /
  クイックモード**、タクティクスバトルの中のふつうのモードが **タクティクスチャレンジ**
  （クラシック側の「チャレンジモード」と同じ位置づけだが、ランキングや記録で並んだときに
  見分けが付くよう別の名前にしてある）
- **公開前でも「準備中」の枠として並べる**（2026-09-20 ユーザー指示「準備中の新モードも
  クイックの上に入れて」）。モンヒロビートの準備中と同じ作りで、押せないカードを出す。
  `TACTICS_MODE_PUBLIC_RELEASE` が立つと準備中が外れて遊べるようになる。
  デバッグのバトルモード入口からは今までどおり遊べる
- デバッグのバトルモード入口も、この入口から入る（新モードの仕組みを選べる）

### 14.2 タクティクスバトルの中のモード（2026-09-20 ユーザー指示で実装）

**「通常/極限、種族とかはどっちのモードにもあるように」を、3つまとめて作った。**

| | クラシックバトル | タクティクスバトル |
| --- | --- | --- |
| 通常 | チャレンジモード（`challenge`） | タクティクスチャレンジ（`tactics`） |
| 極限 | 難易度えらびの「極限」タブ → **専用画面へ移る** | 同じ画面の「極限」タブに**そのまま並ぶ** |
| 種族 | 種族チャレンジ（`speciesChallenge`） | タクティクス種族チャレンジ（`tacticsSpecies`） |
| プロ | プロモード（`pro`） | タクティクスプロ（`tacticsPro`） |

#### 増やしたid（公開後は変えない）

| id | 記録の置き場 | 全国ランキングのキー |
| --- | --- | --- |
| `tactics` | `mh_tactics_hs_*` / `mh_tactics_clears_*` / `mh_tactics_highest_wave_*` | `Tactics<難易度>` |
| `tacticsPro` | `mh_tactics_pro_*`（同じ3種類） | `TacticsPro<難易度>` |
| `tacticsSpecies` | `mh_tactics_species_challenge_progress_v1` | `TacticsSpecies-<血統id>-<難易度id>` |

- **判定は3つ。** `isTacticsMode`（盤面が1体ずつライフを持つ＝この3つ全部）／
  `isProMode`（`pro` と `tacticsPro`）／`isSpeciesChallengeMode`（`speciesChallenge` と `tacticsSpecies`）。
  こうすると、しばり・倍率・編成のような「モードの性格」の分岐はそのまま使い回せる
- **`modeKeyPrefix` は `tacticsPro` を先に見る。** あとに回すと `isTacticsMode` が先に当たって
  `mh_tactics_` になり、タクティクスチャレンジと記録を奪い合う
- **`rankingDifficultyForMode` も `tacticsPro` を先に見る。** 同じ理由
- **`rankingDifficultyBase` は `TacticsPro` を `Tactics` より先に落とす。** 順番を逆にすると
  `ProHard` が残る
- 種族チャレンジのキーは3つ組（`<接頭辞>-<血統id>-<難易度id>`）のまま、接頭辞だけ
  `TacticsSpecies` にした。形が同じなので、読み書き・「全種族」の展開・種族名バッジは同じ道を通る

#### ⚠️ ここで見つけた不具合（記録がチャレンジへ混ざっていた）

タクティクスの器（id・接頭辞）は段階1で作ってあったが、**実際に読み書きする処理が
1つも無かった**。そのため難易度えらびの「この難易度で挑戦」から入ると、

- 自己ベストが `mh_hs_<難易度>`（チャレンジ）へ書かれる
- クリア回数が `mh_clears_<難易度>` へ積まれる（＝極限・種族の解放条件まで進む）
- 最高到達WAVEが `mh_highest_wave_<難易度>` へ書かれる
- 全国ランキングもチャレンジの行へ送られる

という状態だった。デバッグから遊ぶだけなら `debugBattleRef` で止まるが、
難易度えらびの挑戦ボタンが `debugBattleRef` を false に戻すため、実際には素通りしていた。
`submitTacticsScoreOnce` と、クリア回数・最高到達WAVEのタクティクス用の枝を足して直した。

#### 極限を「同じ画面のタブ」にした理由

クラシックの極限は `EXTREME_MODE`（id `extreme`）という別モードで、押すと専用画面へ移る。
同じ作りをタクティクスへ持ち込むと**新しいモードidと記録の置き場がもう1つ要る**うえ、
タブを押した先がクラシックの極限チャレンジになってしまう。
そこで `challengeExtremeTab` をタクティクスでは false にして、難易度の一覧
（`TACTICS_DIFFICULTY_IDS` ＝通常9＋極限5）をそのまま「通常 / 極限」で分けた。

- **走らせ方は種族チャレンジと同じ。** 極限の段を選んだら `difficulty` を `'Normal'` にして
  `extremeDifficulty` に段を入れ、`extremeRun` を立てる。特殊ルール・倍率・ルール表示は
  既存の極限の仕組みがそのまま効く
- **記録に使う難易度は `tacticsRecordDifficulty()` が1か所で決める**
  （極限のときだけ `extremeDifficulty`）。自己ベスト・クリア回数・最高到達WAVE・
  ランキングのどれもここを通す
- **解放は タクティクスの記録だけで決める**（`isTacticsDifficultyUnlocked`）。
  クラシックの進み具合は混ぜない（混ぜると片方の進行がもう片方の解放に化ける）

  | 難易度 | 開く条件 |
  | --- | --- |
  | Beginner / Easy / Normal / Hard | **最初から**（`TACTICS_DIFFICULTY_INITIAL_UNLOCK_COUNT = 4`） |
  | Expert 〜 Legend | **1つ前の難易度を1回クリア**（2026-09-21 ユーザー指示） |
  | EXTREME（極限の入口） | タクティクスで Master 以上を1回クリア |
  | NIGHTMARE 以上 | 1つ前の極限をクリア |

  ユーザーの言葉は「**エキスパート以上は解放条件ありにしたい**」「**タクティクスの全モード、
  クラシックは据え置き**」「**1つ前をクリアで次が開く**」。
  タクティクスの種族チャレンジも同じで、`speciesChallengeInitialUnlockCountOf(mode)` が
  段数を出し分ける（**クラシックの種族チャレンジは Expert まで開いたまま＝据え置き**）。

  > ⚠️ **クラシックの5モードには入れない。** すでに遊んでいる人の解放状況が変わり、
  > 「Hard を飛ばして Expert を遊んでいた人」が閉め出される。
  > `SPECIES_CHALLENGE_INITIAL_UNLOCK_COUNT`（5）は動かさない。

  > ⚠️ デバッグのバトルモード入口から入ったときは `debugBattle` が立つので**全部開く**。
  > 鍵の見た目を確かめたいときは、公開フラグを立てて通常の入口から入る。
- **`addAssistantBond` へ `'extreme'` を渡さない。** タクティクスの極限は
  「極限チャレンジで遊んだ」ではない
- **ランキング画面の `keyOf` もタクティクスだけ別扱い。** 極限の段でも `Extreme*` ではなく
  `Tactics*` の行を読む（直さないと極限チャレンジの記録が並ぶ）

#### 種族チャレンジを2つ持つときの形

- 進み具合（解放・自己ベスト・クリア回数）は**モードidをキーにした入れ物**で両方同時に持つ
  （`speciesProgressByMode`）。モード選択ではどちらのカードも記録を出すため
- 保存キーは `speciesChallengeProgressKeyOf(mode)` が決める。
  `persistSpeciesChallengeClearRewardTransaction` も `progressKey` を受け取る形にした
- **どちらの周回かは `run.mode` が持つ**（`speciesChallengeRunMode`）。
  `mode` を持たない古い run は、これまでどおりクラシック扱い

`tools/battle/battle-system-select-check.js`。仕組みの定義・公開フラグでの出し入れ・

> 「HOMEの『バトル』を押して、次の画面で何かする」と書いてあったため。

> **HOMEのボタンが出るまで押す**形にしておくと、次に画面を増やしても落ちない。
