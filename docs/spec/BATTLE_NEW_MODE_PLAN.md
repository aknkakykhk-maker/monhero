# バトル新モード 設計案（2026-09-19 提案・未実装）

## 0. この文書の位置づけ

**まだ実装していない提案**である。ユーザーと決めた事項と、コードを読んで確かめた現状だけを書く。
合意できた時点で実装へ進み、実装後にこの文書を仕様書として書き直す。

## 1. なぜ作るか（2026-09-19 ユーザー）

- プレイヤーの1人が最高難易度 RAGNAROK（敵強度×200）をクリアした
- **「ただ強いだけの難易度」をさらに足しても面白くない**
- ほしいのは「めちゃめちゃ強い人でも苦戦し、それより弱い人でも多少はやれる可能性がある」遊び

## 2. 現状で確かめた事実（コードが正本）

### 2.1 いまの難易度は「強さの単調増加関数」

極限の特殊ルール（`specialRules`）は、アシスト効果減／正負補正／距離強化減／ガッツ増／累計ターンで敵強化／
与ダメ減衰／トレーニング減衰／DISTANCE BREAK／WAVE段階（神威・黄昏 Lv1〜5）／不死。
**どれも「敵を上げ、味方を削る」一方向**で、強い人と弱い人の差を縮める仕組みが1つもない。

### 2.2 スコアは与ダメージの総量

```text
finalRoundScore = floor((与ダメ総量 × (1 + wave×0.1) + 与ダメ総量 × turnMult) × 難易度スコア倍率)
turnMult = max(1.0, 2.0 - (turnCount - 1) × 0.05)
```

育成力の差がそのままスコア差になる。**弱い人が上位に来る余地が数式上ない**。

### 2.3 各WAVEは20ターン制限

`nextTurn > 20` で `setHp(0)`（`60-app.jsx:8615`）。
火力が閾値に届けば勝ち、届かなければ即敗北で、**中間の手応えが存在しない**。

### 2.4 敵の行動は5種類しかなく、20%は何もしない

`ENEMY_ACTION_DEFINITIONS`（`22-enemy-and-bond-entries.jsx:26`）

| 行動 | 重み | 中身 |
| --- | ---: | --- |
| 通常攻撃 | 50 | ×1.0 |
| ためる | 15 | 次ターンの必殺技が確定 |
| 必殺技 | 0 | ためた次に必ず発動（×2.5） |
| **様子を見ている** | **20** | **何もしない** |
| 移動 | 15 | 別の間合いへ（1ターン前に予告） |

5回に1回は敵が動かない。高難易度ほど「運で助かった」になり、読み合いになっていない。

### 2.5 供モン加入で5つが同時に起きる

`setupMon`（`60-app.jsx:9995` 付近）。WAVE 2・4・6 の後に最大3体。

1. 最大HP・ちから・丈夫さ・ガッツへ `plusStats` を加算
2. **現在HPも同額そのまま回復**（`setHp(p=>p+(nMaxHp-bHp))`）＝加入が回復イベントを兼ねる
3. **4距離すべての距離適性補正を加算**（置いた距離と無関係。Mなら+25%が4距離ぶん）
4. **固有技カードが1枚増える**（デッキが太り、手札の選択肢が増える）
5. 強化ポイント +1〜4（ランダム）

ベースモンのモッチー（ちから120）にゴーレム・モノリス・ザンが合流すると、ちからは120→240。
育成済みマスモン4体が全距離Mなら距離適性だけで**与ダメ+100%**が別枠で乗る。
**後半ほど雪だるま式に強くなる。**

## 3. 決まっていること（2026-09-19 ユーザーが選択）

| 項目 | 決定 |
| --- | --- |
| 位置づけ | **常設モード（6つ目）**。期間限定イベントではない |
| 方向性 | バトルシステム自体を変える。**敵の行動を増やす** |
| 供モン加入 | **加入と同時に敵を大幅強化**する ＋ **加入ボーナス自体も下げる**（両方） |
| 敵の強化量 | **連れてきた供モンの強さ（総合力）で決める**（§6.2 案B） |
| ターン制限 | **現状の20ターンのまま** |
| スコア式 | **現状の式のまま。ただし数値が高すぎるので 1/1000 ほどへ縮める**（§7.1） |
| モードの名前 | **あとで決める**。idは先に固定する（下記） |

加入時のHP回復をなくす案・加入を選択制にする案は採らない。

### 3.1 idは先に決める（あとから変えられないため）

モードのidは**保存キー（`mh_<id>_*`）と全国ランキングの `difficulty` へ焼き付く**ので、
公開後に変えるとその人の記録が消えたように見える。画面に出す名前とidは一致していなくても動く
（プロ＝`pro` のように一致しているのは結果で、決まりではない）。

そこで **id は `tactics` で固定**し、画面に出す名前だけをあとから差し替える。

| 使うところ | 値 |
| --- | --- |
| モードid | `tactics` |
| 自己ベスト・記録 | `mh_tactics_hs_<難易度>` ほか `mh_tactics_` 接頭辞 |
| 全国ランキング | `difficulty` へ `Tactics<難易度>`（例 `TacticsHard`） |
| 画面に出す名前 | **未定**。候補は 戦術モード / 討伐モード / 決戦モード |

## 4. モードの設計

### 4.1 売り（既存5モードと被らせない）

| モード | 売り |
| --- | --- |
| チャレンジ | 強化を選んでスコアを伸ばす王道 |
| クイック | モンスターの育成 |
| プロ | ベースモンだけで挑む難しさ |
| 極限チャレンジ | 育てたモンスターで限界へ挑む高難度 |
| 種族チャレンジ | ひとつの種族だけのしばり |
| **新モード** | **敵の技を読んで受け方を決める、対応力のモード** |

名前はあとで決める（§3.1）。id は `tactics` で固定する。

### 4.2 難易度

通常の9段階（Beginner〜Legend）をそのまま使う。専用の段階は作らない。
敵の行動が主役なので、敵の倍率を増やす方向の段階は足さない。

### 4.3 解放条件

既存の `mh_clears_<難易度>` をそのまま読む（**専用の解放フラグを作らない**ので旧セーブもそのまま解放される）。
案: チャレンジで Expert 以上を1回クリア。

## 5. 敵の行動（このモードの中心）

### 5.1 行動表はモード別に持つ

`ENEMY_ACTION_DEFINITIONS` を直接書き換えず、**新モード専用の行動表**を別に持つ。
難易度の `specialRules` と同じ「その行動を持っているか」方式にすれば、
既存モードのコードには分岐が増えず、挙動も変わらない。

**「様子を見ている」は新モードでは外す。**

### 5.2 足す行動の語彙

どれも既存の予告システム（`enemyIntent` が次のターン、`enemyNextIntent` がその次）へそのまま乗る。

| 行動 | 効果 | 予告 | 受け方 |
| --- | --- | --- | --- |
| 薙ぎ払い | 指定した2距離へ ×1.6、ほかの距離は ×0.4 | 対象の距離を出す | 安全な距離へ移る／距離撃で敵を動かす |
| 連撃 | ×0.6 を3回 | 回数を出す | ガード（ヒットごとに軽減が効く） |
| 貫通撃 | ×1.8・**ガード無効** | 出す | 回避／反射／スタン／無敵 |
| 咆哮 | 次のターンから敵の攻撃 +50%（重ねがけあり） | 出す | あつの挑発で潰す／急いで削る |
| 足止め | 1ターンのあいだ距離撃と移動を封じる | 出す | 先に配置を整えておく |
| 呪詛 | 3ターン後に ×4.0。それまでに敵HPを20%削れば解除 | 残りターンを出す | 集中攻撃で解除する |
| 再生 | 最大HPの8%を回復 | 出す | 削り切る／妨害を挟む |

### 5.3 敵ごとの割り当て（案）

WAVEが進むごとに読むことが増えていく形にする。

| WAVE | 敵 | 持つ行動（通常攻撃・ためる→必殺・移動に加えて） |
| ---: | --- | --- |
| 1 | ディノ | 連撃 |
| 2 | ゲル | 薙ぎ払い |
| 3 | ブラックディノ | 連撃・咆哮 |
| 4 | ジャアクソウ | 呪詛 |
| 5 | ブルーマウンテン | 貫通撃・薙ぎ払い |
| 6 | ガリ | 足止め・咆哮 |
| 7 | ナーガ | 呪詛・薙ぎ払い |
| 8 | リリム | 再生・貫通撃 |
| 9 | デュラハン | 連撃・咆哮・貫通撃 |

### 5.4 直す場所（5か所）

1. 行動の定義（新モード用の表）
2. `evaluateEnemyActions` … その行動が今使えるか
3. `chooseEnemyAction` … intent を作る（対象距離・回数などを持たせる）
4. `handleEnemyTurn` … `intent.type` の分岐を足す（`60-app.jsx:8450`〜）
5. `enemyActionLabel` / `ENEMY_ACTION_ICONS` … 予告の見た目

SCAN（敵の行動一覧）も同じ定義を読むので、**プレイヤーは事前に敵の手札を確認できる**。

## 6. 供モン加入（決定ずみの2つを両方入れる）

### 6.1 加入ボーナスを下げる

既存の部品でそのまま書ける。

- `allyJoinBonus: 0.5` … `plusStats` の加算を50%（CHAOSと同じ枠）
- `positiveModifier: 0.5` … 距離適性の**正の補正**を半減（NIGHTMAREと同じ枠）

固有技が1枚増えることは**そのまま残す**。加入の価値を「数字が上がる」から
「**手札の選択肢が増える**」側へ移す。

### 6.2 加入と同時に敵を大幅強化（新ルール）

`specialRules` へ1つ足す。持たない難易度・モードでは倍率1で、既存の挙動は変わらない。

**採用：案B（連れてきた供モンの強さで決める）**（2026-09-19 ユーザーが選択）。
加入した供モンの**総合力**（`monsterPowerOf`。既にある派生指標で、セーブデータには保存しない）に比例して
以降のWAVEの敵HP・攻撃を強化する。

```text
敵の倍率 = 1 + min(上限, 加入した供モンの総合力 / 基準値)
```

- 育成済みマスモンを連れてくるほど敵が強くなる
- ベースモンや育てていない個体なら敵の強化も小さい

→ **「強い人ほど苦戦し、弱い人でも多少はやれる」がここで成立する。**

採らなかった案A（人数ごとに固定倍率を累積）は、仕組みは単純だが**弱い編成ほど苦しくなる**ため。

実装で決めること:

- **基準値と上限** … 総合力がどれくらいで何倍になるか。ベースモン（総合力の実測）と
  育成済みマスモンの実測を並べてから決める。青天井にしない
- **勇者モンを数に入れるか** … 加入の話なので供モンだけを数える（勇者モンは開始時点で決まっており、
  「加入と同時に強化」という形にならないため）
- 倍率は難易度名でハードコードせず、`specialRules` の1項目として持つ（持たない難易度では1倍）

## 7. スコアと記録

| 項目 | 決め方 |
| --- | --- |
| 記録の保存キー | `mh_<新モードid>_` の新しい接頭辞。**既存キーは読みも書きもしない** |
| 全国ランキング | `rankings` テーブルの `difficulty` へ接頭辞を付けた値（`ProHard` と同じ作り）。**テーブル・列は増やさない** |
| スコア式 | 現状の式のまま。**新モードだけ 1/1000 ほどへ縮める**（下記） |
| クリア報酬 | 通常難易度どおり＋虹のプシュケー（`CLEAR_PSYCHE_REWARD`） |
| スキップチケット | 使えない（スコアを競うモードのため。チャレンジ・プロと同じ） |
| マスモン登録 | 既存のしくみをそのまま使う |

### 7.1 スコアは現状の式のまま、桁だけ縮める（2026-09-19 ユーザー決定）

計算の中身（与ダメージ総量ベース）は**変えない**。ただし極限では数字が大きくなりすぎて読めないので、
**新モードのスコアだけ 1/1000 ほどのスケールにする**。

- 縮める係数は新モードの設定として1か所に持つ（数値を画面やヘルプへ書き写さない）
- **既存モードのスコア式・既存のランキングの値には一切触らない**。新モードは別の
  ランキング名前空間（`Tactics<難易度>`）なので、既存の記録と混ざることはない

実装で気をつけること:

- **0 にしない。** `submitRunScoreOnce` は先頭で `score <= 0` を見て送信を打ち切るので、
  1/1000 にした結果が 0 になると記録もランキングも残らない。
  WAVEを1つでもクリアしたら最低1が残るようにする
- 自己ベスト・ランキング・リザルトの表示がすべて同じ縮めたあとの値を見ること

なお、ターン制限を現状どおり・式も据え置きにしたので、**スコアの順位は引き続き育成力に比例する**。
「弱い人でもランキング上位を狙える」ようにはならない（苦戦するかどうかは §6 の敵強化で調整する）。
ここを変えたくなった場合は、上限のある採点（到達WAVE・残ターン・敵の技をどれだけ正しく受けたか）へ
寄せる案がある。

## 9. 実装の段取り（案）

名前が決まるまでは**公開フラグを OFF** にして進める（種族チャレンジが
`SPECIES_CHALLENGE_PUBLIC_RELEASE` で段階公開したのと同じやり方）。
フラグがOFFのあいだは新しい入口に出ないので、途中の状態を本番へ出したままにならない。

| # | 中身 | 通す検査 |
| ---: | --- | --- |
| 1 | モードの器（id `tactics`・カード・説明・記録キー・ランキング名前空間・解放条件・公開フラグ） | `battle-mode-check.js` / `battle-mode-select-check.js` |
| 2 | 敵の行動を足す（定義・可否・抽選・実処理・表示・SCAN） | `battle-check.js` / `enemy-scan-check.js` / `battle-scenario-check.js` |
| 3 | 供モン加入の調整（ボーナス減＋総合力に応じた敵強化） | `battle-check.js` / 新規の検査 |
| 4 | スコアを縮める（最低1の保証を含む） | `battle-mode-check.js` / ランキング関係 |
| 5 | 名前を決めて公開フラグをON。更新履歴・ヘルプ・助手の告知（`changelog-help-update` スキル） | `player-words-check.js` ほか |

各段階で `node tools/run-checks.js --changed` を通す。

更新履歴と助手の告知は**5の公開時にまとめて1件**書く（1〜4はプレイヤーに何も起きていないため、
CLAUDE.md ⑤の「デバッグ専用・プレイヤーに現れないものは載せない」と同じ扱いにする）。
告知の `type` は新モードなので `mode`。
