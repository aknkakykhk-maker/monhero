# UIルール設計書

## 1. 対象環境

本作はスマートフォン縦画面・タッチ操作を主対象とする。PWA manifest は `portrait`、配信HTMLは `maximum-scale=1.0`、`user-scalable=no`、`viewport-fit=cover` を指定する。ルート直下は幅100%、高さ100%、最大幅600pxで中央寄せし、外側のスクロールを隠す。safe-area の上下余白を body に適用する。

## 2. 起動とグローバル操作

- HTMLは React / ReactDOM、Tailwind CDN、画像、ゲームデータ、更新履歴、本体生成JSの順に読む。本体取得は失敗時にキャッシュ回避URLで1回再試行する。
- セーブ読み込みとタイトルBGM準備が終わるまでローディングを表示し、その後 `TAP TO START` のユーザー操作で音声を解除する。
- 起動タップの後続clickが背後のタイトルUIへ届かないよう、直後のclickをキャプチャ段階で破棄する。
- 全buttonのclickに共通タップSEを付ける。音量はSE/BGM別の0～100で、クイックミュート解除時は双方1にする。
- `visibilitychange` で音声状態を調整する。画面状態に応じてタイトル、プロフィール、メニュー、マーケット、強化、融合、通常戦、ボス戦、リザルトのBGMを切り替える。
- `version.json` のbuildが本体 `BUILD_DATE` と違えば更新通知を表示する。

## 4. タッチ操作規則

- ボタンは `active:scale-*` 等で押下反応を示す。ホバーだけを必須操作にしない。
- 戦闘カードはタップ選択とスロットへのpointerドラッグの双方に対応する。短い移動はタップ、閾値を越えた移動はドラッグとして扱う。
- 攻撃カードを選ぶと対象モンスター指定待ちになる。割当不可、ガッツ不足、枚数上限の場合も詳細表示は可能だが選択状態にはしない。
- 固有技は所有スロット以外へドロップできない。通常は1スロット1攻撃だが、ハム勇者かつハム枠はカード上限まで割り当てられる。
- モンスター編成は選択中の下書きと確定済み編成を分離し、「決定」まで永続化しない。
- マスモン一括強化も下書きと確定を分離する。
- モーダル状態（カード詳細、敵・勇者情報、音量、ランキング、ヘルプ、更新履歴、終了確認等）はReact stateで重ね、画面状態そのものと分ける。

タップ対象の最小ピクセル寸法を一律に強制する共通定数は**未確認**。各画面のTailwindクラスで個別指定されている。

## 5. 視覚言語

- 背景は黒～濃紺、本文は白／slate、機能ごとにアクセント色を使う。
- 距離は零=赤、近=黄、中=緑、遠=青で統一する。
- カードは攻撃=赤、距離攻撃=青、固有=黄、ガード=緑、バフ=紫、デバフ=藍、回復=桃、ドロー=灰。Tailwind JIT欠落を避けるためカード本体色は `TYPE_INLINE_STYLE` でも明示する。
- 難易度色も動的クラスだけに依存せずinline styleを使う。
- 敵行動はラベルとアイコンで事前表示し、予測ダメージも表示可能にする。
- ダメージ、回復、状態、教え、ガード、画面振動、リップル、攻撃モーションは一時stateとCSS animationで表示する。
- 画像はドラッグや長押し保存を抑止する箇所があり、マスモン画像は元画像と部位別再着色レイヤーを重ねる。

## 6. レスポンシブとスクロール

- アプリ全体は100dvh内に収め、画面ごとの内部領域だけを `overflow-y-auto` 等でスクロールする構成である。
- 最大幅600pxを超える端末では中央のゲーム面を広げない。
- ノッチ対応はHTMLの `env(safe-area-inset-top/bottom)` が担う。
- 画面幅ごとのブレークポイント仕様書や横画面専用レイアウトは**未確認**。manifestは縦向きを要求する。

## 7. 文言・入力

- UI文言は日本語を基本とし、状態名・難易度・装飾ラベルに英語を使用する。
- ブリーダー名はtrim後10文字、マスモン名はtrim後12文字。空文字は保存しない。
- バックアップ復元エラーは「コードが正しくありません」、本体ロード再試行失敗は通信確認と再読み込みを案内する。
- 更新履歴は開いた時点で最新日時を既読保存し、開いている間のNEW表示判定には開く直前の値を使う。
