# モンヒロビートの遊んだ記録と、譜面生成ツールの学び（2026-09-28）

ユーザー指示「人間が関与しないで完璧なツールに仕上がる仕組みを作ってほしい」（遊ぶのはプレイヤーが勝手にやる）。
決めたこと（ユーザー判断）: **全プレイヤーから送る** ／ 学んだ作り方は **新曲にだけ使う**（公開中の曲はユーザーが指示したときだけ作り直す）／ **週1回** 動かす。

## なぜ要るか

譜面の物差し（`rhythm-chart-quality-report.js` / `rhythm-chart-feel-report.js`）は、解析の結果を正解として測る。
そのため解析のくせ（低音の打点が遅れて記録される、など）は見抜けず、直すほど点が下がることさえあった
（`RHYTHM_CHART_ENGINE_ROADMAP.md` の8章・only my railgun）。ここは **プレイヤーが実際に押した時刻を正解として** 測り、
生成器の調整値をその向きへ少しずつ動かす。人は何も判定しない。

## 流れ

```
プレイヤーが公開中の曲をふつうに最後まで遊ぶ
  ↓ ゲームがノーツごとの判定のずれを縮めて送る(26-supabase.jsx の sbSendRhythmPlayLog → rhythm_play_logs)
サーバーに記録がたまる
  ↓ 週1回の定期実行: node tools/mode/rhythm-play-log.js --fetch --report --learn --write
まとめ(tools/mode/authoring/playlog/summary.json)へ足し、譜面ごとの遊んだ感覚を測る
  ↓ 証拠が足りたときだけ、調整値(tools/mode/authoring/chart-play-tuning.json)を少し動かして新しいリビジョンとして書き足す
次に足す曲が、そのリビジョンの作り方で作られる
  ↓ その曲も遊ばれ、記録が次の週の学びに入る(行き過ぎていれば戻る)
```

## ゲーム側（`monster-hero/src/parts/30-rhythm-play.jsx` / `26-supabase.jsx`）

- 送るのは、**公開中の曲（`RHYTHM_DEMO_SONG_IDS`）を最後まで遊んだとき**だけ。デバッグ画面・練習・タイミング合わせ・アシストモードは送らない
- 中身: 曲id・難易度・譜面の指紋（ノーツ数と最初・最後の時刻。譜面メモと同じ `rhythmChartFingerprint`）・版の日付・
  端末ごとのでたらめなID（`mh_rhythm_play_log_device_v1`）・判定タイミング調整の値・左右反転か・クリアか・ずれの並び
- ずれの並び: 譜面のノーツの並び順に1ノーツ2文字。ずれ（ms・押した時刻 − ノーツの時刻・判定タイミング調整を通したあと）に600を足して
  0〜1200に挟み、36進2桁。MISS は `zz`、判定されずに終わったノーツは `--`、ずれの無い判定は `__`。HOLD / SLIDE は押し始めのずれ。
  MASTER の800ノーツでも1.6KB
- **名前・ブリーダーID・セーブデータは送らない。** 送れなくても何もしない。表が無い（404）・権限が無いと分かったら、ページを閉じるまで送らない
- 判定・スコア・保存には一切関わらない。プレイヤーへの知らせはヘルプ（難易度ごとの中身と「Lv.」の読み方）と更新履歴

## サーバー（`docs/sql/rankings/RHYTHM_PLAY_LOG_*.sql`）

- 新しい表 `public.rhythm_play_logs` を作るだけ。既存の表・ビュー・関数・RLS・ポリシー・権限には触らない
- 誰でも追加・読み出しはできるが、書き換え・削除はできない。行の形と大きさは check 制約で縛る（ずれの並びの長さ＝ノーツ数×2 など）
- **表はユーザーが1回だけ作る**（`RHYTHM_PLAY_LOG_IPHONE_STEPS.md`）。アプリの公開と SQL の適用はどちらが先でもよい
- 手元の PostgreSQL 16 で、予行演習・本番・2回目の本番・確認が通り、anon の立場で「追加できる・読める・書き換えと削除は拒まれる・形の違う行は拒まれる」を確かめた

## 道具（`tools/mode/rhythm-play-log.js`）

| 使い方 | 中身 |
| --- | --- |
| `--fetch` | サーバーから前回より新しい記録を取り（`curl` でプロキシを通す）、まとめへ足す |
| `--import <file>` | サーバーの行と同じ形の JSON / JSONL から取り込む（ネットワークが使えないとき・検査） |
| `--report [--json]` | 譜面ごとに、回数・端末数・押す時刻のばらつき・ミス・いちばん合わせにくい区間・低音の聞こえ方 |
| `--learn [--write]` | 調整値を計算する。`--write` で動いたときだけ新しいリビジョンとして書き足す |

- まとめは生の記録を持たない。譜面ごとに、ノーツごとの「その回の中央値を引いたずれ」の件数・和・二乗和・MISS 数と、回ごとのばらつきだけ
  （端末の遅れや人のくせは、その回の中央値を引いて消す）
- 同じ端末の記録は1譜面あたり5回まで（1人の記録が多すぎて偏らないように）。左右反転の回は数えない
- 作り直す前の譜面への記録は「作り直す前」として数え分け、学びには使わない

## 学ぶもの（`tools/mode/rhythm-chart-play-tuning.js`・生成器 Rev.17 から読む）

| 調整値 | 意味 | 学び方 |
| --- | --- | --- |
| `lowLagFactor`（0〜1.2） | 低音の打点の遅れ（`rhythm-chart-low-lag.js`）を何倍差し引くか | 低音だけが鳴っている所のノーツで「解析の時刻 − ノーツの時刻 − 押したずれ」＝プレイヤーが聞いている遅れを出し、解析の遅れとの比を件数の重みで平均。今の値との差の半分だけ動かす（0.05刻み）。2曲・150件から |
| `lineBoost`（0〜1.2）/ `lineDemote`（＝半分） | フレーズごとに決めた1本の線（歌・旋律かドラム）の打点を前に、もう一方だけの打点を後ろに | 小節ごとの「つまみ食い」（歌とドラムの線をかわるがわる拾う度合い）と押す時刻のばらつきの傾き。つまみ食いの多い小節ほど 4ms より合わせにくければ 0.15 強め、逆なら 0.15 弱める。200小節から |
| `virtualSigmaScale` / `virtualMissScale`（0.5〜2） | 仮想プレイヤー（`rhythm-virtual-player.js`）の押す時刻のばらつき・ミスの倍率。Rev.18 の区間の差し替えが使う | 記録の押す時刻のばらつき（その回の中央値を引いたずれの二乗平均）とミス率を、同じ譜面で仮想プレイヤーが出した値と比べ、差の半分だけ寄せる（0.05刻み）。3譜面・1譜面5回から |

- 調整値がすべて0なら、Rev.17 は Rev.16 と同じ譜面（`rhythm-play-log-check.js` が見張る）
- 書き足すたびに新しいリビジョン（作り方の最新・作法の重み・調整値の最新のいちばん大きいもの＋1）。前の値は消さないので、
  そのリビジョンで作った曲は、いつ作り直しても同じ譜面になる
- **既存の曲には効かない。** 一覧（`rhythm-song-registry.json`）に書いてあるリビジョンのまま。新しく解析した曲だけが最新になる（CLAUDE.md ⑩-2）
- 作り物の記録での確かめ（検査）: 解析の遅れの0.9倍が本当なら 0→0.4 へ動き（推定0.84）、遅れが本物の音のずれなら動かない（推定0.03）。
  つまみ食いの小節ほど合わせにくいなら強め（傾き13ms）、関係が無ければ動かさない（0.4ms）

## 限界

- 遊ばれた分しか学べない。遊ぶ人が少ない曲・難易度はなかなか動かない
- 押す時刻には腕前・端末・見た目に合わせる癖も混ざる。その回の中央値を引き、曲どうし・区間どうしで比べて打ち消すが、読み違いは残りうる
  （たとえば、音ではなくノーツの見た目に合わせて押す人が多いと、低音の遅れは「解析のくせ」の側に読まれる）
- 学ぶのは「音に合わせて押しやすいか」まで。「気持ちいい」そのものは測れない

## 週1回の定期実行でやること

1. `git fetch origin main` して作業ブランチを最新の main にそろえる
2. `node tools/mode/rhythm-play-log.js --fetch --report --learn --write`
   - サーバーへつながらないとき（ネットワークの設定で `zrzevudkbgtxlbvmuziy.supabase.co` が許可されていない等）は、何も書かずに止まり、その旨を報告する
3. まとめ（`playlog/summary.json`）と、動いたときは調整値（`chart-play-tuning.json`）が変わる。変わったら
   `node tools/mode/rhythm-play-log-check.js` と `node tools/mode/rhythm-chart-v3-check.js` を通す
4. コミット → プッシュ → PR → マージ（CLAUDE.md ②③）。ゲームも公開中の譜面も変わらないので、更新履歴・ヘルプは書かない
5. 何を学んだか（`--learn` が出した理由の行）を報告に残す
