## 入力と出力

```js
const catalog = ASSISTANT_MASMON_BATTLE.buildCatalog({ ALL_PLAYER_MONSTERS, ASSISTANT_MASMON_TECHS }); // 技表の写し(JSON にできる)
ASSISTANT_MASMON_BATTLE.simulate({ seed, catalog, teamA, teamB, balance?, roundLimit?, trace? })
// team = { assistantId:'mua'…'erubin', tactics:0〜100(戦術経験), plan?, swapPace?, members:[1体, …](1〜3体) }
// 1体 = { species, name, lv:1〜99, stats:{ life, pow, wise, hit, eva, tough }(0〜999),
//         techs:['技id', …](覚えている技。無ければ技表の learn.start の技), mastery:{ [技id]:0〜100, guard, dist, swap } }
// balance = 'A'|'B'|'C'(能力の差の効き方。省くと A)
// → { version, balance, winner:'A'|'B'|'draw', reason:'wipe'|'judge', rounds, log:[1手ずつ], final, digest }
```

- 育成(キズナ4・`mh_assistant_masmon_grow_v1`)と修行(シュギョウ・`mh_assistant_masmon_train_v1`)からは
  `unitFromGrow(row, amgEntryOf(…), amgtEntryOf(…))` で1体を作る(row = `assistantMasmonRowsOf` の行。
  修行の入れ物の `m` が熟練、`learn` が覚えた技の id の配列。入れ物が無ければ既定値)
- `VERSION` は計算を変えたら上げる(サーバの試合の行に残る)。**2 = 技を MF のように一新**(2026-11-11)
- 疲労・ストレス・好き嫌い・型(攻撃型など)は**入力に取らない**(強さに効かせない)
- `trace:true` で、各手に AI が付けた点(`cands`)が記録に付く(観戦で「なぜその手か」を見せる用)

## きまり

- **距離** 零・近・中・遠(0〜3)。種で 近・中 のどちらかから始まる(「零が得意」「遠が得意」に片寄らせない)。場の2体で1つの距離を共有し、移動は1歩
- **技** 助手のマスモン専用の技表 `ASSISTANT_MASMON_TECHS`(シュギョウ担当)。社長「距離撃はなしにして、技の性能自体も一新して作ってほしい。モンファーみたいな感じで」。
  **既存のモンヒロバトルの技(通常攻撃・距離撃・固有技・ガード)は使わない**(検査⑧が見張る)

  | 項目 | 形 | 幅(MF2 の技の幅) | 計算での使い方 |
  | --- | --- | --- | --- |
  | `id` | 種の中で一意の文字 | — | 記録の `move`・熟練のキー |
  | `kind` | `pow`(ちから技)/`wise`(かしこさ技) | — | 撃つ能力 |
  | `dist` | 届く距離 [0〜3] | 1〜2段 | その距離でだけ撃てる。どの種もどの距離にも1つは届く(検査⑧) |
  | `power` | 威力 | 1〜70 | ÷20 が倍率(20 でふつうの1発) |
  | `hit` | 命中の段(%の数) | −25〜+22 | 版9から最後に掛ける係数: 5 で1段 = 当たりやすさの比 ×1.35(B=0 で ×1) |
  | `guts` | 消費ガッツ | 5〜60 | 熟練で ×(1−熟練/100×15%) |
  | `crit` | クリティカル(%) | 0〜30 | ×1.5 |
  | `gd` | ガッツダウン | 0〜45 | 当たったら相手のガッツを減らす(AI は相手のガッツが少ないほど点を上げる) |

- **ガード** 技ではなく行動。次の手番まで受けるダメージ −35〜60%(丈夫さで増える)+ ガードの熟練/100×8%
- **熟練**(社長「中」): 技ごとに 命中 + 熟練/100×6%・ガッツ消費 −熟練/100×15%(四捨五入)
- **技ごとの強化 `techBoost`**(2026-11-13 社長・モンサクの熟練から作る。フレンド対戦・ランキングにも効く): `members[].techBoost = { 技id: { pow, hit, guts } }`。
  威力 ×(1+pow)・命中 +hit・消費ガッツ ×(1−guts)(熟練の直しのあと・四捨五入は1回)。芯の `normTechBoost` で切りそろえる:
  pow 0〜0.20・hit 0〜0.10・guts 0〜0.15(上限を超えたら上限)/数でない・負は 0/覚えていない技は無視。無い・空・0 なら今までと同じ試合(同じ指紋)。
  サーバ(masmon-pvp `parseTeam`)は形が違う(オブジェクトでない)ものを `techBoost` で断り、数は同じ `normTechBoost` で切って保存・計算に渡す(公平の区分でもそのまま)
- その距離の得意(`distAptitude`)で威力が変わる: C=1.0、1段ごとに ±5%(0.8〜1.25)
- **命中**(版9・2026-11-14 社長)= 下の「命中とダメージ(版9)」。基準50%・能力差と技の係数で 1〜99%。会心は ×1.5
- **ダメージ** =(20 + 撃つ能力×0.6)× 距離の得意 × ガッツ(撃つ前 0→×0.7・99→×1.3)× 全体 ×1.3 × 300÷(300 + 丈夫さ×0.9 + 同じ種類の能力×0.45)× 体・受ける側の得意・移動速度 × **技の power÷20(最後に掛ける)** × 0.9〜1.1
- **ライフ** = 100 + ライフ×1.5
- **ガッツ** 0〜99(版9)。始め 50・毎ラウンド +9〜11(種ごと。モンヒロバトルの基礎ガッツ `baseGuts` が大きい種ほど速い)・移動とガード +4・ためる +22・交代/倒れて出たとき最低 40
- **順番** 毎ラウンド、場の2体が1手ずつ。先に動くのは「回避 + 命中÷2 + 種の揺れ」が高い方
- **交代** 手番を使う。出てきてから自分の手番2回は交代しない(行ったり来たりを防ぐ)。倒れたら相性の良い1体が出る
- **決着** 全滅で負け。150 ラウンドで決まらなければ判定(残りライフの割合)。同じなら引き分け

## 命中とダメージ(版9・2026-11-14 社長「ステータスで基礎ダメージや基礎命中を決めて、技性能は係数として最後にかかる」「命中率はステや技性能で 1% も 99% もある」)

1. **基礎命中**: 当たりやすさの比(当たる:外れる)= exp(0.11·x + 0.028·x·|x|)(x =(命中−回避)÷100。差が大きいほど効きが急)× ガッツ(0 → ÷1.85・99 → ×1.85)× 小さい体 ×0.9 → 確率へ
2. **間合いの適性**: いまの強さのまま 1段 ±1.5% を基礎命中に足す(技の係数の前=上下の端をつぶさない)
3. **技の係数**: 比に 1.35^(hit÷5) を掛ける(G 0.25・D 0.55・B 1.00・A 1.35・SS 2.46。熟練・techBoost の上乗せも hit と同じ物差し)
4. 最後に1回だけ **1〜99%** で切る(試合の上乗せ buffs も 1〜99%)

`Math.exp`・`Math.pow` は端末とサーバで最後の桁がずれうるので、芯の `expDet`(四則演算だけ)で計算する(検査⑦)。
技表だけの目安(準備の画面・代表の決め方)は `techHitPreview(hit)`(命中=回避・ガッツ半分。B の技で 50%)。

| 見本(ガッツ半分) | G | D | B | A | SS |
| --- | --- | --- | --- | --- | --- |
| 差 −1000 | 1.0 | 1.1 | 2.0 | 2.7 | 4.7 |
| 差 −300 | 12 | 23 | 36 | 43 | 58 |
| 差 0 | 20 | 35 | 50 | 57 | 71 |
| 差 +300 | 31 | 50 | 64 | 71 | 81 |
| 差 +1000 | 92.5 | 96.4 | 98.0 | 98.5 | 99.0 |

参考資料(`docs/reference/line-mf/hit-rate-2026-11-14/`)の間合いに左右されない8つの数との差は平均4.4ポイント。
試算(能力合計2400・型5つの総当たり・各組2000試合): 型の勝率 30〜79% → 33〜62%、平均の命中 70% → 46%、決着までのラウンド 13.1 → 13.6。

## その試合だけの上乗せ(buffs・2026-11-12 キズナ)

モンヒロサクセスの助手の「特別な1話」(頂への道の1回戦だけに効く)のための入口。**端末だけ**で使う。

```js
ASSISTANT_MASMON_BATTLE.simulate({ seed, catalog, teamA, teamB,
  buffs: { A: { guts: 10, hit1: 0.15, crit: 0.10, missCut: 0.5, eva: 0.10, noSulk: true } } });
```

| 項目 | 効き方 | 範囲 |
| --- | --- | --- |
| `guts` | 始まりのガッツに足す(その側の全員) | 0〜50 の整数 |
| `hit1` | その側の**最初の攻撃**の命中に足す | 0〜0.5 |
| `crit` | 会心の率に足す | 0〜0.5 |
| `missCut` | 外れる率をこの割合だけ減らす(0.5 = 技の失敗 −50%) | 0〜1 |
| `eva` | 相手の命中から引く(回避 +) | 0〜0.5 |
| `noSulk` | `true` で忠誠度の「動かない番」を出さない | true のみ |

- 命中は もとの率 → `hit1`・`eva` を足し引き → 0.05〜0.99 に切る → `missCut` → もう一度切る。AI の見積もりには入れない(実際の判定だけ)
- **渡さない・null・空・壊れた値だけ なら今までと1つも変わらない**(乱数の列・記録・指紋も同じ)。効く項目があるときだけ記録の1行目(`start`)に `buffs: { A, B }` が付く
- 試合中のけが(0%)は芯の外(サクセスの側で扱う)
- **サーバ(masmon-pvp)は buffs を受け付けない**: `core.js` は `simulate({ seed, catalog, teamA, teamB, balance })` と項目を名指しで渡す。検査 `tools/masmon-battle/masmon-buffs-check.js` ⑤ が見張る
- 相手の最初の行動: `ASSISTANT_MASMON_BATTLE.firstAction(r.log, 'B')` → その側の1手目の行(`tech`・`move`・`guard`・`charge`・`swap`。`tech` なら `name`・`hit`・`dmg` など)。無ければ null

## 自分で操作する試合(createMatch・2026-11-12 ジン)

社長「モンサクは自分操作にして」(台帳 #5751)。モンヒロサクセスのバトル用。**オート(`simulate`)の結果は1つも変えない**
(止まれる形にする前の計算の指紋の控え `tools/masmon-battle/auto-golden.json` 2000戦と、検査 `masmon-manual-check.js` ①が突き合わせる。VERSION は上げていない)。

```js
const m = ASSISTANT_MASMON_BATTLE.createMatch({ seed, catalog, teamA, teamB, buffs?, control: { A: 'human' } });
m.pending()   // いまの手番の選べる手。null なら決着(m.result() が simulate と同じ形)
m.choose({ type: 'tech', key })  // { ok:true } で次の自分の手番まで進む(相手の手番は AI)。選べない手は { ok:false, reason:'invalid' }
m.auto('A')   // ここからオート(手の列に { type:'auto', side } が残る)
m.log / m.view() / m.choices() / m.done() / m.result()
ASSISTANT_MASMON_BATTLE.replay(同じ入力, 手の列) // → { ok, at?, match }。見返し・中断の続き・サーバの確かめに使う
```

- 中身は1本の試合の流れ(`battleFlow`・ジェネレータ)。`control` の側だけ手番で止まる。`simulate` は両側 AI で最後まで回すだけで、`control` は受け付けない(サーバの masmon-pvp も変わらない)
- 手の形: `{type:'tech',key}` / `{type:'move',step:-1(前へ=近づく)|1(後ろへ)}` / `{type:'guard'}` / `{type:'charge'}` / `{type:'swap',to}` / 倒れたあと `{type:'enter',to}`
- `pending()` の中身(帯の4つの見出し用): `tech`(全部の技に `reach` 届くか・`ok` 選べるか・`need` 足りないガッツ・`p` 命中%・`guts`)・`guard`・`move`(`to` 行き先の距離・端では ok:false)・`charge`(満タンで ok:false)・`swap`(`swapWait` の間は ok:false)・`hint`(AI ならこの手。試合の乱数は引かない)・`guts`・`dist`・`hp`
- 忠誠度の「動かない番」は手を聞く前に決まる(その番は聞かない)。自分で選んだ手番では AI のゆらぎの乱数を引かないので、同じ種でもオートとは違う試合になる
- 記録: 1行目に `ctl:{A:'human'}`、自分の手の行は `why:'player'`(`WHY.player` = あなたの指示)。オートにしたあとの手は AI の理由
- 保存は「種+手の列」だけでよい(`replay` で同じ所まで進む)

## 記録(log)の形(観戦の画面が読む)

| ev | 中身 |
| --- | --- |
| `start` | `v`(計算の版)・`balance`・`a`/`b`(名前の並び)・`aHp`/`bHp`(最大ライフ)・`aMoves`/`bMoves`(1体ごとの技 [{id,name,kind,guts,dist}]・熟練の後のガッツ) |
| `enter` | `side`・`i`(何体目)・`name`・`guts`(倒れたあとに出たとき) |
| `tech` | `side`・`i`・`ti`(受けた側の何体目)・`p`(撃つ前の命中率 %)・`move`(技 id)・`name`・`kind`・`hit`・`crit`・`dmg`・`guarded`・`guts`(撃ったあと)・`foeHp`・`gd`・`foeGuts` |
| `move` | `side`・`i`・`step`(−1 近づく/+1 離れる)・`to`(新しい距離)・`guts` |
| `guard`・`charge` | `side`・`i`・`guts` |
| `swap` | `side`・`from`・`i`・`name`・`guts` |
| `ko` | `side`・`i`・`name` |
| `judge`・`end` | 判定の点・`winner`・`reason` |

どの行にも `r`(ラウンド)と `d`(その時の距離)。手の行(tech・move・guard・charge・swap)には `ga`/`gb`(手のあとの両方の場のガッツ)と `why`(手の理由。`ASSISTANT_MASMON_BATTLE.WHY` に日本語の言い方: 倒しきれる・ガッツを削る・大技・攻める・技が届く所へ・有利な間合いへ・危ない間合いから離れる・ライフが少ないので守る・相手の大きい一撃にそなえる・ガッツが足りない・大技のためにためる・倒されそうなので下げる・相性のよい仲間へ)。`trace:true` なら手の行に `cands`(AI が付けた点)。

## 端末とサーバで同じにする

- 乱数は種(文字列)から作る(`makeRng`)。計算は + − × ÷ と floor/round/min/max/sqrt だけ
- 技表に `version` を持たせ、catalog の `techVersion` に写す(技表を変えたら上げる)
- サーバ(第④段階)では、`buildCatalog` の結果を JSON にして本体と一緒に関数へ持っていく(検査①で JSON を通しても同じ結果を見ている)。
  MFバトルカードの `card-tournament-run` が `game.js` を写して持つのと同じ形
- `digest` は記録の指紋(`cands` は除く=`trace:true` でも同じ値)。端末の見返し(リプレイ)とサーバの結果の突き合わせに使う

## MF との対応(2026-11-11 社長「モンスターファームの計算方法を調べて参考にして」)
