# モンヒロビートの見た目の目標(参考動画の観察メモ)

2026-09-26、ユーザーが「モンビーをこのレベルまで仕上げたい」と、他社の音ゲー(バンドリ！アワーノーツ)の
プレイ動画を2本とスクリーンショットを送ってきた。この文書はそこから読み取ったことの控え。
**まねるのは完成度と手ごたえで、デザインをそのまま写すことではない**(色・形はモンスターヒーローらしく作る)。

- 動画1: iPad を机に置いて横向きで遊ぶ手元の録画(YouTubeの画面録画。640×360で細部は粗い)
- 動画2: スマホ横向きの画面録画(メニュー → 曲えらび → 読み込み → 開始演出 → 演奏)
- スクリーンショット3枚: モンヒロビート(横向き)とアワーノーツ2枚の並べ比べ

## 1. 読み取れたこと

### 道(レーン)

| 項目 | 参考動画 |
| --- | --- |
| 形 | 両端がまっすぐな三角形。画面の上の一点(画面のすぐ外)へ向かって細くなる |
| 判定ライン | ピンクの細い線が2本平行に走り、その間が判定の帯。画面の下から2割ほどの高さ。ラインの下にも道が続いて画面の下端から外へ抜ける |
| 道の色 | ほぼ黒の半透明。後ろの背景がうっすら透ける。境目の線は細く控えめ |
| レーン数 | 真ん中に境目の線がある(偶数)。6レーンに見える |
| 開始演出 | 始まる直前、レーンの線が光のレーザーのように奥へ走って道が組み上がる |

### ノーツ

| 種類 | 見た目 |
| --- | --- |
| TAP | 白〜水色の薄い板。奥では細く、手前で太く(遠近どおり) |
| HOLD | 明るい青白の太い帯。押している間はそのレーンが光り続ける |
| SLIDE | 太い帯が**S字にうねって**レーンをまたぐ。幅も途中で変わる |
| FLICK | 向きの付いた矢印。左右は `<<<`(緑)・`>>>>`(ピンク)の連なった山形、上は黄色の山形。**払う向きが一目でわかる** |
| 同時・連続 | 板が階段のように何段も積み重なって落ちてくる形がある |

### 叩いたときの演出

- 叩いたレーンから奥へ向かって**光の柱**が立つ(青〜水色、長押し中は緑)
- 判定ラインで**白い十字の光(レンズフレア)**と細かい粒がはじける
- 判定の文字は道の中央、判定ラインの少し上。PERFECT は虹〜緑、GREAT はピンク、GOOD は緑、BAD は白
- コンボ数は道の右外(空いた三角のすき間)に大きく。「COMBO」の上に数字
- 盛り上がる場面で、キャラクターの絵が画面の端から斜めに差し込まれる(カットイン)

### 画面のまわり

- 背景は演奏中ずっと動く舞台(3Dのライブ映像)。道の左右の三角のすき間に見える
- 左上に小さくスコアとランクの目盛り(進むほど埋まる)、右上に細いライフのゲージと一時停止
- 曲えらびは、左に曲の一覧(ジャケット・レベル)、右に大きなジャケットと難易度ごとのレベル。
  演奏前に「アシストモード」の説明が出る

   **過去の記録(自己ベストと全国ランキング)はそのまま残す**(2026-09-26 ユーザー判断「過去の記録はそのままでおっけー」)

**改修のたびに重さを測る**(ユーザー指示)。CPUを1/4に絞った実ブラウザで、叩かないとき
(`tools/mode/rhythm-live-frame-report.js --cpu 4 --runs 3`)と叩き続けたときの両方を、main と比べる。

## 4. 気をつけること

- 発熱: 塗る画素の多さが原因(RHYTHM_ROADMAP 1-O)。ぼかし・影・filter を毎フレーム変えない。
  光は canvas に焼いた画像を重ねる形で足す
- 縦向きのスマホ: 参考動画は横向き前提。縦で6レーンにすると1レーンが今の8割ほどの幅になる
- 見た目の方向を大きく変えるときは、撮影のときだけ差し替えた見本画像を先に見せて決める
  (今回のノーツ・道・奥行きはこのやり方で決めた)
