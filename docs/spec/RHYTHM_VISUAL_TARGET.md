2026-09-26、ユーザーが「モンビーをこのレベルまで仕上げたい」と、他社の音ゲー(バンドリ！アワーノーツ)の
プレイ動画を2本とスクリーンショットを送ってきた。この文書はそこから読み取ったことの控え。
**まねるのは完成度と手ごたえで、デザインをそのまま写すことではない**(色・形はモンスターヒーローらしく作る)。

- 動画1: iPad を机に置いて横向きで遊ぶ手元の録画(YouTubeの画面録画。640×360で細部は粗い)
- 動画2: スマホ横向きの画面録画(メニュー → 曲えらび → 読み込み → 開始演出 → 演奏)
- スクリーンショット3枚: モンヒロビート(横向き)とアワーノーツ2枚の並べ比べ

## 1. 読み取れたこと

### 道(レーン)

| 項目 | 参考動画 |
| --- | --- |
| 形 | 両端がまっすぐな三角形。画面の上の一点(画面のすぐ外)へ向かって細くなる |
| 判定ライン | ピンクの細い線が2本平行に走り、その間が判定の帯。画面の下から2割ほどの高さ。ラインの下にも道が続いて画面の下端から外へ抜ける |
| 道の色 | ほぼ黒の半透明。後ろの背景がうっすら透ける。境目の線は細く控えめ |
| レーン数 | 真ん中に境目の線がある(偶数)。6レーンに見える |
| 開始演出 | 始まる直前、レーンの線が光のレーザーのように奥へ走って道が組み上がる |

### ノーツ

| 種類 | 見た目 |
| --- | --- |
| TAP | 白〜水色の薄い板。奥では細く、手前で太く(遠近どおり) |
| HOLD | 明るい青白の太い帯。押している間はそのレーンが光り続ける |
| SLIDE | 太い帯が**S字にうねって**レーンをまたぐ。幅も途中で変わる |
| FLICK | 向きの付いた矢印。左右は `<<<`(緑)・`>>>>`(ピンク)の連なった山形、上は黄色の山形。**払う向きが一目でわかる** |
| 同時・連続 | 板が階段のように何段も積み重なって落ちてくる形がある |

### 叩いたときの演出

- 叩いたレーンから奥へ向かって**光の柱**が立つ(青〜水色、長押し中は緑)
- 判定ラインで**白い十字の光(レンズフレア)**と細かい粒がはじける
- 判定の文字は道の中央、判定ラインの少し上。PERFECT は虹〜緑、GREAT はピンク、GOOD は緑、BAD は白
- コンボ数は道の右外(空いた三角のすき間)に大きく。「COMBO」の上に数字
- 盛り上がる場面で、キャラクターの絵が画面の端から斜めに差し込まれる(カットイン)

### 画面のまわり

- 背景は演奏中ずっと動く舞台(3Dのライブ映像)。道の左右の三角のすき間に見える
- 左上に小さくスコアとランクの目盛り(進むほど埋まる)、右上に細いライフのゲージと一時停止
- 曲えらびは、左に曲の一覧(ジャケット・レベル)、右に大きなジャケットと難易度ごとのレベル。
  演奏前に「アシストモード」の説明が出る

   **過去の記録(自己ベストと全国ランキング)はそのまま残す**(2026-09-26 ユーザー判断「過去の記録はそのままでおっけー」)

(`tools/mode/rhythm-live-frame-report.js --cpu 4 --runs 3`)と叩き続けたときの両方を、main と比べる。

(`--suite` でシンプル・派手・ライブ・全部ONの4つ)。この環境に GPU は無いので、実機の速さではなく「GPU にやらせている仕事の量」の比較。

## 4. 気をつけること

- 発熱: 塗る画素の多さが原因(RHYTHM_ROADMAP 1-O)。ぼかし・影・filter を毎フレーム変えない。
  光は canvas に焼いた画像を重ねる形で足す
- 縦向きのスマホ: 参考動画は横向き前提。縦で6レーンにすると1レーンが今の8割ほどの幅になる
- 見た目の方向を大きく変えるときは、撮影のときだけ差し替えた見本画像を先に見せて決める
  (今回のノーツ・道・奥行きはこのやり方で決めた)

## 5. 6レーン化(2026-09-26)

道を5レーン(サブレーン10本)から6レーン(12本)にした。**段階1(本体と生成器)・段階2(全曲の作り直し)とも済み。**

### 段階1: 本体と生成器(済み)

| 場所 | やったこと |
| --- | --- |
| `data/rhythm-mode.js` | `RHYTHM_LANE_COUNT=6`。幅・入力・遠近・SLIDEの寄せはすべてこの定数から作っていたので、そのまま6レーンになる |
| 〃 `rhythmChartOnRoad` | `laneCount` を持たない譜面(5レーン時代)を、サブレーン1本ぶん右へずらして道の真ん中へ置く。形・幅・時刻・ノーツ数は変えない。練習・タイミング合わせ・確認用の手書きの譜面も、作り直さずにそのまま遊べる |
| 〃 `mhChart` | 4つ目にレーン数。6レーンで作った譜面は `mhChart(レベル,ノーツ,長さ,6)` |
| `parts/30-rhythm-play.jsx` | レーン・境目・押したときの光の数を定数から作る(以前は 5 / 10 を直書き) |
| `parts/13-…settings.jsx` | ミラー譜面の左右反転を定数から作る(以前は `4-lane` / `10-sub`) |
| 自動譜面制作 | **版5=6レーン**(`rhythm-chart-v3-revision.js`)。版4までは5レーンのまま作る |
| 〃 生成器・自動修正・品質の報告 | 5 / 4 / 10 の直書きを `LANES` / `LANES-1` / `SUB_LANES` へ。譜面のJSONに `laneCount` を書き、後ろの道具はそれを読む |
| 〃 パイプライン | 本体へ書き出すとき、その譜面を束ねる `mhChart` の4つ目も書く |
| `rhythm-overlap-reach-fix.js` | 真ん中へ寄せた5レーン時代の譜面は書き戻さない(二重にずれるため) |

確かめたこと:

- **版2・版4の生成結果は、変更前のワークツリーと全23曲×5難易度=115譜面でノーツまで完全に一致**(⑩-2)
- 版5で全曲を作ると、ノーツ数は版4とほぼ同じ(EASY 5611→5611 / NORMAL 6494→6487 / HARD 8865→8864 / EXPERT 10777→10764 / MASTER 12270→12244)
- ノーツの中心の平均は 2.98(道の真ん中は3)。左右に偏っていない。
  最初は 2.67 と左へ寄っていた(レーンの使用回数の配列が長さ5のままで、6本目の点数が NaN になっていた)のを直した結果
- 版5の全曲: SLIDE 779本のうち曲線 618本、FLICK 1803本のうち横フリック 340本(MASTERだけ)

- 検査(音ゲーまわり199本): 6レーンで落ちた10本を直した(基礎・サブレーン配置・同時押し・タップの接触幅・SLIDEのサブレーン・
  幅の種類・操作・自動修正・形の点検・レーンの部品)。**変更前(main)でも落ちている31本以外に、増えたNGは無い**
- 重さ(CPU 1/4・叩き続けたとき、3回の中央): 変更後 413 / 426 フレーム、変更前 419 / 421 フレーム。差は計測のぶれの内。
  叩かないときは 1フレームのJS 1.75ms(押したときの光の部品が10枚→12枚になっただけ)
- 確認用・練習用の手書きの譜面は5レーンのまま(本体が真ん中へ寄せる)。デバッグ用の手書き譜面エディタも5レーンの道具のまま
