## 決まったこと(ユーザーの回答)

| 項目 | 決定 |
| --- | --- |
| ボス | カボチャの大王=**ジャック**という名前のモンスター。絵はユーザーが用意する(それまでは仮の絵) |
| 遊びは2本立て | **A. みんなで討伐**(ベースモンで協力) / **B. ダメージ競争**(マスモンで個人戦) |

| 共有HP | サーバー(Supabase)に**新しいテーブルを作る**。既存テーブルには触らない |
| ストーリー | **第5部(終了)で完結**。第2〜4部でジャックが暴れる |

## 追加で決まったこと(2026-10-04・2回目の回答)

| 項目 | 決定 |
| --- | --- |
| 共有HP | **難易度制・5段階**。難易度ごとに別の共有HPを持ち、**前の難易度を全員で倒すと次が解放される** |
| AとBの関係 | **共有HPを削るのはA(ベースモン)だけ**。B(マスモン)は共有HPに触れず、累計ダメージのランキングで競う |
| 専用の1戦 | **ターン制で数ターン勝負**。決まったターン数のあいだに出せるダメージを送る |
| 無料回数 | **1日3回**(5:00に回復)。追加はビートP等で購入 |
| A の報酬 | **難易度ごとに貢献ランキング**を作り、**順位別報酬**と**討伐報酬**(倒せたとき全員)を出す |
| B の公開 | 累計ダメージの**上位100位を常時表示** |
| 第5部の台本 | **倒した段階数で台本が変わる** |
| 追加挑戦 | **ビートPで購入、1日の上限なし、1回100P** |
| 1戦のターン数 | **10ターン** |
| ジャックの行動・ダメージ計算 | **タクティクスバトルと同じ仕様**(`TACTICS_EX_SKILLS.md` 等を正本として使い回す。新しく作らない) |
| 報酬の中身 | **あとで考える**(討伐報酬・順位別報酬とも) |
| 共有HPの基準 | 既存バトルの難易度の `power`(敵HP・攻撃倍率)を基準にして5段階を決める。比率を新しく作らない |
| 不正対策 | **与ダメージの上限は置かない(信頼する)**。公開後に問題が出たら再検討 |
| 公開日時 | **準備ができてから決める** |

## 全体像

```
A 難易度1〜5(ベースモン) ─ 与ダメージ ─ 難易度ごとの共有HPが減る ─ 0で次の難易度が解放+全員に討伐報酬
                                      └ 難易度ごとの貢献ランキング(順位別報酬)
B マスモン                ─ 与ダメージ ─ 期間中の累計ダメージ ─ 上位100位ランキング(順位別報酬)
```

- Aは育成に関係なく全員が同じ土俵。Bは育成の強さがそのまま効く。
- 共有HPとBの累計ダメージは、サーバー側の**別々の新テーブル**に置く。

## 守ること(実装時)

- 保存データは**新しいキー**を足す。既存の `mh_*` は触らない(ルール⑦)。
- ランキング対象外の遊びの扱いと同様に、**このボス戦のダメージで既存の自己ベストを上書きしない**。
- 共有HPのテーブルは新規。SQLは `docs/sql/` へ置き、ユーザーが流す。既存テーブルは変えない。
- 時刻で出し入れするものは、見るたびに数え直す(ルール⑥-4)。
- 更新履歴・ヘルプ・助手の告知・使い方案内をセットで用意する(ルール⑤)。告知の `type` は `content`。
