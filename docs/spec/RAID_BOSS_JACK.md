### レイドバトルのモンヒロビート挑戦(2026-10-06・ユーザー指示)

バトルのほかに、**モンヒロビートを1曲遊び、そのスコアをダメージに換える**挑み方をレイドバトル(A)へ足した。グランドスラム(B)には足さない。

| 項目 | 決めたこと |
| --- | --- |
| 入口 | レイド画面の「モンヒロビートで挑戦する」(Aで、挑める状態のときだけ「バトルで挑戦する」と並ぶ) → ふつうの曲えらび(帯つき)→ 決定 |
| 回数 | **バトルと同じもの**(`state.a` の used / extra・`raidJackRemaining`)。決定して演奏を始めた時点で1回使い、途中でやめても戻らない |
| 換算 | `35-raid-jack.jsx` の `raidJackRhythmDamage` の**1か所だけ**。**いまは式②(判定)**。(2026-10-06・ユーザー「難易度とスコアとコンボ数でダメージ。どんなに高くても30万」→「コンボは数を掛ける」→**提案②「難易度と判定でみるダメージ計算。難易度ごとに、マーベラスなどの判定1個あたりのダメージ換算を決める」**) |
| 送る先 | バトルと同じ表(`raid_jack_hits` へ kind:'a'・選んだ段階)。共有ライフから引かれ、貢献ランキングに足される。倒しきったか(討伐)も同じ判定(大王を倒したあとは倒した扱いにしない) |
| 途中でやめる | ダメージ0・送らない。回数は戻らない。結果は「途中でやめた」 |
| つなげないもの | モンヒロビートの自己ベスト・全国ランキング・周回(クイック)の報酬・みんなで対戦。ビートPは演奏そのものの仕組みなのでそのまま入る |
| 遊び直し | 演奏のリザルトの「もう一度プレイ」と、ポーズの「リスタート」は出さない(同じ1回で何度も遊び直せないように) |
| 実装の場所 | `60-app.jsx` の `startRaidJackRhythmSelect` / `startRaidJackRhythmPlay` / `finishRaidJackRhythm` / `exitRaidJackRhythmPlay`、`rhythmPlay.from==='raid'` |
| 演出と結果の順 | 演奏が終わった直後に**ダメージを与える演出**(`RaidJackDamageFx`・約4.3秒・タップで飛ばせる)→ 演奏のリザルト → 「レイドの結果を見る」でレイドの結果、の順(2026-10-06・ユーザー指示)。演出に出すジャックのライフは演奏の開始時に裏で取っておく。デバッグの「ジャック確認」に、曲を遊ばずに演出を見るボタン(ヒット・撃破・ダメージなし)がある |

**式②(判定・いまの式)**(2026-10-06・ユーザー「ジャストマーベラスを最大基準にして。バッド以下はマイナス補正。最大コンボ数の補正も掛けて(少なめ)」): ダメージ = max(0, Σ(判定の数 × 難易度ごとの判定1個あたりのダメージ))× 最大コンボの補正。**30万で頭打ち**。スコアは見ない。

| 難易度 | ジャスト | マーベラス | エクセレント | グレート | グッド | バッド | ミス |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| EASY | 200 | 190 | 170 | 130 | 70 | -30 | -60 |
| NORMAL | 240 | 228 | 204 | 156 | 84 | -36 | -72 |
| HARD | 280 | 266 | 238 | 182 | 98 | -42 | -84 |
| EXPERT | 320 | 304 | 272 | 208 | 112 | -48 | -96 |
| MASTER | 340 | 323 | 289 | 221 | 119 | -51 | -102 |

- ジャスト=MARVELOUS のうちズレが±20ms以内のもの(`result.precise`・`rhythmJudgmentIsPrecise`)。**最大基準(1.0)**。判定の割合は 1.0 / 0.95 / 0.85 / 0.65 / 0.35 / **-0.15 / -0.30**(バッド以下はマイナス補正)。
- 最大コンボの補正(少なめ)= 0.9 + 0.1 ×(最大コンボ ÷ ノーツの数)。フルコンボで1.0、まったくつながらなくても0.9。掛けるだけで増えはしない。
- 公開中の曲で最大のノーツ数(EASY 394 / NORMAL 470 / HARD 628 / EXPERT 761 / MASTER 882)を全部ジャストでフルコンボしても MASTER でほぼ30万。曲が増えて最大のノーツ数が変わったら表を見直す。
- **式①(コンボ)**: ダメージ = 1コンボあたり(難易度ごと・基準と同じ)× 最大コンボ数 × スコアの割合。残してあり、`RAID_JACK_RHYTHM_FORMULA` を `'combo'` にすると戻る。
- アシストモードは0。

**これから決めること**: 換算の数字の調整(上限・0.7/0.3の割合・クリアか失敗かでの差など)。決めたら `RAID_JACK_RHYTHM_*` の表(判定の割合・難易度ごとの基準・上限)と `tools/mode/raid-jack-check.js` の期待値を直す(更新履歴・ヘルプは数字を出していない)。

### 受け取りの仕組み(実装済み)

- 受け取れる報酬は `raidJackCollectDueRewards` が、サーバーの合計・自分の貢献・上位5人を読んで決める。レイド画面を開いたとき・HOMEへ戻ったとき(5分あける。戦闘のあとはすぐ)に確かめ、`claimRaidJackRewards` がギフトで届ける。期間が終わると入口は消えるが、HOMEで確かめるので終了後の順位報酬も届く。
- ギフトのIDは `raid_jack_2026_<印>`。受け取り済みの印は `mh_raid_jack_v1` の `claimed`(`clear_a1`・`rank_a1`・`clear_b1`・`final_b`・`part_a` など)。「上位5人に入っていなかった」印は `rank_a1_none` のように残し、問い合わせ直さない。ギフトと印は取引保存(`saveStoredValuesOrRollback`)。
- 参加賞は、サーバーに自分の与ダメージが1回でも記録されていれば。Bの討伐は端末の「倒した」記録で判定する。
- **倒したA段階(男爵〜公爵)には挑めない**(順位が倒れた時点で固まるため)。大王だけは倒したあとも続く。倒す直前に始まった戦いの与ダメージが少し遅れて届くと、5位の入れ替わりが起きうる(許容)。
- デバッグの強制表示中(別のイベントID)は報酬を一切配らない。
- 検査: `tools/mode/raid-jack-reward-check.js`(表の数字・受け取り判定・結晶)、`raid-jack-reward-browser-check.js`(報酬一覧)、`tools/masu/soul-crystal-browser-check.js`(結晶を使う画面)。

### 魂格の結晶(新アイテム)

- 報酬で配る。**使うと選んだマスモン1体の魂格Pが+1**(個数を指定して使える)。
- **使える個体はマスモンならどれでも**(Lv500前でも可)。ボーナス分は、魂格進化をしたあとに特性へ振れる。
- **1個体あたりの上限は設けない**(ユーザー判断)。保存値が壊れたときの安全弁として、有限の数かだけ確かめる(ゲーム上の上限ではない)。

## 1戦の細かい決めごと(2026-10-04・実装前に確認)

- **オーバーキルは数える**: ジャックのライフを超えた分も、実際に出したダメージをそのままスコアにする(1回の送信は1億まで)。
- **Aの成長(3/5/8/11ターン目)**: 編成の全員の固有技が**2段階ずつ**(4回で最大の8段階)、選んだアシカ全部が1段階ずつ(最大2段階)上がる(2026-10-05に固有技を1段階→2段階・8ターン目まで→11ターン目までへ変更)。
- **リタイア(降参)**: そこまでの与ダメージを**送る**。回数は使ったまま。
- **中断(アプリを閉じた)**: その1戦は無かったことにして、**回数は戻さない**。送らない。

## 攻撃モーション(2026-10-04・決定)

絵は2枚(1枚目=通常、2枚目=両腕ポーズ)だけ。**動きは「跳ねる・振る・回る・拡大」の組み合わせで作る**(絵は追加しない)。

| 技 | 動き | 当たりの形 |
| --- | --- | --- |
| カボチャ張り手 | 2枚目の腕ポーズから片腕を振り下ろす | オレンジの手形 |
| めいどのトリート | 大きく跳ねて着地、画面が揺れる | カボチャとお菓子が降る |
| おばけキッス | 1枚目の顔が前へ寄る | 紫のハートとおばけ |
| ジャックラッシュ | 左右の拳を交互に連打 | 小さなカボチャ型の連続光 |
| かぼちゃ延髄斬り | 回転して上から斬り落とす | 縦に走る三日月の光 |
| ハロウィンナイト | 両腕を上げる(2枚目)+画面が夜色 | 紫と橙の光の柱 |
| おばけパレード | おばけの行列が画面を横切る | 画面全体を横断する光 |

- **待機中の動きは任せる**(「違和感なく、できるだけいい感じの演出に」)。HOMEのぴょこぴょことの
  つながりを見て決める。
- **バトル中の大きさと置き方はムーと同じラスボスの置き方**(丸枠の外へ大きく出す。吹き出しもラスボスと同じ扱い)。
- 動きは既存の敵の技の動き・当たりの形の仕組みに乗せる。実装後、実際に見て調整する。

## 絵と出し方(2026-10-04・ユーザー提供)

| 絵 | 使い道 |
| --- | --- |
| 1枚目(カボチャの顔の正面) | **バトルグラフィック**。通常の立ち絵 |
| 2枚目(両腕を上げたポーズ) | **バトルグラフィック**。大技・登場・やられ等の別ポーズ |
| 3枚目(デフォルメの顔) | **イベント中の顔アイコン**(ランキングや報酬の表示など) |

- レイドが登場したら、**HOMEの真ん中にバトルグラフィックのジャックが「ぴょこぴょこ」している**。
- **HOMEのジャック**: タップで**レイド画面を開く**。動きは「ぴょこぴょこ跳ねる」を基本に、**ときどき2枚目の両腕ポーズ**を挟む(HPとは連動しない)。
  近くに**共有HPバー**(いま挑める=解放中の難易度の残りHP)を出す。
- 絵は入れる前に軽くする(ルール⑥-2)。実装時に `images/` へ入れ、`node tools/image-asset-check.js` を通す。

## 全体像

```
A 難易度1〜5(ベースモン) ─ 与ダメージ ─ 難易度ごとの共有HPが減る ─ 0で次の難易度が解放+全員に討伐報酬
                                      └ 難易度ごとの貢献ランキング(順位別報酬)
B マスモン                ─ 与ダメージ ─ 期間中の累計ダメージ ─ 上位100位ランキング(順位別報酬)
```

- Aは育成に関係なく全員が同じ土俵。Bは育成の強さがそのまま効く。
- 共有HPとBの累計ダメージは、サーバー側の**別々の新テーブル**に置く。
