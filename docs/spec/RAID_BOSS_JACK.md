## 決まったこと(ユーザーの回答)

| 項目 | 決定 |
| --- | --- |
| ボス | カボチャの大王=**ジャック**という名前のモンスター。絵はユーザーが用意する(それまでは仮の絵) |
| 遊びは2本立て | **A. みんなで討伐**(ベースモンで協力) / **B. ダメージ競争**(マスモンで個人戦) |

| ストーリー | **第5部(終了)で完結**。第2〜4部でジャックが暴れる |

## 全体像

```
ベースモンで挑む(A) ─┐
                     ├─ 与ダメージを送信 ─ 共有HP(全員で1本)が減る ─ 0で全員にクリア報酬
マスモンで挑む(B)  ─┘                     └ 個人の累計ダメージ ─ ランキング
```

- **A**: ベースモンだけで編成して挑む。与ダメージは共有HPを削る。育成に関係なく全員が同じ土俵。
- **B**: 育てたマスモンで挑む。同じ1戦だが、累計ダメージを個人ランキングに積む。
- 共有HPを削る量は、**AとBのどちらの与ダメージも数える**かを決める(未決定・下の「未決定」参照)。

## 未決定(次に詰める)

1. 共有HPの量と、形態の進み方(第2部=第1形態…の段階制にするか、1本か)
2. Bの与ダメージも共有HPを削るか(削るなら、マスモンが強すぎて一瞬で倒れない上限が要る)
3. 1戦の中身: 編成の人数、ターン数、ジャックの行動、ダメージ計算(既存の攻撃計算を使い回す範囲)
4. 無料回数(1日何回)と、追加購入の値段・上限(ビートPのほか何を使うか)
5. 報酬: Aのクリア報酬・マイルストーン報酬・参加賞、Bの順位報酬(順位ごとの個数は共通の決めごとを流用)
6. 不正対策: 1回の与ダメージ上限、送信の検証(サーバー側で上限を切る)
7. 倒せなかった場合の第5部の台本の分岐
8. 公開日時(第2部の頭 10/11 8:00 から? すぐ?)と、終了(11/1 4:00)

## 守ること(実装時)

- 保存データは**新しいキー**を足す。既存の `mh_*` は触らない(ルール⑦)。
- ランキング対象外の遊びの扱いと同様に、**このボス戦のダメージで既存の自己ベストを上書きしない**。
- 共有HPのテーブルは新規。SQLは `docs/sql/` へ置き、ユーザーが流す。既存テーブルは変えない。
- 時刻で出し入れするものは、見るたびに数え直す(ルール⑥-4)。
- 更新履歴・ヘルプ・助手の告知・使い方案内をセットで用意する(ルール⑤)。告知の `type` は `content`。
