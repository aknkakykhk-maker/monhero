# 音ゲーモード設計書

現行確認基準: `main` `c2f0a25a506c38fb23693b8abc47514e76c1c0d2`（可変幅TAP STEP1A 後）

この文書は、Monster Hero の音ゲーモードについて、最初に決めた基礎設計と、その後に正式に追加・変更された現行仕様を分けて残すための設計書。

## この文書の読み方

- **「初期設計」** は当時の決定を残す履歴。現在仕様とは限らない。
- **「現行仕様」** は上記の確認基準SHA時点で最新 `main` と照合済み。
- `main` が進んだ場合は、現行仕様の記述も再確認する。
- 音ゲーの仕様を変更するPRでは、本書の更新要否も確認し、仕様が変わる場合は原則として同じ変更単位で更新する。

現行挙動と数値は、必ず最新 `main` の以下を正本とする。

- `monster-hero/data/rhythm-mode.js`
- `monster-hero/src/game-system.jsx`
- `monster-hero/index.html`
- `tools/mode/rhythm-mode-*-check.js`

この文書とコードが食い違う場合は最新 `main` のコードを優先し、その差異を本書へ反映する。

## 1. 初期設計の出典（履歴）

音ゲーの基礎設計は PR #862 `feat: add rhythm mode foundation (音ゲー基盤 STEP 1)` に残っている。

当時、独立した `docs/spec/` の設計書は作成されていなかったため、この文書で正式に集約した。

初期設計で確定していた骨格は以下。

- 通常公開はせず、デバッグ画面からのみアクセスする
- 5レーン
- ノーツは `TAP / HOLD / FLICK / SLIDE` の4種類
- 難易度は `EASY / NORMAL / HARD / EXPERT / MASTER` の5段階
- 各難易度に最大スコアを持たせる
- 判定は6段階
- スコアは「判定90% + コンボ10%」を基本構成とする
- 曲データは既存BGM登録を正本とし、音ゲー側は `trackId` で参照する
- 設定保存とBEST保存を独立キーで持つ
- 欠損・不正な保存値は読み込み時に正規化する
- 通常HOMEには入口を追加しない
- デバッグ画面で曲、難易度、最大スコア、設定、BESTを確認できるようにする

## 2. 基本構成（現行仕様）

### レーン

- 操作表示は5メインレーン、可変幅TAPの配置単位は10サブレーン
- `TAP` は `subLane`（始点0〜9）と `subLaneWidth`（幅1〜4）を持てる
- `subLane` を持たない従来ノーツは、メインレーン1本＝サブレーン幅2相当として後方互換を維持する
- 可変幅TAPは描画範囲 `subLane` 〜 `subLane + subLaneWidth` と同じprojectionを逆変換して入力判定する
- 幅1の入力だけ、表示を太くせずサブレーン幅0.18ぶんを左右へ許容する。隣接時は中心に近い1ノーツだけをclaimedする
- 1回の入力は1ノーツのみ取得し、別の指はそれぞれ独立して同時取得できる
- HOLD / SLIDEの可変幅には未対応（従来の5レーン幅と操作を維持）
- スマートフォン縦画面・タッチ操作を主対象とする
- レーン、ノーツ、判定ライン、入力座標は同一のprojectionモデルを使う
- 現在は遠近表現を持ち、奥ほど狭く、判定ライン側ほど広く表示する
- 遠近感・収束率・ノーツ幅などの具体値は `monster-hero/data/rhythm-mode.js` を正本とする

### ノーツ種別

| 種別 | 基本操作 |
| --- | --- |
| `TAP` | 判定ライン到達時にタップ |
| `HOLD` | 始点で押し、終端まで保持し、終端タイミングで離す |
| `FLICK` | 始点を押した後、一定距離以上を短時間でフリック |
| `SLIDE` | 始点で押し、指定経路を指で追従し、終端タイミングで離す |

1 authored note = 1最終判定を基本とし、HOLDやSLIDEの途中経過で判定数を増やさない。

### WIDTH TEST

デバッグの専用曲「WIDTH TEST」EASYには、幅1・2・3・4、左右端と中央の幅1、隣接する幅1の同時押し、ワイドTAP、幅1→2→3→4の連続配置を収録する。すべて表示確認だけでなく実入力でき、各 authored TAP は幅に関係なく1判定・1コンボとして扱う。正式譜面や一般公開導線には追加しない。

## 4. 判定（現行仕様）

確認基準SHA時点の判定幅とスコア率は以下。

| 判定 | 許容幅 | スコア率 |
| --- | ---: | ---: |
| MARVELOUS | ±25ms | 1.00 |
| EXCELLENT | ±50ms | 0.98 |
| GREAT | ±100ms | 0.90 |
| GOOD | ±150ms | 0.70 |
| BAD | ±200ms | 0.30 |
| MISS | ±200ms外 | 0 |

スコア構成は以下。

- 判定: 90%
- コンボ: 10%

## 5. HOLD / SLIDE の終端判定とENDバー（現行仕様）

終端リリース判定は PR #906、終端を視覚化するENDバーは PR #910 で追加された。

### 終端判定

- HOLD / SLIDE は、終端まで押し続けるだけでは成功にならない
- 終端タイミングで指を離す必要がある
- 終端の離し判定も開始時と同じ ±25 / 50 / 100 / 150 / 200ms を使う
- ±200msを超えた離しはMISS
- 終端から+200msを超えて押しっぱなしでもMISS
- 最終判定は「始点判定」と「終端判定」の悪い方
- SLIDEは途中の経路追従に失敗した場合もMISS

例:

- 始点 MARVELOUS + 終端 GOOD → 最終 GOOD
- 始点 GREAT + 終端 MARVELOUS → 最終 GREAT
- 始点 MARVELOUS + 終端 MISS → 最終 MISS

### ENDバー

- HOLD / SLIDEの終端には、離すタイミングを示す専用ENDバーを表示する
- ENDバーが判定ラインへ到達したタイミングで指を離す
- 表示専用で、入力を遮らない
- runtimeが一時的に変更する `endTimeMs` ではなく、譜面本来の終端時刻を正本として位置を計算する
- HOLDはそのノーツの終端レーン、SLIDEは `slidePoints` の最終位置を優先して終端レーンを決める
- レーン・ノーツ・帯と同じprojection座標系で描画する

ENDバーの太さ・発光・視認性などの見た目は、判定仕様を変えずに今後調整してよい。

## 6. HOLD / 複数指（現行仕様）

PR #868 で追加された基盤。

- HOLD中に別レーンTAPを入力できる
- 同時2本HOLDに対応する
- 各指を独立して管理する
- ポーズ中は入力・自動MISS・曲時間を進めない
- 再開時は同一runの時間基準を維持する

---

## 7. FLICK / SLIDE（現行仕様）

PR #884 で追加された基盤。

### FLICK

- 方向指定なし
- 24px以上の明確な移動を検出
- 450ms以内

### SLIDE

- `slidePoints` を時間補間して期待レーンを算出する
- 1本の指で経路を追従する
- 途中追従は位置許容幅を使って判定する
- 途中追従で追加スコア・追加判定を発生させない
- 終端では現在の終端リリース判定を使う

---

## 8. 再生・ポーズ・リスタート・リザルト（現行仕様）

STEP 2B以降で確定したライフサイクル。

- AudioContext基準の曲時間を正本にする
- ポーズ中は曲時間を止める
- 再開時は新しいBufferSourceを作り、保存したoffsetから再開する
- 完走時にリザルトを生成する
- 中断時はBESTを保存しない
- BESTは新スコアが過去BESTを上回った場合に更新する
- clear / fullCombo / allExcellent / allMarvelous 等の達成履歴は保持する
- リザルト再プレイやポーズリスタートは、旧runの状態を残さないようcleanupする

## 9. 保存キー（現行仕様）

初期設計から以下を使用する。

- `mh_rhythm_settings_v1`
- `mh_rhythm_best_v1`

欠損値・旧データ・不正値は読み込み時に正規化する。
