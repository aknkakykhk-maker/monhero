# 音ゲー 今後の実装候補

更新日: 2026-09-02

この文書は `docs/spec/RHYTHM_MODE.md` を補助する将来実装候補メモ。現行挙動は常に最新 `main` と `RHYTHM_MODE.md` を正本とする。以下はユーザーと会話で追加した将来候補であり、数値・細部は実装時に改めて確定する。

## 1. HOLD / SLIDE の途中追従判定強化 — **実装済み（暫定値、`RHYTHM_MODE.md` §5「途中追従判定」参照）**

### 目的
HOLD / SLIDE を「始点を取ればほぼ通る」状態にせず、途中も正しく保持・追従していることを確認する。

### 実装内容
- チェックポイント方式ではなく、pointermove / touchmove と毎フレームの再評価による**継続的な判定**にした
  （SLIDEはもともとこの方式で経路追従していたため、HOLDもこれへ揃えた）。
- HOLDは帯の中心からの横ズレ、SLIDEは経路(`slidePoints`)からの横ズレを継続して確認する。
- 猶予（暫定120ms）を超えて外れたままの場合だけMISSを確定する。猶予内に戻ればカウントをリセットする。
- 内部チェックポイントごとのスコア判定は増やしていない。`1 authored note = 1最終判定` を維持する。
- 途中で失敗確定したHOLD / SLIDEは、指を離すのを待たずその場でMISS扱いにする。
- MISS確定後はノーツ本体・HOLD帯・SLIDE帯を半透明のグレーへ変更する（PR #973で先行実装済み）。
- 失敗後に正しい位置へ戻しても、そのノーツは復活しない。
- 失敗済みノーツは終了時刻まで薄い状態で流す。

### 暫定値（実機確認のうえで調整する）
- 猶予: 120ms
- HOLDの横ズレ許容: 帯の半分幅 + 0.15レーン（0.3サブレーン）
- SLIDEの経路外許容: 既存の `rhythmSlideTrackingTolerance`（幅に応じて可変、変更なし）

`node tools/mode/rhythm-mid-tracking-check.js` で確認する。

## 2. 特殊ノーツ「モンスターノーツ」（仮）

### 目的
設定中のマスモンと音ゲーのゲーム性を直接つなぎ、モンスターを設定する意味を持たせる。

### 基本案
- 通常ノーツとは見た目を明確に区別した特殊ノーツを追加する。
- 仮称は「モンスターノーツ」。正式名称は未確定。
- モンスターノーツを成功すると、現在設定しているマスモンの能力を発動する。
- モンスターノーツをMISSした場合は能力を発動しない。
- 能力発動中は、効果内容や残り時間が分かるUIを用意する方向。

### 能力候補
まずはランキングのスコア計算へ直接影響しにくい「生存系」を中心候補とする。

- 回復型: ライフを一定量回復する。ただし不可逆のDOWN後は回復しない。
- バリア型: 数秒間、MISS等でもライフが減らない。
- 丈夫さ型: 一定時間、受けるライフ減少量を軽減する。

将来的に別能力を追加する余地は残すが、スコア倍率UP・判定窓拡張などランキング公平性へ直接影響する能力は別途設計確認してから実装する。

### 実装前に決めること
- 音ゲーのライフ最大値・MISS時の減少量・回復上限
- マスモンごとの能力割り当て方法
- 回復量
- バリア継続秒数
- 丈夫さ軽減率と継続秒数
- モンスターノーツの出現頻度・譜面上の配置ルール
- 同じ能力の重複発動・上書き・延長ルール
- 能力中の画面表示
- 全国/週間ランキングでの扱い
