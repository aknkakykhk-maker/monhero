更新日: 2026-09-02

## 1. HOLD / SLIDE の途中追従判定強化

### 目的
HOLD / SLIDE を「始点を取ればほぼ通る」状態にせず、途中も正しく保持・追従していることを確認する。

### 候補仕様
- HOLDは始点・終点だけでなく、途中にも内部チェックポイントを持つ。
- SLIDEは `slidePoints` 間も含め、経路上へ内部チェックポイントを持つ。
- 各チェック時点で、指がその時刻の正しいレーン・幅・SLIDE経路内にいるか確認する。
- 指が範囲から外れた、途中で離した等の条件で失敗を確定する。
- iPhoneの指ブレで即失敗しないよう、短い猶予や既存の追従許容を考慮する。
- 内部チェックポイントごとにPERFECT等のスコア判定を増やさず、原則 `1 authored note = 1最終判定` を維持する。

### 途中MISS後の見た目
- 途中で失敗確定したHOLD / SLIDEは、その時点でMISS扱いにする。
- MISS確定後はノーツ本体・HOLD帯・SLIDE帯をグレー系または半透明へ変更し、「すでに失敗済み」と分かる表示にする。
- 失敗後に正しい位置へ戻しても、そのノーツは復活させない。
- 失敗済みノーツは必要な終了時刻まで薄い状態で流し、視覚的に状態を把握できるようにする。

### 未確定
- チェックポイントの時間間隔
- 範囲外を許容する猶予時間
- HOLDの横ズレ許容
- SLIDEの経路外許容
- 途中MISS確定時の具体的な演出・色・透明度

## 2. 特殊ノーツ「モンスターノーツ」（仮）

### 目的
設定中のマスモンと音ゲーのゲーム性を直接つなぎ、モンスターを設定する意味を持たせる。

### 基本案
- 通常ノーツとは見た目を明確に区別した特殊ノーツを追加する。
- 仮称は「モンスターノーツ」。正式名称は未確定。
- モンスターノーツを成功すると、現在設定しているマスモンの能力を発動する。
- モンスターノーツをMISSした場合は能力を発動しない。
- 能力発動中は、効果内容や残り時間が分かるUIを用意する方向。

### 能力候補
まずはランキングのスコア計算へ直接影響しにくい「生存系」を中心候補とする。

- 回復型: ライフを一定量回復する。
- バリア型: 数秒間、MISS等でもライフが減らない。
- 丈夫さ型: 一定時間、受けるライフ減少量を軽減する。

将来的に別能力を追加する余地は残すが、スコア倍率UP・判定窓拡張などランキング公平性へ直接影響する能力は別途設計確認してから実装する。

### 実装前に決めること
- 音ゲーのライフ最大値・MISS時の減少量・回復上限
- マスモンごとの能力割り当て方法
- 回復量
- バリア継続秒数
- 丈夫さ軽減率と継続秒数
- モンスターノーツの出現頻度・譜面上の配置ルール
- 同じ能力の重複発動・上書き・延長ルール
- 能力中の画面表示
- 全国/週間ランキングでの扱い
