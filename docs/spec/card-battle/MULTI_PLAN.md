**社長の決め・カゲあつくんの指摘で変えたこと**
- 切断から戻れる時間は **60秒**(iPhone でアプリを切り替えて戻ってくる分。社長)
- 「だれとでも」の受付に、**いま待っている人の数**を出す(モンヒロビートのフリーマッチと同じ形)。待つのは**上限90秒**で、来なかったら「助手と対戦へ」の案内を出す
- 社長に見せる文には中の言葉を出さない
- **強さの点数は、3つの部屋(だれとでも・合言葉・フレンド招待)のどれでも動く**(社長「マルチは全部動くようにして」)。同じ相手と続けて当たっても点数は小さくせず(いつも最大32点)、同じ相手からのカードポイントの「1日3戦まで」も入れない(社長「同じ相手と続けて当たったときも小さくしないで。1日制限もいらない」)。カードポイントの1日の上限(2,200)もなくし、何戦してももらえる(社長の決め直し)

## 1. つなぎ方(モンヒロビートの「みんなで対戦」と同じ仕組みを使う)

- 通信は **Supabase Realtime の Broadcast だけ**(モンヒロビートと同じ)。低いところの部品 `rhythmMultiOpenSocket`(77-screen-rhythm-multi.jsx)は、モンヒロビートに依らないのでそのまま使う。
  部屋のチャンネルは `realtime:mhc-room-<コード>`、受付は `realtime:mhc-lobby-free`(モンヒロビートの部屋と混ざらない)。
- **ホスト = 先に入った人**。ホストが先攻・後攻をくじで決めて知らせる。
- ターン制なので、知らせは「1手ごとに1通」。各手に通し番号(`seq`)を付け、相手は「受け取った」を返す。返ってこなければ同じ手を送り直す(届かない・二重に届くを防ぐ)。
- **相手の番の待ち方**: 相手の番は、画面に「あいての番」と残り時間を出して待つ。相手の手が届くたびに、自分の端末でも同じルール(82-card-battle-core.jsx)で計算して、場を動かす。守りの番(相手に攻められたとき)だけ、こちらが選ぶ。
- **時間切れ**: ルールの本文(CARD_BATTLE.md 1-3)のとおり、自分の番60秒・守り15秒。過ぎたら、その番は終了・守りはパス。**3回続けて使い切ったら負け**。時間は番の持ち主の端末が数え、相手の端末も同じ時刻で数えて食い違いを見張る。
- **切断**: 2秒ごとの「生きている」の知らせ(モンヒロビートの `hb`)。**120秒届かなければ、抜けた扱い(相手の勝ち)**(2026-10-27 社長が60秒→120秒。相手の電波が途切れている間は相手の持ち時間の時計を止め、この120秒だけで決める)。120秒のうちに戻れば、同じ部屋に入り直して、相手から「それまでの手の一覧」を受け取り、なぞり直して続きから遊べる。
  自分から抜けた(降参・タブを閉じた)ときは `bye` を送る。抜けた人には、モンヒロビートと同じく少しのあいだ受付に入れない時間を置く(新しい保存キー `mh_card_pvp_penalty_v1`)。

## 2. 部屋の作り方

| 入口(マルチ対戦の中) | 中身 | 強さの点数 |
| --- | --- | --- |
| **だれとでも** | 受付で、待っている人と2人そろったら部屋へ | 動く |
| **合言葉** | 4文字の合言葉で部屋を作る/入る(モンヒロビートのルームと同じ作り) | 動く |
| **フレンドから** | フレンド一覧から招待する | 動く |

- フレンドの招待は、いまの表 `friend_invites` が「4文字の合言葉」しか持てず、モンヒロビートの部屋と見分けられない。そのため、**カード用の新しい表**(`card_battle_invites`)にする(いまの表は触らない)。作るのは最後の区切り。
- 報酬は台帳どおり: 勝ち 24周・200 / 負け 12周・50 / 抜けた 0。1日の上限は無し(何戦してももらえる・社長)。自分の番が3回より前に終わった試合は0。どの入口でも同じ。

## 3. ズルを防ぐ

1. **手札・山札は相手に送らない**。送るのは「何枚引いた」「何枚伏せた」と、使ったカードの番号だけ(使った瞬間に表になるので、見せてよい)。
2. **はじめに「山札の順の封筒」を交換する**: 試合の前に、自分の山札の切り方(乱数の種)とデッキを、ひと続きの文字にして**指紋(SHA-256)だけ**を相手へ送る。中身は試合が終わるまで見せない。
3. **終わったら封筒を開けて、試合をまるごとなぞり直す**: 両方が種とデッキを見せ合い、相手の端末で**最初から全部の手を計算し直す**。次のことを確かめる。
   - 引いたカード・使ったカード・伏せたカードが、本当にその順で山札から出ていたか
   - 50枚・同じ技は3枚まで・持っているカードか
   - 勝ち負けが合っているか
   合わなければ、その試合は「無効」にする(点数もポイントも動かさない)。ルールは手順だけで結果が決まる作りなので(乱数は山札を切るところだけ)、なぞり直しが使える。
4. **結果の書き換え**: 強さの点数は、端末から表へ直接書かせない。**2人がそれぞれ結果を届け、2つが合ったときだけ**データベースの関数が1回だけ点数を動かす(同じ試合を2回数えない)。
   ただし、いまのランキングと同じく、遊ぶ人だけが持つ秘密の印(ログイン)は無い。そのため、同じ人が2台で自分と戦うようなズルや、友だちどうしの勝ちの譲り合いまでは防げない(社長の決めで、同じ相手との対戦も点数を小さくしない)。
5. 受け取った知らせは、モンヒロビートと同じく**必ず掃除してから使う**(知らない形は捨てる・数は上限で切る)。ルールに合わない手(持っていないカード・ガッツが足りない手)は、受け取った側がはねて、その試合を無効にする。

## 4. Supabase に足す表(足すだけ。いまある表には触らない)

下書き: [`docs/sql/card-battle-pvp/CARD_BATTLE_PVP_APPLY.sql`](../../sql/card-battle-pvp/CARD_BATTLE_PVP_APPLY.sql)(まだ流していない。区切り3で流す)

- `card_battle_pvp_ratings` … 1人1行(強さの点数・勝ち・負け)。**読むのはだれでも、書くのは関数だけ**。
- `card_battle_pvp_matches` … 1試合1行(2人の結果の届け)。2人の届けが合ったら、関数が点数を1回だけ動かす。
- 関数 `card_battle_pvp_report(...)` … 結果を届ける入口。点数は Elo(はじめ1500・1試合で最大±32)。
- `card_battle_invites` … フレンドの招待(区切り4)。
