# モンヒロビート みんなで対戦(マルチ)仕様書

プロセカの「みんなでライブ」を参考にした、最大5人の協力ライブ。
実装: `monster-hero/src/parts/77-screen-rhythm-multi.jsx`(部屋の状態 `RHYTHM_MULTI` と画面 `RhythmMultiScreen`)。
モンヒロビートの入口「モードえらび」(`RHYTHM_MODE_SELECT`)も同じ部品で描く(`modeSelect` を渡したとき)。部屋に入れたら `onRoomEntered` で `RHYTHM_MULTI` へ移り、`RHYTHM_MULTI` で部屋が無くなったらモードえらびへ戻る。
検査: `node tools/mode/rhythm-multi-check.js`(通信と時間を偽物にして、複数人ぶん動かす)。
画面を自前で回している間(`data-mh-view-rotation`・iPhoneの「横」ボタン)は、端末の向きが縦のままなので、`portrait:` と `max-height` の指定は縦画面のほうが効いてしまう(`landscape:` はビルドが回転中へ写してくれる)。この画面は、そうした指定の横に回転中の写し(`[[data-mh-view-rotation=true]_&]:`)を並べて書く。
配置の検査: `node tools/mode/rhythm-multi-layout-check.js`(モードえらびと結果画面を実際に開いて、実機に近い大きさと「回転中」を含む縦横の数サイズで、はみ出し・カードの中身の切れ・MVPの札の重なり・定型文の段数を測る。通信は同じブラウザの2ページを BroadcastChannel でつなぐ偽物)。

## 1. 流れ

```
モードえらび RHYTHM_MODE_SELECT(フリーマッチ / ルーム作成 / ルーム入室 / フレンドの招待。ベテランは2026-10-03に画面から外した)
 → マッチング(5人そろう / ホストの「メンバー確定」/ 公開ルームは2人以上で15秒出入りなし)
 → 選曲 30秒(曲 or おまかせ。全員そろうか時間切れで次へ)
 → MUSIC SHUFFLE(全員の選曲から1曲を抽選。全員おまかせなら全曲から)
 → 難易度選択・準備完了 30秒(全員の準備完了か時間切れでライブ開始)
 → ライブ(各自の端末で演奏)
 → 結果(チームのランク・カード・MVP・メンバーの成績)
 → 同じメンバーのまま次の選曲へ(ホストの「次へ」、または45秒で自動)
```

| 段(`room.phase`) | 制限時間 | 時間切れのとき |
| --- | --- | --- |
| `matching` | なし(公開ルームは2人以上で15秒出入りなし→確定) | — |
| `select` | 30秒(+3秒、届くのを待つ猶予)。**部屋にいる人(CPU を除く)がひとりだけのあいだは制限時間なし**(`deadline` 0・全員が選ぶまで待つ。人が入ったらその時点から30秒。2026-10-07・ユーザー指示) | 選んでいない人は「おまかせ」。おまかせは抽選の箱に入らない(ほかの人の選曲が優先) |
| `ready` | シャッフル2.4秒+30秒(+3秒の猶予) | 準備していない人は、いまの難易度で準備完了 |
| `playing` | 曲の長さ+準備(3秒+3.2秒)+10秒 | 結果が届かない人はリタイア扱い |
| `result` | 45秒 | 次の選曲へ |

ホストは「待たずに進む」を持つ: マッチング「このメンバーで始める」/ 選曲「締め切る」/ 難易度選択「すぐ開始」(準備していない人もいっしょに始める)/ 結果「次へ」(ライブ中の人がいても次の曲へ)。

## 2. 作り(サーバーを持たない)

- 通信は Supabase Realtime の **Broadcast だけ**(テーブル・SQL なし)。部屋ごとに `realtime:mhb-room-<コード>`、フリー/ベテランの受付は `realtime:mhb-lobby-free` / `-veteran`。
- **ホスト = いる人の中でいちばん早く入った人**(同時なら id の小さい順)。全員が同じ並びを計算できるので、決める役を選ぶやりとりは要らない。
- **部屋の進行はホストの端末だけが決める**(`hostTick`)。ほかの人はホストの `hb` に載った進行に従う。ホストが抜けたら、次のホストが手元の進行をそのまま引き継ぐ。
- 残り時間は「あと何秒」で配る(`lf`)。0秒と「制限時間なし」は `dl` で区別する(0を「なし」と読むと時間切れが動かなくなる。実際に踏んだ)。
- 状態は React の外(`RHYTHM_MULTI`)に置く。演奏画面へ行って戻っても部屋は切れない。

### 知らせ(`payload.t`)

| t | 送る人 | 中身 |
| --- | --- | --- |
| `hb` | 全員(2秒ごと) | 名前・Lv・アイコン・フレーム・選曲・準備・難易度・結果。ホストは進行(`room`)も |
| `draw` | ホスト | 抽選で決まった曲 |
| `start` | ホスト | ライブ開始(回の id・曲・参加者) |
| `res` | 全員 | 自分の結果(スコア・最大コンボ・クリア・リタイア・難易度・FC・判定の数・FAST/SLOW) |
| `chat` | 全員 | 40文字まで。0.8秒に1回まで。直近50件だけ覚える(保存しない) |
| `bye` | 抜ける人 | ルームを出る・タブを閉じる(`pagehide`)とき |

受け取った知らせは必ず `rhythmMultiCleanMessage` で作り直してから使う(知らない形は捨て、数は上限で切る)。
`start` と `draw` は**ホストから来たものだけ**受ける。

### 演奏中の通信

- **演奏中は何も送らない**(ライブ開始の1回だけ `hb` を送る)。届いた知らせは処理せずに溜め(上限300件)、自分の結果を送るときにまとめて処理する。演奏の判定と描画に一切割り込ませないため(2026-10-03・ユーザー指示)。
- ライブ中の人は何も送ってこないので、ライブの上限時間まで抜けた扱いにしない(`playUntil`)。
- 「抜けます」を送れない閉じ方(強制終了など)は、曲が終わってから10秒で抜けた扱いになる。

### チャット(2026-10-03 強化)

- 💬(画面右上。結果画面では下の定型文の右)で開く。閉じているあいだに届いたほかの人の発言の数を赤い丸で出す。
- 定型文は `rhythmMultiStampsFor(phase)`: 画面ごとの文(`RHYTHM_MULTI_CHAT_STAMPS_BY_PHASE`)を先頭に、共通の文を後ろへ。結果画面は「もう一回!」「ありがとう!」が先頭。
- 結果画面・待機画面には定型文の帯を常に出す(開かなくても1タップで送れる)。
- 発言は受け取った時刻(`at`)を持ち、その人のカード・結果の行の上に6秒だけ吹き出しで出す(`RHYTHM_MULTI_CHAT_BUBBLE_MS`)。
- 続けて送れない(0.8秒)ときは「少し待ってね」を出す。

## 3. 結果と報酬

- **チームのランク** = 参加者全員の平均スコアを `rhythmRankForScore` に通したもの。リタイア・抜けた人は0点で平均に入る。
- **MVP** = 最後まで演奏した人の最高スコア(同点は先に入った人)。
- **周回報酬とビートP**は、ひとりで遊ぶときと同じ計算に**人数ボーナス**を掛ける: 参加者1人ごとに+50%(`rhythmMultiRewardScale`: 2人1.5倍〜5人3倍)。呼んだマスモン(CPU・docs/spec/RHYTHM_BUDDY.md)は1体目+30%・2体目+20%・3体目と4体目+10%(2026-10-07)。
- **連続ボーナス**(2026-10-03): 前のライブの参加者が全員また参加していれば連続が1つ増える(`liveStreak`・`liveIds`)。メンバーが増えただけなら続き(同日・ユーザー指示)、だれかが抜けたら1に戻る。2曲目+10%…11曲目より後は+100%(`rhythmMultiStreakBonus`)。人数ボーナスと掛け合わせる(`rhythmMultiTotalScale`)。
- **MVP**はごほうびを付けず、結果画面と記録に出すだけ(2026-10-03・ユーザー指示)。
- **全国ランキング**(2026-10-04): 部屋の中の各画面のヘッダー(結果画面は下の行)に🏆。`rankingSupport`(60-app が渡す)で、既存の `RhythmRankingScreen` を**対戦の画面の上へ重ねて**出す(`gameState` は移さない。移すと、ライブ開始の合図を受ける側が外れて取り逃す)。ライブ開始の合図が来たら閉じる。
- **記録** `mh_rhythm_multi_record_v1`: 結果がそろったら1回ぶん足す(`RhythmMultiRecordSaver`)。モードえらびの「記録」で見る。
- **フレンド申請**: `hb` にブリーダーid(`bid`・英数字と記号だけ)を載せ、結果画面のカードから `sbSendFriendRequest`。
- **待ち人数**: モードえらびで受付を聞き(`watchLobby`)、最近8秒に「ここにいるよ」を送ってきた部屋の人数を足して出す。フリーで45秒ひとりのままなら、プライベートルームを勧める。
- 自己ベスト・全国ランキングにも、ひとりで遊ぶときと同じく入る(`from==='multi'` も送信対象)。
- マスモン設定のマスモンは出る。アシストモード・ラッキーラッシュは使えない。
- 演出は `multiLook` の段階を重ねる: LIGHT(既定)/STANDARD/VIVID は `RHYTHM_LOOK_PRESETS` の値、OWN は自分の設定のまま(2026-10-03)。難易度えらびの画面で選ぶ。保存してある見た目は書き換えない。
  `multiLook` が無い古い保存値は `multiLightLook` から決める(ON→LIGHT・OFF→OWN)。選び直すと `multiLightLook` も合わせて書く(古い版で開いても近い見え方になる)。

## 5. 決めごと(壊しやすいところ)

- 演奏画面へ渡す設定は `useMemo` で作る(描画のたびに作ると演奏画面が作り直される)。
- 全画面・画面ロック防止は「指で押した直後」しか許されない。対戦は自動で演奏に入るので、「準備完了」のタップで頼む。
- 曲の試聴(本体が鳴らす)には、対戦の画面が「いま鳴らしたい曲」を知らせる(選曲中は見ている曲、曲が決まってからライブまでは決まった曲)。知らせないと、ソロで選んでいた曲が鳴る(実際に「Monster Hero」が一瞬流れた)。
- 既存の検査が見ている書き方(演奏画面の戻り先・文言、周回報酬の配り方、ビートPの付与)は崩さず、対戦の分岐は外側に足す。
- 通信量: 5人の部屋で `hb` が1秒に2.5件(全員に届くので受信は約12件)。Supabase の無料枠を使い切りそうなら、間隔を延ばす・変化のあるときだけ送る、で減らせる(未対応)。
