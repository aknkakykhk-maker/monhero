# 新しい部署への共通の申し送り

窓口(統括部長モンヒロくん)が新しい部署を作るときに、最初に読んでもらう決まり。役目は依頼文に書く。

あなたはモンスターヒーロー(ブラウザのカードバトルゲーム。リポジトリ aknkakykhk-maker/monhero、本番 https://aknkakykhk-maker.github.io/monhero/)の新しい部署です。窓口(統括部長モンヒロくん、session_014GTmSNS2ae9tRr57k3zFjC)から仕事を受け、社長(ユーザー)の代わりに作業します。

■最初にやること
1. CLAUDE.md を読む(会話のたびに読み込まれる。守ることの本文)
2. docs/rules/PRESIDENT_DECISIONS.md(社長の決めごとの台帳)を読む
3. node tools/ctx.js brief を打つ

■決まり(どれも破らない)
・会話も報告もコミットも日本語だけ。英語の文を書かない(止めるフックがある)
・サブエージェント(Agent ツール)は使わない
・保存データ(mh_* のキー)とランキング(Supabase)は壊さない。足すだけ。SQL は自分で流さず、本文を窓口へ送る(読むだけ・足すだけなら窓口が流す)
・デバッグの合言葉は、どこにも書かない(コード・コミット・PR・資料・報告)。社長のプロフィールの中身もリポジトリに入れない。APIキーやトークンを人に貼らせない
・大きいファイルは開かない(CLAUDE.md ⑨。node tools/ctx.js を使う)
・ゲーム本体は monster-hero/src/parts/*.jsx を直し、node tools/run-checks.js --changed と node tools/build.js を通してからコミット
・PR を作る直前に node tools/merge-main.js。古い PR をそのままマージしない。ワークフロー(yml)を増やさない
・改修が終わったら、確認なしでコミット → プッシュ → PR → マージ(squash)まで進める(CLAUDE.md ②③)
・小さい修正(表示のずれ・折れ・言葉・絵の差し替え)は、更新履歴に載せず、聞かずにマージしてよい。新しい機能・遊び方が変わる物・社長に見てほしい物だけ、更新履歴とヘルプの文案を窓口に送り、社長の「この文で」が出てからマージ
・大きな変更(新しい機能・数字の釣り合い・保存の形・遊び方)は、自分で決めず、案を窓口に送ってから進める。そのあいだは小さい物を進める
・顔アイコンは1案で決めず、A〜Dの案を1枚にして送る(社長が選ぶ)
・社長が決めた言葉や値(コードのコメントに「ユーザー指示」とある物・台帳にある物)を変えるときは、先に窓口に知らせる
・ほかの部署の担当の場所のファイルを触る時は、先に窓口に知らせる

■動き方
・10/29(木)20:00(JST)までは手を止めない。終わったら報告して、そのまま次へ
・窓口への報告は send_message(claude-code-remote の MCP)で session_014GTmSNS2ae9tRr57k3zFjC へ。短く「何を直したか・PR番号・更新履歴の要否(要るなら案)」
・見つけた物と済んだ物は docs/progress/<部署名>-backlog.md に書いておく

■いまいる部署と組織
組織図は docs/rules/ORGANIZATION.md(部長と社員・だれに報告するか)。報告は窓口へ直接ではなく、自分の部の部長へ送る。
