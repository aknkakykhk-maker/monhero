### ⑥-3 モンヒロビートの新曲は「動画1本＋ジャケット画像1枚」で受け取る

2026年9月にユーザーがそう指示した。**「新曲実装」と動画・画像だけが投げられたら、
それ以上聞き返さずに最後まで通す**。曲名は動画のファイル名から取る
(UTF-8を16進で綴った名前で届くことがあるので、その場合はデコードする)。

> ⚠️ **例外はひとつだけ。難易度は、こちらで決めずに聞く**(2026-09-12にユーザーがそう指示した)。
> 下の「出来上がったレベル」の項を参照。ここ以外では聞き返さない。

手順はスキルにしてある。**`rhythm-song-add` スキルを開いてから始める**
(`.claude/skills/rhythm-song-add/SKILL.md`)。コマンド列・落とし穴・聞き返す場所が
1枚にまとまっているので、そこだけで最後まで通せる。
譜面生成の仕組みそのものを触るときは [`docs/spec/RHYTHM_MODE.md`](../spec/RHYTHM_MODE.md) の
「動画1本から曲を足す手順」が正本。
とくに引っかかりやすい3点だけ、ここにも書いておく。

- **mp4から音を出すには `npm i ffmpeg-static` が要る。** Playwrightの Chromium は AAC を
  持っていないので、`rhythm-audio-reencode.js` へ mp4 を直接渡すと
  `EncodingError: Unable to decode audio data` で止まる。ffmpeg で映像とタグを落として
  WAVにし、mp3にするのはリポジトリのツールへ戻す(既存曲と作り方をそろえるため)。
  ffmpeg-static はリポジトリの依存には足さない
- **名前は5か所で綴りが違う**(songId / 音源の一覧のid / BGMのtrack id / 譜面のマーカー名 /
  ファイル名)。`tools/mode/rhythm-runtime-notes.js` の `RELEASED_MARKERS` と
  `RELEASED_TRACKS` への1行ずつを書き忘れると、検査だけが静かに対象外になる
- **出来上がったレベルは、勝手に決めずにユーザーへ伝えて聞く**(2026-09-12にユーザーがそう指示した。
  「今後難易度についてはこちらから指定がない場合は解析後、難易度をこっち伝えてどうするか聞くようにして」)。

  自動で出る歯ごたえは音源から測れることしか見ないので、曲の雰囲気と食い違うことがある
  (実際に crossing field が EASY Lv.11・MASTER Lv.38、SIX ÉTERNEL が MASTER Lv.39 になった)。
  **依頼の中で難易度の指定があればそれに従う。指定が無ければ、解析と生成を通したうえで
  いったん止めて、次の3つを並べて報告し、どうするか聞く。**

  1. 出たレベルとノーツ数と密度(ノーツ毎秒)を、難易度ごとに
  2. 既存曲の帯の中でどのあたりに来るか(とくに帯から外れているならその旨)
  3. `challengeFactor` を変えたときの候補(いくつか実際に生成して数字で示す)

  決まったら `challengeFactor` に書く。**測り方(`CHALLENGE_*`)は触らない**(ほかの曲まで変わる)。
  決めた理由は `docs/spec/RHYTHM_MODE.md` に残す(`rhythm-song-challenge-check.js` が見張る)。

  > ここで止まるのは難易度だけ。ジャケットの加工・音量そろえ・マーカー登録・更新履歴など、
  > 難易度に関係しない作業は聞かずに進めてよい。
- **音量をそろえてから入れる。** ⑥-2 のとおり -14 LUFS / 真のピーク -1 dBTP へ。
  そろえ忘れると「その曲だけ小さい」と必ず言われる(実際に言われた)。
  `node tools/audio/rhythm-loudness-check.js` で確かめる
- **ヘルプは触らない。** 曲の一覧・絵の有無・レベルの幅は `{t:'data', id:'…'}` が
  実データから作るので自動で載る。手で書き写すと古くなるだけ。
  かわりに更新履歴へ1件書き、`assistantNotice:{id:'update_notice_◯◯_v1',type:'content'}` を付ける
- **お知らせにジャケットの絵を付ける**(2026-09-13にユーザーがそう指示した。「今後の新曲更新は
  お知らせにジャケット画もつけて」)。更新履歴の項目へ `image:'images/song-art/◯◯.jpg'` を1行書く。
  それだけで**更新情報の詳細にも、みゅあの告知にも同じ絵が出る**(`entry.image` を
  `assistantUpdateNoticeFromChangelog` がそのまま持っていくので、2か所に書かない)。
  `?v=` は手で書かない(`tools/stamp-version.js` が中身のハッシュから付ける)。
  書き忘れると画面はふつうに動いてしまうので、`node tools/changelog/song-art-notice-check.js` を通す
- **お知らせに書いてよい Lv. は、その曲のものだけ**(2026-09-13にユーザーがそう指摘した。
  「違う譜面の難易度を出す文面はそもそもおかしくない？」)。比較のつもりで
  「これまでの最高は EASY Lv.10／…／MASTER Lv.38 でした」とほかの曲の数字を並べたら、
  どちらがこの曲の難易度なのか分からなくなった。上下の関係を伝えたいなら
  「いままででいちばん難しい譜面になりました」のように**数字を出さずに書く**。
  同じ検査が「1行にLv.の5つ組が2回出ていないか」を見張る
- **よその作品の曲を入れたときは、お知らせから相手のページへリンクを出せる**(2026-09-14)。
  更新履歴の項目へ `link:{url,label}` を書くとボタンが出る。**https だけ通る**関門
  (`changelogSafeLink`)を必ず経由し、`target="_blank"` と `rel="noopener noreferrer"` が付く。
  `node tools/changelog/external-link-check.js` を通す。
  **宣伝の文面は教えてもらった事実だけで書く**(ゲームの中身はサンドボックスから確かめられない。
  確かめていないことを足すと嘘になる)。作者名は `BGM_TRACKS` の `creator` へ入れる
- **レベルとノーツ数は行を分ける**(同・「並びが分かりづらいね」)。
  `レベルは EASY Lv.◯ ／ … ／ MASTER Lv.◯ です。` と
  `ノーツ数は ◯ ／ … ／ ◯ です。` の2行にする。1行へ
  `EASY Lv.14（376ノーツ）／…` と詰めると、折り返した画面で数字が追えない
- **難易度が既存の帯から大きく外れるときは、`chartIntensity` を使う**(2026-09-13)。
  `challengeFactor` は5難易度まとめて効くうえ、上げすぎると量が頭打ちになって
  **レベルがむしろ下がる**(FREEDOM DiVE↓ で 33→31 になった)。ボス曲のように
  上だけを尖らせたいときは、曲の一覧へ `chartIntensity:'extreme'` を書く。
  書いた曲にしか効かないので、ほかの曲の譜面は1音も変わらない。
  中身と数字は [`docs/spec/RHYTHM_MODE.md`](../spec/RHYTHM_MODE.md)「19曲目 FREEDOM DiVE↓」
