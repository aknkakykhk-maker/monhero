## 作るのは最新リビジョンだけ(2026-10-12)

社長「段階を分けず、一気に古い版を外して最新だけにする」。計画: [`docs/playbot/reports/2026-10-12/revision-cleanup-plan.md`](../playbot/reports/2026-10-12/revision-cleanup-plan.md)

- 生成器・区間の差し替え・自動修正・仕上げの流れは、最新の作り方しか持たない。`--chart-revision` に最新以外を渡すと止まる
  (`tools/mode/rhythm-chart-generate-latest-check.js` が見張る)
- 古い作り方は git の記録から取り出す。外す直前のコミットは **c2094ad53**:
  `git worktree add /tmp/old c2094ad53` → `cd /tmp/old && node tools/mode/rhythm-chart-v3-generate.js --track <曲> --chart-revision <N> --write --output-dir <dir>`
  (浅い取り込みなら先に `git fetch --deepen`)。2026-10-12 に monster_hero_theme を Rev.21 で作れることを確かめた
- 曲の一覧(`authoring/rhythm-song-registry.json`)の `chartRevision` の数字はデータのまま残す。遊んだ記録の学び直しで、その曲がどの作り方で作られたかの印
- 既に作った譜面を**読む**ための読み方は残す: 速さの表(`rhythm-chart-tempo-warp.js` の `tempoWarpForChart`)・手のモデル(`handModelFlagsForRevision`)・
  レーン数(`laneCountOfChart`)。週次の学び直し(`rhythm-play-log.js`)が公開曲の遊んだ記録の時刻を、その曲を作ったときの速さの表で読み解くため
  (最新だけにすると時刻が数十 ms ずれる)
- 外したときの確かめ: 曲の一覧の43曲を最新で作った出力(215ファイル)・自動修正(3曲)・区間の差し替え(Sheriruth)が、外す前と1バイトも同じ

### 強化するとき

- 古い版へ分ける分かれ道(`chartRevision>=N`)は作らない。最新の作り方を直接よくする。公開中の譜面は生成器を通らないので変わらない
- 作る譜面が変わる強化は、`CHART_REVISION_CODE_LATEST` を**いまの最新リビジョン(`CHART_REVISION_LATEST`・学び直しの番号を含む)の次**にし、
  `rhythm-chart-v3-revision.js` の一覧に1行足す(その番号で作った曲がどんな作り方かの記録)
- 参考動画から学んだ「引き出し」(R1〜R5)は決まりではない。曲の解析を見て合う曲・区間にだけ使い、使う/使わないと理由を書き出しに残す(2026-10-16 社長「全てを当てはめるわけではない」)。本文: [`tools/mode/CHART_DRAWERS.md`](../../tools/mode/CHART_DRAWERS.md)
- 変更前のワークツリーを別に立てて、新しい曲を作った結果を突き合わせる(変わらないはずの直しなら1バイトも同じ・変える直しなら中身を確かめる)。手順: [`SCOPE.md`](SCOPE.md)

## 手の決まり(2026-10-12・HELL と Grievous Lady で分かったこと)

`tools/mode/rhythm-chart-hand-rules.js` が数え、`rhythm-chart-hand-rules-check.js` が公開中の全譜面で控えより増えていないかを見る
(譜面を変えたら必ず回す表に入っている)。左右はレーンの真ん中で分け、押し始めと長押しの終わりを点にする(同時押しは除く)。

- 同じ側で地上⇔空中を変えるのは **150ms 以上あける**(親指で上げきれず落ちる・#2830)。空中は同じ側の地上から **250ms 以上**が目安(テンポくん #2826・#2840)
- 押さえている帯と同じ側に来るノーツは、反対の手が空いているときだけ(押さえている親指では叩けない・#2843)
- 長押し中の手は使えない。押さえている間に来るノーツは、レーンの側に関係なく反対の手で取る。その手でも高さの切り替えは150ms/250ms あける(`heldHandSwitch`・テンポくんの前後比べで見つかった型・10/12)
- 同じ側の押し始めは **90ms 未満**にしない目安(遅れた叩きが次のノーツへ移りやすい・9/5)
- 新しい曲を足したら件数を見てから `--update --reason` で控えに足す。HELL は件数を出すだけ(公開前・社長が決める)
- **HELL の交差は上下に分ける**(2026-10-13 社長「ヘル譜面で水平クロスは意味ない・クロスのときは上下を活用」)。2本の帯の左右が入れ替わる瞬間は、片方が空中・片方が地上。
  同じ高さのまま入れ替わる「水平クロス」は作らない(`flatCross`・検査が HELL で0を見張る)。上下に分かれていれば親指の先どうしは当たらない。
  形は Sheriruth 見せ場1(#2910 ほか)と同じ: 上の帯が越える(越える幅は1レーンまで)・交差の前後160msも高さを分けておく(交差が解けた直後に2本が同じ高さで並ぶと詰まる)・
  交差したまま長く続けない(長い所は帯の道を入れ替えて解き、交わる瞬間だけ短い X にする)。テンポくんの bot で指先どうし 80px 前後以上を確かめる
- **押さえている帯の中にノーツを置かない**(2026-10-13 社長「ホールド・スライド中に同じところにノーツを出すのはやめたほうがいい」
  「地上と空中なら同じ位置でも良いけど、地上同士・空中同士は無理。半レーン被りならまだしも。ただ、1レーンのノーツに半レーン被りはかなり厳しい」)。
  長押しを押さえている最中に来る別のノーツを、その時刻の帯の位置(スライドはその時刻にいる位置)と比べる(`onHeldBand`):
  - 地上の押さえと空中のノーツ(またはその逆): 同じ位置でもよい
  - 同じ高さで半レーンより深く重なる(「重なる」): 置かない
  - 同じ高さで半レーンまで重なり、押さえている帯か来るノーツが幅1レーン以下(「半レーン(幅1が絡む)」): 置かない
  - 同じ高さで半レーンまで重なり、両方とも幅1.5レーン以上: 許す(検査は数だけ出す。幅1.5も許す・2026-10-13 社長)

  直し方は共通(`fixHeldBand`): 時刻はそのまま(音に合わせたまま)、帯を押さえていない手の側へ半レーンあけて置き直す(押さえている手の側へ出すと空いている親指が交差する)。
  入らなければあけずに・幅を詰めて、それでも無理なら取り除く(モンスターノーツは左右を反対側へ写す)。
  `rhythm-hell-mix.js`(HELL)はいつも、`rhythm-chart-v3-generate.js`(5難易度)は**新しい曲だけ**直す(決まりより前からある43曲は
  `rhythm-held-band-existing.json` の `tracks` にあり、作る譜面は1つも変わらない。`--held-band-rule` で確かめる用に効かせて出せる)。
  検査(`rhythm-chart-hand-rules-check.js`)は、前からある譜面は同じファイルの `charts` の件数を上限に、新しい譜面は0を見張る。
  公開中の5難易度にも同じ形がある(2026-10-13 に数えた。直すかは社長が決める・決めた曲だけ直す): 重なる626・半レーン(幅1が絡む)286
  (EXPERT 39譜面・MASTER 38譜面・HARD 2譜面)、許す半レーン238。Against My Own Shadow の EXPERT(23)・MASTER(16)は社長の決定で直した
  (時刻・幅・ノーツ数はそのまま。EXPERT は式の値が 22.44→22.58 で丸めると23になるので、表示は Lv.22 のまま `LEVEL_OVERRIDES` で固定)。公開中の HELL は Grievous Lady の半レーン(幅1が絡む)3か所(64.67・117.31・131.31秒)を
  社長の了承で直した(時刻とノーツ数はそのまま、置き場所だけ。Lv.60 のまま)。Sheriruth・風がそよぐ場所の HELL は0
- **HELL の上下の交差は、交わる所で帯を持ち替える遊び方でも押せるか確かめる**(2026-10-13 Against My Own Shadow 94.2秒)。

## 各難易度は難易度ごとに作る(2026-10-13 社長の決定)

**参考動画がない限り、各難易度は難易度ごとにちゃんと作る。** 上の難易度を、下の難易度の写しに割増しを足して作らない
(Against My Own Shadow の HELL を MASTER の写し+空中で作ったら「多分36ってマスターに2割増しただけだよね?」→「ヘル用に作り直して」)。

- これから作る新曲・新しい HELL から当てはめる。公開中の曲の譜面は変えない(⑩-2)
- **HELL**: `rhythm-chart-v3-generate.js --difficulty HELL` が、曲の解析から HELL の量・できること(PROFILES.HELL・DENSITY_TARGET.HELL)で骨組みを一から作り、
  `rhythm-hell-mix.js` が曲の設定 `source:'audio'` のときその骨組みを読んで空中・上下の交差を付ける(MASTER の譜面は読まない)。Lv. は作った譜面から道具で出す(空中を測る式・下の節)
- **5難易度(EASY〜MASTER)**: いまの道具は「同じ音の順位の上から何個取るか」で分けている(下の難易度は上の難易度の部分集合)。
  新しい決まりに合わせて難易度ごとに組み立てる形へ変えるのは道具の大きな作り替えになるので、次の新曲の前に別で見積もる(まだ変えていない)
- 参考動画がある曲(Sheriruth・Grievous Lady の HELL)は、参考の譜面を土台にしてよい

## HELL を重くする(2026-10-18・Toward the Stars で社長「マスター以上をもっとむずく」「HELL をもっと上げる」)

- MASTER だけ重くするのは曲の一覧の `chartIntensityByDifficulty`(例 `{"MASTER":"extreme","HELL":"extreme"}`)。EASY〜EXPERT は変わらない
- HELL は量の倍率を上げても、**拾える音の数**が天井になって増えない(Toward the Stars: 目標950に対して拾える音566・打点881)。そこで2つの手を足した。
  どちらも**書いた曲の HELL にだけ効く**。書いていない曲(公開中の曲すべて)は1音も変わらない(公開中の譜面は `rhythm-released-chart-lock-check.js` が見張る)
  - 曲の一覧に `hellDensity`(1より大きく2まで)を書くと、その曲の HELL だけ量に掛け、拾う範囲を広げる(弱い裏の音も落とさない・格子からのずれの許容はどの音も 43ms。
    格子へ寄せても最良の判定 ±55ms の中)。Toward the Stars は 467 → 566 ノーツ(指で押せる形に残るのは 563)
  - `rhythm-hell-mix.js` の曲の設定 `phrases` で、タップの空中・地上の回し方(1小節ずつ `L`=左手が空・`R`=右手が空・`ground`=両手とも地上・`both`=両手が空)を選ぶ。
    書かなければ今までの `['L','R','ground','both']`。両手とも地上の小節を減らすほど、切り替えが増えて重くなる(Toward the Stars は `['L','both','R','both']` で Lv.37 → 46)
- 重くすると、持ち替えの交差・届きにくい所の目安(横持ちの数)は増える。押せない0・水平クロス0・帯の中0・モンスター4個は必ず守る(variant を比べて選ぶ)

## HELL の地上と空中の入り乱れ・見分けにくさ(v3・2026-10-21 社長の決定)。次の新曲から使う

社長「地上と空中が近辺で入り混じってるのはかなり難易度高い。気安くいれていい譜面の形ではない」
「空中地上は基本は指を離した位置に置くのが基本」「**見分けづらいってのが相当難易度高いんだよ**」。
難しさのいちばんの元は、同じ左右の位置へ来る地上と空中のノーツが画面の上で重なって見え、どちらの高さか一瞬で読み分けられないこと
(指の動き・押す場所の余裕・指で隠れる、より重い)。

- **数え方**(`rhythm-chart-hand-rules.js` の `skyConfusable`): 押し始めの点どうしで、500ms 以内(同時も含む)・横に重なって見える
  (真ん中の差が2つの幅の半分の和以下)・高さが違う組を「見分けにくい所」として拾う。近いほど・短いほど重い(score 0〜1)。
  形が同じ(タップどうし・長押しどうし)で高さだけが違う組は重く、形が違えば 0.6 倍。1つのノーツにはいちばん重い組だけ付ける。
  同じ手が離した位置から1レーン以内で高さを変える(指を離した位置へ・`skyMixedSwitch` の near)は数えない
  - 数は同時のノーツの並び順で変わらない(2026-10-21 Journey の HELL で、道具の形では0・ゲームの形では2と食い違った)。
    「1つ前に離した位置」は同じ時刻の点をまとめて見て、その手が同時に2つ以上触っていたら自然な形とみなさない(数える側にそろえる)。同時の組は空中の側に1つ数える。
    `rhythm-hell-mix.js --write` は書いたあとゲームの形で数え直し、食い違えば止まる。`rhythm-chart-hand-rules-check.js` が、
    見分けにくい形を入れない決まりで作った HELL 7譜面がゲームの形で0件であることと、並びを入れ替えても数が同じことを見る
- **Lv. の測り方 v3**(`rhythm-chart-level.js` の `WORK_V3`。いまの既定): v2 に、見分けにくい所1つにつき `SKY_CONFUSE_WORK`(10)× score を足し、
  指を離した位置への持ち上げ・下ろしは1つにつき `SKY_NATURAL_RELIEF`(0.6)軽くする。
  2026-10-20 にあった全曲は v1 の一覧のまま、**公開中の HELL 9譜面の表示は v2 の値のまま**(v3 は参考値)
- **作るときの決まり**(`rhythm-hell-mix.js`): 空中を付け終えたあと、見分けにくい所に関わる空中のタップ(モンスターのノーツは除く)を地上へ下ろす。
  HELL の空中・地上は**指を離した位置へ持ち上げる・下ろすのが基本**
  - 見分けにくい形を残してよいのは、その曲の**山場**だけ。曲の設定 `mixedWindows: [[開始ms,終了ms], …]` か `'peak'`(押し始めの数がいちばん多い区間を1つ)。
    合わせて曲の長さの `PEAK_SHARE`(12%)まで。超えると止まる。`--peak` でその場だけ `'peak'` を試せる
  - `--keep-mixed` は比べるためだけ(前の作り方の形を出す)。`--write` と一緒に使わない
  - 残る数個は、モンスターのノーツ・長押しなど下ろせない所
- 公開中の譜面は1音も変わらない(`rhythm-released-chart-lock-check.js`)。作り直すかは社長が決める。
  測り直しと作り直しの試しの一覧は `docs/playbot/reports/2026-10-21/hell-mix/README.md`

## HELL の Lv. は空中の難しさを測って出す(2026-10-13 社長の決定)

「今後作るものは測る形で。今あるものは変えなくていい。あくまでもこれから作るものに対応」。

- `rhythm-chart-level.js` の `chartLevel` は、空中のある譜面を**空中込みでそのまま測る**(一律の `SKY_LEVEL_FACTOR` 倍はやめた)。1ノーツの重さに次を足す:
  地上⇔空中の切り替え(前からの `skySwitch`)・250ms より速い切り替えほど重く(`skySwitchFast`)・上下に分かれた交差1回ぶん(`skyCross`・帯の途中で起きるのでその時刻の仕事として足す)・
  片手が空中・片手が地上で押さえている最中のノーツ(`skySplit`)。空中の無い譜面では一度も起きないので、地上の5難易度の Lv. は1つも変わらない
- 公開中の HELL 3曲は表示を前の値のまま固定(`LEVEL_OVERRIDES`: Sheriruth 54・Grievous Lady 60・風がそよぐ場所 23・古い試作の Sheriruth 47)。
  `rhythm-chart-level-check.js` が固定値と、新しい式が空中を地上と見なした Lv. を下回らないことを見張る
- 重みは 2026-10-13 夜に合わせ直した(社長「空中はけっこう難しい。見積もりが甘い」)。その後、社長が AMOS HELL を遊んで「Lv.42 はありそう」(式では36)。

  左右交互の連打と同じ重さになっていた → **同じ側の速い連打**(`sameHandFast`: 同じ側の1つ前のノーツとの間隔が叩き直しの快適な150msより短いほど、最大6)を足した(空中のある譜面だけ)。
  いまの重み: 切り替え 0.7・速い切り替え 1.0・上下の交差 1.2・片手空中のあいだ 0.5・同じ側の速い連打 6。

## 手の流れを狙う配置(2026-10-21 社長「新しい譜面から流れを狙う」)。新曲から使う

社長の質問「Arcaea の譜面は流れで押せる配置になっているが、モンビーはそうなっているか」。それまでの生成は「無理な形を外す」中心で、
手が一続きに動く並び(なで・階段・往復・左右交互)を狙って作ってはいなかった。

- `rhythm-chart-v3-generate.js` の `flowCostFor`: 速い続き(半拍以内)の1歩ずつに費用を付けて、置き方の候補の費用に足す。
  - 隣のレーンへ同じ向きに進む(階段・なで)は安く、折り返す(往復)も安くする。左右の手に分かれる(真ん中をまたぐ)は少し安くする
  - 同じ側で1.6レーンより大きく跳ぶのは高く、同じ所の速い連打は少し高くする。山場・アクセントの跳びは、ほかの費用が勝てば残る
  - 流れの費用が残る形は、次の候補の形も3つまで試し、合計の費用がいちばん低いものを採る
- **既定は切**。曲の一覧(`rhythm-song-registry.json`)に `flowPlacement:true` を書いた曲か、`--flow` を付けたときだけ効く(`--no-flow` で切る)。
  書いていない曲は今までと1バイトも同じ譜面になる(公開中の曲は作り直さない・⑩-2。`rhythm-chart-flow-check.js` が見張る)
- 効き目は `rhythm-chart-flow-report.js --track <曲> --difficulty EXPERT,MASTER` で、オン/オフを書き込みなしに比べる。
  2026-10-21 に5曲10譜面(ROSE・トリコ・FREEDOM DiVE↓・Journey・crossing field の EXPERT/MASTER)で比べた結果:
  流れの割合 平均 81.6% → 84.7%(9譜面で上がる)・跳び 256 → 226・同じ所の連打 275 → 244・腕の交差 157 → 126・押せない 20 → 20・届きにくい 278 → 291。
  FREEDOM DiVE↓ MASTER だけは流れの割合が下がり、押せないが 2 → 4 に増えた(新曲で使うときも、押せない・届きにくいは自動修正と検査で見る)
