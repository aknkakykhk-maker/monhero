### ⑥-4 モンヒロビートのイベントは、決まった手順で開く

2026-09-11にユーザーがそう指示した(「今後イベントはこの形式になると思うから記録に残しといてね」)。
週末ゲリラ杯(初開催)で作った形が雛形になっている。

手順の実体は [`docs/spec/RHYTHM_EVENT_PLAYBOOK.md`](../spec/RHYTHM_EVENT_PLAYBOOK.md) にまとめてある。
**イベントを足すときは必ずそちらを開いてから始める。** とくに引っかかりやすい3点だけ、ここにも書いておく。

- **足すのは `data/rhythm-event.js` へ1件だけ。** 画面のコードもSQLも触らない。
  部門(対象曲ごと＋総合)の数は `songIds` から自動で作られる。順位ごとの個数は共通の決めごとなので、
  イベントごとに変えない(変えると全イベントに効く)
- **終わりは週の区切り(月曜5:00)に合わせる。** イベントが週をまたぐと、その記録が2つの
  週間ランキングへ割れ、「イベントで出した記録なのに今週の週間に半分しか入っていない」に
  なるため。週間ランキングは**イベント中もずっと動いている**(別のタブ)。お休みにはならないので、
  「イベントが終わると週間へ戻る」という理解は違う
- **時刻で出し入れするものに、読み込み時に1回だけ決まる値を使わない。**
  開始前に起動して開きっぱなしの端末では、その答えが永久に残る。初開催では
  `enabled` と `HIDDEN_UPDATE_NOTICE_IDS` の2つで踏み、「開催したのに会話も告知も出ない」を出した。
  時刻の判定は見るたびに数え直すこと

開始時刻より前に公開してよい。更新履歴の `visibleFrom` と告知の `notifyFrom` が時間まで止める
(この2つは**同じ時刻にそろえる**。一覧と助手の告知が同時に出はじめる)。

**イベント対象曲の譜面を作り直したくなったら、終わりと同時に入れ替える**
(2026-09-13にユーザーがそう指示した。「イベント終わると同時の時刻で最新譜面に変わるようにできる？」)。
イベント中に譜面が変わると記録が割れるので、**開催中は触らない**。かわりに
新旧どちらの譜面も持っておき(`-v3-` と `-v4-` のマーカー)、`RHYTHM_SWITCHING_CHARTS` が
時刻で選ぶ。切り替えの時刻は `data/rhythm-event.js` の `endAt` と**同じ値**にする。

- **読み込み時に1回だけ決めない。** `RHYTHM_SONGS` は起動時に1回組み立てて freeze するので、
  入れ替わる曲の `difficulties` は **getter** にして参照のたびに選ぶ
- **演奏のあいだは固定する**(`rhythmChartSwitchHold`)。曲の途中でまたぐと
  総ノーツ数とレベルだけが変わり、スコアの計算とズレる
- 旧譜面は消さない。切り替わったあとの更新で消す
- `node tools/mode/rhythm-chart-switch-check.js` を通す。
  中身は [`docs/spec/RHYTHM_MODE.md`](../spec/RHYTHM_MODE.md)
  「イベントの終わりと同時に譜面を入れ替える」

**フラグ1つを外すだけでも「譜面が変わる」。** 2026-09-18、終点フリックの置き場所が悪い箇所から
`endFlick` を外したとき、開催中の対象曲3曲(13本)を既定では外さなかった
(`rhythm-end-flick-swing-fix.js` が `heldByEvent` で避ける)。ノーツの時刻も位置も種類も変えず
フラグ1つを消すだけでも、**弾かなくてよくなる＝条件が変わる**ので同じ扱いにしている。

そのうえで、ユーザーが「まだ始まったばかりだから全部直して」と判断したので、
`--include-event` を付けて同時に外した(開催の翌日・残り3日)。
**この判断はユーザーがするもの**で、こちらから勝手に外さない。既定は避ける側のまま。
開催の終盤で同じことが起きたら、記録がもう積み上がっているので、
上の節のとおり `RHYTHM_SWITCHING_CHARTS` で終わりと同時に入れ替えるほうを選ぶ。
