# ChatGPT → Muse / Claude 引き継ぎ標準

対象: ChatGPT が実装を担当し、Muse または Claude がビルド・検査・CI修正・マージ・公開を引き継ぐ作業。共通ルールは [AGENTS.md](../../AGENTS.md) と [DEVELOPMENT.md](../../DEVELOPMENT.md) が優先。Claude固有の指示は [CLAUDE.md](../../CLAUDE.md) を尊重する。

## 目的と完了の区別

- **ChatGPT側の「引き継ぎ可能」**: GitHub上の作業ブランチに実装内容がコミット・push済みで、ブランチ名、コミットSHA、変更ファイルをGitHubから再取得して確認できる状態。ローカル保存、ローカルcommit、チャット内のコード、パッチ添付だけでは不可。
- **引き継ぎ先の「開発完了」**: 正規ビルド、必要な検査、CI成功、マージ、Pages公開確認まで完了した状態。
- 未ビルド、未テスト、CI失敗、未マージを「完成」「公開済み」と呼ばない。引き継ぎ可能と配信可能を混同しない。

## ChatGPTの作業順

1. 最新main、AGENTS.md、DEVELOPMENT.md、関連仕様を確認する。進行中のMuse/Claudeのブランチと重複・衝突しないよう変更範囲を限定する。
2. 既存の引き継ぎ対象ブランチがあればそれを使用し、なければ最新mainから `chatgpt/<task>` を作成する。作業開始時に**ブランチがGitHub上に存在すること**を確認する。ブランチを作れないときは未保存と報告する。
3. 編集元（ゲーム本体は `monster-hero/src/parts/*.jsx`）に実装する。途中でも意味のある単位でコミットし、**GitHub上へのpushを最優先**する。コミット後はGitHubからSHAと変更内容を再確認する。
4. 利用可能なら `node tools/build.js`、`node tools/build.js --check`、`node tools/run-checks.js --changed` などを実行し、実行結果を記録する。Node環境がない場合はビルドしたと偽らず、生成物未同期の可能性を明記して引き継ぐ。
5. PRを作れる場合は引き継ぎ先が参照できるように作成し、未検証ならDraftまたは未完成と明記する。**PR作成を完了条件にしない。**
6. 最終報告には下記の引き継ぎ票を必ず付ける。GitHub上に実装が存在しない場合は引き継ぎ可能と報告しない。

## Muse / Claudeへの引き継ぎ

- 引き継ぎ先は**MuseまたはClaudeのいずれか**。同一ブランチに二者同時で書き込まない。
- 指定されたリポジトリと**ブランチ・コミットSHA**をGitHubから取得し、変更内容を確認する。**最初から再実装しない**。対象ブランチが見つからない、SHAが一致しない場合は作り直す前にGitHubの状態を調査する。
- 最新mainを安全に取り込み、競合は既存の `node tools/merge-main.js` の手順に従う。ユーザーの変更や他AIの進行中作業を消さない。
- `node tools/build.js` → `node tools/build.js --check` → 必要なテストを実行し、生成物を同期してpushする。
- CI失敗時はログを調べ、原因を修正して再実行する。テスト条件を弱めて通すことは禁止。既存main起因の失敗も区別して報告する。
- CI成功を確認してマージし、GitHub Pages公開と対象コミットの反映を確認する。Claude/Museそれぞれの既存運用規則を優先する。
- 作業完了後は既存のブランチ削除ルールに従う。CI失敗や未完了を放置しない。

## 禁止事項

- GitHubへpushできていないコードを「引き継ぎ済み」と呼ぶこと。
- 他AIにブランチを指定せず、チャットの説明だけで実装を再現させること。
- 未確認のビルド・テスト・公開を成功と記載すること。
- 既存Actionsワークフローの追加、`on:` の変更、検査の無効化。
- ユーザーの承認なしに他AIの作業ブランチを上書きすること。
