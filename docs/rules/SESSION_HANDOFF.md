# 会話の区切り(引き継ぎメモ1枚 → 新しい会話)

2026-11-11 社長「トークンを無駄に使わない仕組み」(案A)。会話が長いまま続くと、返事のたびにその全部を読み直す
(窓口は数日分、部は公開を重ねた分)。区切りでメモ1枚にして、新しい会話へ替える。

## 部署は替える・窓口は要約(機械が数えて知らせる)

**要約(`/compact`)は窓口の会話だけ。部署の会話は要約しない**(台帳 2026-11-11「各部署はいまのまま(長くなったら引き継ぎメモで会話を替える)」・
2026-11-12 社長「ここ以外は要約しないんじゃないの？ 何回も同じこと言わせないでちゃんと仕組み確立させろよ」)。
前は部署にも「1段目 = 区切りで要約」があり、部署が社長に要約を頼んで決めごとと食い違った。いまは部署に要約の段は無い。

| 会話 | いつ(どちらかを超えたら) | すること |
| --- | --- | --- |
| 部署 | やりとり40回・公開5件、または仕事の種類が変わる | 区切りで引き継ぎメモ1枚 → 窓口が新しい会話を作る。要約は頼まない |
| 窓口 | **文脈が50万トークン**(そのあと5万ごと。routing.json の「窓口の要約のトークン」) | 会話は替えない。AskUserQuestion で「要約してよいか」を社長に聞き、許可されたら `/compact` の1行を出す |

`node tools/ctx.js handoff <部> --compact` は NG で止まる(部署の要約の指示文は出さない)。窓口は部署から要約を頼まれても社長に回さず、
引き継ぎメモ → 新しい会話にさせる。検査は `node tools/team/team-tools-check.js` ③(部署の知らせに要約の勧めが無いこと)。
台帳の決めごとと、フック・手引きの文が食い違っていないかは `node tools/team/decision-lock-check.js`(決めごとの錠。[`DECISION_LOCKS.md`](DECISION_LOCKS.md))が毎回見張る。

フック `tools/hooks/session-length-nudge.js`(`.claude/settings.json` の UserPromptSubmit)が、目安で1行知らせる(その後は10回ごと)。
**窓口は替えない**(2026-11-12 社長)。窓口の会話(`routing.json` の「窓口の会話」)では、フックは「替える」を出さず、**文脈のトークン数**(記録に残る返事ごとの usage)が50万を超えたら「AskUserQuestion で要約してよいかを社長に聞く」とだけ知らせる(2026-11-12 社長「トークン数で管理するんじゃないの？」。回数で数えていたので、要約のあと30回・約31万トークンで早すぎる問いが出た)。自動の要約(autoCompactWindow 700000)はそのまま。この設定は窓口の端末のユーザー設定にあるので、フックが窓口の会話でだけ値を見て、700000 でなければ知らせる(最初の頼みと、そのあと10回ごと)。
目安の数は [`tools/team/routing.json`](../../tools/team/routing.json) の「区切り」。日数・文字数ではなく「やりとり・公開の数」で数えるのは、
会話の重さがそれで決まり、会話の中から機械で数えられるから。

**数えるのは「最後の要約のあと」から**(2026-11-11 社長「そこちゃんとしてくれないと信用できない」)。要約(`/compact`・自動の要約も同じ)をすると、
会話は「要約文+そのあとのやりとり」まで軽くなる。要約の前の数まで引きずると、要約した直後でも「やりとり890回・公開222件」と出て、
もう一度の要約をすすめてしまう(窓口で実際に起きた)。フックは会話の記録から、要約の境目の行(`type:'system'`・`subtype:'compact_boundary'`)と
要約文の行(`isCompactSummary:true`)を探し、見つけたらそこまでの数を捨てて数え直す。要約の直後は0・0なので何も知らせない。
目安の数(40回・5件)は、要約のあとも同じでよい(要約のあとは「要約文+新しいやりとり」からまた重くなっていくので、
最初と同じ重さの目安で足りる)。2回目以降の要約でも、数えるのは最後の要約のあとだけ。知らせの文には「最後の要約のあと」と付く。
検査は `node tools/hooks/session-length-nudge-compact-check.js`(偽の記録で、要約の前は出る・あとは出ないを確かめる)。

- **作業の途中では替えない(窓口も要約しない)。** やりかけの仕事は先に終わらせる(公開が済んだ所が区切り)
- 大きい仕事が1つ終わって次が別の種類なら、目安の前でも替えてよい

## 窓口の要約のかけ方

`/compact` は、その会話の画面で人が打つ命令(会話が自分で自分にかけることはできない。文脈がいっぱいになったときは自動でかかる)。
窓口は AskUserQuestion で要約してよいかを聞き、許可されたら、残すもの・捨てるものを入れた `/compact` の1行をコードブロックで出す。
社長がそれを窓口の会話でそのまま打つ。

## 替える手順(部署)

**替える側(部・窓口)**

```
node tools/ctx.js handoff <部> --write     docs/progress/handoff/<部>-<日付>.md に下書きができる
```

1. 下書きの「手で書く所」だけ埋める(やりかけ・返事待ち・はまった所・窓口に頼んだまま済んでいないもの。無ければ「なし」)。
   最近の公開・残りの仕事・社長の決めごとは道具が埋めてある
2. コミットして公開する(メモだけなら検査は `node tools/run-checks.js --changed`)
3. 窓口へ send_message: 「会話を替えてほしい。メモは docs/progress/handoff/<部>-<日付>.md」

**窓口**

```
node tools/ctx.js newsession <部> "<続きの仕事>" --name <担当の名前と番号>
```

出てきた title / model / prompt をそのまま create_session に渡す(いちばん新しい引き継ぎメモの場所は、道具が依頼文に入れる)。
前の会話はそのまま置いておく(消さない)。新しい会話から前の会話へ質問しない。足りないことはメモを書き直す。

**窓口自身が替わるとき**: `node tools/ctx.js handoff hq --write` → 社長に「窓口を替える」と伝え、新しい窓口の会話を作る。
部の会話の報告先(session の番号)が変わるので、[`ORGANIZATION.md`](ORGANIZATION.md) と `tools/team/newsession.js` の窓口の番号を直して公開してから替える。

## 新しい会話が読むもの(これだけ)

1. `CLAUDE.md`(自動)
2. `docs/depts/<部>.md`(部の手引き1枚)
3. `node tools/ctx.js decisions <部>`(社長の決めごと。台帳は300KBを超えるので全文は開かない)
4. 引き継ぎメモ(あれば)

立ち上がりで読む量は合わせて約35〜50KB(仕組みの前は台帳だけで320KB。`tools/team/team-tools-check.js` が60KB未満を見張る)。
依頼文の型はこの4つと「仕事・守ること・報告先」だけ。共通の決まりを依頼文に貼り直さない(CLAUDE.md にある)。

## メモの型

`node tools/ctx.js handoff <部>` が出す形がそのまま型。見出しは「いまの状態 / 最近の公開 / 完了でない社長の頼み / 残りの仕事 / マージしていない自分の枝 / 手で書く所 / 社長の決めごと」。
「マージしていない自分の枝」は道具が自動で書く: その会話の作業中の枝・ローカルの枝・reflog の枝のうち main に入っていない物(squash なので追加行が main に何%あるかで判定)と、開いている PR の番号。**PR なしの枝は枝のまま引き継がない**(入れ直して公開するか、捨てる理由を書く。2026-11-15 ドラの寝顔の枝が落ちた)。
1枚に収める。会話の流れ・試したことの全部は書かない(次の会話が要るのは「次の1手」と「やってはいけないこと」)。
