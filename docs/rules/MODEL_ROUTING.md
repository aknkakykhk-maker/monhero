# モデルの使い分け(仕事の種類 → モデル)

2026-11-11 社長「トークンを無駄に使わない仕組み」「開発品質は落としたくない」「新しいモデルを有効活用したい」(案B・C)。
それまでは文言の直しも原因不明の不具合も、同じ高いモデルで動かしていた。

**覚えなくてよい。窓口が新しい会話を作るときに道具が引く。**

```
node tools/ctx.js newsession <部> "<仕事の文>"     create_session に渡す title / model / prompt が出る
node tools/ctx.js model "<仕事の文>"               モデルだけ引く(--failed 2 / --kind <種類> / --table)
```

正本は [`tools/team/routing.json`](../../tools/team/routing.json)(語・モデル・実例)。この表を変えるときはそちらを直す。

## 表

| 種類 | モデル | いつ |
| --- | --- | --- |
| 定期の見張り・読むだけ(`watch`) | `claude-haiku-5-5` | コードを変えない。決まった手順で読む・数える・まとめる |
| 小さな直し・文言・検査(`small`) | `claude-sonnet-5-5` | 直す場所と直し方が分かっている。1つの部の中で終わる |
| できた道具を回して結果をまとめる(点検)(`run`) | `claude-sonnet-5-5` | 点検の道具がもうある。回して、出てきた結果(問題の大きい順の上位)をまとめるだけ。直すのは別の頼みにする。読むだけで済むなら watch(haiku) |
| 段取りどおりに作る(中くらいの改修)(`build`) | `claude-sonnet-5-5` | 段取り書・スキル・前の会話の引き継ぎメモがあり、決めることが残っていない。保存データ・ランキング・Supabase に触るなら design へ上げる |
| 設計・原因不明の不具合・壊すと戻せない所(`design`) | `claude-opus-5-5` | 何を作るか・どこが悪いかから考える。または保存データ・ランキング・Supabase・複数の部にまたがる |
| 要所だけ(新機能の公開前の最終確認・2回直しても直らない不具合)(`final`) | `claude-fable-5-2` | ①新しい画面・新しい遊び方を公開の印で開ける直前の通し確認(1回) ②同じ不具合を2回直して、まだ直らない。それ以外では使わない |
| 点検・定期の仕事に使う道具を作る・強化する(1回)(`tool`) | `claude-fable-5-2` | 何度も回す点検・見張りの道具そのものを作る・強化する1回だけ。できた道具は run / watch のモデルで回す。道具の出力は小さく(要約・上位だけ・問題の大きい順) |

値段の目安: haiku < sonnet(opus の約半分)< opus < fable(opus の約2倍)。

## 道具を作るのは最新モデル、道具を回すのは安いモデル

2026-11-11 社長「今後は仕組みづくりの一環としてつくって。トークン抑えて品質維持」(全曲の譜面チェックの話)。

- **何度も回す点検・見張りは、まず道具にする。** 道具を作る・強化する1回だけ `claude-fable-5-2`(`tool`)
- **できた道具を回して結果をまとめる**点検・定期の仕事は `claude-sonnet-5-5`(`run`)、読むだけなら `claude-haiku-5-5`(`watch`)。
  例: 譜面の全曲点検(`tools/mode/` の `rhythm-chart-review.js`)・全譜面の MISS 探し・毎晩の見張り
- 回す側が道具の不足に気づいたら、自分で作り込まず窓口へ(道具づくりの会話を別に作る)

**道具を作る側の決まり(出力は小さく)**: 回す側は安いモデルで、読む量がそのまま費用になる。

- 既定の出力は「要約・件数・問題の大きい順の上位だけ」(目安 50行以内)。全部は `--all`・`--json <ファイル>` を付けたときだけ
- 最後の1行に結論(`OK: …` / `NG: … 件`)。回す側は `2>&1 | tail -20` で足りるように
- 続きの見方(どのオプションで詳しく出るか)を最後に1行出す。先頭に「何をするものか」のコメント(`node tools/ctx.js checks` が引く)

## 安いモデルを使ってよい条件・上げる条件

2026-11-11 社長「弱いモデルを使うのは、それでも問題ないときね」。**安いモデルは、品質が落ちないと分かっている仕事だけ。迷ったら上のモデル。**

| 安いモデル(sonnet・haiku)でよい条件(全部当てはまること) | 上げる条件(1つでも当てはまれば) |
| --- | --- |
| 直す場所と直し方が分かっている(判断がいらない・小さい) | 判断や設計が要る → `claude-opus-5-5` |
| 道具の結果が決まった形で出る(回してまとめるだけ) | 結果がおかしい・道具の答えと画面が合わない → `claude-opus-5-5` |
| 間違えても検査(`run-checks.js --changed`)で止まる | 2回やってうまくいかない → `claude-opus-5-5`、それでも直らなければ `claude-fable-5-2` |
| 保存データ・ランキング・Supabase に触れない | 壊すと戻せない所に触れる → `claude-opus-5-5` 以上 |

安いモデルの会話が仕事の途中で「上げる条件」に当たったら、自分で続けず窓口へ知らせる(窓口が上のモデルの会話を作る)。

## 決め方(道具の中身)

1. 仕事の文に「最終確認」「2回直しても」などがある、または `--failed 2` → `claude-fable-5-2`。「道具を作る・強化する」「仕組みづくり」も → `claude-fable-5-2`(`tool`)
2. 「保存データ・移行・ランキング・Supabase・SQL・`mh_`」のどれかがある → 必ず `claude-opus-5-5` 以上(壊すと戻せないので、ほかの語が何でも下げない)
3. それ以外は、当たった語がいちばん多い種類。**同点なら高いほう。何も当たらなければ(分からない仕事)`claude-opus-5-5`**
4. 道具の答えが合わないと窓口が思ったら `--kind` で決めてよい(上げる方向は自由。下げるのは上の「安いモデルでよい条件」が全部当てはまるときだけ)

## 要所だけ `claude-fable-5-2`(案C)

使うのは次の3つだけ。ふだんの会話には使わない。

| いつ | だれが呼ぶ | どう呼ぶ |
| --- | --- | --- |
| 新しい画面・新しい遊び方を、公開の印で開ける直前の最終確認(1回) | `node tools/ctx.js gate` が「確認のモデル: claude-fable-5-2」と出したとき、窓口がミハリの会話を作る | `node tools/ctx.js newsession kensa "<何の最終確認か>" --kind final` |
| 何度も回す点検・見張りの道具を作る・強化する(1回) | 窓口 | `node tools/ctx.js newsession <部> "<何の道具か>" --kind tool` |
| 同じ不具合を2回直して、まだ直らない | 直していた部が窓口へ知らせる(3回目を自分でやらない) | `node tools/ctx.js newsession <部> "<不具合>" --failed 2` |

終わったらその会話は閉じる(続きの小さな直しは、いつものモデルの会話へ戻す)。

**この3つから外れて `claude-fable-5-2` を使いたいときは、窓口が社長に選択式で聞いてから使う**
(2026-11-11 社長「Fable を使うときは、決まりから外れている場合は俺に聞いてね」)。聞かずに使わない。
`node tools/ctx.js newsession` は、モデルが `claude-fable-5-2` になるとき、当てはまる条件を出して確かめさせる。

## いま動いている会話は

モデルは会話を作るときに決まる(途中で替えない)。いま動いている部の会話は、区切り
([`SESSION_HANDOFF.md`](SESSION_HANDOFF.md))で替えるときに、この表のモデルで作り直す。

窓口(統括部長)の会話そのもののモデルは、この表では決めていない(社長と窓口が決める)。窓口の仕事は
「振り分け・台帳・報告のまとめ」なので、種類でいえば「小さな直し・読むだけ」に近い。
