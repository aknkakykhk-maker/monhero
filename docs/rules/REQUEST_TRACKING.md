# 社長の頼みの追跡表(頼んだ先と、できたかを完了まで追う)

2026-11-14 社長「なんかお願いしたのに漏れてるの多いのは何で?」。

## なぜあるか

もれの原因は3つあった。

1. 決めごとは台帳([`PRESIDENT_DECISIONS.md`](PRESIDENT_DECISIONS.md))に書いていたが、**「どの部に頼んだか・できたか」を追う物が無かった**
   (例: 11/13「大会の賞品にビートP」は台帳にあるのに、受けた会話が区切りで替わり、引き継ぎメモに載らず消えた)
2. 会話の区切り(引き継ぎメモ)・窓口の要約で、小さな頼みが落ちた
3. 窓口が止め絵を決まりに照らして見る手順が無かった(言葉の途中の折れ・下の空きを見落とした)

前の頼みの台帳(`docs/playbot/dashboard/ledger.json`)は手で書く物で、10/22 から更新が止まっていた。
今度は**台帳の行を機械で表に取り込み、取り込み忘れは検査で止め、頼みは道具が毎回出す**。人が覚えて追う物にしない。

## 仕組み

| もの | 役目 |
| --- | --- |
| [`tools/team/requests.json`](../../tools/team/requests.json) | 追跡表(正本・1件1行)。**手で開かない・手で直さない**(100KB を超える) |
| `node tools/ctx.js todo` | 完了でない頼みの数(部ごと)と、先に見る物(未依頼・止まっているかも★) |
| `node tools/ctx.js todo <部>` | その部の完了でない頼み(未依頼が先・古い順) |
| `node tools/ctx.js todo sync` | 台帳に足した行を表へ取り込む(状態は未依頼。頼んだ先は行の末尾の「(窓口経由・クラフト12)」から読む) |
| `node tools/ctx.js todo set <id> <状態> [--to 名前] [--pr 番号] [--memo "…"] [--dept 部]` | 状態を変える(id は「,」でつなげて何件でも) |
| `node tools/ctx.js todo add "<中身>" --dept <部> [--to 名前]` | 台帳に載らない小さな頼みを1件足す |
| `node tools/ctx.js todo show <id>` / `find <語>` | 1件の全部(台帳の行も)/ 中身から探す |
| `node tools/ctx.js asked <語> [<語>…]` | **社長に聞く前に打つ。** その語が入った台帳の決めごとを新しい順に短く出す(追跡表の id と状態つき。上書き済みは古い決め)。もう決まっていれば聞かずに進める |
| `node tools/ctx.js stale-branches` | **窓口の見回りで毎回打つ。** 直近7日に動いた枝のうち、本体(`src/parts`・`data`・`images`)を変えたのに main に入っていない物(マージ済み PR の枝・【保留】【β公開の日にマージ】の PR は除く)を、件数と新しい順の上位10件で出す。PRなし★は OK済み の頼みに当たらないか確かめる |
| `node tools/team/requests-check.js` | 見張り(いつも回る)。表の形・取り込み忘れ・古い印・道具から頼みが出ること |

1件の項目: `id`(r<月日>-<連番>)・`日付`・`台帳`(台帳の行の印)・`中身`・`部`・`会話`(頼んだ先の名前)・`状態`・`PR`・`メモ`・`更新`。

状態: **未依頼 → 依頼済み → 作業中 → 確認待ち → OK済み → 完了**。**OK済み**=社長が止め絵や案に OK を出した・まだ公開していない(閉じない)。**OK済み・確認待ちは、PR が無い・PR がマージされていない間は ★(`★PR無し`/`★PR未マージ`)を出し続ける**(マージ済みかは `git log origin/main` の「(#番号)」で判定。2026-11-15 ドラの寝顔が OK のあと枝のまま本番に入らなかった)。ほかに **止め中**(優先順位などで一時止めた・閉じない。いつも ★ で出続ける。止めた理由をメモに。**止めるときは台帳の行で済ませず、必ずこの状態にする**: 2026-11-12 に「止めたもの」を進め方の行に書いただけで追跡表に入れず、フレンドの家から対戦の入口が3日落ちた)と **やめた**(社長がやめた・理由をメモに)と
**上書き済み**(後の決めごとで変わった。新しい方の id をメモに)。完了にするには PR の番号か、確かめた所のメモが要る
(できたことを確かめずに完了にしない)。依頼済み・作業中・確認待ちのまま2日を超えると ★ が付く(止まっていないか窓口が確かめる)。

**自動で出る所**(見張りが確かめる):

- 新しい会話の依頼文(`newsession`)に「■この部の完了でない頼み」(上位6件と残りの数)
- 引き継ぎメモ(`handoff`)に「完了でない社長の頼み」
- `brief` に完了でない数
- 窓口の「会話が長くなってきた」の知らせに完了でない数(要約の前に `todo` で確かめる)

## 窓口の流れ

1. 社長が決めた・頼んだ → 台帳に1行足す(いままでどおり。足すだけ・消さない・書き換えない)→ **`node tools/ctx.js todo sync`**
   (台帳に書くほどでない小さな頼みは `todo add`)。同じ PR に入れる。入れないと見張りが NG で止める
2. 部へ頼んだ → `todo set <id> 依頼済み --to <会話の名前>`
3. 部から報告(済ませた頼みの id と PR 番号が付いてくる)→ 本番か止め絵で確かめて `todo set <id> 完了 --pr <番号>`。
   社長の確認が残るなら `確認待ち`
4. 区切り・要約の前、社長に「全部できた」と言う前に `node tools/ctx.js todo` を打つ(未依頼・★ を残さない)
5. 窓口が自分で済ませた記録の行(配り直しなど)は `todo set <id> 完了 --memo 記録`

部の会話は、自分の部の頼みを `node tools/ctx.js todo <部>` で見る。済ませたら**報告に id を書く**(表の状態は窓口が変える。
部が `作業中` にするのはよい)。

## 窓口の止め絵の点検

部から止め絵が届いたら、社長に見せる前に **`node tools/ctx.js still <絵…> --screen <画面の語>`** を打つ。
道具は ①**空きの帯**(横1行がほぼ1色の行が 48px を超えて続く所)を測り ②絵を3つに切って拡大した切り出しを作り
③その画面の参考(REF-MAP の行)と台帳の決めごと(追跡表の行)を並べる。そのうえで、5つ全部を見る。

1. **言葉の途中の折れ**: 拡大した切り出しを1枚ずつ開き、行の終わりが言葉の途中・1〜2字だけ落ちた行が無いか
2. **下の空き**: 中身のいちばん下とボタンの列のあいだは 48px まで([`MONSUC_UI.md`](../spec/MONSUC_UI.md) 1)
3. **数字のそろえ方**: 見せ場の数字は真ん中・右寄せの数字は無し・3けたごとの「,」・差は +12 / −12(同 2)
4. **参考との比べ**: [`REF-MAP.md`](../reference/line-mf/REF-MAP.md) のその画面の行を引き、参考の実物を開いて比べる
5. **台帳の決めごととの突き合わせ**: その画面の決めごとを1行ずつ絵に当てる(`todo find <語>`・`decisions --grep <語>`)

1つでも外れたら、社長に見せずに部へ返す。小さいままの絵を眺めて通さない。
言葉の途中の折れは絵からは機械で数えられないので、画面を撮る側の道具(部の検査)で数える形に寄せていく。

## 台帳との関係

- 台帳は**決めたこと**の正本、追跡表は**頼んだ先と進み具合**の正本。台帳の行は消さない・書き換えない
- 進め方の決めごと(「<日付> 進め方:」)は錠([`DECISION_LOCKS.md`](DECISION_LOCKS.md))が受け持つので、追跡表には入らない
- 表に入るのは台帳の 2026-11-15 からの行の全部と、2026-11-09〜11-14 のモンサクの行(Fable が1件ずつ突き合わせた分)
