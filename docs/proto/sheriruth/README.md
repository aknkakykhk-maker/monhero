## 直したこと(2026-10-10 15:40)

比較動画の左右のずれを直した。最初は「参考動画の時刻 = 曲の時刻 + 0.27秒」としていたが、相関の向きを取り違えていた。
正しくは **参考動画の時刻 = ゲームの音源の時刻 − 0.414秒**(オンプくんが6区間で測った値。元の mp4 の音とでは −0.38秒、差の 34ms はゲームの音源の頭の遅れ)。
試作の譜面は、この誤ったずれで動画を読んだので、2本のアークの始まりが参考より約2拍早い(照合の結果は r2610101500sheri の返信)。

| どこ | 何 |

### 空中のタップの見た目の案(16時)

### 押せる形・奥行き・止まって動く(16時台・社長「現実的に押せる配置に見えない」「奥行き感」「画面が止まって動く演出」)

- 譜面は「押せる形に間引いた版」(オンプくん・交わらない版から): 親指2本のモデルで、押せない・間に合わない・指の交差・同じ手の地上⇄空中1拍未満がすべて0。94ノーツ・MASTER Lv.37(交わる版は131ノーツ・Lv.54)
- 人の指のくせのボット(`human.js`・thumb/lean/normal)で MISS 0/1/0。ただしボットの指はすり抜けるので、交差や届きの判断は手のモデルの一覧のほうを使う
- 直したこと
  - 空中の指の横の位置: 判定ラインより上を押した指は、すべて判定ラインの高さの道幅で測る(奥の狭い道幅で測って、端の空中のノーツから外れていた)
  - 空中と地上の受け付けを重ねた: 空中のノーツは地上の線の3.5%上まで、地上のノーツは空中の線の5%下から。あいだは両方を受け付けて、時刻と位置の近いほうを取る
  - ボットの空中の押し方: 親指の「下を押すくせ」を空中にもそのまま足すと、地上の線より下を押していたので、空中では空中と地上の間の45%までに抑えた(ボットの側の直し)
- 奥行き感: 空中の面(道と同じ台形を空中の高さへ持ち上げた面・金色の縁・手前の両端に地上から立ち上がる点線の柱)。判定の文字は空中の段がある曲だけ小さく薄く
- 止まって動く(ドライバーくん): 譜面の `scrollChanges`(試作の曲だけ `[[6460,0],[6866,1.8],[7515,1]]`)。見た目の位置だけ変わり、判定の時刻は音楽どおり。表が無い曲は計算が同じ。止まる区間のノーツ2つは抜いた
- 改善部の確かめ(P1〜P3)で直した: 空中のタップを地上の板と同じ幅に(見た目だけ1.5倍・当たりの幅は2のまま)・棒を短く薄く / 空中の面を画面が測った判定ラインの高さで毎回計算(手前の端が SKY の線にそろう)/ 区間1の2本は左手0〜2・右手3〜5へ縮めて写した(見た目でも入れ替わらない)
