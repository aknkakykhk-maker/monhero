- 分析の API: 止め絵20枚+窓の作りの説明で「画面の作り」を1本、項目の文(直近40件+タブごとの代表・数字の統計)で「文」を1本。claude-opus-5-5・effort xhigh・バッチ
  - 答えの原文: [`api-a-screen.md`](api-a-screen.md)(画面)・[`api-b-text.md`](api-b-text.md)(文)

## 文の決まりの案(changelog-help-update スキルへ)

- 題は30字を目安に40字まで。題に「／」を入れない(閉じた札で題をつなぐ印と紛れる)
- イベントの題の頭は【予告】【開催中】【終了】の3つにそろえる。副題は題に入れず、1つめの箇条へ
- 不具合の題は「〔場所〕で、〔正しい様子〕になりました」にそろえる。「〜の修正」のような作業の名前で止めない
- 箇条は1項目3〜5個(イベントでも8個まで)。1つの箇条には1つの事柄、100字まで。超えるときは項目を分ける
- 難易度ごとの数は組にする(「EASY Lv.8(448ノーツ)／…」)。並べて順番で合わせる書き方にしない

悪い例 → 良い例(実際の題から)

| 今 | 案 |
|---|---|
| 助手イラスト（ソラシド）の修正 | ソラシドの全身イラストの表情が、元の絵に戻りました |
| 【期間限定】咲かせて！ハナウタ・ノート ～花の3人、曲づくりに夢中！～ を開催します | 【予告】『咲かせて！ハナウタ・ノート』を開催します |
| モンヒロビートの結果の画面で、スコアや MARVELOUS などの数が滑らかに数え上がるようになりました | モンヒロビートの結果画面で、数がなめらかに数え上がるようになりました |

## API の指摘の確かめ

| API の指摘 | 確かめ | 案にしたか |
|---|---|---|
| 開幕・予告の項目に NEW が無い | 当たり。札の項目を更新情報の未読から外す作り(60-app.jsx 3466行) | 小2 |
| 状態の札が場所で違う(更新情報「開催中」・イベントタブ「開催予定」) | 当たり。20077行が開始前を見ていない。🎃 も固定 | 小1 |
| 入口の名前と印が3通り | 当たり(止め絵) | 小5 |
| 絵が大きすぎる・横で一覧が埋まる | 当たり(止め絵) | 小3 |
| タブレットで窓が小さい | 当たり。CSS で 440×760 に止めている | 小4 |
| 開幕が「その他」の札に入る | 当たり(group:'other') | 小6 |
| 不具合タブの札がタブ名と同じ | 当たり(止め絵) | 小9 |
| イベントタブの「!」が、開くと消える | 決めたとおりの動き(イベントタブを見たら既読)。直さない | ― |
| タブレットで「仲良し度 +2」の知らせが暗幕より前に出る | 見えたが、更新履歴の外の話。窓とは重ならない | ― |
| 文の点検で「issue の例が抜粋に無い」 | こちらの抜き出しの漏れ(直近40件と重なる分を除いたら空になった)。不具合の文の決まりは fix の例だけで作った | ― |
| 呼び名の揺れ(きせかえ/着替え など) | 「着替え」はダイヤショップの売り場の名前で、わざと分けている所もある。そろえるかは要相談 | 入れていない |
| 題の頭がばらばら・作業の名前止め・新曲の数字の並べ方 | 当たり(changelog.js の実物) | 文の決まり |

ほかに自分で見つけた事: 11/11 の「譜面制作ツール『MHB CHART ENGINE』の強化に合わせて…」は、題に作る道具の名前が入り、箇条が46個(1箇条796字)。分けるか表にした方が読みやすい。
撮影の種のせいで、11/23 のモンヒロビートの札に「16件 NEW」が出ている(時刻で出す項目の既読の直しが種で走った)。実際の遊び手の様子とは違うかもしれないので、案には使っていない。
