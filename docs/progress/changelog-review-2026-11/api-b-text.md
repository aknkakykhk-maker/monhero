# 「更新履歴」の文の点検

## 前提
- **止め絵は届いていません。** 根拠は changelog.js 抜粋の文だけです。各指摘の［なし・日時］は「止め絵なし／抜粋のその日時の項目で確認」という意味です。
- 画面の見え方(閉じた札に何件覗くか、どこで折れるか)は、すべて**要確認**です。確認に要る止め絵は「閉じた札の一覧」「開いた長い札」「不具合情報タブ」の3枚です。
- 抜粋の「不具合情報の直近8件」は空で、「イベント直近5件」は2件しかありません。issue の項目は1件も見えないので、issue に関わる話はすべて要確認です。

## A. 所見

### 観点2 題名の長さ・そろい方
1. **約50字の題があります。** 「モンヒロビートの結果の画面で、スコアや MARVELOUS などの数が滑らかに数え上がるようになりました」と「曲の鑑賞で、MARVELOUS などの文字とコンボ数を別々に切り替えられ、操作を隠せるようになりました」です。中央値28字のほぼ倍で、閉じた札の2行をこの1件で占めるおそれがあります(要確認)。［なし・11/24 22:37, 19:34］

## C. 文の書き方の決まり(案)

### 題名
- 長さは30字を目安に、40字まで。英字の画面語は1つまでにします。
- 「／」は閉じた札のつなぎに使われるので、題には入れません。
- 更新の型：「〔場所〕で、〔何〕が〔どうなりました〕」。新しい物は「〜を追加しました」「〜が並びました」。期間つきの変化も完了形で書き、期間は本文に回します。
- イベントの型：「【予告】『名前』を開催します」「【開催中】『名前』がはじまりました」「【終了】『名前』が終わりました」。副題は本文の1箇条目に入れます。

### 箇条
- 数は1項目3〜5個、イベントでも8個までにします。超えるときは項目を分け、別項目にある事は1行の案内で済ませます。
- 1箇条には1つの事柄だけを書き、60字を目安に100字までとします。数の列は1箇条に1組までにして、100字の上限からは外します。
- 1箇条目には「いつ・どこで・何が変わるか」を書きます。最後の箇条には「遊ぶ人がする事」(止め方、買い直し不要など)を書きます。作り方(切る・畳む・作り直す)は書きません。

### 不具合情報
- fix の型：題は「〔場所〕で、〔正しい状態〕になりました」、本文1箇条目は「〜ことがあったのを直しました」。本文が「直しました」の項目は fix に置きます(いまのタブの決まりは要確認)。
- issue は実例が見えないため要確認です。案としては、題「【調査中】〔場所〕で〔起きていること〕」とし、本文に避け方と「直ったらお知らせします」を書きます。

### 長い数字
- 名前と数を隣に置きます(例：「HELL Lv.45（1,186ノーツ）」)。別の箇条にある数を順番で対応させる書き方はしません。
- 4桁からカンマを付け、単位は数の後ろに置きます(1,000ビートP)。
- 日時は「11/28(土) 10:00」の形にそろえます。

### 悪い例→良い例
1. 「助手イラスト（ソラシド）の修正」→「ソラシドの全身イラスト（表情）が元の絵に戻りました」。あわせて、何が違って見えていたかを本文に1文足します(中身は要確認)。
2. 「【期間限定】咲かせて！ハナウタ・ノート ～花の3人、曲づくりに夢中！～ を開催します」→「【予告】『咲かせて！ハナウタ・ノート』を開催します」
3. 「モンヒロビートの結果の画面で、スコアや MARVELOUS などの数が滑らかに数え上がるようになりました」→「モンヒロビートの結果画面で、数がなめらかに数え上がるようになりました」(約50字→34字)
4. 「原曲のレベルは EASY Lv.8 ／…／ HELL Lv.45 です。」と「原曲のノーツ数は 448 ／…／ 1186 です。」→「原曲 Lv.（ノーツ数）：EASY 8（448）／NORMAL 10（530）／HARD 15（736）／EXPERT 28（1,155）／MASTER 33（1,257）／HELL 45（1,186）」(開いた札での折れ方は要確認)
