## はまった所・やってはいけないこと

- **検査の多くが、本体の行を文字どおり探している。** `processTurn`・`handleEnemyTurn`・`getDmg` の行を書き換えると、関係なさそうな検査(`damage-parity`・`poltz-assist`・`tactics-enemy-actions`・`extreme-challenge` など)が落ちる。B では9本落ちて目印を直した。C で行を動かすときは、先に `node tools/ctx.js checks <語>` と `grep -rn "<その行の一部>" tools/` で見ている検査を探す
- `run-checks.js --changed` は415本・10〜25分かかる(ブラウザの検査が長い)。裏で回して、そのあいだは別のことをする。作業コピーを2つ使うときは、ブラウザの検査を同時に回さない(同じポート 8899)
- マージ済みの作業ブランチを main に合わせる強制プッシュは、権限の判定で止められる。main を取り込む(ふつうのマージ)でそろえる
- スカッシュでマージしたあと、その上に積んだ別ブランチへ `merge-main.js` をかけると本体でぶつかる。自分のコミットだけを新しい main の上へ `cherry-pick` で乗せ直す(生成物は main 側を採ってビルドし直す)
- マージの直前に main が進んでいると 405(コンフリクト)で断られる。`merge-main.js` → 要の検査 → プッシュ → もう一度マージ
- 計測の道具(前の会話が使ったもの)はリポジトリの外にあり、もう残っていない。C の前後は `tools/battle/battle-feel-perf.js` で測る(テゴタエへ頼み済み)
