## 出したもの(すべてマージ済み)
- **#5256 マルチの招待リンク**: ビートの共有ボタンが `?beatRoom=コード`、カードの部屋に「リンクをフレンドに送る」の `?cardRoom=コード`。引数は読んだらすぐ URL から消し、新キー `mh_pending_room_link_v1`(3時間で捨てる)に預けて、起動の流れ・はじめての案内が済んだ HOME で部屋へ入る(`60-app.jsx` の `pendingRoomLink`・`mhRoomLink*` は `77-screen-rhythm-multi.jsx`)。カードが未解放の人には「まだ開いていません」の帯。iPhone のホーム画面アプリは保存領域が Safari と別なので、リンクは Safari で開く(アプリ側はコードを打って入る)
- **#5359 観戦(譜面つき)・#5412 その直し**: 設計 `docs/progress/beat-multi-spectate/PLAN.md`・仕様 `docs/spec/RHYTHM_MULTI.md`「観戦」・検査 `node tools/mode/rhythm-multi-spectate-check.js`(`MH_PLAYERS=5` 5人・`MH_PORTRAIT=1` 縦・`MH_MEASURE=1` 重さの表)。保存は新キー `mh_rhythm_multi_spectate_v1` だけ

## 観戦の作り(要点)
- 見る人は部屋のメンバーではない(`hb` を送らない・10人まで・結果/報酬/ランキングに入らない)。入口は ①フリーマッチの窓の「演奏中の部屋」の一覧(`wroom`・フレンドは🤝で先頭) ②誘われて入ったら演奏中だった待機のメンバー。フレンドのプライベートの部屋は外から見せない
- 送る側: 見られている1人だけ、ループの外の1秒ごと(`watchSend`)。演奏のループの中は `RHYTHM_PLAY_WATCH.jd`(見られていなければ null)への push と `frames++` だけ(30-rhythm-play.jsx。ドウキ・ズレに連絡済み)。重い端末(40枚/秒を切る状態が2秒)は譜面をやめて数字だけ
- 見る側: `RHYTHM_WATCH`(store)・`RhythmWatchScreen`・`RhythmWatchLane`(canvas・1.5秒遅らせて流す)。ミラー譜面の人のレーンは左右逆に見える
- 「👁 観戦を許す」を切っても、切った人の名前・順位・スコアは見える(隠れるのは譜面・判定の数・ライフ)。社長が「文を直す」(案A)を選んだ。更新履歴・ヘルプはそのとおり

## 残り・気をつけること
- 本番で見る所(社長の実機): ①フリーマッチの窓に「演奏中の部屋(観戦できます)」が出て「観戦」で入れる ②名前を押すと譜面と判定が流れる ③誘われて入ったら演奏中だった人に待機のあいだ観戦の画面が出る ④「観戦を許さない」にすると外の人から見えない ⑤曲の紹介のあとでも譜面が出る(フレームが進まない間は重いと数えない直しを入れた) ⑥iPhone で演奏する人の端末が重くならない(縦・横)
- 既存のNG(この仕事と無関係): `rhythm-judgment-line-height-check`(main にも出る)・`card-battle-browser-check`(助手ライフの保存キー)・`assistant-bond-check`(助手の行動表)
- ナラビ(札 `pg`)・テンポ・ドウキ・ズレとは、上の3か所の連絡で足りている。次に `liveSend` / `liveReceive` / `pg` の形を触るときは、先に観戦(`p`・`k`・`l`・`j`・`lt`)を壊さないこと
- 作業のあとで直す案: ミラー譜面のレーン反転・曲の位置の合わせ(いまは試聴の鳴らし方)・本物の Realtime での量(観戦10人・演奏5人)
