# MFバトルカードの軽量化(カード部カルク・2026-11-11)

社長の「新モデルでやるべきこと」5位。狙い: スマホで長く遊んでも重くならない。見た目と遊び方は変えない。

## 測り方

`node tools/card/card-perf-measure.js`(縦 390×844・CPU 4倍遅く=スマホのつもり)

- ① フリー対戦(ほかのブリーダーとオート・×4)を30回 ② 画面の行き来(カードの部屋 → 対戦 → 助手えらび → デッキえらび → 助手と対戦して投了 → 結果 → トップ → HOME → カードの部屋)を30回
- 回ごとに GC をかけてから、JS のメモリ・DOM の数・受け口・タイマー・画像の読み込み・長いタスク/長いコマ(LoAF)を記録
- `PERF_PROFILE=1` で CPU プロフィール、`PERF_ANIM=1` で対戦中のアニメ、`PERF_NET=1` で立ち絵の頼み元
- 数字の生データ: `before-portrait.json`

## 直す前の数字(30回ずつ・はじめの3回 → おわりの3回)

| 見るもの | 対戦 30回 | 行き来 30回 | 判定 |
| --- | --- | --- | --- |
| JS のメモリ | 32.9 → 33.2MB(+0.01MB/回) | 33.8 → 34.9MB(+0.04MB/回) | 持ちっぱなしは無い(ほぼ横ばい) |
| DOM の数 | 314 → 246 | 325 → 327 | 増えない |
| イベントの受け口 | 433 → 432 | 449 → 449 | 増えない |
| setInterval / rAF | 11 / 1 で一定 | 11 / 1 で一定 | 残りは無い |
| 画像の読み込みの記録 | 1回の対戦で約85件(全部キャッシュから・通信0) | 1回で約40件 | 同じ絵の読み直し・展開し直し |
| 長いタスク | 1回の対戦で 4〜18件・合計 250〜1300ms | 1回で 5〜11件・最大 450ms | 下の原因 |

→ 長く遊んで「たまって重くなる」ものは見つからなかった。重さは毎回の処理の重さ(1コマ・1押し)から来ている。

## 原因の一覧(証拠の数字つき)

| # | 原因 | 証拠 | 場所 |
| --- | --- | --- | --- |
| 1 | 対戦の盤が描き直されるたびに、依存なしの useLayoutEffect が `scrollHeight`/`getBoundingClientRect` を読み、レイアウトを毎回強制する | 対戦1回の CPU プロフィールで自分の時間 1714ms(JS で1位) | 84 `CardBattleBoard` のまんなかの欄の合わせ(stageFit)・盤の合わせ(boardFit) |
| 2 | 字の大きさ合わせが 0.5px ずつ縮めて、そのたびに `scrollWidth` を測る(14→9px で最大10回) | 対戦1回で 663ms(JS で2位) | 84 `CardFitLabel` の `fit` |
| 3 | 場の立ち絵(1024×1536 の PNG・展開すると1枚約6MB)を、技・被弾・よけ・守りの動きのたびに `key` で作り直し、キャッシュから読み直して展開し直す | 1回の対戦で同じ立ち絵を 3〜9回ずつ読み直し(1種につき)・合計約85件 | 84 場のモンスター(`key={mv ? mv.key : 'still'}`)・残像・技の演出・光る型抜き |
| 4 | 助手えらびで AI のデッキを組むとき、`cardAiMonWave` が呼ばれるたびに全モンスターを線形に探す | 行き来1回の CPU プロフィールで 282ms(JS で1位)+ `cardAiMonScore` 74ms | **82**(ルール本体)`cardAiMonWave` |
| 5 | 相手えらびを開くたびに、助手8人の顔を読み直す | 行き来1回で顔 8〜16件 | 84 相手えらび |

見たが問題なかったもの: 対戦中のアニメ(30本。ほとんど transform/opacity で合成処理向き)・タイマーと受け口の片付け(どれも外している)・裏の事前ダウンロード(fetch でキャッシュへ入れるだけ。メモリに持たない)。
