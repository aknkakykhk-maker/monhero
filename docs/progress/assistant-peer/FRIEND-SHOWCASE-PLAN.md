# フレンドの家で、その人の助手のマスモン(とデッキ)をくわしく見る(案・第2版)

2026-11-11 オトズレ。社長「フレンドの部屋に行ったときにマスモンとかデッキとか見れないんだっけ？詳細的な」→「自分のと同じぐらい見れるようにして」
→「マスモンって助手ライフのほうね」「(デッキも)これも助手マスモンのこと」。

第1版(プレイヤー本人のマスモン・デッキ)は対象違いのため取り下げ。

止め絵: `friend/showcase-masmon-tate.jpg`(① 部屋から開く ② マスモンのタブ ③ 1体の詳しい画面 ④ デッキのタブ)/差の表: `friend/showcase-masmon-diff.jpg`

## 決まったこと(窓口経由・社長)

- 送り方: 変わったぶんだけ送る
- 見せる設定の既定: はじめは入

## 1. いまの差

自分の助手ライフでは、部屋のシートの「🐾 マスモン」(`AssistantMasmonSheet`)で 4つのタブ(🐾 マスモン / ⚔ 編成 / 🃏 デッキ / 💗 好み)と、
1体の詳しい画面(`AssistantMasmonDetail`: 能力・育ち方・育て方・技・染めた色・選んだ理由・思い出)が見られる。
フレンドの家では、控え(`alfBuildMore` の `ms`)に入っている **種類・ニックネーム・染め色・勇者モンの印(助手ごと8体まで)** だけで、部屋を歩く絵と名前しか出ない。

| 見られるもの | 自分 | フレンドの家(いま) | 案 |
| --- | --- | --- | --- |
| 種類・ニックネーム・染め色・勇者モン | ○ | ○ | そのまま |
| Lv・育ち方(型)・育て方 | ○ | × | 送る |
| 6つの能力 | 数字と棒 | × | 送る(数字か棒かは選ぶ) |
| 技 | ○ | × | 種類と Lv から見る側で出す(送らない) |
| 編成(勇者モン・仲間・型) | ○ | × | 送った中身から見る側で組む |
| MFバトルカードのデッキ(推し・好き・素顔) | 3つの中身 | × | 3つの中身を送る |
| これまでのデッキ | 10個まで | × | 名前だけ / 出さない(選ぶ) |
| 好き・苦手・好きな色 | ○ | × | 助手ごとに決まった表なので見る側で出す |
| 選んだ理由のひとこと | ○ | × | 送る(40字まで・置き手紙と同じ見張り) |
| 迎える前の「？」の枠 | ○ | × | 数だけ |
| 思い出・今日の育成の記録・疲れ・ストレス | ○ | × | 出さない |
| 提案・育てる・チケット・名前の付け直し | ○ | × | 出さない(見るだけ) |

## 2. 送るもの・大きさ

- マスモン1体: 種類・名前・色・枠・勇者・Lv・型・育て方・6能力・理由 → 約150字。助手8人×5体で 約6KB
- デッキ1つ: 名前・ひとこと・3体・切り札・カード(id×枚数)→ 約350字。8人×3つで 約8.5KB
- 合わせて約15KB。いまの控え(1人6000字まで・`ALF_MORE_MAX_CHARS` と表の決まり `alf_more_size`)には入らない → **新しい表を足す**(既存の表・列は変えない)

## 3. 作り(案)

- 表 `alf_masmon_share`(ブリーダー × 助手 で1行: マスモンの JSON・デッキの JSON・更新時刻。大きさの決まり付き)。足すだけの SQL は窓口へ
- 端末は「前に送った中身の指紋」を新しい保存キー `mh_alf_masmon_share_sent_v1` に持ち、**変わった助手の行だけ**送る。起動の1分後と、変わってから最短10分。見えていないあいだは送らない
- 見せる設定: 新しいキー `mh_alf_masmon_share_show_v1`(既定は入)。切ったら送らず、自分の行を消す。見る側には「この人は見せていません」
- 見る側: フレンドの家の部屋のシートに「🐾 ◯◯のマスモン ›」。押すと自分の助手ライフと同じシート(4つのタブ)を**見るだけ**で開く。読むのは開いたときに1行だけ
- 古い版の相手・表が無いとき: いまの絵と名前だけを出す(今までどおり)。受け取った JSON は型を確かめ、知らないモンスター・カードは捨てる

## 4. ほかの部とぶつかる所(読むだけで使う口)

- **キズナ(助手マスモン)**: `assistantLifeMasmonTeamOf` は 種類・名前・色・勇者 だけを返す。Lv・型・育て方・理由・枠は `assistantMasmonPlanOf` の行、6能力は `amgEntryOf`(育成基盤・公開の印 `assistantMasmonGrow`)から読む必要がある。
  キズナ側に「フレンドに見せる1体の形」を返す口(例 `assistantLifeMasmonShareOf(id)`)を足してもらうか、こちらで上の口を読むだけにするかを決めたい(おすすめ: キズナの口を足してもらう。形が変わったときに壊れにくい)
- シートの見た目: `AssistantMasmonSheet` / `AssistantMasmonDetail` は自分の保存を読む作り。見るだけの形(相手の中身を渡す・ボタンを出さない)に分けるには、キズナの部品に「見る専用」の口が要る
- **カード部(ツナグ)**: 助手のデッキは端末ごとに組まれる(`cardAiDeckChoices`・`mh_card_ai_deck_v1`)ので、相手の中身は送ってもらうしかない。中身を見せる `CardAssistantDeckView` は who と型から自分の端末のデッキを読む作り → 相手のデッキを渡して見せる口が要る
- **タイセン(マスモン対戦)**: フレンド対戦に登録した編成は、すでにサーバの表に能力入りで載っている。ただし登録した人・助手だけで、見せる目的でもないので、今回は別の表にする(対戦の表は読まない)

## 5. 決めてほしいこと(おすすめが先頭)

1. デッキの範囲: **いまの3つ(推し・好き・素顔)の中身だけ(推奨)** / これまでのデッキの名前も / これまでのデッキの中身も
2. 6つの能力の見せ方: **数字まで(推奨・自分と同じ)** / 棒だけ(フレンド対戦の手の内が見えすぎないように)
3. 口の作り: **キズナ・ツナグに「見る専用」の口を足してもらう(推奨)** / オトズレが読むだけで組む

## 6. 作るとき

- SQL(表1つ・足すだけ)は本文を窓口へ
- フレンドに送るデータが増える新機能なので、公開前に `gate` → ミハリの確認
- 更新履歴・ヘルプは「助手ライフ: フレンドの家」の節に1項目(文案は作るときに出す)
