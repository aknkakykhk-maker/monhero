## 1. 育成基盤(第①段階)【§2〜§5・§7・§8】(見本 `v2-1-grow.jpg`)

- マスモンごとに **6能力**(ライフ・ちから・かしこさ・命中・回避・丈夫さ)・**疲労**・**ストレス**を持つ【§2・§5】
- 成長 = 血統の適性 × 個体差 × 育成方針(型) × 助手の指導【§3・§7】。上限は仮に999【§2】
- 助手が**自分で**1日の行動を選ぶ: 軽トレ・重トレ(6能力ぶん)・特殊4種・休養・遊び【§4・§8】
  - 選び方: 苦手な能力・型・疲労・ストレス・性格(みゅあ積極型=重トレ多め、ももすけ安定型=休養多め など【§7】)・プレイヤーの相談
  - 疲労が高いと伸びにくい・ストレスが高いと失敗しやすい。助手が見て休ませる。取り返しのつかない失敗はない【§5】
- 開いていなかった日の分は、開いたときにまとめて決める。1日の上限があるので、放っておくのが得にならない【§8】
- プレイヤー: マスモンのくわしい画面で、6能力・疲労・今日の訓練の記録を見る/「💡 提案する」で「命中を鍛えて」「休ませて」「バランス型に」「任せる」と相談する(好き嫌い・仲良し度で受ける)【§8】
- 助手のブリーダー能力(育成知識・指導力・観察力・戦術力・信頼構築・育成経験)は、第①段階では**性格の初めの傾向だけ**持たせ、育つのは第②段階【§7・§14】

## 2. 完全オートバトル(第③段階)【§9】(見本 `v2-2-battle.jpg`)

- **3対3**。1体ずつ場に出て、**3体全滅で負け**
- 場は零・近・中・遠。毎ターン、助手の AI が次から選ぶ: 技を出す・移動・防御・ガッツをためる・交代
- AI の選び方: それぞれの手に点を付けて一番高いものを選ぶ。点 = 期待ダメージ(威力×命中率)・ガッツの残り・自分の残りライフ・反撃されそうか・距離・交代したときの得 を足したもの。**性格**で重みを変え(みゅあ=攻め・えるびん=守り など【§7】)、**戦術経験**(試合をするほど増える)で読みが良くなる。初めでも、明らかに損な手は選ばない
- 技は既存のデータ(威力・ガッツ消費・距離)を使う。命中は「命中 対 回避」、ダメージは「ちから(またはかしこさ) 対 丈夫さ」【§2】
- 同じ種(たね)なら同じ結果になる → **端末とサーバで同じ計算**にして、見返し(リプレイ)は種と編成だけで再現する
- 試合の種類【§9】: (a) 助手どうしの**自主模擬戦**(助手が自分でライバルと)/(b) プレイヤーが**2人を選んで戦わせる**
- 試合のあと【§9】: 戦術経験が増える/負けた助手が育成方針を見直す(「次は回避を鍛えよう」)/ライバルとの会話/「今日あったこと」に記録

## 3. フレンド対戦=非同期PvP(第④段階)【§10】(見本 `v2-3-pvp.jpg`)

- 助手の編成(3体)を**登録**する。相手がいなくても、登録した編成どうしで戦う(助手の編成どうしだけ・台帳 11-11)
- 対戦は**サーバの関数が回す**(MFバトルカードの大会 `card-tournament-run` と同じ形)。結果は端末から送らない=自己申告を信じない【§10】
- **ランキングを作る**(台帳 11-11)。対戦の履歴・リプレイ・リーグ(週ごと)・大会は順に
- §10 の2区分:

| | 区分 | 中身 |
| --- | --- | --- |
| A(推奨) | 両方作る | 「育成値そのまま」(育てた強さで勝負)と「公平」(能力を同じ合計にそろえ、戦術と相性で勝負)の2つのランキング |
| B | 「育成値そのまま」だけ | |
| C | 「公平」だけ | |

### サーバでの確かめ方(ランキングを守る)

育成は端末で進むので、登録する能力の数字が正しいかを確かめる必要がある。

| | 確かめ方 | よいところ | 気になるところ |
| --- | --- | --- | --- |
| A(推奨) | **上限の見張り**: 登録のときサーバが「迎えてからの日数 × 1日の成長上限」「能力の合計の上限」「技の習得条件」を見て、超えている編成ははじく。対戦はサーバだけが回す | 軽い。すぐ作れる | 上限ぎりぎりまでの改ざんは見分けられない |
| B | **育成の記録を再現**: 毎日の行動と種を送り、サーバが同じ計算で能力を作り直して比べる | 改ざんをほぼ防げる | 計算をサーバに写す手間・記録が増える |
| C | **育成もサーバで**: 1日の育成をサーバの関数が決める | いちばん固い | 端末で開いたときにすぐ育たない・サーバの負担が大きい |

推奨は「A で始め、ランキングが盛り上がったら B を足す」。「公平」の区分は能力をそろえるので、A でも十分守れる。

## 4. 助手ライフとの連携【§11】

- 入口は助手の部屋の「その助手とできること」の列に「🐾 マスモン」(ナカヨシ9 とすり合わせ済み)。中に 育成のようす・相談・模擬戦・戦績
- 部屋=育成の記録/育成場=トレーニング/友情=合同訓練/ライバル関係=模擬戦/掲示板=育成と対戦の日誌/生活リズム=自主育成の時間【§11】
- 好き嫌いは会話とマスモンの選び方にだけ効かせ、戦闘の強さには効かせない【§11】

## 5. 長期やり込み【§12】

能力が上限に届いたあとは、技の熟練・戦術の研究・戦績・大会・染色・助手との特別な出来事で続ける。数字は無限に増やさない。第②〜④段階の中で決める。

## 6. 保存とサーバ【§13】(どれも足すだけ)

- 端末: 新しいキー(例 `mh_assistant_masmon_grow_v1`)に 6能力・疲労・ストレス・訓練の記録・戦績・戦術経験。いまの `mh_assistant_life_masmon_v1` は書き換えない
- 移行: いまのマスモンから6能力の初めの値を**一度だけ**作る(移行の印つき・二重に当てない・今の値は残す)【§13】
- サーバ(第④段階): 登録編成の表・対戦の表・ランキングの表を新しく足す。既存の表とランキングには触れない【§1・§13】

## 7. 作る順【§14】

1. **育成基盤**: 6能力・個体差・訓練・疲労とストレス・自主育成・記録
2. **修行と助手の成長**: 技の習得・熟練・ブリーダー能力・相談・日常の出来事
3. **助手どうしのバトル**: 3対3オート・距離・ガッツ・交代・模擬戦・リプレイ
4. **非同期PvP**: 登録編成・サーバでの確かめ・リーグ・大会・ランキング

## 8. 第①段階を始める前に決めること【§15 から絞った】

①に要るもの(保存の形が決まらないもの)だけ。AI の評価式・修行・熟練・PvP の補正などは、その段階の前に聞く。
