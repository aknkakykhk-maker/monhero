# 助手ライフ 新UI改修マスタープラン（旧UI維持）

作成: 2026-11-10。**本書は未実装の改修計画**。現行挙動は最新mainのコードを正本とする。

## 目的と範囲

ユーザー方針: **完成像と工程を先にまとめて決め、実装は小さな単位で確実にビルド・公開する**。各回の変更を思いつきで増やさない。

- 新UI（既存の `mh_assistant_life_ui_v2` 切替がONのとき）の家、居場所、助手詳細、交流、友情、持ち物、画面遷移を統一する。
- 旧UIは表示・操作・機能・既定値を変えない。新UIの切替ボタンも維持する。
- 寝顔PNG/目の描画は**対象外**。助手の行動決定、時間帯、友情計算、報酬、セッション券、セーブ、ランキング、音声、画像は変更しない。
- 既存の家の断面図・8人の部屋・地図・場面・助手画像を再利用。新規画像・ライブラリ・保存キーを増やさない。
- スマホ縦画面を最優先（iPhone Safari、Safe Area、狭い画面、44px程度のタップ領域）。Android Chrome/PC Chromeの回帰も防ぐ。

## 完成時の画面設計

### 1. 家（入口・中心画面）
- 上部は既存ヘッダーと時間帯・次の行動更新。家の断面図を中心に残す。
- 家の直近に「みんなの今」コンパクトな状況リスト。助手8人を**名前・場所・行動・一緒にいる相手**で確認でき、行をタップすると既存の助手詳細へ。未登場の助手は既存の出会い条件を尊重して情報を出さない。
- 画面の高さを食い尽くさないよう、状況リストは折りたたみ／スクロール可能。家と下部の今日やれること・ナビゲーションを隠さない。
- 「今日やれること」は現行アクションを維持し、回数・利用不可理由を短く表示する。

### 2. 居場所
- マップとリストの助手・場所・時間帯の情報源を共通化。表示内容を別計算して矛盾させない。
- リストの助手を選択すると対象を強調し、詳細を開ける。マップ→詳細→戻るでは地図の閲覧状態を維持する。
- 出かけている助手の「見守る」「会いに行く」は既存の許可条件と処理を再利用。

### 3. 助手詳細・交流
- 助手の名前・今いる場所・行動・同席者・友情/仲良し度・セッションLvを整理して表示。
- 「話す」「見守る」「贈る」「モンヒロビート」のアクションを文脈に応じて見せる。**実行条件や回数消費は既存ロジックのまま**。
- 声かけ・贈り物は対象選択を明示し、誤った助手に作用しない。閉じる／戻るで元の家・地図へ戻る。

### 4. 友情・道具・今日あったこと
- 現行の友情情報・贈り物残数・所持道具・日記を読みやすく整理。数字の定義や算出元は変更しない。
- 長い説明やリストは独立スクロールを許し、下部ナビを押せる状態に保つ。

### 5. 共通ナビゲーション
- 家／居場所／友情／アルバム／道具（現行タブ構成を正本に確認）を一貫した見た目・操作に。
- モーダルやシートは閉じる操作、戻り先、スクロール位置、背景操作の可否を統一。
- 新UI専用表示は `uiV2` の明示的な分岐または専用部品に隔離。旧UI用のDOM・クラス・操作経路を巻き込まない。

## 実装工程と受け入れ条件

| STEP | 実装単位 | 完了条件 |
| --- | --- | --- |
| 1 | 新UI共通レイアウト・戻る操作の基盤 | 新UIだけの共通領域が動作、旧UIの画面・操作に差分なし |
| 2 | 家の状況一覧と助手選択 | 家・一覧・部屋詳細が同じ助手状態を示し、8人/未登場/外出/同席を扱える |
| 3 | 居場所マップ・一覧連携 | マップ→助手詳細→戻るで地図維持、情報の矛盾なし |
| 4 | 助手詳細と交流操作の統一 | 声かけ・見守り・贈り物・セッションの対象と回数消費が従来どおり |
| 5 | 友情・アルバム・道具・日記の表示整理 | 表示が欠けず、残数/数値/所持数が従来と一致 |
| 6 | スマホ表示・回帰検査・仕上げ | 旧UI、新UI、iPhone縦、Android、PCの主要動線を確認し未解決点を記録 |

各STEPは**原則1ブランチ・1PR**。実装→正規ビルド→関連検査→PR CI→マージ→Pages公開確認で閉じる。作業量が多く止まる場合は同一STEP内でコミットを分けるが、未ビルド・未公開の変更を「完了」としない。

## 技術上の禁止事項・注意

1. 編集元は `monster-hero/src/parts/*.jsx`。生成物 `src/game-system.jsx` と `game-system.compiled.js` は `node tools/build.js` で同期。生成物だけを手編集しない。
2. `mh_*` のキー名・意味を変えない。新UI表示だけのために生活状態を保存し直さない。
3. 時間帯や助手の場所は既存の `assistantLifeWhereOf` 等の計算結果を使う。新しい乱数抽選・状態更新をUIの描画で呼ばない。
4. 既存の `AssistantLifeRoomSheet`、`AssistantLifeHouseArt`、マップ、贈り物処理を再利用。旧UIと新UIで友情/報酬ロジックを複製しない。
5. UI表示に関係する変更は `monster-hero/data/changelog.js` と `help.js` の更新要否を確認し、ルールに従い双方更新。新しいワークフローを作らず、既存のビルド・検査を使用。
6. 旧UIを削除・既定で新UIに変更する判断は、この計画に含めない。ユーザーの別指示が必要。

## STEPごとのテスト観点

- 旧UIで従来の家/地図/部屋/声かけ/贈り物が使えること。切替の前後で保存・進行が変わらないこと。
- 家にいる/外出中/眠っている/2人でいる/未登場の各表示が破綻しないこと。
- 新UIの一覧・地図・部屋が同じ時刻の状態を示すこと。助手の誤選択がないこと。
- 画面遷移を往復してもシート・背景・スクロール・ナビが壊れないこと。
- iPhoneの狭い縦画面で、文字切れ・下部ボタン隠れ・ホームインジケーター重なりがないこと。
- 正規ビルド、`node tools/build.js --check`、`node tools/check-syntax.js`、関連する助手ライフのチェックとPR CIを実施。実機未確認は未確認と明記する。
