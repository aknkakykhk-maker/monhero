# MFバトルカードの保存の大きさの見回り(2026-10-27・ミカエシくん)

部長ソランドくんの依頼。直すのは案を見てもらってから。保存の形は変えない。

## 1. MFバトルカードの分(いちばん遊び込んだ人の想定)

ゲームの関数(正規化・記録の作り方)でいちばん大きい形を作り、JSON の文字数を測った(`localStorage` は文字数で数える)。

| キー | 想定 | 文字数 |
| --- | --- | --- |
| `mh_card_replays_v1` | 50試合。MASTER どうし60戦でいちばん長い試合(171手・6.5K字)を50個 | 約 327,000(平均の長さなら 約 222,000) |
| `mh_card_pvp_history_v1` | 30試合。相手と自分のデッキ・見えた札60枚・名前いっぱい | 約 48,000 |
| `mh_card_collection_v1` | 全カード・全モンスターを99枚ずつ | 約 4,400 |
| `mh_card_record_v1` | 最近30戦・数はどれも大きく | 約 2,800 |
| `mh_card_decks_v1` | 5デッキ・名前20字 | 約 2,100 |
| そのほか(設定・BGM・曲の並び・日々・天井・印など 15キー) | | 合わせて 約 5,000 以下 |
| **合計** | | **約 39万字(平均なら 約 28万字)** |

## 2. ゲーム全体の見込み

- iPhone の Safari の上限は「だいたい5MB」。2026-09-21 の事故の記録(`tools/boot/storage-quota-guard-check.js` の冒頭)では、保存 1,678,420 字で上限に迫っていた(1字=2バイトで数えると約3.4MB)。安全に見る上限は **約 250万字**
- その事故の保存のうち、ランキングの控え以外は 約 23万字。ランキングの控えはそのあと保存の形を軽くした(難易度は直近6つ・詳細を落とす)
- 見込み: ほかの遊び 約 25〜50万字 + MFバトルカード 最大 約 39万字 = **約 65〜90万字(上限の 約 26〜36%)**。いますぐ溢れる大きさではない

## 3. 書けなかったとき(上限)の守り

| キー | 書き方 | 上限で書けないとき |
| --- | --- | --- |
| `mh_card_replays_v1` | localStorage へ直に書く(93 の `cardReplayStore`) | ○ 古い試合(★以外)から消して入れる。書いたあとも 128KB の空きを残す。ゲーム全体の「保存できない」の数に入れない。入らなければその試合だけあきらめる |
| `mh_card_pvp_history_v1` | `storeSet`(92 の `cardPvpHistoryWrite`) | △ 30試合まで(約4.8万字)で止まるが、書けないと「保存できない」の数が増え、知らせとクイック周回の停止が出る。古い物から消して入れ直す守りは無い |
| 持ち物・デッキ・記録・日々・天井・ビートP など | `persist` = `saveStoredValuesOrRollback`(84) | ○(わざと消さない) 進行に要るので、書けなければ全部を元に戻して失敗を知らせる。ここは「捨てる」守りを入れてはいけない |
| 設定・BGM・トップの助手・おしゃべりの入切・途中の試合の印・ランキングの控え | `storeSet` | 小さい(どれも1K字前後)。失敗は「保存できない」の数に入る |

## 4. 案(どれも保存の形は変えない)

1. **マルチの履歴にも、過去の対戦と同じ守りを入れる**(92・ツナグくんの場所): 書けなければ古い試合から減らして書き直す。ゲーム全体の「保存できない」の数に入れない
2. **上限が近いときは、過去の対戦から先に空ける**(25-storage の見張り・開発部の場所): 進行のキーが書けなかったとき、まず `mh_card_replays_v1` の★以外を半分に減らしてから書き直す。過去の対戦はいちばん大きく、無くなっても進行は困らないため
3. **設定のデータバックアップの「大きさ」の画面に、MFバトルカードの分(とくに過去の対戦)を出し、手で減らせるようにする**(あとから・社長に聞いてから)

いちばん効くのは 2(上限に近い人を救える)。1 は小さい。3 は見える化。
