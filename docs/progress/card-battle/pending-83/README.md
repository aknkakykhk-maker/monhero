## 決めてほしいこと(窓口・社長へ)

1. **280 おいのり**(相手の「全体カード」を打ち消す)
   - 全体カードはいま0枚なので、このままでは使える場面がありません。
   - 案A(推奨): いまはパックに入れずに残しておく。全体カードを入れる日に、文どおりに作って一緒に入れる。
   - 案B: 文を読み替えて、「相手のブリーダーカード1枚を打ち消す」守りとして入れる。全体カードが来たら、文どおりの効き目に戻す(効き目が一度変わる)。
   - 案C: パックには入れるが、全体カードが出るまでは「使えない」と出す(手札で場所を取るだけになる)。
2. **222 羽化**(カードの絵の中で、文が途中で切れている)
   - 入れ替わる先になれる混血(ワームがサブ)は、ムラサキチュウ(C-062)の1体だけ。
   - 案(推奨): 「取りかえたモンスターは、元のモンスターのダメージを引きつぎ、そのターンは攻撃できない」で埋める(合体・ヒノトリの復活と同じ書き方)。
   - 元のカードの文が分かれば、それに合わせる。
3. **派生モンスターを出すカード**(合体 352・羽化 222・ヒノトリの復活 128)
   - 場の3体が途中で入れ替わります。強さの点数とランキングの数え方は変えません。
   - 結果の画面とマルチの「なぞり直し」は、入れ替わりも含めて確かめます。

## 進め方(区切りごとに PR でマージ)

- 区切りごとに、次の4つを1つの PR で入れます。
  1. カードの文から効き目を作る所(`tools/card/card-data-build.js`)
  2. ルールの本体(`82-card-battle-core.jsx`)
  3. 1枚ずつ文どおりに動くかの検査(`card-rules-check`)
  4. コンピューターの点の付け方
- 「準備中」の印(ready)は、効き目が動いて検査が通った札から外します。
  - パックへの入れ方(どの弾か・割合)は、カード部と話して決めます。
  - デバッグからだけのままです。
- マルチ対戦: 区切りごとに、なぞり直しの確かめ(cardPvpVerify)が新しい札を含む試合で通ることを見ます。
- 助手の強さ: 区切り3・4・7のあとに `tools/card/card-ai-balance.js` で測り直します。新しい札が入ったデッキで、勝率がずれていないかを見ます。
- 区切り4(選ぶ場面)と区切り7(入れ替わり)は、画面(84)にも選ぶ窓・入れ替わりの見せ方が要ります。ほかの区切りより時間がかかります。
