# 能力の上限アップの案と試算(r1115-103)

クラフト34。**まだ作っていない**(社長が決めてから作る)。社長が決めたこと:
編成(アシスト)の子ごとに、500 を超える能力の上位3つについて、その能力の 20% を育てる子の同じ能力の上限に足す。
同じ能力を持つ子が何体いても全員分を足す(命中800が2体 → 999+160+160=1319)。天井なし。総合力は 999 を超えた分から緩やかに。
上限アップの割合を上げるアシスト能力も足す。

- 試算の道具: `node tools/success/monsuc-cap-sim.js`(芯の写しで試す。本物のファイルは書き換えない)
  - `--rate 0.3`(割合)・`--gens 4`(何代つなぐか)・`--clampBonus`(下の①-5 の案)・`--nocap`(いまのまま)
- 試合の確かめ: 芯の写しで 999 の切りを外し、能力の組ごとに 200試合ずつ

## 要点

1. **育てる子の能力は、いまは育成の伸びが 999 で捨てられている**。上限を外すと、強い編成(いまの「育て終えた子らしい子」6体)の1代目で、いちばん高い能力が 中央 1,076・最大 1,757(=上限)まで届く
2. **代を重ねると伸び続ける**(天井なしのため)。上限アップの子で編成を組むと、2代目 最大 2,069・4代目 最大 2,863(①-5 の案を入れた形)。1代目は「20%×6体=120%」で上限が 999 から +758 まで上がる
3. **総合力の曲がり方は案α(999 を超えた分は1点 3.5=999 のときの伸びの半分)がおすすめ**。評価 M の割合は いま 48% → 1代目 55% → 4代目 67%。曲げないと4代目で MG 以上が半分を超える
4. **新しいアシスト能力は「上限アップブースト」(自分だけ型・1目盛り +1%・10目盛り・1目盛り 6ポイント)**。その子が足す割合だけが上がり、ほかの子とは重ならないので、093 の重なり方の表と食い違わない
5. **試合は壊れない**(NaN・無限大なし)。ただし 999 を超えた子どうしは試合が長くなる(全部1500どうしで 35ラウンド・2500どうしで 57ラウンド)。モンサクの相手は 999 までのままなので、999 を超えた子は勝ちやすくなる
6. **保存は「999 までは今の場所・超えた分は新しい項目/新しいキー」に分ける**。古い版で開いても超えた分が消えない。ランキングとフレンドのレンタルはサーバの直し(SQL と masmon-pvp の配り直し)が要る。助手のマスモン対戦(masmon_pvp)は触らない

## ① 上限の決め方

| 項目 | 案(おすすめ) | ほかの案 |
|---|---|---|
| 500 超えの判定 | 能力が **501 以上**(500 ちょうどは数えない。「500を超える」のとおり) | 500 以上 |
| 上位3つ | 500 を超えた能力のうち高い順に3つまで。超えたのが2つなら2つだけ | — |
| 同点 | **いまの「上位3つ」(`top3Of`)と同じ**: 同じ値なら、その子の種の伸びやすさが高い方 → 能力の並び順(ライフ・ちから・かしこさ・命中・回避・丈夫さ)。3位と4位が同点でも3つまで | 同点は全部数える(4つになることがある) |
| 足す量 | その能力 × 割合(20%)の**切り捨て**。命中800 → +160・命中1319 → +263 | 四捨五入 |
| 保存枠の子 | 数える | — |
| フレンドから借りた子 | 数える(借りた子の能力は送られた6能力から出し直す。いまと同じ) | 数えない |
| ベースモン | 数える決まりにする(初めの能力が最大 224 なので、実際は足されない) | — |
| 助手 | 数えない(能力が無い) | — |
| 決めるとき | **育成を始めたときに決めて、育成の終わりまで変えない**(途中の育成に保存) | 毎ターン出し直す |
| ①-5 編成の子の補正 | 編成の子の「能力の補正(能力 ÷40)」「はじめに受け継ぐ能力(能力 ÷ START_STAT_DIV)」は **999 までで数える** | 999 を超えた分も数える(代を重ねるほどトレーニングの伸びも増える。下の試算 B) |

- 上限 = 999 + 編成の6体それぞれの(その能力が上位3つに入っていれば 能力 × 割合)の合計。天井なし
- 画面: 編成を決める画面と育成中の能力の札に「上限 1,319」を出す(どの子がいくつ足したかは長押し・詳細で)

## ② 総合力の曲がり方と評価の区切り

いまの能力の分: 能力1つの総合力 = 能力 ×(2.5 + 2 × 能力 ÷ 900)。999 で 4,715・999 のときの伸びは 1点あたり 約6.94。

| 案 | 999 まで | 999 を超えた分の1点 | 能力1500 の値 | 2000 の値 |
|---|---|---|---|---|
| **案α(おすすめ)** | いまのまま | **3.5**(999 のときの伸びの半分) | 6,469 | 8,219 |
| 案β | いまのまま | 1.75(4分の1) | 5,592 | 6,467 |
| 比べる用: 曲げない | いまのまま | 6.94(999 のときの伸びのまま・まっすぐ) | 8,192 | 11,662 |

- 評価の区切り(G〜M・M 20,000・その上は 500 ごとに M1〜M9・MG…)は**変えない**。M より上は名前が続いているので足りる
- 「強さの段」(タッグ・仲良しの始まり・アシストポイントに使う、能力 ×2.5 の数え方)は **999 で切ったまま**(育成の釣り合いと、もらえるアシストポイント 最大400 を動かさない)
- 修行の仕上がり(総合力 ÷14,000 で 1 まで)も今のまま

## ③ 新しいアシスト能力

| 項目 | 案(おすすめ) | ほかの案 |
|---|---|---|
| 名前 | 🔓 **上限アップブースト**(参考の「〜ブースト」の言い方) | 限界突破 |
| id | `genkai` | — |
| 型 | **自分だけ型**(この子が足す上限の割合だけが上がる) | いるだけ型(編成でいちばん高い1つ・全員の割合が上がる) |
| 1目盛り | 割合 **+1%**(20% → 21%) | +2% |
| 目盛りの数 | **10**(満タンで 30%) | 10(+2% なら満タンで 40%) |
| 1目盛りの値段 | **6ポイント**(満タン 60。トレ効果アップの満タン 100 より安い) | 8 |
| 効く場面のタブ | 育成スタート | — |
| 説明 | 「この子が足す能力の上限が、能力の{v}%ぶん増える(はじめは20%)」 | — |

- 093 との関係: 093 の表では自分だけ型は「その子自身の分だけで重ならない」。この能力も同じで、6体が満タンで持っても「それぞれの子の分が 30%」になるだけ(割合どうしは足さない)。093 の決め方がどれになっても変わらない
- いるだけ型にすると、1体が持つだけで全員の割合が上がり、6体×(能力×割合)の上がり方が大きくなる(試算の rate 0.3 は自分だけ型の満タン6体と同じ)

## ⑤ 試合への影響

芯の写しで 999 の切りを外し、モッチどうし・作戦40・200試合ずつ(ガードの効き 丈夫さ÷999 は今のまま):

| 組み合わせ | A の勝ち | 試合の長さ(ラウンド) | A の命中 | A の1撃 | おかしな値 |
|---|---|---|---|---|---|
| 全部999 どうし | 51% | 23.2 | 45% | 225 | 0 |
| 全部1500 どうし | 45% | 34.8 | 44% | 220 | 0 |
| 全部2500 どうし | 39% | 57.1 | 44% | 223 | 0 |
| 命中2500・ほか999 対 全部999 | 97% | 13.0 | 99%(上限で止まる) | 202 | 0 |
| ちから2500・ほか999 対 全部999 | 89% | 13.8 | 48% | 442 | 0 |
| ライフ2500・ほか999 対 全部999 | 96% | 29.2 | 46% | 213 | 0 |
| 全部999 対 全部1500 | 0% | 10.1 | 21% | 182 | 0 |

- 命中は 1〜99% で止まり、ダメージ・ライフは能力に比例して増えるだけなので**数は壊れない**
- 999 を超えた子どうしは**試合が長くなる**(ライフが増え、ダメージは攻めと守りで打ち消し合う)。30ターン判定に行く試合が増える
- 命中だけ高い子は、回避 999 の相手にほぼ必ず当てる(97%勝ち)。モンサクの大会・ライバルは 999 までのままなので、999 を超えた子は勝ちやすい
- **試合の芯の直し方(おすすめ)**: r1115-090 のガッツと同じく「モンサクの試合だけの決まり」として試合の入力に `rules.statMax` を足し、モンサクの試合だけ 999 を超えて読む。助手のマスモン対戦・フレンド対戦のサーバ(masmon-pvp)は rules を受け付けないので**今のまま照合が通る**。ガードの効き(丈夫さ ÷999)は別の名前の定数にして 999 のまま
  - 芯を直すとサーバの写し `engine.js` が作り直される(`tools/build.js`)。動きは同じだが、写しをそろえるため masmon-pvp の配り直しを窓口へ頼む
