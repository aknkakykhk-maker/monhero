# MFバトルカード マルチの3つの新しい機能の案(マルチ部 ツナグくん)

2026-10-27 01:30(JST)。リプレイくんから引き継いだ社長の3つの依頼の案。**社長に見せてから作る。**

- 「バトルカードの過去のマルチの戦績とかで相手のデッキが見れるようにとかもほしい」
- 「あとは過去の対戦をみれるとか」
- 「ほかにはマルチの観戦機能とか」

## まとめ(おすすめの順)

| 順 | 案 | 大きさ | 先に小さく出せる物 | Supabase |
| --- | --- | --- | --- | --- |
| 1 | マルチの対戦の履歴と相手のデッキ | 小(1日) | 履歴の一覧だけ(相手・勝ち負け・日時・点数の増減) | **要らない** |
| 2 | 過去の対戦を見る(リプレイ) | 中(2〜3日) | マルチの試合だけのリプレイ(材料がもうそろっている) | 要らない(人に見せるなら、あとで表を1つ) |
| 3 | マルチの観戦 | 大(3〜4日+2台での試し) | フレンドの対戦だけ見られる | **要らない**(通信だけ) |

1 → 2 → 3 の順をおすすめします。1 で作る「試合の記録」を 2 がそのまま使い、2 で作る「手を1つずつ当てて見せる画面」を 3 がそのまま使うためです。

いまのマルチは、試合のあとに両方が「封」(山札の切り方とデッキ)を開けて見せ合い、相手の端末で試合をなぞり直しています(`cardPvpVerify`)。
**つまり、試合が終わった時点で、相手のデッキも、乱数の種も、両方の手の一覧も、もう自分の端末に届いています。** 3つとも、これを捨てずに取っておくところから始まります。

## 案1 マルチの対戦の履歴と相手のデッキ

### 見え方
- MFバトルカードのトップ →「記録」(いまの戦績の画面)に「マルチの履歴」の札を足す
- 1行に1試合: 相手のアイコンと名前・勝ち/負け(投了・時間切れ・相手が抜けた も小さく)・日時・強さの点数の増減(例 `+16` `-14`)・部屋の種類(だれとでも/合言葉/フレンド)
- 行を押すと、相手のデッキ: モンスター3体の絵と、技カード50枚を「同じ札は×3」でまとめた一覧。長押しでカードの詳しい画面(いまの対戦画面と同じ部品)
- 自分のデッキも並べて見られる(その試合で使ったデッキ。あとで組み替えていても、そのときの中身)

### 保存の場所と大きさ
- **新しいキー `mh_card_pvp_history_v1`**(端末の中だけ。いまのキーは触らない)。新しい30試合まで
- 1試合の中身: `{ at, room, outcome, reason, turns, foe:{ id, name, icon, frame, deckName }, foeDeck:{ monsters, cards } | null, myDeck, rating:{ before, after } | null, verified }`
- 大きさは1試合およそ0.8KB → 30試合で **約25KB**
- 読むときは正規化の関数を通す(壊れていたら空・知らない項目は捨てる)。`SAVE_DATA.md` に1行足す

### 強さの点数の増減
- いまの関数 `card_battle_pvp_report` は「点数を動かした/相手を待っている」しか返さず、増減を返しません
- **SQL を足さずに出す案(おすすめ)**: 試合の前に、点数の表(だれでも読める)から自分の行だけを読んでおき、届けたあと、点数の表の自分の行を数秒おきに数回読み直して、勝ち負けの数が増えたら差を書く。読めなかった試合は「—」にして、次に履歴を開いたときに埋める
- 関数を作り直して増減を返させる案もありますが、いまある関数を変えることになるので、おすすめしません

### 相手のデッキを見せてよいかの考え
- 相手のデッキは、いまでも試合のあとに相手の端末へ送られています(ズルを見抜くための封)。**新しく相手に渡す物は無い**ので、見せる仕組みを足しても、相手から見て「漏れる物が増える」わけではありません
- 紙のカードの大会でも、終わったあとにデッキを見せ合うのはよくあること
- 見せるのは**その試合をした本人だけ**。ほかの人(ランキングなど)には出さない
- 相手が途中で抜けた試合は封が開かないので、**その試合で見えた札だけ**(使われた札・捨て札)を出し「全部は分かりません」と書く
- 社長に決めてほしいこと: 「試合のあと相手のデッキを全部見せる(おすすめ)」か「その試合で見えた札だけ」か

### 小さく先に出せる物
- 一覧だけ(相手・勝ち負け・日時・点数の増減)。デッキの画面はその次

## 案2 過去の対戦を見る(リプレイ)

### 見え方
- 履歴の行(マルチ)と、助手と対戦の「最近の対戦」の行に「▶ 見る」
- 対戦画面と同じ見た目で、最初から再生。操作は「⏮ はじめ / ◀ 1手もどる / ▶ 1手すすむ / ⏭ 番の終わりまで / 自動で流す(速さ2段)」
- 下に「◯番目の番・あなた/相手」と、いまの手の説明(いまの技の帯と同じ言葉)
- 手札の見せ方: はじめは**自分の見え方**(相手の手札は伏せたまま)。終わったあとなので「両方の手札を見る」に切り替えられる(社長に決めてほしいこと)

### 作り
- ルールの本体(82)は、乱数を山札を切るところでしか使わないので、**乱数の種・両方のデッキ・先攻・手の一覧**があれば、最初から同じ試合を作り直せる
- マルチ: 上の4つは試合のあと全部そろっている(`cardPvpVerify` に渡している物)。そのまま取っておくだけ
- 助手と対戦: 種とデッキはもうある(`cardCreateGame` に渡している)。84 の「手を当てる所」で、手を一覧に足していく口を1つ足す(デッキくん・ブレイブくんの場所なので、触る前に知らせる)
- ルールを直した後に昔の試合をなぞり直すと、途中で合わなくなることがある。そのため、**保存のときにルールの版の番号を一緒に書き**、なぞり直しで手が当てられなくなったら「古い版の試合なので、ここまでしか見られません」と出す(勝手に別の試合にしない)

### 保存の場所と大きさ
- **新しいキー `mh_card_replays_v1`**。1試合の手の一覧は、短い形に詰めて **約5〜15KB**
- 保存の空きは大事(前に端末の保存が 3.2MB まで膨らんだことがある)ので、**新しい10試合まで**(合わせて最大 約150KB)。「お気に入り」の印を付けた試合は消さない(お気に入りは3つまで)
- 消えた試合の行は、履歴には残り「▶ 見る」だけが出なくなる

### あとから足せる物(いまは作らない)
- 人にリプレイを見せる(フレンドへ送る・ランキング上位の試合を見る)。そのときは Supabase に表を1つ足す。下書き:

```sql
-- 案2のあとから(いまは流さない)。リプレイを人に見せるための表。足すだけ
create table if not exists public.card_battle_replays (
  replay_id   text        not null primary key check (replay_id ~ '^[A-Za-z0-9_-]{8,64}$'),
  owner_id    text        not null,
  kind        text        not null check (kind in ('pvp', 'cpu')),
  body        jsonb       not null check (octet_length(body::text) <= 40000),
  created_at  timestamptz not null default now()
);
alter table public.card_battle_replays enable row level security;
create policy card_battle_replays_select on public.card_battle_replays for select to anon, authenticated using (true);
create policy card_battle_replays_insert on public.card_battle_replays for insert to anon, authenticated with check (true);
grant select, insert on public.card_battle_replays to anon, authenticated;
create index if not exists card_battle_replays_owner_idx on public.card_battle_replays (owner_id, created_at desc);
```

### 小さく先に出せる物
- マルチの試合だけのリプレイ(材料がそろっているので、84 に手を入れずに作れる)。助手と対戦はその次

## 案3 マルチの観戦

### 見え方
- マルチ対戦の画面に「観戦」の札。いま対戦している人の一覧: **フレンド**と、**強さの点数の上位**の人
- 押すと、対戦画面と同じ見た目で、両方の場を横から見る。手札は**両方とも伏せた札**(枚数だけ)。見えるのは、使われた札・場・ガッツの数・捨て札だけ
- 見ている人の数を、対戦している2人の画面に小さく出す(「👀 3」)。見る人からは何も送れない(スタンプも無し)
- 途中から入っても、その試合のはじめからの手をもらってなぞり、いまの場面から見始める

### 作り(手札を見せない仕組み)
- いまの通信では、**どちらの端末も自分の手札を送っていません**(送るのは使った札の番号と捨て札の並びだけ)。だから観戦の画面が受け取れる物は、もともと「2人とも見えている物」だけで、手札は**仕組みの上で見る人に届きません**
- 見る人の端末では、両方の手札と山札を「仮の札」にした場を作り、2人から届く手を、いまの `cardPvpApplyRemote` と同じやり方で当てる
- 観戦用の通り道は、対戦の部屋とは別(`realtime:mhc-watch-<試合の番号>`)。合言葉の部屋の合言葉を見る人に教えないため、見る人が対戦の部屋へ手を送り込めないため
- 「いま対戦している人」の一覧は、対戦中の端末が10秒おきに `realtime:mhc-live` へ「対戦中・名前・点数・フレンドの印」を知らせる(表は要らない)
- 2人とも新しい版でないと観戦できない(古い版の人は一覧に出ない)

### 決めてほしいこと
- 自分の対戦を見られてよいか: 「だれとでもは全員に見せる・合言葉とフレンドの部屋はフレンドだけ(おすすめ)」/「全部見せる」/「オプションで切れる」
- 観戦のときの曲(対人戦と同じバトルテーマ by いちか でよいか)

### 保存
- 端末に足す物は、オプションの「自分の対戦を見せる」の入/切だけ(足すなら `mh_card_settings_v1` に項目を足す。無い人は既定で補う)
- Supabase の表は要らない

### 小さく先に出せる物
- フレンドの対戦だけを見る(フレンドの名簿はもうある)。点数の上位の人はその次

## 社長に聞くこと(まとめ)

1. 3つの順(1 → 2 → 3 がおすすめ)
2. 相手のデッキ: 試合のあと全部見せる(おすすめ)/見えた札だけ

4. 観戦: だれに見せるか(だれとでも=全員・合言葉とフレンドの部屋=フレンドだけ がおすすめ)
