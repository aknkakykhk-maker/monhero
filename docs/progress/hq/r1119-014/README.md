# r1119-014 バランス研究と見た目の点検を Claude API で回す仕組み(案・社長の確認前)

社長「API の仕組みを作って、そっちで回して、その報告をこっちにする」。重い「読む・見る・考える」は Claude API に任せ、
会話(Claude Code)は道具を起動して、短い要約を読むだけにする。社長の週の使用量をほとんど使わないのがねらい。

## 流れ(図)

```
 会話(窓口・部署)                       道具(会話の機械の中で動く計算。AIは使わない)
 ───────────────                     ─────────────────────────────────
 ① コマンドを1つ打つ ───────────────▶ ② バランス: 試し対戦を最大10万回(ゲーム本体の芯を読み込む)
                                         見た目: 全画面を縦・横・小さい横・PCで撮る+機械の見つけ方
                                                │ 結果の表・止め絵
                                                ▼
                                       ③ 分析の入り口(Supabase の Edge Function・新設1本)
                                         ・合言葉が合うときだけ受け付ける
                                         ・1日の回数と費用の上限を超えたら断る
                                         ・今の ANTHROPIC_API_KEY で Claude API を呼ぶ(キーは機械の外に出ない)
                                                │
                                                ▼
                                       ④ Claude API
                                         バランス: 数字の表を読んで偏り・強すぎる組み合わせ・直し方の候補
                                         見た目: 止め絵を1枚ずつ見て、崩れ・重なり・切れ・読みにくさを表に
                                         (急がない物は Batch API で半額)
                                                │ 報告書(Markdown)と問題の表(JSON)
                                                ▼
 ⑥ 窓口が要約を社長へ ◀─────────── ⑤ リポジトリの docs/progress/ に置く(PR)。会話が読むのは要約と上位だけ
```

## 費用の見込み(2026-11 の API 価格: 1M トークンあたり 入力/出力 Opus 5.5 $4/$20・Sonnet 5.5 $2/$10・Haiku 5.5 $0.10/$0.50)

画像1枚は、縮めて送ると約1,500トークン(画面の大きさで変わる)。

| 仕事 | 1回の量の見込み | Haiku 5.5 | Sonnet 5.5 | Opus 5.5 |
|---|---|---|---|---|
| 見た目の点検(モンヒロ全体・約1,400枚 = 約350場面 × 4つの大きさ) | 入力 約280万・出力 約40万トークン | 約$0.5 | 約$10(Batch で約$5) | 約$20(Batch で約$10) |
| 見た目の点検(モンサクだけ・約800枚) | 上の約6割 | 約$0.3 | 約$6 | 約$12 |
| バランス研究の分析(10万回の結果をまとめた表を読んで報告書) | 入力 約5万・出力 約1万トークン | — | 約$0.2 | 約$0.4 |

- 試し対戦の10万回と、画面の撮影そのものは計算なので、API の費用はかからない(会話の機械の時間だけ)。
- 上限: 1日 $25・1回 $20 まで(社長の選択: 見た目の点検の目も Opus 5.5。急がない物は Batch API で半額)。超えたら入り口が断り、窓口へ知らせる。
- 2026-11-08 時点の API の残高は約 $170(月の上限 $500)。今の残高は社長の Console で確かめてもらう。

## 会話(社長の週の使用量)で使う量

- コマンドを打つ・要約を読む・窓口が社長へまとめる、だけ。部署の会話1本あたり、ふつうの小さな直し1本より少ない見込み。
- 目で見る判断は API が受け持つので、会話は止め絵を開かない(問題の上位の数枚だけ)。

## 作る物(PR の見込み)

| PR | 中身 |
|---|---|
| 1 | 分析の入り口(Edge Function 1本・合言葉・回数と費用の上限・記録の表)。配るのは窓口 |
| 2 | バランス: 試し対戦の道具をゲーム本体と同じ渡し方にそろえる(試合型アシストの上乗せ・覚醒・aptUp・MONSUC_MATCH_RULE)。結果の表と、入り口へ送る口 |
| 3 | 見た目: モンヒロ全体の場面の一覧と撮影の入り口(既存の撮影の道具を束ね、幅を足す)。機械の見つけ方(未置換の変数・重なり・読みにくい色・コンソールのエラー・前の版との比べ)。入り口へ送る口 |
| 4 | 1回目を回す: モンサク以外の見た目の点検の報告(直さない)。バランスは直しの公開のあと |

## 決まりとの関係

- ゲーム本体・保存・ランキング・バランスの数値は変えない。見つけた問題は直さず、表にして社長へ。
- 新しい API キーは登録しない(r1115-192 の補足)。社長の作業はなし。
- GitHub Actions の新しいワークフローは作らない(CLAUDE.md ⑧)。
- 画像に写るのはゲーム画面だけ(社長の個人の情報・合言葉は写さない)。

## 必ず調べる項目の追加(2026-11-20 社長・r1119-018)

| 項目 | 記録するもの | API に見てもらうこと |
|---|---|---|
| アシスト効果の数値 | 編成ごとのアシスト効果(種類・値・ランク・親密度・タッグ)と、育成の結果(6能力・大会の成績) | メモモン(命中+58% など)とベースモン(+3〜6%)の差は妥当か。メモモンを入れると強すぎないか。上限(合計100% など)に早く届きすぎないか。ランクごとの差 |
| 甘え度・恐れ度 | 毎ターンの甘え度・恐れ度と、動かした行動・イベント・その量 | 甘えの側ばかり上がり、厳しい育て方の側へ寄せられない偏りの原因。プレイヤーが手を打てる道があるか。直し方の案 |

画面で「何で上がったか」を見せる直し(r1119-019)は④が受け持つ。数値の直しは、この研究の結果を社長に見せてから。
