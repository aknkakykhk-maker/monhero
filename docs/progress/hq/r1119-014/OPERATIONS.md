# API の点検の運用(r1119-024・2026-11-20 社長)

入り口は analysis-gateway(Opus・1日 $25・ゲームの助手と同じキー)。使い分けは r1119-023(重い・繰り返しの点検は API)。
窓口は見回りのたびに、その日の使用量を社長へ伝える(`node tools/analysis/gateway-client.js usage`)。

## 優先順位(上から順に回す。同じ日に重ねて $25 を超えないよう、1つずつ)

| 順 | 点検 | 中身 | 結果を渡す先 |
|---|---|---|---|
| 1 | モンサク全点検 | 全画面を縦・横・小さい横で撮って Opus に見せる(tools/browser/visual-*.js)。直しの公開が進むたびに、変わった画面を回し直す | ②④⑤⑥⑦ |
| 1 | バランス点検 | 10万回の育成の記録を Opus に分析させる(r1119-014①・r1119-018 のアシスト効果と甘え度/恐れ度を含む)。本番はモンサクの直しの公開後 | 窓口 → 社長 |
| 2 | モンヒロビート見た目点検 | 曲選び・プレイ・結果・イベントの画面 | Muse(社長経由・r1119-012) |
| 2 | モンヒロビート譜面点検 | 全曲を何往復も機械で通し、譜面の記録(ノーツの時刻・間隔・重なり・難しさの偏り・音との合い)を Opus に見せ、おかしい所を挙げる。配信中の曲の譜面と既存の解析は作り直さない(tools/mode/CLAUDE.md)。点検だけ | Muse(社長経由) |
| 3 | 全体の見た目・文字列点検 | モンサク・モンヒロビート以外の全画面と、画面の文(用語・漢字・言葉の揺れ・ネタバレ) | 受け持ちの部 |

## その後: 定期点検

- 主に **見た目** と **譜面** を回る。見た目は前回から変わった画面を中心に、譜面は新曲と直した曲を中心に
- 間隔は、1〜3 が一巡したところで社長に決めてもらう(案: 週1回)
- 結果は docs/progress/kensa/ に日付つきで残し、前回からの差だけを社長へ伝える
