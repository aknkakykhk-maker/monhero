## ① 流れと日程

| 日 | すること |
| --- | --- |
| 1〜3日目(例 金〜日) | エントリー受付。締め切りまでは、デッキと戦術カードを何度でも変えられる |
| 締め切り(3日目 23:59) | エントリーが確定。その時のデッキと戦術カードの**写し**を取る |
| 4日目の朝 | リーグ分けと総当たりの組み合わせを発表 |
| 4〜8日目の毎日 21:00 | 1日1試合ずつ、自動で対戦(6人なら5試合で全員と1回ずつ) |
| 8日目 21:00 のあと | 最終順位が決まり、ごほうびを受け取れる(受け取りは次の大会の受付が終わるまで) |

- **リーグ**: 近い強さ(カードランク)の6人ずつ。6人なら毎日3試合で、5日で総当たりが終わる
- **人数が割り切れないとき** ★: 案1(推奨)… 足りない席に助手(デッキの賢さに近い強さ)を入れて6人にする / 案2 … 5人のリーグにして、毎日1人がお休み
- **途中でアプリを消した・デッキを消した人**: 大会は写しで戦うので、最後まで試合は続く(不戦敗にしない)。ごほうびは本人が受け取りに来たときに渡す
- **順位の決め方**: 勝ち数 → 倒したモンスターの数 → 2人の対戦の勝ち負け → それでも同じなら、エントリーが早い人

## ② エントリー

- 自分のデッキ(3体・50枚)と、組んだ戦術カード(基本カード・セットした戦術カード)を選ぶ。切り札も写す
- 変えられるのは締め切りまで。締め切り後に自分のデッキを変えても、大会には影響しない
- 賢さは戦術カードで決まる(ちゃんと効く戦術カードだけ数える・#4258)。何もセットしていないデッキは「でたらめ」で戦う
- **参加の条件** ★: 案1(推奨)… カードランク5以上 ・助手と対戦の HARD で1回勝った人 / 案2 … 条件なし(だれでも)
- 1人1デッキまで(同じ大会に2つは出せない)

## ③ 自動の対戦(だれも見ていないときに、公平に決める)

カードの対戦は、**同じデッキ・同じ戦術カード・同じ乱数の種**なら、どの端末で回しても同じ結果になる(マルチ・見返しで確かめずみ)。
乱数の種は「大会の番号+試合の番号」から決め、組み合わせ発表のときにサーバへ残す。

- **★ 回す場所**
  - **案1(推奨) サーバで回す**: 毎日 21:00 に、サーバの決まった時刻の仕組み(`pg_cron`。もう入っている)から、
    試合を回す処理(Edge Function `card-tournament-run`)を呼ぶ。処理はゲームと同じルール本体(82-card-battle-core と 82-card-tactics-core。
    画面を触らない作りなので、そのまま動かせる)で試合を最後まで回し、結果と手の並びを表に残す。だれが見ても同じ結果で、ずるができない
  - 案2 端末で回す: 試合の時刻を過ぎて、最初に大会の画面を開いた人の端末が回し、結果を送る。ほかの人の端末でも回して食い違いを確かめる。
    サーバの仕事は少ないが、改造した端末がうその結果を送れる・だれも開かないと結果が出ない
- **打ち方**: 登録デッキと同じ。賢さの段(戦術カードで決まる)で考え、セットした戦術カードどおりに動く(cardSharePolicy と同じ)
- **ルールの版**: 試合を回した時のルールの版(`CARD_REPLAY_RULES`)を試合と一緒に残す。大会の途中でルールが変わっても、その日から新しい版で回す

## ④ 見せ方(参考の絵を手本にした)

- 大会の入口: カードのトップに「大会」。受付中・開催中・結果の3つの顔(案A-1・案A-2・案A-5)
- 対戦表(案A-2): ○×の総当たり表。自分の番号は色を変える。これからの試合は日付
- 今日の対戦(案A-3): その日の試合の勝ち負けと「見返す」。まだの試合は時刻
- 見返し(案A-4): 今の「過去の対戦を見る」の画面を使う。はじめに会場の絵と助手の実況(参考の動画のような入場)。
  ダウン・逆転・決着で助手がひとこと。実況する助手は、その日の担当を順番に回す ★(または、自分の今の助手)
- 試合のあとの知らせ: 次にアプリを開いた時、助手が「きのうの試合、勝ったよ!」と知らせて、見返しへ案内する
- 自分の成績: 自分の試合だけの一覧

## ⑤ ごほうび ★(数は社長に決めてもらう)

| 順位 | ごほうび(例) |
| --- | --- |
| 1位 | ビートP・称号「◯◯杯 優勝」・優勝の印のプロフィール枠 |
| 2位 | ビートP・称号「◯◯杯 準優勝」 |
| 3位 | ビートP |
| 4位から下 | 参加賞のビートP |
| 全員 | 勝った試合の数 × ビートP |

- リーグの強さ(ゴールド・シルバーなど)で、ごほうびの量を変える ★
- 受け取りは1回だけ(サーバで受け取り済みを記録。保存データは新しいキーを足すだけ)

## 確かめたこと(2026-10-30)

- 登録デッキ(ツナグくん): `card_deck_register` は同じ持ち主の登録を上書きして version を +1、`card_deck_unregister` は行を残して active=false にするだけ。
  → 締め切りで deck・tactics・**version** を大会の表へ写す。「どの版で出たか」も残る
- 持ち主の見分け(ツナグくん): owner_id(ブリーダーID)+ 端末の鍵(`mh_card_deck_owner_key_v1`・表には md5 だけ)。カードランクも同じ鍵。
  → 大会のエントリーも同じ見分けにそろえる。新しい保存キーは増やさない
- 見返し(リプレイくん): 93 は「はじめの場を作り直して、手を1つずつ当て直す」だけなので、2人のデッキ・種・先攻・手があれば開ける。戦術カードは記録に要らない
  - 種はサーバで1つ決めて、助手と対戦と同じ形(seeds:[種, 0])にそろえる
  - 両方の名前を出すには、93 に大会用の種類(例 kind:'cup')を1つ足す(今は pvp・cpu 以外を捨て、cpu は名前が「あなた」固定)
  - 試合を回した時のルールの版を rules に入れる。版がちがう試合は、開く前に知らせる(当て直しが途中で止まるため)
  - 表の1行から開く入口を足す(端末の保存 mh_card_replays_v1 には入れない。50試合の枠を食わない)

## ⑥ サーバの表と関数(足すだけ・今の表は触らない)と、作る量

| 足す物 | 中身 |
| --- | --- |
| 表 `card_tournaments` | 大会(名前・受付の期間・開催の日・リーグの人数・ごほうびの表・状態) |
| 表 `card_tournament_entries` | エントリー(大会・owner_id・鍵の md5・名前・アイコン・デッキと戦術カードの写し・登録デッキの version・賢さ・リーグ・席) |
| 表 `card_tournament_matches` | 試合(大会・リーグ・日・2人の席・乱数の種・先攻・勝った方・手の並び・倒した数・ルールの版) |
| 表 `card_tournament_rewards` | ごほうびの受け取り済み |
| 関数 | `card_tournament_enter`(エントリー・締め切りまで差し替え)/ `card_tournament_withdraw`(締め切りまで取り消し)/ `card_tournament_view`(表・今日の対戦)/ `card_tournament_claim`(ごほうび) |
| 決まった時刻の仕組み | 締め切りの朝にリーグ分け・組み合わせ / 毎日 21:00 に試合を回す(案1) |
| Edge Function | `card-tournament-run`: ルール本体で試合を回して表に書く(案1) |
