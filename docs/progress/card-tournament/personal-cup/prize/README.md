## 1. 出せる物(参加費にも使える物)

持ち物の表(`docs/spec/SAVE_DATA.md`)とギフトで配れる種類(`GIFT_REWARD_LABELS`・`gameItem`)から作った。
**数えられる物は全部**。出す物の名前(`item`)は、端末のギフトの種類と同じ言葉にそろえる(受け取りをギフトの作りに乗せるため・下の「受け取り」)。

| 出せる物 | 保存キー | `item` | 1杯に出せる上限(案)| 参加費の上限(案)|
| --- | --- | --- | --- | --- |
| ダイヤ | `mh_gold` | `diamond` | 50,000 | 5,000 |
| ビートP | `mh_rhythm_event_points_v1` | `beatPoint` | 5,000 | 500 |
| 虹のプシュケー | `mh_owned_items.rainbow_psyche` | `rainbowPsyche` | 30 | 3 |

| 勇者の証 | `mh_owned_items.hero_proof` | `gameItem:hero_proof` | 3 | 参加費には使えない |
| 勇者の証片 | `mh_owned_items.hero_proof_shard` | `gameItem:hero_proof_shard` | 30 | 3 |
| セッション券 | `mh_owned_items.session_ticket` | `gameItem:session_ticket` | 10 | 1 |
| スキップチケット(序・破・急) | `mh_owned_items.skip_ticket_*` | `gameItem:skip_ticket_*` | 10 | 1 |
| トレーニングチケット | `mh_owned_items.training_ticket` | `gameItem:training_ticket` | 10 | 1 |

| バトルカードカタログ | `mh_card_catalogs_v1` | `card:catalog` | 3 | 参加費には使えない |

- 上限の数は**案**。サーバの表 `card_cup_prize_items` の1行ずつに持たせ、窓口が行を足す・数を変えるだけで増やせる(消さない。止めるときは `enabled` を false)
- 1人が1日に預けられる上限も、物ごとに持つ(ダイヤ 100,000・ビートP 10,000 など)
- スキップチケット・極/覇、重トレーニングチケット、魂の結晶、種族の超越の実、各リセットの書なども同じ形で足せる(最初は上の表だけにして、様子を見て増やすのをおすすめ)

**出せない物(理由)**

| 物 | 理由 |
| --- | --- |
| ブリーダーP | 2度と手に入らない(社長) |
| マスモン・円盤石・アシストカード | ひとつずつの物で、育てた中身や解放の意味がある |
| アイコン・プロフィールフレーム・助手の着替え | 一度買ったら外さない物(保存の決まり) |
| バトルカード(1枚ずつ) | **あとから**。番号ごとの預かりと、99枚を超えたときの扱いが要る |
| 経験値(ブリーダー・カード・ビート)・ランク・記録・解放や既読の印 | 持ち物ではない |
| ガチャポイント | 交換の途中の数(パックを買うと増える)。出せるようにもできるが、最初は外す |

## 2. 参加費と配り方

- 参加費: **なし / 1つの持ち物 × 額**(主催がえらぶ。上の「参加費の上限」まで)
- 集まった参加費は、主催・主催仲間が出した物に足して、まとめて配る(例: ダイヤ 10,000 + 5,000 + 参加費 500 × 6人 = 18,000)
- 配る割合: 主催が決める。すぐ選べる形(優勝が全部 / 7:3 / **6:3:1** / 5:3:2)と「自分で決める」(1位から8位まで・1つ1%以上・合計100%)
- 分けた端数(勇者の証のように割り切れない物)は1位へ
- 同じ順位の人がいる(トーナメントの3位が2人など)ときは、その順位の割合を人数で分ける
- 主催・主催仲間は配る順位に入れない(下の「ずる」)。主催・主催仲間が上位でも、その分は次の順位の人へ
- 参加費を払ったあとは、配り方を変えられない(サーバで止める)

## 3. 主催仲間

- 主催が**フレンドから2人まで**誘う(主催と合わせて3人)。誘われた人が「受ける」で仲間になる(断れる)
- 受付中だけ誘える・外せる。外した主催仲間が出していた物は、その人に戻る

| | 主催 | 主催仲間 |
| --- | --- | --- |
| 自分の持ち物をごほうびに出す | ○ | ○ |
| 参加者・合言葉を見る / 合言葉をフレンドへ知らせる | ○ | ○ |
| 杯の取り消し・時刻・配り方・参加費を変える | ○ | × |
| 主催仲間を誘う・外す | ○ | × |
| 参加費を払う | 払わない | 払わない |
| 試合に出る | ○(今の決まりのまま) | ○(出たいとき) |
| ごほうびを受け取る | × | × |

- 取り消しを主催だけにするのは、預けた物が全員へ戻る大きな操作だから。設定の直しも、参加費を払った人がいると変えられないので、主催1人に決めるのがわかりやすい

## 4. サーバで預かる仕組み(★いちばん大事)

持ち物は端末に保存されていて、サーバは本当の数を知らない。そこで「端末から減らす」「サーバに預けた記録を残す」「終わったら記録の範囲で配る」を、
**どこで途切れても二重にも消えもしない順番**でつなぐ。**どの持ち物でも同じ作り**にする(物ごとの保存キーに足す・引くだけ)。

### 預ける(主催・主催仲間のごほうび / 参加費)
1. 端末: 持ち物を減らすのと**同じ取引で**(`saveStoredValuesOrRollback`)、新しいキー `mh_card_cup_wallet_v1` に「送っている途中」の印を書く
   `{ cup(杯), kind('prize'|'fee'), item, amount, nonce(端末で作る長い文字), state:'sending', at }`
   - 減らす前に、売り場と同じく「書く直前の読み直し」と、ほかのタブとぶつからない鍵(`navigator.locks`)を使う(2026-10-27 の2タブの直しと同じ)
2. サーバ: `card_cup_deposit`(参加費は `card_cup_join_pay` = 参加と預けるを1回で)。**nonce ごとに1行**なので、同じ送り直しは1回分しか数えない
3. 返事が `ok` / `dup` → 印を `held` にする。返事が `closed`・`full`・`over` など → 端末で同じ取引で持ち物を戻し、印を `returned` にする
4. 返事が来ない(通信が切れた)→ 印は `sending` のまま。次に MFバトルカードを開いたとき、同じ nonce で送り直す

### 受け取る・戻す
- 終わった杯・取り消された杯を開くと「受け取る」。端末は先に `mh_card_cup_wallet_v1` に「受け取りの途中」の印と nonce を書き、`card_cup_claim` を呼ぶ
- サーバは、その人の分を計算して返す
  - 終わった … 配り方と順位から。**その杯で預かった量を超えないように**、これまでに配った量と合わせて確かめてから返す
  - 取り消し・人数が足りない・受付中に抜けた・外された主催仲間 … その人が預けた分だけ戻す
  - 最初に来た nonce を覚え、**同じ nonce なら何度でも同じ中身**、ちがう nonce(バックアップから戻した端末など)には「受け取り済み」だけ返す → 二重に受け取れない
- 端末は、返ってきた中身を**ギフトボックス**へ1件で入れる(`grantGiftOnce`。ギフトの id は `card_cup_<杯>` で、同じ id は二度入らない)。ギフトの印と wallet の印を同じ取引で書く
  - ギフトにしておくと、持ち物ごとの足し方(ダイヤは `mh_gold`、勇者の証は `mh_owned_items` …)を今のギフトの受け取りがそのまま受け持つ。**持ち物ごとに新しい足し方を書かなくてよい**
  - ギフトに無い種類(戦術カードのかけら・カードパック券・カタログ)は、ギフトの種類を**足す**(`cardTacticShard` など)。この種類を知らない古い版では「受け取れないギフト」として残るだけ(今のギフトの決まりのまま)

### 保存データ(CLAUDE.md ⑦)
- 新しいキーは `mh_card_cup_wallet_v1` だけ(`[{ cup, kind, item, amount, nonce, state, at }]`・新しい200件まで。終わった物から消す)。今のキーの形は変えない
- 持ち物の増減は、今のキー(`mh_gold`・`mh_owned_items` など)の今の形のまま、足す・引くだけ。読み込みは型を確かめ、壊れていたら何もしない
- ランキングへ送る物・ランキングの表は触らない

## 5. ずるへの備え(正直に)

| | 防げるか | どうやって |
| --- | --- | --- |
| 同じ参加費・ごほうびを二重に払う・二重に数える | ○ | 1回ごとに nonce の1行。参加費は1杯1人1回(抜けて入り直しても取らない) |
| 同じごほうびを二重に受け取る | ○ | サーバの受け取り済み + 最初の nonce だけに中身を返す + ギフトの id は1回だけ |
| 預かった量より多く配られる | ○ | 配る前に、その杯で預かった量とこれまで配った量をサーバで確かめる。**サーバで預かった分を超えて、持ち物は生まれない** |
| 人の鍵でなりすます(払う・受け取る・主催仲間になる) | ○ | 登録デッキと同じ持ち主の鍵(md5) |
| 主催・主催仲間が自分の出した物を受け取る | ○ | 主催・主催仲間は配る順位に入れない |
| 杯を開いてすぐ取り消して、預けたまま | ○ | 取り消し・人数不足は全部戻る |
| 改造した端末が、減らさずに「払った」と送る | **×(防げない)** | サーバは端末の持ち物の本当の数を知らないので、送られた量を信じるしかない。その量は、ほかの人へ配られる |
| 持っていない物を出す | **×(防げない)** | 同じ理由 |

- 防げない2つの害は「**本物でない持ち物が、ほかの人へ移る**」こと。改造した端末は、今でも自分の持ち物を好きに増やせる(端末の保存なので)。個人杯で新しく増える害は「**ほかの人へ移せる**」所だけ
- 移せる量は、物ごとの上限(1杯・1人1日)で頭打ちになる
- **気をつける所**: 勇者の証・勇者の証片・虹の超越の実・虹のプシュケー・トレーニングチケットは、マスモンを強くする物。うその量が移ると、受け取った人の総合力が上がり、**総合力のランキング(`bond_levels`)に響きうる**。そのため、この5つは上限を小さくした(上の表)。もっと抑えるなら「最初はダイヤ・ビートP・チケット類だけにして、強くなる物は様子を見て足す」
- さらに抑える案(必要なら): 1日の預け量の上位を窓口が見られる関数(見張り)/ 強くなる物を出せるのはブリーダーレベル◯以上(レベルも端末の値なので、手間を増やすだけ)

**主催・主催仲間のずる**
- 自分で出て自分で受け取る … 受け取れない(配る順位に入れない)
- 仲間どうしで回す(主催がフレンドへ渡す道に使う) … 出した物が仲間へ移るだけ。上限で頭打ち。新しく持ち物が生まれることは無い
- 捨てアカウントで参加費を集める … 参加費は参加する人が自分で払う。知らない人から集めるには、その人が自分で参加する必要がある

## 6. リアルタイム杯との合わせ方(ブレイブくんの #4356)

- 「ごほうびのある杯は、2台のなぞり直しが合ったときだけ確定」の口 `card_cup_live_reward(杯)` を、**この関数1つだけ差し替える**:
  その杯に預かった物があるか、参加費があれば true(SQL の下書きの「差し替え1」)
- 今の関数は `immutable` で表を読まない形。差し替えは表を読むので `stable` にする(引数と返り値は同じ)
