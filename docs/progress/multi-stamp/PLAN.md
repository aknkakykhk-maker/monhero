# マルチにスタンプ(モンヒロビート・MFバトルカード) 案

2026-11-11 ビート部 スタンプ。社長「モンビーやバトルカード(マルチ系)にチャットのほかにスタンプがほしい」

## 1. いまの仕組み(調べた結果)

| | モンヒロビートのマルチ(`77-screen-rhythm-multi.jsx`) | MFバトルカードのマルチ(`91-card-battle-multi.jsx`) |
| --- | --- | --- |
| 通り道 | Supabase Realtime の Broadcast だけ(表・SQL なし)。部屋ごとの通信路 | 同じ(Broadcast だけ。観戦の人へはホストが中継) |
| 送る形 | `{ t:'chat', id, name, text(40字), cid }`。定型文も自由文も同じ「文字」 | 定型 `{ t:'chat', i:番号 }`(6つ)/ 自由文 `{ t:'chat', x:30字 }` |
| 見せ方 | 💬 の板+席のカードの上に6秒の吹き出し。結果画面は結果の行の上 | 💬 コメントの板・対戦中は相手の所にひとこと・観戦は流れるコメント |
| 悪い言葉 | **掃除なし**(制御文字を消すだけ) | `cardChatMask`(●に置き換え)・URL/連絡先は送れない・相手ごとに🔇 |
| 回数 | 0.8秒に1回 | 定型 1.5秒に1回 / 自由文 3秒に1回・1試合30回(観戦20回) |
| 演奏中・対戦中 | **演奏中は何も送らない・届いたものは溜めて結果のあとに処理**(判定と描画に割り込ませない決まり) | 対戦中も送れる |
| 設定 | なし | `mh_card_chat_prefs_v1`(自由文を出す・観戦のコメントを流す) |
| 残る物 | 保存しない(直近50件だけ覚える) | 保存しない(直近50件) |

**スタンプは「いまの chat の知らせに、スタンプの番号を1つ足す」だけで作れる。表・関数・Supabase の設定は変えない。**
古い版のアプリには言葉(「ナイス！」など)だけが届くので、混ざっても壊れない
(ビートは `text` をそのまま出す/カードは近い定型の番号 `i` を付けて送る)。

## 3. 案

### Q1 絵柄
- **A 助手の顔+短い言葉(推奨)**: いまある顔の絵(8人×8表情・256×256)。絵代なし・すぐ作れる・助手が好きな人ほど使う
- B モンスターの顔+短い言葉: いまある顔アイコン。表情は1種なので気持ちは言葉で出す
- C 新しく描く: スタンプ専用のデフォルメ絵。見た目はいちばん良いが、絵を用意してから(受け取った絵はそのまま入れず整える)
- A で始めて、あとで B・C を足すこともできる(番号で送るので足すだけ)

### Q2 数と増やし方
- **はじめ8個(助手1人1個)+ 仲良し度の段が上がるとその助手のスタンプが増える(推奨)**。助手1人あと3個 → 最大32個
- はじめ8個+ ビートPで買い足す(交換所)
- はじめから全部(16〜32個)。増やす仕組みなし
- 増えた分は新しいキー `mh_multi_stamps_v1` に足す(既存のキーは触らない)。相手は持っていなくても絵が見える

### Q3 出す場所
- 部屋(待機・曲えらび・準備)・結果画面・カードの対戦中・カードの観戦: 出す(送る・見る)
- モンヒロビートの演奏中:
  - **受け取りだけ。ナラビの「演奏中の札」が入ってから、届いたスタンプで札の顔を2秒だけ差し替える(推奨)**。送るボタンは出さない(手がふさがっている)。絵は部屋に入ったときに読み込み済みにし、演奏中に新しく読み込まない。ナラビと同じ道具(`rhythm-live-frame-report.js`)で「札なし/札あり/札+スタンプ」の重さを測り、重くなるならやめる
  - 演奏中は出さない(今と同じ。届いたものは結果画面でまとめて吹き出し)

### Q4 連打の防ぎ方
- **2秒に1回まで・続けて同じスタンプは3回まで(推奨)**。受け取る側も1人あたり2秒に1個しか出さない(ずるい版を使われても画面が埋まらない)
- カードは今の定型と同じ 1.5秒に1回(1試合の30回には数えない今の決まりのまま)

### Q5 出さない設定
- **「スタンプを絵で出す」入切。切ると届いたスタンプは言葉だけ(「ナイス！」)で出す(推奨)**。設定は両方の遊びで共通の新しいキー `mh_multi_stamp_prefs_v1`
- 切ると、届いたスタンプを全く出さない
- 置き場所: モンヒロビートは ⚙ オプションとチャットの板、カードはコメントの板の下(今の2つの入切の隣)

## 4. 作るときに触る所
- `77-screen-rhythm-multi.jsx`(ビート・部屋と結果)/ `91-card-battle-multi.jsx`(カード・対戦と観戦)。共通のスタンプの表・部品は新しい parts に1つ置く
- ナラビ(演奏中の札)・キラメキ(ビートの見た目と軽さ)・ソランド(カード部長)・テンポ(ビート部)に触る前に知らせる
- 新しい機能なので公開の前に止め絵(本物の画面)と更新履歴・ヘルプの案を窓口へ

## 演奏中に出すときに守ること(ナラビより・演奏中の札 PR #5243)
本文は docs/spec/RHYTHM_MULTI.md「演奏中の札」、重さの測り方は docs/progress/beat-multi-live-score/PLAN.md。
1. 届いても部屋の emit() を呼ばない。演奏中のスタンプは札と同じ道(`RHYTHM_MULTI.onLive`)で札だけに知らせる。演奏画面と部屋の画面は作り直さない
2. 札の行(`RhythmMultiLiveBoard` の行)を React で作り直さない。顔は img の src を差し替えず(画像の復号が走る)、前もって置いた2枚目の表示を切り替える(opacity)
3. 行に will-change を付けない。ずっと回るアニメーションは置かない(箱は contain:strict なので、はみ出す飾りは切れる)
4. 幅(縦98px・横196px)と行の高さ(28/22px)を変えるなら、`tools/mode/rhythm-multi-live-board-check.js` の止め絵で道と重ならないか確かめる
5. 送る量に上限を付ける。古い版は演奏中に届いた知らせを300件まで溜め、それを超えると古い順に捨てるので、増やしすぎない
6. 札を設定(multiLiveBoard)で消している人に、スタンプをどう見せるかも決める(案: 結果画面でまとめて吹き出し)
