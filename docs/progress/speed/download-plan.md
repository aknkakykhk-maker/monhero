# 案: 事前ダウンロードに「ゲーム本体とデータ」も入れる(速さ部ハヤテくん・2026-10-27)

社長「本体とデータもダウンロードに入れる」を受けた案。**まだ作っていない。** 社長に見せてから作る。
組む相手: sw.js を作ったストックくん。今の仕組みの説明は [`docs/spec/ASSET_PREFETCH.md`](../../spec/ASSET_PREFETCH.md)。

## 1. いちばん大事な決まり(新しい版を出したら必ず新しい版が動く)

今の sw.js と同じ考え方を、JS・CSS にも広げるだけにする。

- **ページ本体(index.html)は今までどおり SW を通さない。** どの版の JS を読むかを決めるのは、毎回ネットから来る index.html。
  index.html の `<script src="…?v=<版>">` の **版が1文字でも違えば別の物** として扱う
- SW が返すのは「**URL の版(?v=)が、ためた物の版とぴったり同じ**」ときだけ。違えばふつうに取りに行き、新しい版をためる。
  だから古い JS が残って動き続けることは起きない(古い版の URL を、新しい index.html はもう読まない)
- version.json・Supabase・HTML・保存データ(localStorage)には今までどおり手を出さない(sw.js の頭の決めごとはそのまま)

## 2. ためる物

| ファイル | 圧縮後 | 直近3日で変わった回数 | ためて効くか |
| --- | ---: | ---: | --- |
| `data/rhythm-mode.js`(譜面) | 1,072KB | 0回 | **よく効く**(ほぼ変わらない) |
| `data/assistants.js`(助手) | 207KB | 11回 | 効く |
| `data/breeder.js`・`ally-monsters.js`・`images-*.js` などの小さいデータ | 約200KB | 数回 | 効く |
| `data/card-battle-cards.js` | 18KB | 14回 | 少し |
| `data/changelog.js`(更新履歴)・`data/help.js`(ヘルプ) | 532KB | 各16回 | 1日に何回も変わるので、遊ぶたびに取り直しになりがち |
| `game-system.compiled.js`(本体) | 1,395KB | **268回** | **ほとんど効かない**(ほぼ毎回の公開で中身が変わる) |
| `tailwind.css` | 32KB | 214回 | ほとんど効かない |
| `vendor/react*.js` | 47KB | 0回 | 効く |

**正直な見込み**: 1日1回遊ぶ人は、本体JS(1.4MB)と更新履歴・ヘルプはほぼ毎回新しい版になる。
ためて効くのは譜面・助手・データ類で、**起動のたびに約1.3〜1.5MB(圧縮後)減る**(全体 3.4MB のうち)。
遅めの4G でおよそ 7〜8 秒。iPhone はふつうのブラウザのキャッシュを早めに捨てるので、SW にためる意味はある。

本体JSにも効かせるには、本体を「よく変わる部分」と「めったに変わらない部分」に分ける必要がある(下の 7.)。

## 3. 版の確かめ方

- data/*.js・vendor・CSS: 今も index.html の URL に中身のハッシュ(`?v=<sha256 先頭12桁>`)が付いている。これをそのまま使う
- 本体JS: 今の版は **ビルドの時刻**(`GAME_BUILD = '202610270126'`)。中身が同じでも作り直すたびに変わり、ためた物が無駄になる。
  → `tools/build.js` で **中身のハッシュ** に変える(時刻は BUILD_DATE と version.json に残す。更新のお知らせはそのまま動く)
- `asset-manifest.json` にも JS・CSS を足す(`pack: "core"`)。sw.js の古い物の掃除(pruneCache)は、一覧に無い・版の違う物を消すので、そのまま使える

## 4. 更新の届き方

1. 新しい版を公開 → GitHub Pages の index.html が変わる(ブラウザのキャッシュは最長10分。これは今と同じ)
2. 開いた index.html が新しい版の URL を読む → SW の手元に無い → ふつうに取りに行く(今と同じ速さ)→ ためる
3. 変わっていないファイル(譜面など)は URL も同じなので、SW の手元から返す(速い)
4. 古い版は、次に一覧(asset-manifest.json)を取り直したときに消える

遊んでいる最中に新しい版が出たときの「新しいバージョンがあります」の案内(version.json)は今のまま。

## 5. 失敗したときの戻り方

- 本体JSの読み込み処理(index.html の loadGame)は、失敗すると `&retry=<時刻>` を付けて取り直す。
  **SW は `retry` の付いた取得には手を出さない**(必ずネットから取る)。ためた物が壊れていても2回目で直る
- ためた物を返して `MonsterHeroGame` が無いとき(壊れていた)は、その版をためた所から消してから取り直す
- 設定の「ダウンロード」を切にすると、今と同じく全部消えて何もしなくなる(本体とデータも同じ)
- 万一のための止め札: sw.js に「JS・CSS をためない」1行の印を置き、問題が出たら印を立てて公開すれば、次に開いたときから止まる
- 保存データ(localStorage)とランキングには触れない

| --- | --- | --- |

## 7. はじめて開く人にも効く物(A〜D の並べ直し)

ダウンロードは2回目からしか効かない。はじめて開く人(いちばん離れやすい)に効く物だけ残し、効く順に並べた。

| 順 | 案 | はじめての人に効く量 | ダウンロードとの関係 | 見た目・遊び方 |
| --- | --- | --- | --- | --- |
| 1 | **A. 譜面を曲ごとのファイルに分け、曲えらびで読む** | 起動が圧縮後 **1.07MB** 軽い・素で 3.9MB の解釈が無くなる | 曲ごとのファイルもダウンロードにためられる | 変わらない(曲を選んだときに一瞬待つことがある) |
| 2 | **D. HOME の裏の先読みを、持っている物とランキングに出ている物だけにする** | はじめての2分で約 **15MB** の画像の取り合いが減る(遊び始めの通信が軽い) | 先読みしなくなった物は、事前ダウンロードが入れる | 変わらない(マーケットで持っていない物の絵は開いてから出る) |
| 3 | **C. 更新履歴・ヘルプを開いたときに読む**(未読の印に要る先頭だけ先に) | 起動が圧縮後 **約0.5MB** 軽い | 開いた分はためる | 変わらない(開くとき一瞬待つことがある) |
| 4 | **B. タイトル曲を待たずにタイトルを出す** | 遅めの4G で **10秒以上** 早い | 2回目からはダウンロードで曲が手元にある | タップ直後の数秒が無音になることがある → 社長に聞く |

助手のデータ(C に入れていた)は HOME ですぐ使うので外した。

本体JSを分ける案(よく変わる画面ごとに分ける)は、はじめての人にも効くが大きな作り直しになるので、A〜D のあとに改めて案を出す。

## 8. 作る順(社長の「この案で」が出たら)

1. 本体JSの版を中身のハッシュにする(build.js)。今の動きは変わらない
2. sw.js に JS・CSS を足す(ストックくんと組む)。手元の検査: 版が変わったら必ず新しい JS が動く・retry は SW を通らない・切にしたら消える
3. A → D → C の順に、はじめての人向けを1件ずつ。B は社長の答えを待つ
