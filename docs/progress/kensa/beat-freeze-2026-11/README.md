# モンヒロビート: 新しい曲で「固まる・飛ぶ」の調べ(2026-11-21 00:35 ミハリ)

社長「最近の新曲をやっていると固まる・たまに飛ぶ。ノーツが一瞬止まって先へ飛ぶ(曲は流れたまま)。気づいたのは最新曲。Muse に作らせた曲の作りをあまり信用していない」。
**監査だけ。ゲームのコード・譜面・音源は変えていない。API は使っていない。** 基準 main `0dad11d7`。

対象: 天翔る翼(`amakakeru_tsubasa`)・Dr.WILY STAGE 1(`dr_wily_stage_1`・`dr_wily_stage_1_okkussenman`)・グルメレース(`gourmet_race_64`・`gourmet_race_dx`)・英雄の証(`eiyuu_no_akashi`・`eiyuu_no_akashi_milktea`)。
比べた前からの曲: トリコ・LAMIA・FREEDOM DiVE↓・Grievous Lady・Sheriruth・Monster Hero・crossing field。

## 結論

1. **新しい曲の作り(譜面・登録・音源)に、固まる原因になる誤りは見つからなかった。** 譜面は前からの曲と同じ形で、時刻の逆・NaN・重複・同時の重なりは0件。密度とホールド・スライドの点の数も、前からの曲の範囲に収まる
2. **CPU を4倍遅くすると、どの曲でも「止まって飛ぶ」が起きる。** 新しい曲だけ多くはない(50ms を超えるフレームは1分あたり、新しい曲 5〜53回・前からの曲 6〜42回。同時に回した組どうしで同じように増減した)。曲は音の時計で進み、ノーツは画面の描き(メインスレッド)が詰まると止まって、追いついたときに先へ飛ぶ。これは曲によらない作り
3. **止まりは、どの曲でも演奏の始まり(0秒目と2.2〜2.9秒目)に固まって出る**(100〜400ms)。途中の止まりは1曲で0〜5回、ばらばらの時刻で、譜面の密な所・ホールドの始まりとは重ならなかった
4. 新しい曲だけが違う所は2つ。**音源が 256kbps(前からの曲は 96〜128kbps が多い)と、ジャケットが 1170×1170(前からは 512×512)。** どちらも 11/15 の社長の決め(r1115-143「音質・画質を下げない」)どおり。演奏中の重さには、ここでは差が出なかった。ただし iPhone の記憶の少なさで効くかは、Chromium では確かめられない

**見立て: 主な原因は、社長の端末の重さと、曲によらない演奏画面の作り(とくに始まりの数秒の重い処理)。** 「最新曲で気づいた」のは、新しい曲を何度も遊んでいたためか、新しい曲が長め(166〜177秒)で、端末の記憶の余裕が減った可能性がある(下の「確かめられなかった物」)。

確かめられなかった物:

- MASTER・HELL: 鍵が開いていない状態で測ったので HARD だけ。社長が遊んでいる難易度で同じかは、鍵を開けて測る必要がある

## 3. 直し方の案(直す順)

| 順 | 何を | 中身 | 種類 |
