# 曲鑑賞(案B 詳細の窓から)を入れた(r1119-112 追記・2026-11-23 ビート)

選んだ譜面を自動で叩きながら曲を最後まで流す。止め絵は本物の画面を人と同じボタンで開いて撮った(切り欠きの余白あり・曲は MF × ICHIKA MIX)。
撮り直しと動きの確かめ: `node docs/progress/beat/auto-listen-b/shoot.js`(縦 390×844・横 844×390・小さい横 667×375・小さい縦 320×568。結果は [check-result.txt](check-result.txt))

## 記録に載せない(CLAUDE.md ⑦)

- 演奏は `from:'listen'` で始める。曲の終わりで結果へ行かないので、スコア・自己ベスト・全国ランキング・ビートP・周回・ミッション・日課・実績・相棒の処理を通らない(受け口でも `listen` は弾く)
- 練習と同じくライフは減らない・プレイの記録は送らない。保存するキーは増やしていない
- 確かめ: 鑑賞の前と後で `mh_rhythm_best*`・ビートP・ミッション等の保存値が同じ(縦・横とも OK)
- デバッグの曲えらびと、レイドの挑戦中の曲えらびには出さない。買っていない曲には出さない

## 作り

- 詳細の窓: `29-rhythm-screens.jsx` の `RhythmSongSelect`(`onListen` を渡したときだけ欄が出る。マルチの曲えらびは渡さないので変わらない)
- 自動で叩く手: オプションの「▶ 見てみる」と同じ `rhythmPreviewHandsStart`(`30-rhythm-preview-hands.jsx`)。曲の時刻が跳んだら指を離して移した先から叩き直すようにした(見本は跳ばないので動きは同じ)
- 鑑賞の帯と送る・戻す: `30-rhythm-play.jsx` の `RhythmListenBar`・`listenSeek`(音源の `seek` と、ノーツの作り直し)
- 始め方・戻り方: `60-app.jsx` の `startRhythmListen`・`rhythmListenProps`

## 分かっていること

- 単独の短いホールドを、まれに自動の手が取りこぼす(1曲に2つほど。回によって出ない)。鑑賞中は判定を出さないので、画面ではそのホールドが光らないだけ。オプションの見本の手と同じ叩き方なので、直すなら両方まとめて
- 🔄横(縦の端末で絵だけ回す)の鑑賞中は撮っていない
