# 「HELL でノーツがいきなり表示される」の調べ — Beyond the Same Sky HELL・横持ち(2026-11-22・ビート)

台帳 r1119-096 追記2(社長「あつみゅあのヘルでスカイと通常ノーツがかぶってるか何かで、いきなり表示されるみたいな現象があった気がした」)。
社長の答え: 横持ち(秒は不明)。譜面側の筋は前の会話で外れた(`../README.md` と引き継ぎメモ)。**表示側を調べた。直してはいない。**

## 調べ方(道具 `tools/mode/rhythm-note-appear-scan.js`)

実際の演奏画面(canvas・WebGL)を横持ち 844×390 で開き、曲の時計を **50ms ずつ止めて進め**、止めたコマごとに
描き手(`RHYTHM_CANVAS_RENDERER.drawNote`)へ渡ったノーツの番号と頭の位置(画面の座標)を記録した。ノーツごとに
「初めて描かれたコマ」と「頭の真ん中が画面の上端より下に入ったコマ」(=初めて見えた位置)を出し、
画面の途中で初めて見えた・途中で途切れた・判定の前に飛んだ、を数えた。測るブラウザの中だけで曲と HELL を開いた(本物の保存データ・ランキングには触らない)。
切り欠き: 演奏画面は safe-area の余白を持たない作りなので、横持ちの切り欠きが隠すのは左右の端だけ(ノーツの出る上端には関わらない)。

## 結果

| 譜面 | 向き | 測ったノーツ | 画面の途中でいきなり出た | 途切れ・判定前の飛び | 画面に入ってから判定までの残り(中央値) |
| --- | --- | --- | --- | --- | --- |
| 原曲 HELL | 横 844×390 | 1224(全部) | **0** | 0 | 地上 1972 ms / **空中 1652 ms** |
| short HELL | 横 844×390 | 709(全部) | **0** | 0 | 地上 1971ms / **空中 1651ms** |
| 原曲 HELL(0〜60秒・比べ) | 縦 390×844 | 288 | 0 | 0 | 地上 2049ms / 空中 1949ms |

- どのノーツも、出始め(progress −0.1)では画面の上端より上(y −22〜−37)で描かれ、そこから上端を越えて入ってくる。画面の途中で急に描かれ始めたノーツは両版とも0件
- **違いが出たのは空中ノーツだけ**: 横持ちでは、空中ノーツ(空中の板 原曲106・short48 全部、空中から始まるスライド 原曲13・short8)は地上ノーツより **約0.32秒遅れて** 画面に入る(縦持ちでは約0.1秒)。
  同じ時刻・近い時刻の地上ノーツが先に見えていて、空中ノーツだけが判定の約1.65秒前に、もう道の途中の大きさで上端から現れる
- しかも横持ちでは上端の真ん中に曲の時計(0:58/4:20 など)と進み具合の帯が重なり、空中ノーツはその裏から出てくる

## 原因(見立て)

空中の持ち上げ量 `rhythmSkyLiftPx(rect,yRatio)`(`data/rhythm-mode.js`)は、画面の上端より上(yRatio が0で止まる所)でも0にならず、
`高さ × RHYTHM_SKY_LIFT.ratio × 奥の縮み(0)/判定ラインの縮み` の分だけ持ち上げたまま残る。地上の道は奥の端が画面の上へはみ出ているので(横持ちでとくに大きくはみ出る)、
地上ノーツが上端を越えて見え始める時刻にも、空中ノーツはその分だけさらに上(画面の外)にいて、遅れて現れる。
縦持ちは道の奥が画面の中に近いので遅れが小さく(約0.1秒)、横持ちでは道の奥が大きく切れるので遅れが大きい(約0.32秒)。
「スカイと通常ノーツがかぶって、いきなり表示される」の聞き取りと合う(地上が先に見え、空中は後から急に、途中の大きさで出る)。

## 直し方の案(直す前に社長に確かめる・r1119-036)

1. **空中の持ち上げを道の奥ほど小さくし、画面の上端(道が画面から切れる所)で0にする**: 空中ノーツは地上ノーツと同じ時刻に上端から出て、近づくにつれて空中の段へ上がる。
   判定の所の高さ(空中の判定ライン)は今と同じ。全曲の HELL の空中ノーツの見え方が変わる(遠くでは地上の道に沿って見える)
2. **空中ノーツだけ、出始めを判定の約0.3秒前倒しして描く**(上端より上で描き始める範囲を空中だけ広げる): 見え始めは地上とそろうが、上端から途中の大きさで出る点は残る
3. **上端で薄く出す**(全ノーツ、画面に入ってから約0.15秒で不透明に): 現れ方がやわらぐだけで、空中の遅れは残る
4. 横持ちの時計・進み具合の帯を上端の真ん中からずらす(1〜3と組み合わせ)

おすすめは 1(遅れの元を消す)。どれも演奏画面の見た目だけで、判定・譜面・保存データ・ランキングには触らない。

## ほかの曲で同じ形

空中ノーツがある HELL は **82譜面すべて**(空中の板 3,724個・空中のスライド 1,608本)。この遅れは曲ではなく表示の式によるので、
横持ちで HELL を遊ぶと、どの曲でも空中ノーツが同じように約0.3秒遅れて現れる(多い順: 世界樹の祭壇 196・Stay With Me 188・departure 182・Beyond the Same Sky 147・RPG 143)。

## 道具の使い方

```
SONG_ID=beyond_the_same_sky DIFF=HELL node tools/mode/rhythm-note-appear-scan.js           # 横持ちで通し(20〜40分)
SONG_ID=beyond_the_same_sky W=390 H=844 TO=60 node tools/mode/rhythm-note-appear-scan.js   # 縦持ち・60秒まで
SONG_ID=beyond_the_same_sky FROM=57.65 TO=58.25 SHOT_EVERY=1 node tools/mode/rhythm-note-appear-scan.js  # その範囲を1コマずつ撮る
```

直したあとは同じ道具で、空中の「画面に入ってから判定までの残り」が地上とそろうかを見る。

## 直した(2026-11-22・社長「直す」→ 案1)

- `rhythmSkyLiftRatio`(`data/rhythm-mode.js`)へ式を1つにまとめ、持ち上げを「上端で0・判定ラインで前と同じ」にした。
  GPU の帯のシェーダー(`proj` の lift と `skyK`)と、演奏画面の空中の面・隠しの計算(`30-rhythm-play.jsx` の3か所)も同じ式を通す
- 横持ちで測り直した(原曲 HELL 0〜70秒): 画面に入ってから判定までの残りは **地上 1975ms / 空中 1977ms**(前は 1972 / 1652)。空中の遅れは無くなった
- 縦・横・PC(1280×800)の同じ瞬間を撮り比べ、崩れが無いことを見た。空中がいちばん多い Altar of the World Tree の HELL(148.75秒・横)でも、
  空中ノーツは道の奥から出て空の道へ上がっていく。計算の量は前と同じ(引き算が1つ増えただけ)なので、演奏中の重さは変わらない
- GPU の帯と 2D の絵の描き比べ(`rhythm-gpu-band-check.js`)で、上端で0に切った式は「抜け」が基準(0.3%)を超えた(Black Shout HELL 0.351%・Close to Your Heart HELL 0.315%)。
  上端より上も同じ1次の式のまま延ばす形にした(持ち上げは上端より上で負。画面の位置は地上の位置×(1−持ち上げの比)なので、上端を越える瞬間は地上と同じ)。
  これで Close to Your Heart は 0.000% に戻った。**Black Shout HELL 24.899秒(横 844×390)の1場面だけ 0.351% が残っている**(main は 0.007%)。
  ずれは上端ではなく画面の途中の「地上から空中へ上がっていく途中のスライド」の縁。空中の高さが時刻で変わる帯で、持ち上げとの掛け算を
  GPU(点を粗くつなぐ)と 2D が違う細かさでつないでいるためと見ている。未解決(GPU_BAND_ONLY=black_shout で1曲だけ回せるようにした)
- 測り直し(横・原曲 HELL 0〜45秒・1次の式に戻す前): 地上 1973ms / 空中 1958ms
