# ワルキューレ(原曲)のかくつき 調べと直し(2026-11-28 テンポくん)

台帳 r1126-100・追跡表 r1128-034。社長「ワルキューレの原曲がちょこちょこかくつく。発熱もあると思うけどノーツが多いときに起きやすい。原因調べてなおして」(iPhone)。

譜面(ノーツの数・位置)と判定のタイミングは変えていない。見た目も変えていない。

## 測り方

- 道具: `tools/playbot/rhythm-song-jank-scan.js`(今回作った)。ボットに曲を頭から終わりまで演奏させ、1秒ごとのコマの時間・描いたノーツ数・ノーツの密度、30秒ごとの JS の忙しさ・GC、ヒープ、判定のずれを出す
- 条件: 縦 390×844(端末の倍率2)・CPU を4倍に遅くする(CDP)・偽の Supabase(本物へは送らない)。描き方はゲームの自動(この環境は GPU が無いので 2D)
- 直す前は `origin/main` と同じ版(git worktree)、直したあとはこの枝。同じ条件で1曲ずつ順に測った(並べて測ると重さが混ざるため。HELL・EXPERT の直す前は、ほかの計測と重なったので測り直した数)
- 打ち方: `node tools/playbot/rhythm-song-jank-scan.js --song walkure --diff MASTER --cpu 4 --out <file>`(`--draw webgl` で iPhone と同じ WebGL の描き方、`--alloc 1` でメモリを作った所、`--lines <関数名>` で関数の中の重い行)

## 分かったこと

1. **ノーツが多い秒ほど重い**(MASTER: 1秒に7ノーツ以上の秒は33ms超のコマが15.6%、それ以外は8.2%)。1コマの重さは毎コマの処理(tick)の時間と強く連動していた(相関0.75)
2. **指が触れる・動くたびに、譜面の全ノーツをなめる処理が残っていた**(`heldBandNote`=押さえている帯の上へ置いた指かを探す所)。MASTER は3460ノーツあるので1回が重く、曲の後ろへ行くほど(済んだノーツが増えるほど)重くなっていた。ゲームの JS の中でいちばん重い所だった(iPhone と同じ WebGL の描き方でも上位)
3. 指が動くたびに、押している所の道の光(12本)の DOM を毎回読み直していた(`setPressedLanes`・タッチの幅の光)。iPhone の touchmove は指1本で毎秒60〜120回来る
4. WebGL の描き方では、GPU へ色・位置を送るたびに「前と同じか」を見るため数を文字列につないでいて、2分で約17MBのごみ(GC の元)になっていた(`u4f`)
5. 原曲だけの「音源を約20秒ごとに区切って広げる」仕組み(8分を超える曲だけ)は、**かくつきの元ではなかった**(広げた直後1秒の33ms超は7.4%、それ以外は10.6%)。つなぎ目合わせの作業用の配列だけ使い回すようにした
6. 1曲で1回だけ出る800〜1000msのコマは、曲の始まり(読み込み直後)。直す前も後も同じ

## 直したこと(どの曲にも効く)

| 所 | 直し |

## 見てもらう所(本番で)

- モンヒロビート → ワルキューレ(原曲)の MASTER・HELL を通しで。ノーツが多い所(連打・同時押しが続く所)で止まって飛ぶのが減ったか
- 長押し・スライドを押さえながらほかを叩く所で、取れ方(持ち替え・判定)が前と同じか
- ほかの長い曲・ノーツの多い曲でも同じく軽くなっているはず

## 残り(今回は触っていない)

- この環境で1コマを重くしている大半は 2D の絵を描く処理(drawImage・fill・色の段)で、iPhone(WebGL)では使われない。iPhone の GPU 側の重さはここでは測れない
- WebGL の描き方の道づくり(GL2D の `stroke`・`triangulate`)は描きかけの描画が配列を参照しているので、作り替えになる。必要なら別の仕事で

## 検査

- `run-checks.js --changed`: 必須の4つ(構文・見えない変数・「{」「}」・真っ白)と WebGL のノーツの画素の検査、入力の照合の検査(持ち替え・押さえている指・入れ替え・入力の場面・位置・マルチタッチ・入力の重さ)は通った
- 落ちた検査は、直す前の版(main)でも同じ所で落ちることを1本ずつ確かめた: BGM 4本(クリスマスのホームの曲・BGM の画面)・縦の演奏の題名・GPU の帯(試作の HELL 2場面)・結果の画面の折り返し・曲の購入の試し聴き・助手ライフ・回転の高さ・カードの対戦
- 書き方を文字で見ていた2つ(マルチタッチの「サブレーンを9で切り詰めない」・入力の重さの「変わったサブレーンだけ書く」)は、中身は同じなので書き方と検査を合わせた
