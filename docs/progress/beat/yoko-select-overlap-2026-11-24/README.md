# 横画面の曲選び: 難易度の札が「決定」の段に隠れる(r1119-161)

社長の写真: [`../tate-select-2026-11-24/shacho-select-yoko-overlap.png`](../tate-select-2026-11-24/shacho-select-yoko-overlap.png)
(iPhone 横 844×390・Stay With Me ~Locked Fate~ short ver.・HARD 799,166 などの数字の段が切れる)

## 原因

- 横(🔄横も)の右の欄は、「ランダム・決定」の段を欄の下に貼り付けている(sticky)。欄の中身があふれると、
  貼り付いた段がそのまま難易度の札の上にかぶさる。
- 版が3つある曲は、曲名が2行・版の札3つ・♡が折り返して次の行に落ち、欄が高くなる。iPhone ではさらに
  下の余白(ホームバーぶん 21px)が 8px に**足されて**いて、20px ほどあふれていた。
- あふれた時に詰める作り(r1119-140 の noteFit)は、**助手の一言を出している時だけ**働いていた。社長の写真は一言「切」で、詰める処理が動いていなかった。
- #7477(縦の案A)は縦(`data-rhythm-detail-slim`)だけの変更で、横の並びは変えていない。今回の重なりは #7477 が原因ではなく、
  以前からあった作りが、iPhone の字の幅(検査用の端末より広い)と長い曲名・3つの版で表に出たもの。

## 直したこと

- 横では一言の有無に関係なく、欄があふれたら段階的に詰める(`data-rhythm-song-note-fit` 1〜5)。
  1 札を詰める → 2 一言を出さない → 3 BPM・長さ・ノーツ数の行を畳み決定を46pxに →
  4 版の札と♡を1行に → 5 曲名の字を縮め、難易度40px・決定40px(568×320 など)。
- 横の下の余白は「8px + ホームバー」から「8px とホームバーの大きい方」に。
- 縦は #7477 の形のまま(どちらも横の時だけ効く)。

## 止め絵(`before/` 直す前・`after/` 直した後)

検査 `tools/mode/rhythm-song-detail-landscape-fit-check.js` が撮ったもの(全難易度に自己ベストを入れた形)。
「字が広い」は iPhone の字の幅をまねて字の間を広げた形。
