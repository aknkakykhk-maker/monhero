# 結果の画面の数え上げを滑らかに(2026-11-24・ビート・台帳 r1119-166)

社長(iPhone)「モンビーリザルト画面のスコアとかの数値の上がりだけどもっと滑らかに上がらないの？ カクカクしてる」

## 1. 原因(毎コマの数字を記録して確かめた)

数字の書き換えは、もともと requestAnimationFrame で毎コマ、要素の文字だけを直接書き換える作りだった(setInterval でも React の描き直しでもない)。
スコアは `tabular-nums`、判定の数は等幅の字なので、数字の幅で横に揺れることもない。カクカクの元は次の2つ。

| 原因 | 確かめたこと |
| --- | --- |
| **① 経験値の棒が、見えないうちから同じ時に動いていた** | 結果の下のビートランクの経験値の棒は 2.75 秒まで透明なのに、画面に入った瞬間から動き出し、毎コマ React で描き直し・`offsetWidth` で配置を強制計算・光の粒の要素を足していた。CPU の記録で `bumpAdd`・`boom`・`fullBurst` が上位。3秒間の処理の時間 1.67 秒 → 直した後 0.83 秒 |
| **② 判定の行の数え方が急すぎた** | 1行を 0.2 秒・3乗の減速で数えていて、出だしの1コマで行の数の 23%(189 なら 0→44)が一気に飛ぶ。11コマで数え終わる |

## 2. 直したこと

- 経験値の棒(`PlayerRankXpBar`)に `hold` を足し、モンヒロビートの結果では数え上げが終わる(タップで飛ばしたときも)まで動き出さない。既定は今までどおり(MFバトルカードは変わらない)
- 判定の行と MAX COMBO は2乗のゆるい減速(`rhythmCountEaseSoft`)にし、1行の数える長さを 0.2→0.25 秒(1行の間隔 0.26 秒の中)。スコアは3乗のまま(新記録の時刻が3乗で決まっている)
- 数え上げの長さ(約2.4秒)・順番(案A の1行ずつ)・音の時刻の決まり・入/切の設定は変えていない。演奏・判定・スコアの計算・保存・ランキングも触っていない
