## 今

空中スライドの帯の色は手で分けている。青(37,99,235)=左手・桃(244,114,182)=右手(`data/rhythm-mode.js` の `RHYTHM_SKY_LOOK_BASE.arc` と `RHYTHM_HELL_VIS_PRESETS.v2`、2026-10-12 の決め)。
地上を通る所も空中と同じ手の色なので、高さは色では分からない。**桃は上フリックのピンク(#f472b6)・作る予定のききのチャージノーツのピンクとかぶる。**

## 案

| 案 | 分け方 | 色 | よい所 | 気になる所 |
| --- | --- | --- | --- | --- |
| 案1 通る高さで色 | 同じスライドでも、地上を通る所は地上の色、空中を通る所は空の色。上がり下がりの間でなめらかに移る | 地上=紫(地上スライドと同じ 167,139,250)/空中=金(250,204,21) | 帯のどこが空中かが色だけで分かる。降りてくる所が「地上スライドになる」と読める | 1本の中で色が変わるので、左右同時のときは形で追う |
| 案2 スライドの種類で色 | 地上と空中を行き来するスライドと、空中だけのスライドで色を分ける(1本は1色) | 行き来=金/空中だけ=青(59,130,246) | 1本1色で追いやすい。「この帯は降りてくる」と最初から分かる | 今どの高さにいるかは色では分からない(影と形で見る) |
| 案3 1色+高さの光の幕 | 空中スライドは全部1色。空中を通る所の下へ薄い光の幕と点線を垂らし、地上のどこの真上かを見せる | 全部=金 | 色を覚えることが無い。真上・真下の位置が一番分かる | 幕のぶん描く物が増える(GPU で薄く1枚。重さは作るときに測る) |

## 色の候補(ほかのノーツとかぶらないか)

ほかのノーツ: 地上タップ=水色(56,189,248)・ホールド=緑・地上スライド=紫・上フリック=ピンク・横フリック=オレンジ/黄緑・空中タップと空中フリック=赤い板・ききのチャージノーツ=ピンク(予定)。

- **金(250,204,21)… 推し。** どのノーツとも色相が離れる。紫の道・赤い板の上でいちばん目立つ。横フリックのオレンジ・黄緑とは少し近いが、あちらは地上の小さな矢印なので見分けられる
- 青(59,130,246)… 案2の「空中だけ」。今の左手の青に近い。地上タップの水色より濃いので分かるが、空中だけに使う
- 空色(シアン 34,211,238)… 「空の色」らしいが、地上タップの水色とかぶるので避けた
- 桃・ピンク系 … 上フリック・チャージノーツとかぶるので使わない

## 決まって作ったもの(2026-11-23 社長の決め・r1119-149 追記)

社長「地上スライドはそのままで、スカイスライドを空中と地上で色分けは？いまの真ん中線で判断はそのままで」「空中は赤(青)、地上は青(赤)とかそんなかんじ。切り替わるとこの色はうまくやって」

- 空中スライドの帯は、**白い芯が出ている所=桃(空中)・出ていない所=青(地上)**。新しい色は使わず、今の2色を手(左右)ではなく通る所で使い分ける
- **桃を空中にした理由**: 空中のタップ・フリックが赤い板なので、空中=赤系でそろう。青は地上スライドの紫とも、地上タップの水色(明るい)とも見分けられる濃い青
- 切り替わりは白い芯の出始め・消える時刻(`rhythmSlideSkyCoreSpans`)をまん中に、前後45msでなめらかに移す(`RHYTHM_SKY_COLOR_BLEND_MS`)。2D(`fillSkyQuad`)と GPU の帯(mode 9)で同じ区切り・同じ式
- 白い芯の出方・地上だけのスライドの色・判定・点・譜面は変えていない
- 押さえている間の頭の板・火花も手の色をやめた(頭はその時刻の帯の色、火花は桃)
- ヘルプの見本の絵は「空中を通る所(桃)」「地上を通る所(青)」の2つにした
