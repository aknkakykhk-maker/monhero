## 段変えが残る構造的な理由（コード調査）
- 違反の定義（rhythm-hell-mix.js の levelSwitchViolations）: 同じ親指の連続ノーツで段（空⇄地上）が変わり、間が1.5拍未満。216 BPM では1.5拍＝約417ms と広く、約2,700ノーツ/692秒の密度では空の出入りが多いと恒常的に発生する。
- 既存の仕上げ（settleSwitches）の対象は 150ms/250ms 以内の速い持ち替えだけ。違反の間の分布（phrases を変えた見当付け26件で実測）: 138〜348ms で、277ms 以上が11件と、仕上げの窓の外が4割強。
- 違反の起因（同26件）: 空タップ起因10件・スライド起因3件・「前のノーツが空」13件。9割近くは空タップを地上へ下ろせば消せる種類。
- mixBest の precision 探索は「空の量を9割以上保つ」ことを優先して候補を選ぶため、段変えの少なさでは選んでいない。

### 実装: settleLevelSwitches（段変えの仕上げ）
- 置き場所: 作業用コピー `prep/work/tools/mode/rhythm-hell-mix.js`（本体リポジトリ無変更）。`settleSwitches` の直後に追加し、`module.exports` にも追加。
- 仕様: 同じ親指が1.5拍未満で段を変える違反（窓は BEAT_GAP 拍＝BPM から決まる一般形）について、違反の空側にある空タップ（モンスターノーツ以外・交差の区間の外）を地上へ下ろす。
  - 第1段階（貪欲）: 1つ下ろすたびに物差しを取り直し、違反が減り、かつ 押せない（横持ち＋地上だけのシミュレート）・水平クロス・帯の中・見分けにくい所・指が同じ位置に来る形 が増えないときだけ採る。
  - 第2段階（動的計画法）: 貪欲では「1つ下ろすと反対側に違反ができる」空タップの連なりで止まるため、手ごとに下ろせるタップの段の割り当てを選び直し、タップの下ろしだけで届く違反の最小値を出す。丸ごと当てて違反が減り物差しが悪化しないときだけ採る。
  - スライドが段を作る違反・実ノーツどうしの違反は触らず、残件として内訳（スライド起因／下ろせなかったタップ／その他）を数える。時刻・位置・ノーツ数は変えない。
- opt-in: `mixBest` の `opts.levelSettle`（precision 経路・通常経路の両方）と CLI フラグ `--level-settle`（または SONGS の `levelSettle:true`）でのみ動く。フラグ無しでは従来の呼び出しに一切触らない。`--write` と併用するときは SONGS への `levelSettle:true` 記入を必須にするガードも precision と同じ形で追加。
- 単体テスト: `prep/test-levelsettle.js`（合成ノーツ7ケース: 基本の下ろし／スライド起因は不変／窓の外は無干渉／モンスター不変／ノーツ数不変／連なりのDP解決／スライドに挟まれた空タップは1件残る）— 全件合格。
- 既存挙動不変の確認: フラグ無しの見当付け（下記P1・P2の「mixのみ」「settle後」の段変え件数）が従来 scout の値と一致することでも確認する。

### 結論（見当付け5パターン・2026-11-22 切り上げ）
**後処理の拡張だけでは、上限に届く候補は出なかった。** 最良は P2／P4 の段変え6件（上限4・Lv.61）で、残りは全部スライド起因——タップの下ろしでは原理的に消えない分だった。タップ起因の違反は levelSettle でほぼ消せることが実証できた（P2: 18→6、タップ分は0）ので、残る壁は「スライドの段の出入りをどう扱うか」に絞られた。進め方の決まり（見当付け最大5パターン）に従い、ここで切り上げて判断を上げる。公式測定は合格候補が出なかったため回していない。

### 残る選択肢（トレードオフ付き・判断はあっくん／窓口）
1. **スライド起因への対処を後処理に広げる**: levelSettle の対象に「スライドの端の段を変える（形の反転・down↔up の付け替え）」を含める。P2 の床6件が対象になる。長所: 既存の仕上げ（mix 内の fix がスライドの形を付け替える）の延長で筋が通る。短所: スライドの見た目と空中感が変わる。共有道具の変更範囲が広がるので窓口の判断が要る。
2. **生成側（mix のスライド形の付け方）で段変えを抑える**: fix／backFix の条件に1.5拍窓の違反数そのものを組み込む。長所: 根本対処。短所: 既存曲の再生成結果が変わりうるため影響範囲が最大。検証も重い。
3. **gentle 型で作る**: 段変えはほぼ消える。短所: HELL の空中感と Lv が大きく変わり、この曲の狙い（高速・高密度）から外れる。
4. **基準（上限表）の妥当性を窓口と確認する**: 上限表 0／2／4／6 は SAME_PLACE_ALLOW の流用で、216 BPM 級の既存公開 HELL を同じ物差しで横並びに測った実績がない。実績次第では「この曲だけ届かない」ではなく「物差しが高速曲に合っていない」可能性がある。基準を動かす判断は窓口側。
5. **P2 構成を公式（mixBest）で1回だけ測る**: 見当付けは mix 単体＋energyBias 0 固定だが、公式の mixBest は引き出しの取捨と bias 選択に段変え件数を含むスコア（handRuleScore）を使うため、公式では見当付けより下がる余地が残る。短所: 1回60〜110分かかり、スライド起因の床が mix の中身に残る以上、合格見込みは低い。
