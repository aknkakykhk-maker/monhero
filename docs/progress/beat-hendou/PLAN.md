# 流れの速さが変わる譜面(変動ギミック)の案 — ヘンドウ 2026-11-11

社長「新曲追加。高難易度曲。曲にあわせて止まったり戻ったりとか変動型」。新曲 LAMIA で使う。

## いまあるもの(調べて分かったこと)

**仕組みの土台は、もう本体にある。** 2026-10-10〜11 に試作として入り、公開中の3曲で使っている。

| 曲 | 使っている所 |
| --- | --- |
| Sheriruth(全難易度・HELL) | 止まる |
| Grievous Lady(全難易度・HELL) | 戻る → 止まる → 一気に駆け込む(3か所) |
| Evans(全難易度・HELL) | 止まる・戻る・だんだん遅く(7か所) |

- 譜面に `scrollChanges:[[時刻ms, 書き方…], …]` を書くと、その時刻から先のノーツの**見た目の位置だけ**が変わる。
  判定・スコア・ランキングは曲の時刻のまま(`monster-hero/data/rhythm-mode.js` の `rhythmScrollPos`)。書いていない曲は今までと同じ計算
- 書き方は5つ: 倍率(0で止まる)・`RUSH`(奥から一気に来る)・`MOVE`(道の何割か動く。マイナスで戻る)・
  `LERP`(だんだん変わる)・`GLIDE`(弾むように行って戻る)。動く量は道の長さで決めるので、ノーツ速度3でも10でも同じ見え方
- 組(`scrollGroups` + ノーツの `scrollGroup`): 「次に叩くノーツはふつうに来て、その奥だけ止まる・戻る」が書ける
- ヘルプに「ノーツの流れが止まる・戻る曲があります」がもうある

**足りないもの**(今回作るのはここ)

1. 止まる・戻る前の**予告**、速さが変わる所の**色の帯**が無い(初見では読めない)
2. 苦手な人向けの**弱める/切る**の設定が無い
3. **マルチ観戦**(#5359 `RhythmWatchLane`)は時刻どおりの直線で描いていて、止まる・戻るが映らない
4. **譜面生成ツール(MHB CHART ENGINE)から置く口が無い**。Evans は `rhythm-mode.js` に手で表を書き、
   止まる間に叩くノーツへ組を手で付けた。曲ごとに手書きだと間違えやすい
5. 検査が曲ごと(`grievous-lady-scroll-check.js`)で、**どの曲にも効く検査が無い**
6. 「一瞬で位置が飛ぶ」(速度ジャンプ)は書けない(`MOVE` を短くして近いことはできる)

## 社長に選んでもらうこと

### 問1 LAMIA で使う動き(複数可)

- **A 今ある5つ(止まる・戻る・一気に来る・だんだん速く/遅く・弾む)だけで作る(推奨)** — 本体の計算は変えない。公開中の3曲と同じ見え方
- B Aに「一瞬で位置が飛ぶ(ワープ)」を足す — 計算に1つ足す。ノーツが目で追えなくなるので HELL・MASTER だけ
- C Aに「ノーツごとに速さが違う(速い列と遅い列が混ざる)」を足す — 組の仕組みで書ける。読みが大幅に難しい

### 問2 見やすさの手当て

- **A 予告(止まる・戻る の約1拍前に、判定線の上へ小さく「STOP」「BACK」)+ 速さが変わる区間だけ道の両はしに色の帯(推奨)**
  (止まる=水色・戻る=赤紫・速くなる=橙。帯は道の奥から流れて来るので、来る前から見える)
- B 色の帯だけ(文字は出さない)
- C 何も出さない(今の3曲と同じ。初見殺しも楽しみのうち)

### 問3 苦手な人向けの設定

- **A 付けない(推奨)** — 高難易度曲の見せ場なので。叩く時刻は音楽どおりなので、慣れれば読める
- B 「変動を弱める」(止まる・戻るの量を半分)を付け、ランキングは今のまま送る — 叩く時刻は同じなので点数は比べられる
- C 「変動を切る」を付け、切った演奏はランキングへ送らず自己ベストも上書きしない(⑦のクイックと同じ扱い)

### 問4 マルチ観戦の譜面

- **A 観戦でも同じに止まる・戻る(推奨)** — 観戦のレーンの位置の式を同じ表に替えるだけ。持ち場はショウタイなので、触る前に知らせる
- B 観戦は今のまま(時刻どおりの直線。判定が見やすい)

## 作り(問の推奨で進めた場合)

- **譜面の書き方は足すだけ**: 今の `scrollChanges`・`scrollGroups` はそのまま。予告・帯は表から自動で出す(譜面に書き足すものは無い)。
  書いていない曲は今までとまったく同じ
- **判定・スコア・ランキング・保存データは変えない**(見た目の位置だけ)
- **譜面生成ツールの口**: 曲の一覧(`tools/mode/`)に `scrollFx` を書く。
  `[{at:'1:23.450', kind:'stop', len:450}, {at:'1:30.000', kind:'back', amount:0.2, len:800}, {at:'1:40.000', kind:'ease', to:2, len:1000}]` のように**曲の時刻と長さで書く**と、
  ツールが `scrollChanges` に直し、止まる・戻る間に叩くノーツへ組を自動で付けて `rhythm-mode.js` へ出す(Evans の手書きを道具にする)。
  `quiet:true` を付けた区間はノーツを置かない(Grievous Lady の「演出の最中は来ない」)
- **検査を1本**: `tools/mode/rhythm-scroll-fx-check.js` — 表を持つ全曲・全難易度・ノーツ速度1〜12で
  ①判定より前に判定線へ触れるノーツ0 ②曲の終わりまで止まりっぱなし(倍率0)が無い(Evans で固まった件)
  ③1コマで動く量の上限 ④止まる・戻る間に叩くノーツは組で流れて来る ⑤予告が演出の前に出る
- **重さ**: 位置の計算は今もしている(表は数十行・二分探索)。足すのは帯の四角を数枚と予告の文字1つで、1コマの増えはごくわずか。
  軽さ優先の見た目でも予告は出す(読むために要るので)
- **ボットの自動プレイ・Lv.**: ボットは曲の時刻で叩くので影響なし。Lv. の式は変えない(Evans と同じく、表示は社長に見せて決める)。
  点検に「止まった直後・駆け込みの直後のノーツ数」を参考として出す

## 2026-11-11 追記: 社長「変動式はもう何曲かでやってるからそれを参考にしてもっと改善できるとこがあればすればいいよ」

既存3曲を手本にして、**既存の曲の見え方を変えない改善**から入れた。

- **変動の口 `rhythmScrollFxChart`**(`rhythm-mode.js`): 曲の時刻と長さで演出を並べると、表と組を作る。Evans の手書き(止まる間のノーツへ組を付ける)を道具にした。
  Evans MASTER を口で書き直すと、手書きと同じ表になることを確かめた
- **全曲の検査 `rhythm-scroll-fx-check.js`**: 表を持つ18譜面・ノーツ速度1〜12で、早触れ0・終わりで止まりっぱなしにならない・1コマの動きが道の25%以下(いまの最大10.4%)・口の決めどおり
- 書き方: `docs/rules/CHART_ENGINE.md`「流れの速さが変わる譜面」

### 見つかった既存の問題(公開中の譜面なので直していない・窓口へ報告)

Evans の EXPERT・MASTER・HELL で、**84.687秒のノーツが、84.23秒の「行って戻る」の始まりの時点で判定線に着いて見え、奥へ戻ってからまた来る**
(ノーツ速度1以外の全速度)。行きと帰りで差し引き0なので、窓の終わり(84.68秒)の直後のノーツは戻る前から判定線にいる。
直すならそのノーツに組1を付けるだけ(叩く時刻・ノーツ数は変わらない)。検査では既知として通している(増えたら止まる)。
