# モンヒロビートの見た目の強化と重さ(2026-11-11・キラメキ)

社長「モンビーの見た目を強化して更に重さを維持または軽くする方法も見つけさせてほしい」への、①今の重さ ②原因と軽くする方法 ③見た目の案。
**ゲーム本体は変えていない**(足したのは測る道具と、この資料だけ)。譜面・判定・音にも触れていない。

## 2. 重さの原因の上位(`--trace` で名指し)と、軽くする方法

| 順 | 原因 | 数字(標準・横・CPU 1/4) | 軽くする方法 |
| --- | --- | --- | --- |
| 1 | **ノーツの canvas 1枚ぶんの画素**。毎フレーム全面を消して、画像 約58枚(画面0.38枚ぶん)+図形 約37個を描く | 1フレーム 約27ms(全体の半分強)。canvas を隠すと 0.8ms | 描く量はもう少ない。**同じ大きさの canvas をもう1枚重ねると 50→87ms(約1.7倍)**(見本で実測)。だから新しい演出は「今ある1枚の中」に描き、層を足さない |
| 2 | **全部のせ・華やかの背景の層**。光の粒2枚だけで画面4枚ぶん、ほかに全面の層が7枚 | 層 13枚(5.8)→33枚(16.3)。GPU 担当の仕事 4→12ms/フレーム | 動かない光(道のもや・帯・ビームの元絵)を1枚にまとめ、粒は画面の大きさに切る。層 33→約15枚・面積 16→約8枚ぶんの見込み。見た目が同じかを画素で確かめてから出す仕事(次の仕事) |
| 3 | **動き続ける CSS アニメーション**(ライフのハート・判定線の脈・粒・ビーム・盛り上がりの筋)。動かすのは transform と opacity だけだが、演奏中は毎フレーム型の再計算が走る | 標準 1フレーム 5.7要素・全部のせ 28.9要素。全部のせで 9〜13ms(絞って) | canvas の中で描く物へ移せば 0 になる。案 A・B を作るときに一緒に移す |
| 4 | 判定の文字・コンボ・スコアの書き換え(レイアウトが根から走る) | 1フレーム 0.5回・0.5〜1.2ms(絞って) | 小さい。いまは触らない |

**軽くするだけで見た目が変わらない直しは、今回は出していない。** 標準はすでに無駄が少なく、確かめずに出せる大きな直しが無かったため。2位(背景の層をまとめる)は効きが大きいが、見た目が同じことを画素で確かめる必要があるので、案が決まってから同じ仕事でやるのが安全。

## 4. モードえらび・曲えらびの飾り(窓口からの追加・main 取り込み後に測定)

`node tools/mode/rhythm-weight-report.js --screen mode --trace` / `--screen select --trace`(触らずに止まったまま8秒)。

| 画面 | 動き続けるアニメーション | 層(画面◯枚ぶん) | 型の再計算 | 塗り直し |
| --- | --- | --- | --- | --- |
| 曲えらび | 0本 | 2枚(10.3。曲の一覧の長い1枚) | 0 | 0 |
| モードえらび([今の絵](shots/M-mode-select-now.jpg)) | **22本**(光の粒6・のぼる音符6・ビーム3・床と光2・助手の浮き1・ボタンの光るすじ4) | **45枚**(6.9) | 毎フレーム22要素(0.24ms・絞って1.15ms) | 0.4枚/秒 |

- 曲えらびは、止まっていれば何も動いていない(カルクの #5218 のあと)。直す所なし
- モードえらびは CPU の仕事は小さい(60fps・JS 0.1ms)。重いのは GPU 側で、**すりガラス(背景ぼかし)の箱が8つ、動く背景の上に乗っている**ため、後ろが動くたびにぼかしを毎フレーム作り直している。これに層45枚の重ね合わせが加わる
- 案(どれも見た目に関わるので、社長が選んでから作る):
  - **M1 すりガラスをやめて、濃い半透明の色にする**。ぼかしの作り直しが 0 になる。透け感が少し減る(いちばん効く見込み)
  - **M2 飾りをまとめる**。粒6+音符6を「1枚の絵が流れる」形に、ボタンの光るすじは4本同時→順番に1本。22本→約9本・層45→約25枚。見た目はほぼ同じ
  - **M3 10秒触らなければ飾りを止める**(触ったらまた動く)。置きっぱなしのときの電池と熱に効く。触っている間の見た目は同じ

## 5. 道具の使い方

```
node tools/mode/rhythm-weight-report.js            代表の8場面(約5分)。最後の1行が OK / NG
node tools/mode/rhythm-weight-report.js --quick --check   2場面だけ・予算を超えたら NG(約1分)
node tools/mode/rhythm-weight-report.js --quick --trace   原因さがし(時間の内訳・大きい層・動いているアニメーション・再計算の出どころ)
node tools/mode/rhythm-weight-report.js --screen mode --trace    モードえらび(--screen select で曲えらび)を止まったまま測る
sh docs/progress/kirameki-2026-11-11/make-mocks.sh        見本の写しを作る → --inject look-mock-A.js --shot a.png で撮る・測る
```

`--trace` を付けるとレイアウトの時間が大きく出る(測る仕組みの重さ)。時間は付けないときの数字を見る。

## 6. 社長の選択(2026-11-11)と、そのあとの進み

社長は4つとも推奨を選んだ: ①A 判定の光+C コンボの熱・フルコンボ ②標準から入れる(軽さ優先には出さない) ③全部のせ・華やかの背景の層をまとめる ④モードえらびは M1+M3。

### ④ モードえらび(作った・ブランチ `claude/beat-mode-select-light`・**公開は社長の「この文で」のあと**)

- M1: すりガラス(backdrop-filter)をやめ、濃い半透明の色を敷いた(見出し・助手の枠と小さいボタン `.mhms-glass`・立ち絵/コメントの切替)
- M3: 10秒さわらなければ飾りを止める(`html.mhms-idle` で `animation-play-state:paused`。さわれば続きから動く。画面は描き直さない)
- 同じ舞台(`RhythmModeSelectStage`・`.mhms-glass`)を使うモンヒロバトル・MFバトルカードの入口にも同じく効く
- 止め絵: [前](shots/M-mode-select-now.jpg) / [後](shots/M-mode-select-after.jpg)(見た目はほぼ同じ)

| モードえらび・横 | 背景ぼかしの箱 | 層 | 動くアニメーション | 型の再計算 |
| --- | --- | --- | --- | --- |
| 前 | 9個 | 45枚 | 22本(ずっと) | 毎フレーム22要素 |
| 後 | **0個** | 39枚 | 22本 → **10秒で0本** | 止まったあとは0 |

更新履歴の案(社長の「この文で」待ち):

> 題: モンヒロビートのモードえらびを軽くしました
> 本文: モードえらびの画面の動作を軽くしました。しばらく操作しないと背景の光や音符の動きが止まり、画面にさわるとまた動きます。モンヒロバトル・MFバトルカードの入口の画面も同じように軽くなっています。

ヘルプの案: 追記なし(遊び方は変わらないため。入れるなら「動作が重いとき」の項に「入口の画面は、しばらく操作しないと飾りの動きが止まります」の1行)。
