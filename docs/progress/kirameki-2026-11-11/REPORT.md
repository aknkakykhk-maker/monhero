# モンヒロビートの見た目の強化と重さ(2026-11-11・キラメキ)

社長「モンビーの見た目を強化して更に重さを維持または軽くする方法も見つけさせてほしい」への、①今の重さ ②原因と軽くする方法 ③見た目の案。
**ゲーム本体は変えていない**(足したのは測る道具と、この資料だけ)。譜面・判定・音にも触れていない。

## 2. 重さの原因の上位(`--trace` で名指し)と、軽くする方法

| 順 | 原因 | 数字(標準・横・CPU 1/4) | 軽くする方法 |
| --- | --- | --- | --- |
| 1 | **ノーツの canvas 1枚ぶんの画素**。毎フレーム全面を消して、画像 約58枚(画面0.38枚ぶん)+図形 約37個を描く | 1フレーム 約27ms(全体の半分強)。canvas を隠すと 0.8ms | 描く量はもう少ない。**同じ大きさの canvas をもう1枚重ねると 50→87ms(約1.7倍)**(見本で実測)。だから新しい演出は「今ある1枚の中」に描き、層を足さない |
| 2 | **全部のせ・華やかの背景の層**。光の粒2枚だけで画面4枚ぶん、ほかに全面の層が7枚 | 層 13枚(5.8)→33枚(16.3)。GPU 担当の仕事 4→12ms/フレーム | 動かない光(道のもや・帯・ビームの元絵)を1枚にまとめ、粒は画面の大きさに切る。層 33→約15枚・面積 16→約8枚ぶんの見込み。見た目が同じかを画素で確かめてから出す仕事(次の仕事) |
| 3 | **動き続ける CSS アニメーション**(ライフのハート・判定線の脈・粒・ビーム・盛り上がりの筋)。動かすのは transform と opacity だけだが、演奏中は毎フレーム型の再計算が走る | 標準 1フレーム 5.7要素・全部のせ 28.9要素。全部のせで 9〜13ms(絞って) | canvas の中で描く物へ移せば 0 になる。案 A・B を作るときに一緒に移す |
| 4 | 判定の文字・コンボ・スコアの書き換え(レイアウトが根から走る) | 1フレーム 0.5回・0.5〜1.2ms(絞って) | 小さい。いまは触らない |

**軽くするだけで見た目が変わらない直しは、今回は出していない。** 標準はすでに無駄が少なく、確かめずに出せる大きな直しが無かったため。2位(背景の層をまとめる)は効きが大きいが、見た目が同じことを画素で確かめる必要があるので、案が決まってから同じ仕事でやるのが安全。

## 3. 見た目の強化案(止め絵は `shots/`。見本は撮影のために上へ重ねた物で、本体には入っていない)

いまの見た目: [標準](shots/00-now-standard.jpg) / [全部のせ](shots/00-now-full.jpg)

| 案 | 中身 | 止め絵 | 重さの見込み |
| --- | --- | --- | --- |
| **A 判定の光** | 叩いた所から光の柱が立ち、輪が広がり、光の粒が8個はねる。同時に出るのは10個まで | [A](shots/A-hit-light.jpg) | 今ある1枚へ描けば、画像 +最大110枚/フレーム(小さい絵)。JS +0.5ms 前後。3位のアニメーションを canvas へ移すぶんで相殺できる見込み |
| **B レーンと判定線のネオン** | 判定線を太い光に、レーンの境に手前へ流れる光、道のふちを水色とピンクで縁取り、奥に光 | [B](shots/B-lane-neon.jpg) | 動かない部分は1回だけ焼いて貼る(画像 +2枚)。流れる光は 21本。JS +0.4ms 前後 |
| **C コンボの熱** | コンボが伸びるほどコンボの後ろの光が強く金色に、節目(10ごと・本番は50/100ごと)で輪と光の筋、画面の両はしに流れる光 | [C](shots/C-combo-heat.jpg) | 画像 +約20枚/フレーム。JS +0.3ms 前後。いちばん軽い |
| C のおまけ フルコンボ | 曲の最後に帯・虹色の文字・紙ふぶき(約1.5秒) | [C2](shots/C2-full-combo.jpg) | 演奏が終わったあとなので、演奏の重さには影響しない |

- どの案も「軽さ優先」では出さない。標準に入れるかは案ごとに決められる(おすすめ: A と C は標準から、B は華やかから)
- 見本を重ねたままの実測(標準・横・CPU 1/4・canvas を1枚足した多めの数字): 何もなし 50ms/フレーム → A 87 / B 79 / C 73。**この差のほとんどは「足した1枚」のぶん**なので、本番は今ある1枚に描く
- 作ったあとは `node tools/mode/rhythm-weight-report.js --check`(予算 `tools/mode/weight-budget.json`)と `rhythm-gpu-estimate.js --check` の両方で、重くなっていないことを確かめてから公開する

## 4. 道具の使い方

```
node tools/mode/rhythm-weight-report.js            代表の8場面(約5分)。最後の1行が OK / NG
node tools/mode/rhythm-weight-report.js --quick --check   2場面だけ・予算を超えたら NG(約1分)
node tools/mode/rhythm-weight-report.js --quick --trace   原因さがし(時間の内訳・大きい層・動いているアニメーション・再計算の出どころ)
sh docs/progress/kirameki-2026-11-11/make-mocks.sh        見本の写しを作る → --inject look-mock-A.js --shot a.png で撮る・測る
```

`--trace` を付けるとレイアウトの時間が大きく出る(測る仕組みの重さ)。時間は付けないときの数字を見る。
