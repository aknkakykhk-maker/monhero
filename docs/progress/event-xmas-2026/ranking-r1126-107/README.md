## 2. 並べる物と数え方

| 並べる物 | 数え方 | 推し |
| --- | --- | --- |
| **見たエンドの数**(はじめのタブ) | 見たエンドの**種類**の数。サーバーの「数えてよいエンドの一覧」(表 `xmas_novel_end_ids`)にある物だけ数える。**全部の数もこの一覧から数える**ので、分かれ道とエンドを増やしたとき(r1126-108)は、弾を出すときに窓口が一覧に行を足すだけで「◯/33」のように増える。端末の地図・エンドヒストリーは今どおり台本から数える(`xmasNovelMapModel().endTotal`) | ◎ 社長の言葉どおりで、遊ぶほど増え、ずるがしにくい(種類なので同じエンドを何度見ても増えない) |
| **読んだ回数**(社長の「遊んだ回数」) | **エンドに着いた回数**。強制バッド・名指し・おまけも1回。ただし**同じエンドは1日(朝4:00区切り)に1回まで**。見取り図の↺・強制バッドの「選択の直前からやり直す」で着いた分も数える | ○ 「何を1回とするか」はエンドに着いたとき、が一番分かりやすい。1日1回までにすると、強制バッドの往復で数を盛れない(1日の上限=エンドの種類の数) |
| **一発正解** | 推理の問い①〜⑥と1回目の推理(犯人+動機)の7つのうち、**一番はじめに答えたとき**に一発で当てた数(0〜7)。今の起動画面の「一発で当てた数」と同じ(`xmasNovelPerfectCount`)。読み直しでは変わらない | ○ 上手さで並ぶ。ただし多くの人が同じ数になるので、同点の並べ方が大事(下) |
| (候補から外した)クリアまでの速さ | 序章から真グッドまでの時間 | × 読む速さ・オートの速さ・裏へ回した時間で変わり、物語を急がせる |
| (候補から外した)遊んだ日数 | 事件簿を開いた日の数 | △ 数は盛れないが、遊んだ中身が出ない。聞きたい事2の選択肢に残す |

### 同点の並べ方

- 見たエンド: 同じ数なら、**先にその数に届いた人**が上(最後に増えたエンドをはじめて見た時刻が早い順)
- 読んだ回数: 同じ数なら、先にその回数に届いた人が上
- 一発正解: 同じ数なら、**見たエンドの多い人**、それも同じなら先に決まった人が上
- 順位の付け方は今のランキングと同じ `rank()`(同じ数・同じ時刻なら同じ順位)

## 3. ずるの防ぎ方・送る時機

| 心配 | 防ぎ方 |
| --- | --- |
| 数を大きく送る | **端末は数を送らない**。送るのは「どのエンドに着いた」「どの問いを一発で当てた/外した」という出来事だけで、数はサーバーが表から数える。一覧に無いエンドは数えない。一発正解の問いの名前も決まった8つだけ |
| 見取り図の↺・やり直しで増やす | 見たエンドは種類なので増えない。読んだ回数は(人・日・エンド)で1行なので、同じ日に同じエンドは何度着いても1回 |
| 一発正解を後から書き換える | 問いごとに一度入れたら変えない(読み直し・はじめからでも変わらない。端末の `first` と同じ決まり) |
| 他人になりすます | 書くのは関数だけ。持ち主の鍵(助手マスモン対戦などと同じ `mh_masmon_pvp_owner_key_v1`・`masmon_pvp_owner_check`)が合わないと受けない |
| 送りすぎ | 5秒に1回・1日300回まで(`xmas_novel_usage`) |
| デバッグ | 時計をずらす・強制表示などデバッグの状態では送らない(ほかのランキングと同じ) |
| 怪しい人 | 消さずに `hidden` で一覧から隠す(SQL の末尾に例) |

- 端末の側に限っては「数を送る」より弱いので、完全には防げない(作った送り方をまねて、見ていないエンドを送ることはできる)。一覧にある本物のエンドしか数えないので、上限は「全部見た」と同じ所で止まる
- **送る時機**: ①エンドの札が出たとき(今の `xmasNovelRecordEnding` と同じ所)②推理の問いに一番はじめに答えたとき(`xmasNovelRecordFirst` と同じ所)③ランキング・起動画面を開いたとき(ためていた分を送る)
- **前の記録の取りこみ**: ランキングを入れる前に見たエンド・一発正解(`mh_xmas_novel_v1` の `endings`・`endAt`・`first`)は、はじめて開いたときに1回だけまとめて送る(`seed`)。サーバー側も人ごとに1回だけ受ける(`seeded` の印)。日時は `endAt`(無い・おかしい物は送った時刻)
- 端末に足す保存は**新しいキー** `mh_xmas_novel_rank_v1`(`{ v:1, seeded:0|1, pending:[{kind,end_id|qid,ok}] }`・ためる分は50件まで・壊れていたら既定値)。`mh_xmas_novel_v1`・`mh_xmas_novel_route_v1` は読むだけで形も中身も変えない
- 名前はほかのランキングと同じプレイヤー名

## 4. 表の形と SQL

本文は [`xmas_novel_rank.sql`](xmas_novel_rank.sql)。サクセスのランキング(`202611120003_monsuc_rank.sql`)と同じ作り(書くのは関数だけ・見え方は読むだけ・何度流しても同じ)。

| 表・見え方・関数 | 中身 |
| --- | --- |
| `xmas_novel_end_ids` | 数えてよいエンドの一覧(今の16を入れる)。弾を出すたびに窓口が `insert … on conflict do nothing` で足す |
| `xmas_novel_players` | 人ごとの名前・取りこみ済みの印・隠す印 |
| `xmas_novel_plays` | 1行 = (人・日・エンド)。見たエンドの数と読んだ回数はここから数える。一覧に無いエンドも残す(後で一覧に足せば数える) |
| `xmas_novel_firsts` | 1行 = (人・問い)。一番はじめの答えだけ |
| `xmas_novel_usage` | 送った回数(読ませない) |
| `xmas_novel_rank_ends` / `_plays` / `_perfect` | 3つのタブの見え方(順位 `place` つき・持ち主の id は出さない) |
| `xmas_novel_rank_submit(owner, key, row)` | 送る口(`end` / `first` / `seed`)。返り値に自分の数と順位 |
| `xmas_novel_rank_mine(owner, key)` | 送らずに自分の数と順位を見る |

- どの表にも `event_id`(既定 `xmas_novel_2026`)を持たせた。次の事件簿(別の話)を作ったときも同じ表に足せる
- **確かめ: この会話の作業場所では一時的なデータベースが権限で起動できず、SQL を流して試すことはできていない**。文は読み直して確かめた。流す前に窓口の側で一度試してほしい(作るとき、バトル部の検査道具で送る口を試す)

## 6. 社長に聞きたい事(選択式)

1. **はじめに開くタブ(主役)はどれにする？**
   - 見たエンドの数(推奨): エンドが増えるほど遊びがいが続く
   - 読んだ回数
   - 一発正解
2. **「遊んだ回数」は何を1回と数える？**
   - エンドに着いた回数・同じエンドは1日1回まで(推奨)
   - 遊んだ日数(開いた日の数)
   - エンドに着いた回数・制限なし(↺の往復でいくらでも増える)
3. **入口はどこに置く？**
   - 事件簿の起動画面とイベントページの物語タブの両方(推奨)
   - 事件簿の起動画面だけ
   - イベントページの物語タブだけ
4. **順位に応じたごほうびは付ける？**
   - なし・見るだけ(推奨): 物語を急がせない
   - 上位に称号
   - 見たエンドの数で、全員に段階のごほうび
