## ② 特殊ルールの方向(どれもヘルヘイムのルールの上に足す)

強くするだけでなく、1つ「新しい手ごたえ」を入れる。ヘルヘイムをクリアした編成(上位は強化済みの勇者モン+相性の供モン)でも、工夫が要るものにする。

### 案A「霧氷」(NIFLHEIM と合う): 先が読めない
- **霧**: 2WAVEごとに霧が深まり、Lv3から敵の「次の行動」の予告の数字が隠れる(技の種類は見える)。Lv5は1ターンおきに行動の種類も隠れる
- **氷**: 毎ターン手札の1枚が凍り、そのターンは使えない(次のターンに解ける)。凍る札はランダム
- 手ごたえ: 予告を見てガード・距離を合わせる遊び方を崩し、ガードの厚さや「凍ってもいい手札の組み方」で備える
- 手が付く範囲: 予告の表示(`enemyIntent` の出し方)と手札の札の「使えない」印(タクティクスの EX にカードを止める仕組み `cardLock` がある)を使う。新しい画面は要らない

### 案B「業火」(MUSPELHEIM と合う): 時間との勝負
- **業火**: 毎ターン終わりに、味方のライフが上限の◯%燃える(Lv1 2% → Lv5 6%)。自動回復より少し上回る
- **消火**: そのターンに与えたダメージが敵のライフの◯%を超えると、燃える量が半分になる
- 手ごたえ: 守って長引かせる遊び方が効かず、短いターンで押し切る編成・カードの順番が要る
- 手が付く範囲: ターン終わりの自動回復の所(冥府の「最大ライフを削る」と同じ場所)に1行足す形

### 案C「虚無」(GINNUNGAGAP と合う): 頼り切っている物が消える
- **虚無**: WAVE の始めに、いちばん大きい永続の強化(攻撃力・連撃・会心など、強化の札のうち1つ)が、そのWAVEだけ0になる。どれが消えたかは札に出す
- 手ごたえ: 1つの強化に寄せた育て方だけでは押し切れず、強化を散らす・WAVE ごとに戦い方を変える工夫が要る
- 手が付く範囲: 強化の札(`battleBuffChips`)と、その値の読み出し(`getPermaBuff`)の所に「このWAVEは0」を挟む。効果の札(#4206・#4214)で、消えた強化をはっきり見せられる

おすすめ: **A(霧氷)**。予告と手札というゲームの中心に新しい読み合いができ、数字を上げるだけのヘルヘイムと手ごたえが変わる。B は短く押し切る編成が決まると単調になりやすく、C は育成の楽しさを削る印象を与えやすい。

## ④ ヘルヘイムのクリア者を読む SQL(読むだけ・SELECT のみ)

表は `rankings`(`26-supabase.jsx` の送信 `/rest/v1/rankings`、`60-app.jsx` の `submitLocalScore` の行)。
列: `difficulty`(ヘルヘイムは `ExtremeHELHEIM`)・`user_name`・`hero`(勇者モンの名前)・`party`(JSON の配列。1人ずつ `role`('hero'|'ally')・`id`・`name` など)・`score`・`turns`(**クリアしたときだけ入る**)・`reached_wave`・`level`・`created_at`。

```sql
-- ① ヘルヘイムのクリア者の人数と、クリアの回数
select count(distinct user_name) as clear_players, count(*) as clear_runs
from rankings
where difficulty = 'ExtremeHELHEIM' and turns is not null;

-- ② クリアした人ごとの、いちばん良い記録と編成(勇者モン・パーティ)
select distinct on (user_name)
  user_name, score, turns, hero,
  (select string_agg(p->>'name', '・' order by (p->>'role') desc) from jsonb_array_elements(party) as p) as party_names,
  created_at
from rankings
where difficulty = 'ExtremeHELHEIM' and turns is not null
order by user_name, score desc, created_at asc;

-- ③ クリアした編成で多い勇者モン・供モン(人数の多い順)
select p->>'role' as role, p->>'name' as monster, count(distinct user_name) as players
from rankings, jsonb_array_elements(party) as p
where difficulty = 'ExtremeHELHEIM' and turns is not null
group by 1, 2
order by 1, 3 desc;
```

- `party` が JSON でなく文字列で入っている場合は `party::jsonb` にする
- 書き換え・消す SQL は入っていない(読むだけ)

# 出し直し(2026-10-29 社長の答えを受けて)

前の名前3つ・ルール A〜C は見送り。報酬は統括部長が社長とヘルヘイムとの比較で決め中なので、ここでは触れない。

## コードで確かめたこと(ルールの前提)

1. **距離適性ボーナスは「与えたダメージ」で増える**(`19-difficulties-and-rules.jsx` の `DIST_BONUS_PER_DAMAGE` と、60-app.jsx の WAVE の終わり)。WAVE の終わりに「その間合いで与えたダメージ × 0.00001 × 距離強化の率」が永続で足される。数えるのは1発ずつの与ダメ(`waveDistDamage`。倒しすぎた分も入る)。なので**敵のライフを上げると、与ダメが増えてボーナスも膨らむ**。敵の回復・盾も「削る量」を増やすので、そのままでは同じく膨らむ
2. **ターンによるルールは「ランの合計ターン」で効く**。冥府 Lv5 の与ダメ低下は `1 − 合計ターン × 0.02`(最低10%・`extremeStagedDamageTurnMultiplier`)。38ターンのクリアだと最後でも 24% までしか下がらない(=ルールが効ききる前に終わる)
3. **味方の被ダメージは丈夫さで二重に減る**(60-app.jsx の `getIncomingDamageBeforeTurnReduction`)。`(敵の攻撃 − 丈夫さ×0.5) × (1 − min(50%, 丈夫さ×0.015%))`、最低30。丈夫さの高い編成(ユグドラシル・スプーキー・イブリース)だと、引き算で攻撃の大半が消え、さらに最大50%減る。最低30まで落ちると、敵の攻撃はほぼ効かない
4. **1つの WAVE は20ターンで打ち切り**(20ターン経過で全滅)。長引かせる案は、ボス復活の WAVE(W3/5/7/9/10 はライフを2回削る)でも20ターンに収まる長さにする必要がある

## ② 特殊ルール(どれもヘルヘイムのルールの上に足す。(a)長引かせる と (b)丈夫さの調整 の組み合わせ)

### 案1「刻み(1ターンの上限)」+「鎧砕き(丈夫さの上限)」 ← おすすめ
- (a) **1ターンに敵へ通るダメージの上限 = 敵の最大ライフの15%**。ふつうの WAVE は最短7ターン、ボス復活の WAVE は最短14ターン(20ターンに収まる)。距離適性ボーナスは「通ったダメージ」だけで数える(上限を超えた分は数えない)ので、敵のライフを上げたときのようには膨らまない
- (b) **丈夫さで引ける量に上限 = 敵の攻撃の40%まで**(引き算の後の%軽減は今のまま)。丈夫さをいくら積んでも、敵の攻撃の6割は残る
- 剣士モッチー勇者・ユグドラシル・スプーキー・イブリースの見込み: いまの38ターンが**およそ90〜110ターン**(ふつう5 WAVE × 7〜9 + 復活5 WAVE × 14〜16)。与ダメ低下が最低10%まで落ちきるので、後半(W7〜10)は「1ターン15%」に届かなくなり、ここで詰まる。丈夫さの上限で、ユグドラシルの被ダメ−30%(EX)と自動回復だけでは耐えきれず、回復のカードと「世界樹の守り」を切らさない立ち回りが要る
- **作る前に要る調整**: 与ダメ低下(合計ターンで数える)は、このままだと長引いた分だけ早く最低10%に張りつく。この難易度だけ「WAVE ごとのターン」で数えるか、低下の幅を小さくする(例 −0.5pt/T・最低30%)。でないと W9・10 が20ターンで削りきれない
- 作る所: 与ダメの合計に上限を挟む所(`totalDmg` を敵へ当てる直前)と、距離適性ボーナスの数え方(`waveDistDamage` を上限で切る)、被ダメの式(`getIncomingDamageBeforeTurnReduction`)の引き算に上限。どれも specialRules の値で切り替える形にできる

### 案2「殻(WAVE の区切りで盾)」+「貫き(丈夫さを一部無視)」
- (a) **WAVE の始めと、冥府の Lv が上がるたびに、敵が最大ライフの50%ぶんの殻(盾)をまとう**。殻を割るまで本体のライフは減らない。距離適性ボーナスは殻に当てた分を数えない
- (b) **敵の攻撃の30%(Lv5で50%)は丈夫さを無視して通る(貫き)**
- 見込み: ふつうの WAVE は今の約1.5倍、殻が2回張られる WAVE は約2倍で、全体で**およそ65〜80ターン**。殻は一気に削れる固有技の連撃で割りやすいので、剣士モッチーの連撃パワーが活きる。貫きで、丈夫さの高い3体でも毎ターン確実に削られ、Lv5 の W9・10 で回復が追いつかなくなるのが詰まる所
- 作る所: 敵に「盾」の値を足す(ドリーミィのシールドと同じ作りを敵側にも)、被ダメの式に貫きの割合

### 案3「不倒(ボスが一定ターンまで倒れない)」+「侵食(最大ライフ割合の攻撃)」
- (a) **ボスの WAVE(W3/5/7/9/10)は、その WAVE の8ターン目まで、ライフ1で踏みとどまる**(倒れない)。踏みとどまっている間の与ダメは、距離適性ボーナスに数えない
- (b) **敵の攻撃に、狙った子の最大ライフの4%(Lv5で8%)が足される**(丈夫さで減らない)
- 見込み: ボスの5 WAVE が最短8ターン(復活でさらに伸びる)になり、全体で**およそ60〜75ターン**。踏みとどまる間に「ためる」系の行動をはさまれるので、守りの手札が要る。侵食は最大ライフが大きい子ほど痛く、冥府の最大ライフ−25% と重なって、ライフを伸ばして耐える育て方が効きにくくなる
- 作る所: 撃破の判定(`resolveEnemyDefeat`)に「何ターン目まで倒れない」、被ダメの式に最大ライフ割合の上乗せ
