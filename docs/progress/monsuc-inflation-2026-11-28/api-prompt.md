# 点検の材料

## A. コードの読み・試算(検査部がまとめた物)
## 1. 先に結論(コードと試算から)

- **インフレは「育てた子 → 次の育成の編成」の連鎖で起きている。止まる所がない。**
  編成の子の能力が、次の子の ①上限 ②トレーニングの伸び ③はじめの能力 の3つにそのまま比例して効き、どれにも天井がない。
- 今の芯で「前の代の強い6体で次を育てる」を12代つなぐと、いちばん高い能力の中央が **1,239 → 11,087**、総合力の中央が **20,916 → 58,036(約2.8倍)**。代ごとに伸び幅が増えていて、頭打ちの気配がない(§3)
- 強い子は**フレンドへ貸し出せる**ので、インフレは回数を重ねた人だけで終わらない。ベースモンだけの新しい人でも、能力15,000の子を1体借りるだけで総合力の中央が **10,021 → 27,041**(§3-2)
- 大会の相手の強さは固定(いちばん上でも6能力の合計 2,050)。育った子が強くなるほど大会は形だけになる
- **対戦(マスモン対戦のサーバ)とアシストポイント・強さの段は 999 で切られていて、連鎖しない**(壊れるのはモンサクの中とモンサクのランキング)

## 2. コードの読み(どこが青天井か)

正本は `monster-hero/data/monhero-success.js`(芯)。行は 2026-11-28 の main。

| # | 所 | 式 | 天井 |
|---|---|---|---|
| ① | 上限 `capOfTeam`・`capUpOf`(L777〜780) | 上限 = 999 + 編成6体それぞれの「500を超える上位3つの能力 × 割合」の合計。割合 = 20% + 上限アップブースト(最大 +6%) | **なし**(r1115-103「天井なし」)。6体×20% = 120% なので、上限は編成の子の能力より速く上がる |
| ② | 能力の補正 `memberOf` の bonus(L752) | 編成の子がそのトレーニングに来たときの上乗せ = 能力 ÷ 40 × 位置の係数(1.0/0.9/0.8)% | **なし**(r1115-105「999を超えた分も数える」)。能力 4,000 の子は1体で +100%、12,000 なら +300% |
| ③ | はじめの能力 `startAdd`(L759・L818) | 編成の子ごとに、いちばん高い能力 ÷ 25 をはじめに足す(うけつぎ草で2倍) | 上限まで(=①に従う) |
| ④ | 総合力 `powerOverOf`(L1729) | 999 を超えた分は1点 3.5 | なし(サーバの見張りは 1能力 99,999・総合力 2,500,000) |
| ⑤ | 貸し出し(`56-assistant-life-friend-monsuc-lend.jsx` L56・L85) | 999 を超えた子も 99,999 まで送れる・借りた子は①②③にそのまま効く | なし |

連鎖しない所(確かめた):

- 合体の子のはじめの能力は 999 で切る(`fusePlan` L2234)
- アシストポイント・強さの段(タッグ・仲良しの始まり・得意率)は今までの数え方(能力 999 まで・`powerClassic`)
- マスモン対戦のサーバは `statMax` を渡さない = 999 のまま(`assistant-masmon-battle.js` L57〜59)
- ランキングのサーバの旧総合力 `monsuc_rank_power2` も 999 で切る(並びに使う power_v3 は切らない)

なぜ当時の試算(r1115-103 の README・4代で中央 1,739)より速いか: 当時は1代20回・4代までで、伸びが目立つ前に止めていた。
今は ②(補正を999超えも数える)が入っていて、上限と伸びが同時に上がる。代を重ねるほど1代の伸び幅が増える形(§3 の表)。
