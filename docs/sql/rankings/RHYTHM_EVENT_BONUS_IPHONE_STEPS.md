# イベントの「回数ボーナス」 — iPhoneでの手順

2026-09-11・ユーザー指示「イベントランキングでただスコアを競うだけだと、うまい人が毎回上位に行く。
それはそれでいいけど、頑張った人が報われるシステムにもしたい。例えばやった回数×1%の加点が
かかるみたいな」。

**1回やれば、以後のイベントでもそのまま効きます。** イベントごとに流し直す必要はありません。
**このファイルは何度流しても同じ結果になります**（関数を作り直す形）。返す列を増やしたときは、
もう一度 TEST → APPLY → VERIFY の順に流し直してください。
**加点の割合を変えるときもSQLは流し直しません**（割合はアプリから毎回渡しているため。
`monster-hero/data/rhythm-event.js` の `RHYTHM_EVENT_PLAY_BONUS_RATES` を書き換えるだけです）。

## どういう計算か

期間中にその曲を遊んだ**回数ぶん**、自分のベストスコアへ加点します。

| 難易度 | 1回あたり |
| --- | --- |
| EASY | +0.1% |
| NORMAL | +0.2% |
| HARD | +0.3% |
| EXPERT | +0.5% |
| MASTER | +0.7% |

- 加点 = **ベストスコア × （期間中の1回ごとの割合の合計）**
- 1回あたりの割合は**その回を遊んだ難易度**で決まります（EASYを10回より、MASTERを2回のほうが大きい）
- **上限はありません**（回数で抜かれたら抜き返せる）
- 総合部門は、対象曲それぞれの**加点込みのスコア**を足し合わせたものです
- 内訳に出すため、**難易度ごとの回数**（`{"MASTER":2,"HARD":1}` の形）も一緒に返します

## なぜサーバー側でやるのか

並べ替えと上位50件の切り出しは**データベース側**がしています。端末で加点すると、
「50件を切り出したあと」の加点になるため、**加点すれば50位以内に入るはずの人が
一覧から消えます**。だから加点はSQLの中でやり、加点込みの値で並べます。

## やること

Supabase の SQL Editor で、次の順に貼って実行します。

| 順 | ファイル | 何をするか | 本番に残るか |
| --- | --- | --- | --- |
| 1 | `RHYTHM_EVENT_BONUS_APPLY_TEST.sql` | 予行演習（末尾が `rollback;`） | **残らない** |
| 2 | `RHYTHM_EVENT_BONUS_APPLY.sql` | 本適用 | 残る |
| 3 | `RHYTHM_EVENT_BONUS_VERIFY.sql` | 確認（読み取りだけ） | 残らない |

1 がエラー無く通ってから 2 を実行してください。1 で落ちたら 2 は実行せず、
エラーの文をそのまま伝えてください。

> 先に `RHYTHM_EVENT_APPLY.sql` と `RHYTHM_EVENT_DETAIL_APPLY.sql` が適用済みであることが前提です。
> 適用されていない場合は 1 の最初で「先に◯◯を適用してください」と出て止まります。

## 既存のものは何も変えません

足すのは**読み取り専用の関数2つ**（`rhythm_event_song_bests_bonus` /
`rhythm_event_totals_bonus`）だけです。いまある `rhythm_event_song_bests` /
`rhythm_event_totals` はそのまま残り、週間ランキング（回数ボーナスなし）は
これまでどおりそちらを使います。`rankings` テーブルの行・列・RLS・権限は触りません。

## 見るところ

3 は「項目 / 値」の**1つの表**で15行出ます。

> ★Supabase の SQL Editor は**最後のクエリの結果しか表示しません**。
> そのため確かめたいこと全部を1つの表へまとめてあります。

| 行 | 項目 | OKの条件 |
| --- | --- | --- |
| 1 | 回数ボーナスの関数がある | 2つとも並ぶ |
| 2 | 加点なしの関数も残っている | 2つとも並ぶ |
| 3 | アプリ(anon)から実行できる | `anon` が含まれる |
| 4 | 期間中の記録(人×曲) | 0でなければよい |
| 5 | 期間中のプレイ回数(のべ) | 4行目以上の数になる |
| 6 | 加点が入っている行 | **1以上あること** |
| 6-1 | 難易度ごとの回数が返っている | `{"MASTER": 2, ...}` のような形 |
| 6-2 | 難易度ごとの回数の合計が全体と合う | `はい` |
| 7 | 素点＋加点＝表のスコア | `はい` |
| 8 | 素点は加点なしの関数と同じ | `はい` |
| 9 | 総合は曲ごとの合計 | `はい` |
| 10 | 加点でいちばん伸びた人 | 名前と内訳が出ればよい |
| 11 | 総合の1位（加点込み） | 名前と内訳が出ればよい |
| 12 | 1位が入れ替わったか | どちらでもよい（様子を見るため） |
| 13 | rankings の件数 | 適用前と同じ |

## アプリ側は先に公開してあります

SQLを流す前でも画面は壊れません。関数がまだ無い環境では、アプリが**加点なしの
これまでの関数へ自動で戻って**順位を出します（加点と「内訳」が出ないだけです）。
SQLを流したあと、ランキング画面の「更新」を押せば加点込みの順位に変わります。
