# iPhoneでの実行順（残りを1本にまとめたSQL）

「ランキングに**いま設定している**名前・アイコン・プロフィールフレームを出す」ために残っている作業を、
**SQL 1本**で終わらせる手順です。

これまで2本に分かれていたもの（`PROFILE_FRAME_BOND_APPLY.sql` と `BREEDER_PROFILE_APPLY.sql`）を
`PROFILE_LOOK_ALL_APPLY.sql` にまとめました。**中身は同じ**です。どちらでも結果は変わりません。

| | 内容 |
| --- | --- |
| ① | `public.bond_levels` へ `profile_frame` 列を1つ足す（絆Lv・総合力ランキングにフレームを出す） |
| ② | `public.breeder_profiles` テーブルを1つ作る（名前・アイコン・フレームを「いまの設定」で出す） |

**①②は1つのトランザクションに入っています。** 途中で1つでもおかしければ**両方とも元に戻る**ので、
「片方だけ当たった中途半端な状態」にはなりません。

- **既存の記録（`rankings` / `bond_levels` の行）は1行も書き換えません。**
- **順位・スコア・集計は何も変わりません。** 変わるのは見た目だけです。
- 削除の権限は与えていないので、間違って書き始めても行が消えることはありません。

## 先に必要なSQL（すべて適用済みのはず）

`RANKINGS_APPLY.sql` ／ `BOND_LEVELS_APPLY.sql` ／ `BREEDER_ID_APPLY.sql` ／ `PROFILE_FRAME_APPLY.sql`。
どれか足りなければ、**何も変えずに先頭の点検でその場で止まり**、足りないファイル名を出します。

## 手順

1. **Safari で Supabase Dashboard を開く**
   SQL Editor → New query。
2. **いまの件数を控える**
   `select count(*) from public.rankings;` と `select count(*) from public.bond_levels;` を Run して数字を残します。
3. **`PROFILE_LOOK_ALL_APPLY_TEST.sql` を実行**（末尾が `rollback;`）
   予行演習です。本番には何も残りません。**エラーが出たらここで止めて共有**してください。
4. **`PROFILE_LOOK_ALL_APPLY.sql` を実行**（末尾が `commit;`）
   まとめの表（14行）が出れば成功です。とくに次を見てください。
   - `① bond_levels.profile_frame 列` → `text / YES (text / YES なら正しい)`
   - `② breeder_profiles テーブル` → `あり`
   - `② breeder_profiles の権限(DELETEが無いこと)` → `SELECT` `INSERT` `UPDATE` だけで **DELETE が無い**
   - `① bond_levels の件数` と `rankings の件数` → **手順2と同じ数字**
5. **⚠️ ゲームを開き直す（いちばん忘れやすい）**
   **SQLを当てただけでは、いま開いているアプリには反映されません。**
   アプリは「その列・その表はまだ無い」と一度気づくと、**そのページを閉じるまでずっと**使いません。
   Safariならタブを閉じて開き直す／ホーム画面のアプリならタスクを切って起動し直してください。
   **更新のお知らせ（バナー）は出ないこともあります**（本体のファイルが変わっていない場合）。
6. **見た目を変えて、ランキングを開く**
   プロフィールでフレームやアイコンを変えてから、ランキングを開きます。
   - **過去に出した自分の行も、新しい見た目に変わっていれば成功**です
   - 絆Lv・総合力のタブにも枠が出ていれば ① も効いています
7. **`PROFILE_LOOK_ALL_VERIFY.sql` を実行**（読み取りだけ）
   ①②の状態と、登録されているブリーダー数・選ばれているフレームの内訳がまとめて見られます。

## 覚えておくこと

- **ブリーダーIDが付く前の古い記録**（2026-09-11より前）には、誰のものか分かる印がありません。
  その行は**名前で結びつけ**ます。ただし**同じ名前の人が2人以上いる名前は結びつけません**
  （他人の見た目を出さないため）。その場合は今までどおり記録に写した見た目で出ます。
  誰が当てはまるかは手順7の「同じ名前が2人以上いる名前」で分かります。
- **①の列を足す前の絆Lvの記録は NULL のまま**です（NULL＝フレームなし）。あとから埋めません。
  ただし②が入っていれば、その人の**いまのフレーム**で表示されます。
- **すでに片方を当ててしまっていても、そのまま流して大丈夫です。**
  当たっている側は何もしません（`add column if not exists` / `create table if not exists`）。
- **何度流しても大丈夫です。** 二重適用でおかしくなることはありません。

## うまくいかないとき

- **「〜がありません。先に ◯◯.sql を適用してください」**
  そのファイルを先に当ててください。このSQLは**何も変えずに**止まっています。
- **適用したのに古い見た目のまま**
  まず手順5（**ゲームを開き直す**）をやったか確認してください。
  それでも直らなければ、ファイル末尾の `notify pgrst, 'reload schema';` まで実行できているか見てください。
- **絆Lv・総合力だけ枠が出ない**
  ①は「これから出す記録」に効きます。列を足す前の記録は NULL のままなので、
  ②が入っていない場合は一度その画面に載るプレイをすると枠が付きます。

## 個別に流したいとき

まとめずに1つずつ当てたい場合は、これまでどおり次の2本でも同じ結果になります。

- `PROFILE_FRAME_BOND_IPHONE_STEPS.md` → `PROFILE_FRAME_BOND_APPLY.sql`
- `BREEDER_PROFILE_IPHONE_STEPS.md` → `BREEDER_PROFILE_APPLY.sql`

`node tools/ranking/profile-frame-sql-check.js` が、まとめたSQLと個別のSQLが食い違っていないか（要点の文がすべて入っているか）も見張っています。
