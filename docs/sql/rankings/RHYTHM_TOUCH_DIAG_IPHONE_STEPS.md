# iPhoneでの「タッチの診断」の表の作成 実行順

モンヒロビートのタッチの診断を貯める表 `public.rhythm_touch_diagnostics` を**新しく1つ作る**作業です。**既存の表・列・ビュー・関数・RLS・ポリシー・権限には触りません**（`rankings`・`rhythm_play_logs` などへの `alter`・`drop`・`delete`・`update` をしません）。各SQLは新しいクエリにファイル全体を貼り付けて実行します。エラーが出た工程では次へ進まず、結果を保存して共有してください。

> **Supabase の SQL Editor は、ファイル全体を実行すると「最後の1文」の結果しか表示しません。**
> そのため3本とも、**最後の1文が「まとめ」**になっています。1回 Run して出てきた表を
> スクリーンショットするだけで大丈夫です。

> 警告が出たら **「Run without RLS」** を選んでください。このSQLは新しい表に自分でRLSを有効にします。

## なぜ作るのか

「iPhoneで両手の高速連打のとき、押しても音も光も出ないことがある」の原因を、プレイヤーの実機の数字で突き止めるためです（2026-09-30）。
ゲームは1曲ごとに、指がブラウザのどの段階で消えたかを数えて1行送ります。道具が iPhone と Android を比べて原因を判定します
（仕組みは `docs/spec/RHYTHM_TOUCH_DIAG.md`）。

- **名前・ブリーダーID・セーブデータは入りません。** 端末ごとのでたらめなIDと、数だけです
- 誰でも**追加と読み出し**はできますが、**書き換え・削除はできません**
- 1行の大きさに上限があり、形の違う行は受け付けません

## 順番はどちらが先でもかまいません

アプリは表がまだ無いと分かると、そのページを閉じるまで送るのをやめます。**ゲームは何も変わりません。**
表が無いあいだも、消えたタッチの取り戻しはゲームの中で動いています。

## 手順

1. **Safari で Supabase Dashboard を開く**
   プロジェクトを選び、左のメニューから **SQL Editor** → **New query**。
2. **`RHYTHM_TOUCH_DIAG_APPLY_TEST.sql` を実行**（末尾が `rollback;`）
   予行演習です。本番には何も残りません。まとめの表に `列の数(11) = 11`・`RLS(true) = true`・
   ポリシーが `rhythm_touch_diag_insert:INSERT, rhythm_touch_diag_select:SELECT` と出れば成功です。
   **エラーが出たらここで止めて共有**してください。
3. **`RHYTHM_TOUCH_DIAG_APPLY.sql` を実行**（末尾が `commit;`）
   手順2と同じまとめが出て、`記録の件数 = 0` なら成功です。
4. **`RHYTHM_TOUCH_DIAG_VERIFY.sql` を実行**（読み取りだけ）
   `anon の権限 = INSERT,SELECT` と出ることを確かめます。
5. **ゲームを開き直して、公開中の曲を1曲最後まで遊ぶ**（デバッグ画面・練習以外）
   もう一度 `RHYTHM_TOUCH_DIAG_VERIFY.sql` を実行し、`記録の件数` が1以上なら届いています。
