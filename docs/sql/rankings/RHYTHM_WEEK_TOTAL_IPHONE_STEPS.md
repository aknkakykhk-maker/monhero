# 週間ランキングを「累計スコア方式」にする — iPhoneでの手順

2026-09-13・ユーザーが決めた「曲別合算方式じゃなくて、どの曲でもやった分のスコア加算」。

**1回やれば以後ずっと効きます。** 毎週流し直す必要はありません。
**このファイルは何度流しても同じ結果になります**（関数を作り直す形）。

## 何が変わるか

| | これまで | これから |
| --- | --- | --- |
| 数え方 | 曲ごとのその週のベストを、全曲ぶん合計 | その週に出した記録を**ぜんぶ足す** |
| 測るもの | うまさ | **やりこみ量** |

同じ曲を何回遊んでも、そのつど積み上がります。難易度ごとに満点が違う
（EASY 60万〜MASTER 100万）ので、足すだけで難易度差は自然に付きます。重み付けはしません。

「総合」タブ（常設）はこれまでどおり曲ごとのベストの合計です。役割が分かれます。

## 既存のものは何も変えません

足すのは**読み取り専用の関数1つ**（`rhythm_week_score_totals`）だけです。
`rhythm_total_rankings`・`rhythm_event_song_bests`・`rhythm_event_totals` とその `_bonus` は
そのまま残り、総合ランキングとイベントはこれまでどおり動きます。
`rankings` テーブルの行・列・RLS・権限は触りません。

## やること

Supabase の SQL Editor で、次の順に貼って実行します。

| 順 | ファイル | 何をするか | 本番に残るか |
| --- | --- | --- | --- |
| 1 | `RHYTHM_WEEK_TOTAL_APPLY_TEST.sql` | 予行演習（末尾が `rollback;`） | **残らない** |
| 2 | `RHYTHM_WEEK_TOTAL_APPLY.sql` | 本適用 | 残る |

1 がエラー無く通ってから 2 を実行してください。1 で落ちたら 2 は実行せず、
エラーの文をそのまま伝えてください。

> 先に `RHYTHM_TOTAL_APPLY.sql` と `RHYTHM_EVENT_APPLY.sql` が適用済みであることが前提です。
> 適用されていない場合は 1 の最初で「先に◯◯を適用してください」と出て止まります。

## 見るところ

2（と1）は「項目 / 値」の**1つの表**で11行出ます。

> ★Supabase の SQL Editor は**最後のクエリの結果しか表示しません**。
> そのため確かめたいこと全部を1つの表へまとめてあります。

| 行 | 項目 | OKの条件 |
| --- | --- | --- |
| 1 | 足した関数 | `rhythm_week_score_totals` |
| 2 | アプリ(anon)から実行できる | `anon` が含まれる |
| 3-4 | 今週の始まり・終わり(JST) | 月曜 5:00 になっている |
| 5 | 今週の週間に載る人数 | 0でなければよい |
| 6 | 今週のプレイ回数(のべ) | 5行目以上の数になる |
| 7 | **累計が元の記録と一致する** | **はい** |
| 8 | 週間の1位(累計) | 名前・点・回数・曲数が出る |
| 9 | 参考: ベスト合算だったときの1位 | 入れ替わっていても問題ありません |
| 10 | 3回以上遊んだ人(参加報酬の対象) | 参考値 |
| 11 | rankings の件数 | 適用前と同じ |

## アプリ側は先に公開してあります

SQLを流す前でも画面は壊れません。関数がまだ無い環境では、週間タブが
「ただいま準備中です」と出るだけです（総合・イベント・この曲タブはふつうに動きます）。
SQLを流したあと、ランキング画面の「更新」を押せば累計方式の順位が出ます。

## 報酬について

報酬（1〜10位＋参加報酬）は**アプリ側だけ**で成り立っています。SQLには報酬の話は一切
入っていません（順位を出すのに必要な集計だけです）。割合や個数を変えたいときも
`monster-hero/data/rhythm-event.js` を書き換えるだけで、このSQLは流し直しません。
