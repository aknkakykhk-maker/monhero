# 送り直した記録が「今週」に混ざる問題 — iPhoneでの手順

2026-09-14。ユーザー指摘「この時間は開いた時間なんだけど、それがスコアとして
何かしらの方法でカウントされてる？」への対処。

## 何が起きていたか

送れなかった記録を端末に貯めておき、次にアプリを開いたときへ送り直すしくみを
2026-09-13に入れた。このとき `created_at` を付けずに送っていた。
`rankings.created_at` の既定値は `now()` なので、**送り直した瞬間**が記録の時刻になる。

週間ランキング(月曜5:00区切り)は `created_at` で期間を数えているため、
先週以前の未送信記録を送り直すと、遊んでいない今週の合計へ足されてしまう。
9/14(月) 6:22 にアプリを開いただけで4曲ぶんが今週の週間へ載ったのは、これが原因。

## アプリ側は直した(SQLなしで効く)

送り直すときだけ `created_at` に**遊んだ時刻**を入れて送るようにした。
既にあるデータの `created_at` は書き換えない。

## SQLでやること

| 順 | ファイル | 何をする | 残るもの |
| --- | --- | --- | --- |
| 1 | `RHYTHM_RESEND_CREATED_AT_TEST.sql` | anon で `created_at` を指定して入れられるか試す | なし(rollback) |
| 2 | `RHYTHM_RESEND_WEEK_AUDIT.sql` | 今週へ混ざった行を探す(読むだけ) | なし |
| 3 | `RHYTHM_RESEND_WEEK_DELETE.sql` | 混ざった行を消す(**任意**) | 消える(戻せない) |

### 1. 予行演習

Supabase → SQL Editor へ `RHYTHM_RESEND_CREATED_AT_TEST.sql` を貼って実行。
`①` と `③` が **はい(OK)** なら、アプリ側の直し方でそのまま動く。

`①` が「いいえ(NG)」のときは、anon に列単位の制限がかかっている。
そのときだけ次の1行を足す(テーブルの形は変わらない)。

```sql
grant insert (created_at) on public.rankings to anon;
```

### 2. 今週に混ざった行を探す

`RHYTHM_RESEND_WEEK_AUDIT.sql` を実行する。`③` に
「同じ人・同じ分に2件以上」の固まりが出たら、それが送り直しで入ったもの。
`④` の一覧から、その行の `clear_id` を控える。

### 3. 消す(やるかどうかは任意)

消さなくても、次の週(9/21 5:00)には自然に外れる。
ただし**今週の週間ランキングの報酬**に効くので、消したいときは
`RHYTHM_RESEND_WEEK_DELETE.sql` の `values` へ控えた `clear_id` を書き足してから実行する。

- 空のまま流すと0件で何も起きない(安全側)
- 消した記録は戻せない。曲別ランキングからも消える
