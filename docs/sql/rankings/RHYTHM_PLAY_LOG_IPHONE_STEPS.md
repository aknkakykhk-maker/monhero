# iPhoneでの「遊んだ記録」の表の作成 実行順

モンヒロビートの遊んだ記録を貯める表 `public.rhythm_play_logs` を**新しく1つ作る**作業です。**既存の表・列・ビュー・関数・RLS・ポリシー・権限には触りません**（`rankings` などへの `alter`・`drop`・`delete`・`update` をしません）。各SQLは新しいクエリにファイル全体を貼り付けて実行します。エラーが出た工程では次へ進まず、結果を保存して共有してください。

> **Supabase の SQL Editor は、ファイル全体を実行すると「最後の1文」の結果しか表示しません。**
> そのため3本とも、**最後の1文が「まとめ」**になっています。1回 Run して出てきた表を
> スクリーンショットするだけで大丈夫です。

> 警告が出たら **「Run without RLS」** を選んでください。このSQLは新しい表に自分でRLSを有効にします。

## なぜ作るのか

譜面生成ツール（MHB CHART ENGINE）が「プレイヤーが音に合わせて押せているか」を測るためです（2026-09-28）。
公開中の曲をふつうに最後まで遊ぶと、ノーツごとの判定のずれを縮めた文字列が1行届きます。ツールが週1回これを読み、
次に足す曲の作り方を決めます（仕組みは `docs/spec/RHYTHM_PLAY_LOG.md`）。

- **名前・ブリーダーID・セーブデータは入りません。** 端末ごとのでたらめなIDだけです
- 誰でも**追加と読み出し**はできますが、**書き換え・削除はできません**
- 1行の大きさに上限があり、形の違う行は受け付けません

## 順番はどちらが先でもかまいません

アプリは表がまだ無いと分かると、そのページを閉じるまで送るのをやめます。**ゲームは何も変わりません。**
SQLを先に当てても、アプリの公開が先でも、困ることはありません。表を作ったあとに開き直した端末から、記録が届き始めます。

## 手順

1. **Safari で Supabase Dashboard を開く**
   プロジェクトを選び、左のメニューから **SQL Editor** → **New query**。
2. **`RHYTHM_PLAY_LOG_APPLY_TEST.sql` を実行**（末尾が `rollback;`）
   予行演習です。本番には何も残りません。まとめの表に `列の数(13) = 13`・`RLS(true) = true`・
   ポリシーが `rhythm_play_logs_insert:INSERT, rhythm_play_logs_select:SELECT` と出れば成功です。
   **エラーが出たらここで止めて共有**してください。
3. **`RHYTHM_PLAY_LOG_APPLY.sql` を実行**（末尾が `commit;`）
   手順2と同じまとめが出て、`記録の件数 = 0` なら成功です。
4. **`RHYTHM_PLAY_LOG_VERIFY.sql` を実行**（読み取りだけ）
   `anon の権限 = INSERT,SELECT` と出ることを確かめます。
5. **ゲームを開き直して、公開中の曲を1曲最後まで遊ぶ**（デバッグ画面・練習・アシストモード以外）
   もう一度 `RHYTHM_PLAY_LOG_VERIFY.sql` を実行し、`記録の件数` が1以上・`いちばん新しい記録` が
   いまの時刻なら、届いています。
