# iPhoneでのランキングSQL実行順

各SQLは新しいクエリにファイル全体を貼り付けて実行します。エラーが出た工程では、次へ進まず結果を保存して担当者へ共有してください。

1. **`RANKINGS_AUDIT.sql`を実行**
   カラム、制約、Index、RLS、ポリシー、権限、重複候補を確認します。成功時は複数の結果表が表示されます。
2. **結果を保存**
   各結果表をスクリーンショットまたはCSVで残します。保存できなければ次へ進みません。
3. **`RANKINGS_APPLY_TEST.sql`を実行**
   追加処理と安全確認を試し、最後に取り消します。成功時は対象Indexが `indisunique=true`、`indisvalid=true`、`indisready=true` と表示され、完了します。
4. **エラーがないことを確認**
   赤いエラー表示がなく、試験が完了したことを確認します。エラー時は実適用へ進みません。
5. **`RANKINGS_APPLY.sql`を実行**
   同じ安全確認後に変更を保存します。成功時は対象Indexの3状態がすべて `true` となり、完了します。エラー時は次へ進みません。
6. **`RANKINGS_VERIFY.sql`を実行**
   `clear_id` が `text` かつNULL許容、対象Indexの3状態がすべて `true`、RLS・ポリシー・権限が手順2の結果と同じ、重複結果が0行であることを確認します。違いまたはエラーがあれば次へ進みません。
7. **ゲームでMaster、Normal、Hardを確認**
   各ランキングが表示できることを確認します。表示・通信エラーがあれば作業完了とせず、結果を共有します。
8. **重複整理は別工程で行う**
   今回は既存データを整理しません。必要な場合だけ、承認を得た別工程で `RANKINGS_DUPLICATE_CLEANUP.sql` を使用します。
