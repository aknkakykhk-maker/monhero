# iPhoneでのプロフィールフレーム列の追加 実行順

`public.rankings` へ `profile_frame` を1列だけ追加し、モンヒロビートのビュー・関数へその列を通す作業です。**既存の行・列・RLS・ポリシー・権限には触りません**（`drop table`・`delete`・`update` をしません）。各SQLは新しいクエリにファイル全体を貼り付けて実行します。エラーが出た工程では次へ進まず、結果を保存して共有してください。

> **Supabase の SQL Editor は、ファイル全体を実行すると「最後の1文」の結果しか表示しません。**
> そのため3本とも、**最後の1文が「まとめ」**になっています。1回 Run して出てきた表を
> スクリーンショットするだけで大丈夫です。

> **「Run and enable RLS」ではなく「Run without RLS」を選んでください。**
> Supabaseは `alter table` を機械的に「destructive」と判定して警告を出しますが、このSQLは
> 列を足すだけで既存データを消しません。RLSは `rankings` に既に有効です。

## なぜ追加するのか

プロフィールフレームは、ブリーダーアイコンの**外側**に重ねる飾り枠です（2026-09-15）。ランキングには**他の人が選んだ枠も**出すので、記録と一緒にそのidを残す必要があります。

- 既存の `icon` や `party` へ詰め込まず、**NULL許容の列を1つだけ**足します
- 列を足す前の記録は **NULL のまま**で、あとから埋めることもしません（**NULL＝フレームなし**）
- **順位・スコア・集計方法は一切変わりません。** この列は表示にしか使いません

## 先に必要なSQL

このSQLは既存のビュー・関数を作り直すので、下の順に全部当たっている環境で実行します。どれかが無ければ、先頭の点検で「◯◯がありません」と出てその場で止まります（何も変わりません）。

`RANKINGS_APPLY.sql` → `BREEDER_ID_APPLY.sql` → `RHYTHM_TOTAL_APPLY.sql` → `RHYTHM_EVENT_APPLY.sql` → `RHYTHM_EVENT_DETAIL_APPLY.sql` → `RHYTHM_EVENT_BONUS_APPLY.sql` → `RHYTHM_WEEK_TOTAL_APPLY.sql` → **ここ**

## 順番はどちらが先でもかまいません

アプリ側は「列がまだ無い」と分かると、

- **送るとき** … `profile_frame` を外して自動で送り直します（記録は必ず残ります）
- **出すとき** … `profile_frame` を外して取り直します（枠が出ないだけで、順位は出ます）

ですので、SQLを先に適用してもアプリの公開を先にしても、**記録が失われることはありません**。ただし列が無いあいだに遊んだぶんには枠が付かないので、**SQLを先に適用したほうが、枠の付いた記録が早く貯まります**。

## 手順

1. **Safari で Supabase Dashboard を開く**
   プロジェクトを選び、左のメニューから **SQL Editor** → **New query**。
2. **いまの `rankings` の件数を控える**
   新しいクエリに `select count(*) from public.rankings;` だけを貼って Run し、数字を残します。適用後に比べます。
3. **`PROFILE_FRAME_APPLY_TEST.sql` を実行**（末尾が `rollback;`）
   予行演習です。本番には何も残りません。**エラーが出たらここで止めて共有**してください。
4. **`PROFILE_FRAME_APPLY.sql` を実行**（末尾が `commit;`）
   まとめの表に、`profile_frame 列 = text / YES`、ビュー4つ、`rankings の件数`が手順2と同じ、`profile_frame が入っている記録 = 0` と出れば成功です。
5. **`PROFILE_FRAME_VERIFY.sql` を実行**（読み取りだけ）
   ビュー4つ・関数5つがそろっていることを確かめます。
6. **⚠️ ゲームを開き直す（いちばん忘れやすい）**
   **SQLを当てただけでは、いま開いているアプリには反映されません。**
   アプリは「列がまだ無い」と一度気づくと、**そのページを閉じるまでずっと**
   `profile_frame` を外して送り続けます（列が無い環境でスコアが1件も保存できなくなるのを
   防ぐための作り）。適用より前にアプリを開いてランキングを見ていた場合は必ずこれに当たります。

   Safariならタブを閉じて開き直す／ホーム画面のアプリならタスクを切って起動し直してください。
   **更新のお知らせ（バナー）は出ません。** 本体のファイルは変わっていないので、
   出ないのが正常です。開き直したかどうかは自分で気をつける必要があります。

   > 2026-09-15、これで実際に引っかかりました。開き直す前に遊んだ記録は
   > 枠なしのまま残ります（あとから付けることはしません）。
7. **フレームを選んで1回遊ぶ → ランキングを見る**
   自分の行に枠が出れば成功です。
8. **数日後にもう一度 `PROFILE_FRAME_VERIFY.sql`**
   「`profile_frame` が入っている記録」が増えていれば、アプリからちゃんと届いています。

## うまくいかないとき

- **「◯◯がありません。先に △△ を適用してください」**
  上の「先に必要なSQL」の順に当て直してください。このSQLは何も変えずに止まっています。
- **適用したのにアプリで枠が出ない**
  まず手順6（**ゲームを開き直す**）をやったか確認してください。ここがいちばん多い原因です。
  それでも出なければ、ファイル末尾の `notify pgrst, 'reload schema';` まで実行できているか見てください。
- **`42P16: cannot change name of view column`**
  ビューへ列を足す場所が途中になっています。`profile_frame` は必ず**いちばん最後**へ足します（このSQLはそうなっています）。
- **`42P16: cannot change data type of view column "total_score"`**
  2026-09-15 に実際に出たエラーです（予行演習で止まったので、本番には何も残っていません）。
  `rhythm_total_rankings.total_score` の型が、このSQLが作ろうとした型と違うと出ます。
  いまのSQLは本番と同じ **numeric** で作るように直してあるので、もう出ません。
  もし別の環境で出たときは、先頭の点検が「どう直せばよいか」を日本語で教えて止まります。
  経緯は [`../../spec/PROFILE_FRAME.md`](../../spec/PROFILE_FRAME.md) §6.1。
