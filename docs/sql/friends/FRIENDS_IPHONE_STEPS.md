# iPhoneでのフレンド機能のテーブル追加 実行順

フレンド機能（フレンドコード・申請・承認・ブロック・マルチへの招待）で使う**新しいテーブルを3つ**作る作業です。
**既存のテーブル（`rankings` / `bond_levels` / `breeder_profiles`）には一切触りません。**
記録も順位もスコアも見た目の登録も変わりません。

> **「Run and enable RLS」ではなく「Run without RLS」を選んでください。**
> RLSはSQLの中で有効にしています（Supabaseに追加で差し込ませる必要はありません）。

## 先に必要なSQL

`docs/sql/rankings/BREEDER_PROFILE_APPLY.sql`（`breeder_profiles` があること）。
フレンドの名前・アイコン・フレームはそこから引きます。すでに適用済みなら何もしなくて大丈夫です。

## 手順

1. **Safari で Supabase Dashboard を開く**
   プロジェクト `zrzevudkbgtxlbvmuziy` → SQL Editor → New query。
2. **いまの `rankings` の件数を控える**
   `select count(*) from public.rankings;` を Run して数字を残します。
3. **`FRIENDS_APPLY_TEST.sql` を実行**（末尾が `rollback;`）
   予行演習です。本番には何も残りません。**エラーが出たらここで止めて共有**してください。
4. **`FRIENDS_APPLY.sql` を実行**（末尾が `commit;`）
   まとめの表に、3つのテーブルが「あり」・RLSが `3`・権限に **DELETE が無い**・
   `rankings の件数`が手順2と同じ、と出れば成功です。
5. **⚠️ ゲームを開き直す（いちばん忘れやすい）**
   アプリは「その表はまだ無い」と一度気づくと、**そのページを閉じるまでずっと**使いません。
   Safariならタブを閉じて開き直す／ホーム画面のアプリならタスクを切って起動し直してください。
6. **フレンド画面を開く**
   公開フラグ（`FRIENDS_PUBLIC_RELEASE`）が開いたあと、ホームから「フレンド」を開き、
   自分のフレンドコードが出れば成功です。
7. **`FRIENDS_VERIFY.sql` を実行**（読み取りだけ）
   フレンドコードを持つ人の数と、申請・フレンドの件数が見られます。

## 覚えておくこと

- **ログインの仕組みが無い**ので、端末ごとのブリーダーIDで人を見分けています。
  端末のデータを消したり、別の端末へ移ったりすると、別のIDになり、フレンドは引き継がれません
  （ランキングの記録と同じ状況です）。
- **フレンド解除・断る・ブロックでも行は消えません。** 状態（`status`）が変わるだけです。
  削除の権限は与えていません。
- **マルチへの招待**は、同じ2人のあいだで1行に上書きされます。アプリは3分より古い招待を無視します。
  部屋コードが一時的に読める状態になりますが、部屋コードはもともと4文字で、知らない人に呼びかける
  「ルーム解放」でも公開するものです。
- 公開キーで読み書きできる作りなので、**他人になりすまして関係を書き換えること自体は防げません**。
  防いでいるのは「消せない」「1組は1行まで」「ありえない値を弾く」の3点です。
- 誰がフレンドかは、アプリを使う人なら調べられる状態です（ランキングと同じ公開の度合い）。
  フレンドの一覧にはブリーダー名・アイコン・フレーム・最後に開いた時刻だけを出します。

## うまくいかないとき

- **「breeder_profiles がありません」**
  先に `BREEDER_PROFILE_APPLY.sql` を適用してください。このSQLは何も変えずに止まっています。
- **適用したのにフレンド画面が「準備中」のまま**
  手順5（**ゲームを開き直す**）をやったか確認してください。
  それでも直らなければ、ファイル末尾の `notify pgrst, 'reload schema';` まで実行できているか見てください。

## 元に戻したくなったら

フレンドの表は新しく作っただけなので、アプリ側の公開フラグを閉じれば画面は消えます。
表そのものを消す必要はありません（中身はフレンド関係だけで、ほかには影響しません）。
