# バトルシステム設計書

## 1. この文書の位置づけ

現行実装の正本である `monster-hero/src/game-system.jsx`、`monster-hero/data/skills.js`、
`monster-hero/data/enemy-monsters.js` を読んで整理した、現在のバトル仕様である。数値や分岐はコードに存在するものだけを記載する。

## 2. 1ランの進行

1. タイトルで難易度を選び、召喚を開始する。
2. 勇者モンを1体選び、零・近・中・遠の4スロットのいずれかへ置く。
3. ブリーダー教えカードを1枚選ぶと WAVE 1 が始まる。この時点で難易度別挑戦回数を加算する。
4. 各 WAVE の敵を倒すと能力報酬を1つ選ぶ。
5. WAVE 2・4・6 後は、空きスロットと未参加候補があれば供モンが合流する。WAVE 1・3・5・7・9 後は教えカードを獲得または強化する。それ以外は次の WAVE へ進む。
6. WAVE 10 のムーを倒すと優勝となる。敗北・降参・優勝のいずれでも、クリア済み WAVE 数に応じた報酬を確定し、スコアを1回だけ送信する。

画面状態の主経路は `PICK_HERO` → `PICK_TEACHING` → `BATTLE` → `WAVE_RESULT` →
`REWARD_PICK` →（`PICK_ALLY` / `PICK_TEACHING` / `UPGRADE_SKILL`）→ `BATTLE` で、完走時は `CHAMPION` へ進む。

## 3. 難易度と敵

`power` が敵HP・攻撃倍率、`score` がスコア・経験値倍率、`gold` がゴールド倍率である。3つは独立した値で、
Grand Master 以上では一致しない。

| 難易度 | 敵HP・攻撃倍率 | スコア・経験値倍率 | ゴールド倍率 |
| --- | ---: | ---: | ---: |
| Beginner | 0.25 | 0.25 | 0.25 |
| Easy | 0.5 | 0.5 | 0.5 |
| Normal | 1.0 | 1.0 | 1.0 |
| Hard | 1.5 | 2.0 | 1.2 |
| Expert | 3.0 | 3.0 | 1.5 |
| Master | 5.0 | 5.0 | 2.0 |
| Grand Master | 6.5 | 8.0 | 2.5 |
| Hell | 8.0 | 12.0 | 3.0 |
| Legend | 10.0 | 18.0 | 4.0 |

敵順はディノ、ゲル、ブラックディノ、ジャアクソウ、ブルーマウンテン、ガリ、ナーガ、リリム、デュラハン、ムーの固定10体。各 WAVE 開始時に敵の初期距離を4枠から一様に選ぶ。基礎HP・基礎攻撃は `enemy-monsters.js`、倍率は `DIFFICULTY_SETTINGS` にある。

### 敵の行動

行動は `ENEMY_ACTION_DEFINITIONS` の重みで抽選し、ターンごとに予告してから実行する。

| 行動 | 重み | 威力倍率 | 備考 |
| --- | ---: | ---: | --- |
| 通常攻撃 | 50 | 1.0 | |
| ためる（CHARGE） | 15 | — | 次のターンの必殺技を確定させる |
| 必殺技（SPECIAL） | 0 | 2.5 | 抽選では選ばれず、ためた次のターンに必ず発動する |
| 何もしない（WAIT） | 20 | — | |
| 距離移動（MOVE） | 15 | — | 現在以外の3間合いへ。移動した次のターンは選ばない |

- 必殺技は単独では抽選されない。必ず「ためる」を挟み、ためた次のターンは他の行動で上書きしない。
- 移動は1ターン前に吹き出しで予告する（`enemyNextIntent`）。予告のためだけにターンを消費せず、
  予告を出したターン自体は別の行動を行う。ためている間は移動を予告しない。
- 予告と実際の移動先は一致させる。表示した予告を実行時に再抽選しない。
- スタン・眼力・無敵などで敵が行動できなかった場合は、ための状態も予約も取り消す。
- 距離撃による強制移動と敵自身の移動が同一ターンに重なる場合は距離撃を優先し、敵は移動せず「行動しなかった」扱いにする。

## 4. ターンとカード

- WAVE 開始時、構築済みプールの先頭5枚を手札、残りをデッキにする。
- プレイヤーは手札から、使用可能枚数と現在ガッツの範囲でカードを選ぶ。攻撃系カードと「あつの挑発」は使用モンスターのスロット指定が必要。固有技は所有スロットにだけ割り当てられる。
- 使用可能枚数は通常1枚。最大ガッツ120以上かつ参加モンスター2体以上で2枚、最大ガッツ180以上かつ3体以上で3枚。勇者モンがハムならさらに1枚増える。
- ガードの消費ガッツは0。教えカード等は定義値（未指定時20）。通常技・距離技・固有技は、基礎消費に「現在倍率÷基礎倍率」を掛けて切り捨てる。
- 使用カードは墓地へ移る。山札・墓地の再循環と補充の詳細は `processTurn` が正本である。
- ターン終了時に敵の予告行動を実行し、次の行動を抽選する。移動の予告を1ターン前に見せるため、
  予告は2ターン先まで持つ（`enemyIntent` が次のターン、`enemyNextIntent` がその次）。
  表示した予告を実行時に再抽選しない。予約が無効になった場合（ためていないのに必殺技、
  現在地への移動）だけ抽選し直す。

## 5. 攻撃計算

基本ダメージは次の順序で計算し、最後に切り捨てる。

```text
ちから
× スロットと敵の距離差倍率（差0:1.5、差1:1.3、差2:1.1、差3:0.9）
× 技倍率
× 勇者特性倍率
× ターン攻撃倍率
× (1 + 永続攻撃補正 + みゅあ攻撃補正 + 追加おりょう補正)
× (1 + その枠の距離ダメージ補正 + その枠の距離適性補正)
× (1 + 敵のWAVE限定被ダメージ補正 + 追加補正)
```

- 距離適性倍率は G から M まで順に 0.8、0.85、0.9、0.95、1.0、1.05、1.1、1.15、1.175、1.2、1.225、1.25。
  C を ±0% とした差分を、編成した勇者モン・供モン全員ぶん、4距離すべての枠へ加算する
  （どの距離に置いたかは関係しない）。したがって式の「その枠の距離適性補正」は編成全員の合計である。
- 通常技は定義倍率。固有技は `baseMult + 強化Lv×0.5`（アーク／イブリースの累積補正を別途加算）。
- 距離技は敵がカード対象距離にいると定義倍率、違う距離ならその40%。
- ゴーレム勇者は全与ダメージ1.2倍、ピクシー勇者は固有技2倍。
- 同一ターンの2回目以降の攻撃は50%。
- 会心、距離撃の強制移動、各固有技・教えカードの個別効果は `processTurn` 内の分岐が正本。効果一覧を別データへ完全正規化した構造はない。

ザン勇者がザンで攻撃すると基礎ダメージの30%分、ザン固有技は20%分の追加ヒットを持つ。双方は加算され、永続の連撃補正も各割合へ加わる。

## 6. 被ダメージと防御

攻撃予測値は次の式で求める。

```text
max(30, 敵攻撃値×ターン被ダメ倍率 - 丈夫さ×0.15)
× モッチー／ミタラシ勇者補正0.8
× アーク／イブリース勇者の残回数あり補正0.5
× max(0.01, 1 - 永続被ダメ軽減率)
```

最後に切り捨て、最低1。敵攻撃値には WAVE 限定の敵攻撃低下を先に適用する。ガード値はカードごとの `固定値 + 丈夫さ×倍率` の合計で、ガード段階は丈夫さ100ごとに0～8へ自動上昇する。デッキに入るガードカードの枚数は最初2枚で、ガードが2段階進化するごとに1枚増え、最大4枚（`guardCardCount`）。反射、吸収、回避、無効化、スタンはガードより先に判定される。

## 7. デッキ成長とWAVE報酬

- 通常技・距離技の段階は、敵のいる距離枠の「永続距離ダメージ補正＋距離適性補正」の合算率で決まる。Lv0～8の閾値は 0、15、20、25、30、40、50、75、100%。
- 防御技段階は丈夫さ100ごとに上昇し、上限Lv8。枚数はその段階が2つ上がるごとに1枚増え、2〜4枚。
- WAVE後の能力報酬は、攻撃なら `floor(ちから×1.10)`、防御なら `floor((丈夫さ+20)×1.10)` と `floor(最大HP×1.20)`、ガッツなら `floor((最大ガッツ+10)×1.1)`。
- 供モン合流時は、その個体の `plusStats` を現在能力へ加え、距離適性を C 基準の段階差として全枠のラン中補正へ加える。固有技を追加し、強化ポイントをランダムに1～4得る。

## 8. スコア、報酬、終了

WAVE経験値基礎値は `[4,5,6,7,8,10,12,14,16,18]`、ゴールド基礎値はその10倍。クリア済み WAVE 分を合計し、経験値には難易度のスコア倍率、ゴールドにはゴールド倍率を掛け、各WAVE単位で丸める。勇者マスモンの絆経験値は経験値と同量、供モンの各マスモンはその4分の1を切り捨て（最低1）で得る。

スコア加算の完全な式は `processTurn` 内に分散しているため、本書では一つの閉じた式としては**未確認**。ランキング送信は敗北・降参・優勝で非同期に1回だけ行い、通信をリザルト表示の待ち条件にしない。

## 9. バトルモード

`BATTLE_MODES` が正本。難易度の倍率はどのモードでも共通で、そこへモードごとの補正を掛ける。

| モード | id | ブリーダーXP | 絆XP | ダイヤ | スコアランキング | 保存キーの接頭辞 |
| --- | --- | --- | --- | --- | --- | --- |
| チャレンジ | `challenge` | ×1 | ×1 | ×1 | あり（従来どおり） | `mh_` |
| クイック | `quick` | ×1.5 | ×1.5 | ×1.5 | なし | `mh_quick_` |
| プロ | `pro` | ×1.5 | ×3 | ×1 | あり（プロ専用枠） | `mh_pro_` |

- 倍率は `modeBreederXpMult` / `modeBondXpMult` / `modeGoldMult` の3つに分かれている。プロは「全部3倍」ではなく、**絆だけ3倍・ブリーダーは1.5倍・ダイヤは等倍**。
- スコア倍率はモードで変えない（難易度の設定どおり）。
- ランキングは Supabase の列を増やさず、`difficulty` へ入れる値で分ける。プロは `rankingDifficultyForMode` が先頭へ `Pro` を付けた `ProHard` のような値を使う。既存のチャレンジの記録（`Hard` など）は書き換えも変換もしない。表示用に素の難易度へ戻すのは `rankingDifficultyBase`。
- BGMはプロ専用曲を作らず、チャレンジと同じ `battle` / `dullahan` を流す。BGM設定の項目も増やさないので既存の `mh_bgm_arrangement` はそのまま読める。
- 助手（みゅあ）は `battlePro` の場面と `pro` の親密度行動を持つ。既存の `challenge` / `quick` の獲得量・1日上限・合計上限（30）は変えていない。

### 公開状況

プロモードは**まだ本番の導線に出していない**。既存のバトル画面のタブは `PUBLIC_BATTLE_MODES`（チャレンジ・クイックのみ）を並べる。`BATTLE_MODES` には入っているので、ヘルプ・検査・今後のデバッグ入口からは見える。新しいバトルモード選択画面とセットで公開する。

`submitRunScoreOnce` は先頭で `debugBattleRef.current` を見て打ち切るので、デバッグ・練習の周回はどのモードでも全国ランキングにも自己ベストにも残らない。
