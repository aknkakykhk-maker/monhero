### 第3弾で決めた作り方(次回もこのとおりに)

社長の指摘「流れが悪い・ほぼバトルの画面を流してるだけ」「無駄にズームして切れてる」「戦術カードがよわい」を受けて決めたこと。

- **寄るのは「見せたい1点」だけ**(袋・レアキラ・キラ・カードの絵・決めの表示)。手順を見せる所(めくり・デッキ編成・盤面・大会の表)は**寄らずに画面全体を額縁に入れる**(素材と同じ縦横比の窓)。横いっぱいの欄を読ませたいときは、上下だけ詰めた横長の窓にする
- **端の切れは0**: カードの絵・文字・顔・ゲームの見出しが画面や窓のふちで切れるくらいなら寄らない。書き出したら全コマを見直す
- **つなぎは曲の小節の頭**(この曲は 112BPM・1小節約2.1秒)で、フラッシュ/斜めの紫の帯のワイプ/ズームのどれか。黒い間・余計なコマ(次のパックが一瞬映る等)・同じ画面の繰り返しはなし
- **見せ場→説明→次へ** のテンポ。1場面は2〜8拍。大技はカットインで止めてスロー、決めの瞬間に字幕(「作戦どおり！」など)を合わせる
- **仕組みは「組む→決まる」を同じ札で対応させる**(戦術カード: 組んだ作戦と同じ文の札を上に出し、条件がそろった瞬間に光らせる)
- **撮影は3倍の細かさ**(390×844 を deviceScaleFactor 3、CDP の画面配信でコマを集める。Playwright の recordVideo は1倍でしか描かないので使わない)。寄る場面は必ず3倍で撮る
- **名前は架空**(自分=モンヒロ太郎・相手=ブリーダーA など)。「検査ブリーダー」「カード部のテスト」のような作り手側の名前、デバッグの画面、合言葉の数字は映さない
- 字幕は実際の遊び方どおりに、カード部(ソランド・ブレイブ)へ確認してから入れる
- 組み立ては1コマずつ合成する道具(寄り・パン・スロー・額縁・章の帯・字幕の出入り・拍のつなぎ)で作った。素材と絵コンテは作業場所の一時フォルダにあり、リポジトリには入れていない



### HELL の見どころ(ステージ)の作り方(第2版で決めた・次回もこのとおりに)

- 道具は `tools/promo/`: `beat-stage-capture.js`(演奏を撮る)と `beat-stage-build.js`(組み立て)。曲・始まりの時刻・見出し・差し色は設定ファイル(`beat-stage-2.json`)に書く。使い方は各ファイルの頭
- 見本(社長作 monhero-beat-stage.mov)の並び・字の位置と大きさ・色・切り替えの時刻をコマで測って道具に入れてある(`--calib` で見本のコマと重ねて確かめられる)
- 演奏の画面は曲鑑賞のままだとスコア・ライフ・モンスターの飾りが出ないので、ふつうの演奏の画面に鑑賞と同じ自動の手を付けて撮る。飾りは撮影用のセーブに入れたマスモン4体
- 3倍の細かさで描くとこの箱では1秒14コマしか描けないため、撮影用のブラウザの中の時計(時刻・タイマー・音の再生・CSS のアニメ)をそろって 0.15 倍で回して撮り、組み立てで曲の時刻どおりに 60fps へ並べ直す
- 画面配信(CDP の Page.startScreencast)は deviceScaleFactor だけだと1倍で来る。起動の設定 `--force-device-scale-factor` も付ける(第3弾までの道具は1倍で撮って引き伸ばしていた)

### HELL の見どころ 第3版で足したこと(2026-11-24・次回もこのとおりに)

- 設定ファイルは `tools/promo/beat-stage-3.json`。組み立ては `node tools/promo/beat-stage-build.js tools/promo/beat-stage-3.json --work tools/out/<フォルダ>`(作業の物は .gitignore 済みの tools/out に置く)。速度・設定・撮り方が違う撮影は組み立てが使わない(古い録画を混ぜない)
- **撮り方**(社長の選択・r1119-159 追記3): 公開の曲えらびから曲鑑賞に入り(ジャケット → 難易度 → この譜面を鑑賞する)、判定・コンボは入、「操作 隠す」を押して遊ぶ時と同じ画面で撮る(`beat-stage-capture.js --listen`)。描き方の切り替え・デバッグ用の上書きは使わない(ゲームのおまかせのまま)
- **設定**(社長の端末のオプション・docs/promo/requests/beat-stage-3-settings-2026-11-24/): オプション画面で選んで「保存」する(`--ui-settings`・設定ファイルの optionsUi)。道の幅(横向き) 細い / 演奏中は曲名を薄くする OFF / レーン発光 標準 / 軽量モード OFF / 演出量 最大 / 重いときは演出を自動で控えめに OFF / ライブ背景 ライブ / ジャケットのぼかし おまかせ / サーチライト 出す / 光の粒 多い / レーザー 出す / 観客のペンライト 多い / タイミングの光 出さない / 記念ステージ いつもの背景 / 画質 高 / 描画方式 自動 / 曲選びで試聴 ON / タップ時の振動 ON。ノーツの速さ 10.0 だけ保存値に入れる。ほかは初期設定(タップ音スタンダード)。冒頭の記念ステージだけ「本オープン記念」とネオン配色
- **フリックの炎が出なかった原因**(撮影の道具の不具合・ゲームは正しい): 遅回しの時計で、描く時刻(requestAnimationFrame に渡す時刻)を、CDP の Animation.setPlaybackRate でも遅くなる時計からさらに遅くしていた。描く時刻が performance.now より十数秒遅れ、叩いた光・炎の経過時間が負のまま(濃さ0)になっていた。第2版も同じで、炎と叩いた光が出ていなかった。描く時刻を performance.now と同じ時計で渡すよう直した(等倍で撮ったときと同じに炎が出る)
- **タップ音**: 撮影中にゲームのタップ音の仕組み(RHYTHM_NOTE_SE_RUNTIME)の呼び出しを曲の時刻つきで se.json に控え、`beat-stage-taps.js` が同じ仕組みを OfflineAudioContext で鳴らし直して WAV にする。曲(gain 1)とゲームの中と同じ比で足してから見本の音量へそろえる
- **冒頭**: `beat-stage-intro.js` が 720×1280 の HTML を時刻ごとに描いて1コマずつ撮る。字は完成の大きさ、絵は公開済みの元画像、ゲームの画面は撮り直し(マルチは `beat-stage-multi-shots.js` で 390×844 を3倍)。ズームは使わず、幕・照明・文字に走る光・見本と同じ時刻の押し出しだけ。約38秒の別編集版(公開前のステージ絵)は使わない
- **冒頭の記念ステージの音ずれ(2026-11-24 窓口の指摘で直した)**: 冒頭の音は見本のまま使うので、映像の曲の時刻を見本の音に合わせる。見本の 20.2秒 = 曲(bgm-atsu-cup-theme.mp3)の 109.968秒を波形の突き合わせで測り、場面の始まり 19.62秒 = 曲の 109.388秒にした(前は 108.000秒で、映像が音より約1.39秒遅れていた)
- **マルチの結果**: 縦390幅の MVP の枠で「FULL COMBO」が2行に折れてスコアに重なる(ゲームの側の崩れ・窓口へ知らせた)ので、撮るときの作り物の結果はフルコンボにしない。結果の画面は数え上げの動きが止まってから撮る
- **ずれの確かめ**: `node tools/promo/beat-stage-sync-check.js tools/promo/beat-stage-3.json --work tools/out/<フォルダ>`。記念ステージは完成 MP4 の音の立ち上がりとコンボの数字の変わり方、3曲は撮影の判定の時刻とコンボの数字、鳴らし直したタップ音と完成 MP4 の音の位置を突き合わせて、ずれを数値で出す
