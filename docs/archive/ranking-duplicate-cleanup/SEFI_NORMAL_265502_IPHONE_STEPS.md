# セフィ／Normal／265502：iPhone SQL実行手順

Codexは本番Supabaseへ接続・実行しません。以下は、iPhoneのSupabase SQL Editorでユーザーが手動実行する手順です。各ファイルは**新しいQuery**へファイル全体を貼り、順番を飛ばさず実行してください。

## 実行順

1. `SEFI_NORMAL_265502_01_CHECK.sql`
   - 12行が古い順に表示されることを確認します。
   - 先頭だけが `残す（最古）`、残り11行が `削除対象` で、各行の `id`、`created_at`、`clear_id` が見えることを確認し、スクリーンショットを保存します。
   - 12行でない、`created_at` が空、または残す行に疑問がある場合は中止します。
2. `SEFI_NORMAL_265502_02_ROLLBACK.sql`
   - **必ずこちらを先に**実行します。`DELETE 11` 相当の11行と、`remaining_count = 1` が表示されれば成功です。
   - 最後が `ROLLBACK` のため、試験後の本番データは12件に戻ります。赤いエラーが出たら次へ進みません。念のため新しいQueryで `ROLLBACK;` を実行してから中止します。
3. `SEFI_NORMAL_265502_01_CHECK.sql` を再実行
   - 再び12行が表示されれば、ROLLBACK成功です。最初のスクリーンショットと `id` を照合します。
4. `SEFI_NORMAL_265502_03_COMMIT.sql`
   - 手順1〜3がすべて成功した場合だけ実行します。削除された11行が表示され、エラーなく完了すれば確定成功です。
   - 件数が12件／11件でない場合や `created_at` が空の場合は、SQLが例外停止しCOMMITしません。
5. `SEFI_NORMAL_265502_04_VERIFY.sql`
   - 1つ目の結果が1行だけで、その `id` が手順1の `残す（最古）` と一致することを確認します。
   - 2つ目の結果が `remaining_count = 1` なら完了です。

## 安全上の注意

- SQLは `user_name = 'セフィ'`、`difficulty = 'Normal'`、`score = 265502` の完全一致だけを対象にします。
- `id` は同時刻の順序を安定させる補助にだけ使い、最古判定は `created_at` の昇順です。
- エラー、想定外の件数、空の `created_at` が1つでもあれば、その場で中止し、COMMIT版は実行しないでください。
- これらのファイルはテーブル、RLS、policy、GRANTを変更しません。本番操作は11行のDELETEだけです。
