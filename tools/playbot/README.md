# モンヒロくん(遊んでくれるロボット)

実ブラウザ(Chromium)でゲームを開き、**人のように遊んで**「おかしなこと」と「遊びにくいところ」を記録する道具。
検査(`run-checks.js`)と違って**合否は出さない**。見つけたものをスクリーンショット付きで報告し、
直すかどうかは人(とClaude)が決める。毎日の定期実行の手順は [`ROUTINE.md`](ROUTINE.md)。

```
node tools/playbot/playbot.js                         全員(約15分)
node tools/playbot/playbot.js --only time,count       選んだ担当だけ(id でも「数字係」のような名前でも)
node tools/playbot/playbot.js --only clock            担当の中の部分だけ(部分の id でも「時計」のような名前でも)
node tools/playbot/playbot.js --team battle          班の担当だけ(毎晩は4つの班に分けて別々のセッションが動く。roles.js の TEAMS)
node tools/playbot/playbot.js --list                  担当の一覧
node tools/playbot/playbot.js --parallel 3            同時に動かす担当の数(既定3・最大4。1なら順番に)
node tools/playbot/playbot.js --steps 300             探索の手数(既定150)
node tools/playbot/playbot.js --seed 12345            同じ押し方を再現する(報告に種が出る)
node tools/playbot/playbot.js --compare <report.json> 比べる相手を指定する
node tools/playbot/playbot.js --save-baseline         今回の結果を比べる基準(baseline.json)として残す
node tools/playbot/playbot.js --headed                画面つきで動かす
```

結果は `tools/out/playbot/<日時>/` に出る(`report.md` / `report.json` / 画像)。`tools/out` は git に入らない。

## 担当(`roles.js`)

モンヒロくんは**12人の担当**に分かれている(2026-10-07 に22人から組み替えた。ユーザー指示「担当名が細かい。やることは同じで人数を減らしたい」)。
担当はいくつかの**部分**を順に受け持ち、部分ごとに**別のブラウザ**を開き直す(下準備・時計・画面の大きさが部分ごとに違うため)。
1つの部分がつまずいても、同じ担当の次の部分は続ける。報告は担当ごとにまとまり、中に部分ごとの行が並ぶ。
仕事を足すときは `roles.js` の `PARTS` へ1件足し(中身は `scenarios/`)、`GROUPS` のどこかの担当の `parts` へ入れる。

| --- | --- | --- |
| バトル | `battle` | バトル・AUTO・タクティクス |
| イベント | `event` | イベント |
| 音ゲー | `rhythm` | 音ゲー → ランキング(直前の演奏の記録を使う)→ 横画面 |
| マルチ | `multi` | マルチ・相棒 |
| レイド音ゲー | `raidbeat` | レイド音ゲー |

- **同時に動かす。** ふつうの担当は `--parallel` の数(既定3)ずつ同時に動かし、1人で動かす部分
  (音ゲー・ランキング・横画面・マルチ・相棒・レイド音ゲー・小さい画面・通信不良)を持つ担当は、そのあと1人ずつ動かす。モンヒロビートは同時に動かすとコマが止まって押すのが遅れる
  (`tools/mode/rhythm-robot-play.js` 2026-09-29: 3本並べて 125譜面中8譜面で 67〜264ms 遅れた)。
  読み込みの秒数も、1人で動く音ゲーの部分のものだけを数える
- **乱数は部分ごとに分けてある。** 同時に動かしても、`--seed` と `--only` で同じ押し方を再現できる
- 時計は Playwright の `context.clock` で差し替える。差し替えたあとも時間はふつうに進む
- 音ゲーの押し方は、演奏エリアの角に目印を置いて画面上の位置を測る。横画面(絵を90度回す)でも押す位置とはじく向きが合う
- 時間と保存係(時計)が見に行く時刻は、`data/rhythm-event.js` の `RHYTHM_EVENTS` と `RHYTHM_EVENT_POINT_CAMPAIGNS` から
  作る(終わってから3週間より前のものは見ない)。イベントを足せば、勝手に見に行く先も増える

### 報告係の「前回との比較」

前回の結果と比べて、新しく出たもの・前回あって今回出なかったもの・数字の動き(起動の秒数・新人の手数・
到達WAVE(バトル・AUTO・タクティクス)・スコア)を報告の先頭に出す。不具合の数字(px・秒など)は伏せて比べるので、揺れただけでは「新しい」にならない。
比べる相手は ① `--compare` で指定したもの ② 同じ手元で前に回した結果 ③ `tools/playbot/baseline.json` の順に探す。
毎日の定期実行は毎回まっさらな作業場で動くので ③ と比べる。基準は `--save-baseline` で書き直す。

### モンヒロビートの演奏のしかた

ふつうの指と同じ `pointerdown` / `pointermove` / `pointerup` を演奏エリアへ送るだけで、判定には手を入れない。
曲の再生位置とノーツの一覧は、演奏画面が出している読み取り専用の参照
(`30-rhythm-play.jsx` の `window.__mhTestHooks.rhythmSongMs` / `rhythmNotes`)から読む。
レーンの位置は本体の `rhythmProjectBoundary` と同じ式で、判定ラインの高さのレーンの真ん中を求める。
人らしさのため、押す時刻は標準偏差28msでばらつかせ、3%は押し損ねる。TAP は短く押す、HOLD は終わりまで押さえる、
SLIDE は線に沿って指を動かす、FLICK は上へはじく。

## 守っていること(CLAUDE.md ⑦)

- 毎回まっさらなブラウザで動かす。手元・本番のセーブデータには触れない
- **ランキングには載らない。** ゲームはふつうに送るつもりで動き、成功の返事も受け取るが、通信は
  `lib/fake-supabase.js` が受け止めて**本物へは1件も届けない**。受け止めた記録はボットの手元に覚えておき、
  ランキングを読みに来たら返すので、ボットがランキング画面を開くと自分(モンヒロくん)が並んで見える
- 手元(localhost)以外への通信はすべて止める。よその作品へのリンク・削除・初期化・デバッグ系のボタンは押さない

## 苦手なこと

- 「楽しいか」は判断できない。毎日の定期実行では、Claude が画像を見て遊びにくいところを拾う
