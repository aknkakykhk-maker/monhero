# モンヒロくん(遊んでくれるロボット)

実ブラウザ(Chromium)でゲームを開き、**人のように遊んで**「おかしなこと」と「遊びにくいところ」を記録する道具。
検査(`run-checks.js`)と違って**合否は出さない**。見つけたものをスクリーンショット付きで報告し、
直すかどうかは人(とClaude)が決める。毎日の定期実行の手順は [`ROUTINE.md`](ROUTINE.md)。

```
node tools/playbot/playbot.js                         全員(約15分)
node tools/playbot/playbot.js --only clock,legacy     選んだ担当だけ(id でも「時計係」のような名前でも)
node tools/playbot/playbot.js --team battle          班の担当だけ(毎晩は4つの班に分けて別々のセッションが動く。roles.js の TEAMS)
node tools/playbot/playbot.js --list                  担当の一覧
node tools/playbot/playbot.js --parallel 3            同時に動かす担当の数(既定3・最大4。1なら順番に)
node tools/playbot/playbot.js --steps 300             探索の手数(既定150)
node tools/playbot/playbot.js --seed 12345            同じ押し方を再現する(報告に種が出る)
node tools/playbot/playbot.js --compare <report.json> 比べる相手を指定する
node tools/playbot/playbot.js --save-baseline         今回の結果を比べる基準(baseline.json)として残す
node tools/playbot/playbot.js --headed                画面つきで動かす
```

結果は `tools/out/playbot/<日時>/` に出る(`report.md` / `report.json` / 画像)。`tools/out` は git に入らない。

## 担当(`roles.js`)

モンヒロくんは担当ごとに分かれている。担当ごとに**別のブラウザ**を開き、決まった仕事だけをして、
報告も担当ごとにまとまる。担当を足すときは `roles.js` へ1件足し、仕事の中身は `scenarios/` に置く。

| 担当 | id | 下準備 | 仕事 |
| --- | --- | --- | --- |
| 新人係 | `new` | まっさら | 名前「モンヒロくん」を打ち、アイコンを選んで、はじめての設定を終えるまで(手数と秒数を測る)。そのままクラシックの最初のバトルを数ターンと、少しの探索 |
| バトル係 | `battle` | いつもの | クイックモードを手で10ターン。勇者モンを毎回ちがう子で選び、カードを選ぶ → 枠に置く → ACTION。WAVE の合間は「次へ進む」や報酬えらびを人と同じく押す |
| タクティクス係 | `tactics` | いつもの | タクティクスバトル(入れなければタクティクスプロ)を手で6分。敵の予告で狙われた子が危ない(見込みのダメージが最大ライフの3割以上、または半分を切る)なら守りのカードを先に選ぶ。味方が2体以上なら攻撃カードの置き場所(誰が使うか)も選ぶ。ときどき EX スキルを使い、ガッツ切れのときは1枚捨てる |
| AUTO係 | `auto` | いつもの | クイックモードを AUTO で3分放っておき、途中で止まらないか見る |
| 案内係 | `tour` | いつもの | HOME のボタンを1つずつ開き、中で8手遊んで戻る。探索の乱数で行かない場所を残さない |
| 探検係 | `explore` | いつもの | 見えているボタンを、まだ押していないものを優先して押す(モンキーテスト)。名前の入力欄には名前を打つ |
| 久しぶり係 | `legacy` | 昔のセーブ | マスモン導入前のセーブで開き、①持ち物が消えない・減らない ②もう一度開いても移行や補填が二重にかからない ③そのまま遊べる ④遊んだあとも名前と昔のキーが残る、を見る |
| 時計係 | `clock` | いつもの | 端末の時計を動かして開き直す。ログインボーナス(4:00の区切りの前後・同じ日にもう一度・時計を過去へ戻す)と、イベント・キャンペーンの開催中と終わったあと(HOME の札が出る・消える)を見る |
| 音ゲー係 | `rhythm` | いつもの | ソロライブで曲と難易度(EASY〜HARD)を選び、**ノーツに合わせて最後まで演奏**する。**1人で動かす** |
| 育成係 | `grow` | いつもの+昔のキー | マスモンの強化ポイントを「＋」で振り、画面下の「◯ptを使って強化する」で確定(二度押し)。確定前は保存が変わらない・確定後は振った数だけ減って入る・二度押しでも1回分、を見る。「完了」で下書きが黙って消えるかも見る。編成・図鑑・放牧も開く |
| 買い物係 | `shop` | いつもの+ダイヤ | ダイヤショップで1つずつ買い、ダイヤが買う画面の「購入後 残り」と同じか・所持が1つ増えたかを見る。ギフトは受け取ったぶんの報酬だけダイヤが増えるか。ミッションの報酬も受け取る |
| 意地悪係 | `mean` | いつもの+ダイヤ | 買う・ギフト・ミッションを二度押し(1回分だけ動くか)/買う画面を開いたまま読み込み直す/ブラウザ(スマホ)の戻る/AUTO バトル中に裏へ回して戻す |
| イベント係 | `event` | いつもの | 開催中のレイド(ジャック)にバトルで挑戦し、速度を上げて20ターン戦い切る。残り回数が1回分だけ減るか・与えたダメージ(`raid_jack_hits`)が送られるか。ハロウィン・ナイトの札も押す。開催していなければ何もしない |
| マルチ係 | `multi` | いつもの+昔のキー | モンヒロビートのプライベートルームを作り、マスモンを二度押しで呼ぶ(今日の無料が1回分だけ減るか)。メンバー確定 → 選曲 → 準備完了 → 最後まで演奏。**1人で動かす** |
| レイド音ゲー係 | `raidbeat` | いつもの | レイドに「モンヒロビートで挑戦」し、「決定」は二度押し。最後まで演奏して「レイドの結果を見る」。挑戦回数(`mh_raid_jack_v1`)が1回分だけ増えるか・`raid_jack_hits` が1件だけ送られ、結果のダメージと同じか。**1人で動かす** |
| 横画面係 | `landscape` | いつもの | モンヒロビートで「横画面にする」(絵を90度回す)。遊びかた・記録・ビートLv・オプション・曲えらび・全国ランキング(イベント詳細)・部屋を開き、閉じる/戻るで本当に閉じられるか(見えなければスクロールして探す)。横向きのまま1曲演奏して MISS が3割を超えないか。**1人で動かす** |
| 相棒係 | `buddy` | いつもの+マスモン4体+券2枚 | 時計を朝4:40に合わせて起動し、部屋でマスモンを4体呼ぶ(3体目まで無料・4体目で券が1枚だけ減るか)。1曲遊んで経験値が増えるか。5:10に開き直して無料が3回に戻るか。**1人で動かす** |
| ストーリー係 | `story` | いつもの(既読を入れない) | 時刻で流れるストーリー(ハロウィン・ナイト第1部)を、開始の1時間前と10分後に起動して、前は流れず後は流れるか。プロフィールのイベント回想を6本まで、最後まで読む |
| ランキング係 | `ranking` | いつもの | 音ゲー係が送った記録に、名前の長い大勢のライバルを足してランキングを開く。自分が見えるか・崩れないか・タブを切り替えても困らないか。**1人で動かす** |
| 報告係 | — | — | 遊ばない。全員の結果を担当ごとにまとめ、前回と比べて「新しく出たもの」を先頭に出す |

- **同時に動かす。** ふつうの担当は `--parallel` の数(既定3)ずつ同時に動かし、音ゲー係とランキング係は
  そのあと1人ずつ動かす。モンヒロビートは同時に動かすとコマが止まって押すのが遅れる
  (`tools/mode/rhythm-robot-play.js` 2026-09-29: 3本並べて 125譜面中8譜面で 67〜264ms 遅れた)。
  読み込みの秒数も、1人で動く音ゲー係のものだけを数える
- **乱数は担当ごとに分けてある。** 同時に動かしても、`--seed` と `--only` で同じ押し方を再現できる
- 時計は Playwright の `context.clock` で差し替える。差し替えたあとも時間はふつうに進む
- 音ゲーの押し方は、演奏エリアの角に目印を置いて画面上の位置を測る。横画面(絵を90度回す)でも押す位置とはじく向きが合う
- 時計係が見に行く時刻は、`data/rhythm-event.js` の `RHYTHM_EVENTS` と `RHYTHM_EVENT_POINT_CAMPAIGNS` から
  作る(終わってから3週間より前のものは見ない)。イベントを足せば、勝手に見に行く先も増える

### 報告係の「前回との比較」

前回の結果と比べて、新しく出たもの・前回あって今回出なかったもの・数字の動き(起動の秒数・新人の手数・
到達WAVE(バトル・AUTO・タクティクス)・スコア)を報告の先頭に出す。不具合の数字(px・秒など)は伏せて比べるので、揺れただけでは「新しい」にならない。
比べる相手は ① `--compare` で指定したもの ② 同じ手元で前に回した結果 ③ `tools/playbot/baseline.json` の順に探す。
毎日の定期実行は毎回まっさらな作業場で動くので ③ と比べる。基準は `--save-baseline` で書き直す。

### モンヒロビートの演奏のしかた

ふつうの指と同じ `pointerdown` / `pointermove` / `pointerup` を演奏エリアへ送るだけで、判定には手を入れない。
曲の再生位置とノーツの一覧は、演奏画面が出している読み取り専用の参照
(`30-rhythm-play.jsx` の `window.__mhTestHooks.rhythmSongMs` / `rhythmNotes`)から読む。
レーンの位置は本体の `rhythmProjectBoundary` と同じ式で、判定ラインの高さのレーンの真ん中を求める。
人らしさのため、押す時刻は標準偏差28msでばらつかせ、3%は押し損ねる。TAP は短く押す、HOLD は終わりまで押さえる、
SLIDE は線に沿って指を動かす、FLICK は上へはじく。

## 見張っているもの

| 分類 | 種類 | 中身 |
| --- | --- | --- |
| 不具合候補 | JSエラー / コンソールエラー | `pageerror` と `console.error`(通信を止めたことで出るものは除く) |
| 不具合候補 | 真っ白 | `#root` が空、または文字も絵も無い |
| 不具合候補 | 横はみ出し | ページ全体が画面幅(390px)より広い |
| 不具合候補 | 行き止まり / 進めない | 押せるものが無い、決まった手順で先へ進めない |
| 不具合候補 | 進行停止 | AUTO中にWAVE/ターンが動かない、演奏が終わらない |
| 不具合候補 | データが消えた / 二重に適用 / データの移行 | 久しぶり係: 昔のセーブの持ち物が消えた・減った、もう一度開いただけで一度きりの値が変わった、移行が終わらない |
| 不具合候補 | 日付の切り替え / 時刻のずれ | 時計係: ログインボーナスが増えない・増えすぎる、開催中に札が出ない・終わっても出ている |
| 改善のヒント | 守りが足りない | タクティクス係: 狙われて危ないターンの多くで、使える守りのカードが手札に無かった |
| 不具合候補 | 買い物の数が合わない / 受け取りの数が合わない / 育成の数が合わない / レイドの数が合わない | 画面の表示や押した回数と、保存値の増減が合わない |
| 不具合候補 | 二度押しで二重 / 確定前に保存が変わる / 途中で読み込み直すと変わる / 裏から戻ると止まる | 意地悪係・育成係・マルチ係 |
| 改善のヒント | 戻るでゲームの外へ出る / 下書きが黙って消える | 意地悪係(ブラウザの戻る)・育成係(強化の「完了」) |
| 不具合候補 | 横画面で閉じられない / 横画面で押した位置がずれる | 横画面係 |
| 不具合候補 | 相棒の数が合わない / ストーリーが流れない / 回想が最後まで読めない | 相棒係・ストーリー係 |
| 不具合候補 | ランキングに出ない | ランキング係: 送った記録や並べた記録が見えない |
| 改善のヒント | 反応なし | 同じボタンを3回押しても画面の文字が1つも変わらない |
| 改善のヒント | 小さいボタン | 32px未満のボタンが1画面に3つ以上 |
| 改善のヒント | 長い会話 | スキップの無い会話で12回以上押した |
| 改善のヒント | 読み込みが遅い / たどり着けない | 起動に15秒以上 / はじめての設定に60手以上 など |
| 既知 | — | 調べて意図どおりだと分かったもの(`lib/session.js` の `KNOWN`) |

意図どおりだと分かった挙動は、`KNOWN` へ**理由と根拠の場所**を書いて足す。消さずに「既知」として
報告の下へ回るので、毎回同じものを調べ直さずに済む。

## 守っていること(CLAUDE.md ⑦)

- 毎回まっさらなブラウザで動かす。手元・本番のセーブデータには触れない
- **ランキングには載らない。** ゲームはふつうに送るつもりで動き、成功の返事も受け取るが、通信は
  `lib/fake-supabase.js` が受け止めて**本物へは1件も届けない**。受け止めた記録はボットの手元に覚えておき、
  ランキングを読みに来たら返すので、ボットがランキング画面を開くと自分(モンヒロくん)が並んで見える
- 手元(localhost)以外への通信はすべて止める。よその作品へのリンク・削除・初期化・デバッグ系のボタンは押さない

## 苦手なこと

- 「楽しいか」は判断できない。毎日の定期実行では、Claude が画像を見て遊びにくいところを拾う
- 画面の名前は `gameState` を外から読めないので、テーマの分類と見出しの文字で呼び分けている
- 乱数で押すので、毎回見る画面は少しずつちがう。気になる結果は `--seed` で再現する
