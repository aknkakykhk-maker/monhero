# モンヒロくんの毎日のプレイ(定期実行の手順書)

毎日 2:52(JST)に Claude Code の Routine が動き、新しいセッションがこの手順書のとおりに動く。
2026-10-07 にユーザーが決めた(「毎日、全部を人間がプレイするかのようにやって、気付いた点を改善や提案をするように」)。
しくみと引き継ぎは、いちばん下の「定期実行のしくみと引き継ぎ」を見る。

## 決めごと(ユーザーの指示)

- 名前は **モンヒロくん**
- **ランキングには載せない。** ゲームはふつうに送るつもりで動くが、ボットが通信を受け止めて本物へは届けない
  (`lib/fake-supabase.js`)。**この仕組みを外して動かさない**(CLAUDE.md ⑦)
- 見つけた不具合は**直してPRを作るところまで。マージはしない**(ユーザーが確認してからマージする)。
  CLAUDE.md ③の「マージまで自動」は、この定期実行には当てはめない
- 改善の提案は、作らずに報告する(どれをやるかはユーザーが決める)

## 手順

0. **前の日までの記録を読む**: [`docs/playbot/HISTORY.md`](../../docs/playbot/HISTORY.md)。このセッションは前の日の会話を
   覚えていないので、ここに書いてある「決まったこと」「マージ待ちのPR」を前提に進める(同じ提案を繰り返さない)
1. 準備
   ```
   git fetch origin main && git checkout -B claude/playbot-$(TZ=Asia/Tokyo date +%Y%m%d) origin/main
   (cd tools && npm install --no-audit --no-fund)
   ```
   ブランチは日ごとに分ける(前の日のPRがまだマージされていなくても、ぶつからないように)。
2. 遊ぶ(15分ほど。担当ごとに分かれて、3人ずつ同時に動く)
   ```
   node tools/playbot/playbot.js 2>&1 | tail -40
   ```
   結果は `tools/out/playbot/<日時>/report.md`。担当の一覧は `--list`、担当の仕事は `README.md`。
3. 報告と画像を読む
   - まず先頭の「前回との比較」を見る。**新しく出たもの**と、前回は通ったのに今回つまずいた担当から調べる
     (前回は `tools/playbot/baseline.json`。前からあるものは、すでに報告済みか既知のことが多い)
   - 次に「担当ごとの結果」を担当の順に見る。❌ の担当は、どの段でつまずいたかを先に確かめる
   - `report.md` の「不具合候補」を1件ずつ、画像と「直前に押したもの」から確かめる。
     **ボットの勘違い**(押し方が悪い・待ち方が足りない)なら、ボットのほう(`tools/playbot/`)を直す
   - 「見た画面」の画像をひととおり見て、**人が遊んで引っかかりそうなところ**を拾う
     (文字が切れている・ボタンが押しにくい・何をすればいいか分からない・説明が足りない・待たされる)
   - 「改善のヒント」(小さいボタン・長い会話・反応しないボタンなど)は、本当に困るものだけ提案に回す
   - 意図どおりの挙動だと分かったものは、`lib/session.js` の `KNOWN` へ理由と根拠の場所を書いて足す
4. 不具合を直す(あれば)
   - ふつうの改修と同じく CLAUDE.md のとおりに直す(⑥の検査、⑤の更新履歴。プレイヤーに見えない修正なら書かない)
   - ボットで再現できるなら、直したあとに同じ種(`--seed`)と担当(`--only`)で回して消えたことを確かめる
   - PRを作る日は、直したあとに全員で回し直して `--save-baseline` で基準を書き、そのPRに含める
     (基準が古いままだと、毎日「新しく出たもの」に同じものが並ぶ)
   - コミット → プッシュ → PR を作る。**マージはしない**。PRの本文に、ボットの報告のどれを直したかを書く
   - 直すのが大きい・仕様の判断が要るものは、直さずに報告へ回す
5. 報告する(このセッションの最後の返答。日本語)
   - 前回との比較(新しく出たもの・出なくなったもの・数字の動き)
   - 担当ごとの結果を1行ずつ(新人係の手数、バトル係・AUTO係・タクティクス係の到達WAVE(タクティクス係は「危ないときに守った回数」も)、音ゲー係のスコア、
     ランキング係・久しぶり係・時計係で見たこと)
   - 見つけた不具合と、作ったPR(リンク)
   - 改善の提案(多くて5つ。画面の名前と、どう変えるとよいか)
   - ボットそのものを直したところ
   - 何も見つからなければ「きょうは問題なし」と短く
6. **記録を残す**: `docs/playbot/HISTORY.md` のいちばん上(「ずっと守ること」の下)へ、その日のぶんを5〜10行で足す。
   このファイルだけを変えたブランチ(`claude/playbot-history-<日付>`)で PR を作り、**それだけはマージまで進める**
   (ゲームには何も起きない記録なので。不具合の修正 PR とは混ぜない)。PR を作る直前に `git fetch origin main` して取り込む
7. 終わったら PushNotification で、報告のひとこと(不具合の有無と PR の番号)をユーザーへ送る
8. **報告の要点を窓口の会話へ送る**: `send_message`(`session_id` は `@parent`)で、5〜10行の要点を送る
   (担当ごとの結果を1行ずつ・不具合と PR の番号・改善の提案・ユーザーに決めてほしいこと)。
   ユーザーは窓口の会話で報告を読み、マージや提案えらびを決める

## してはいけないこと

- 本物の Supabase へ通信させる(`fake-supabase.js` を外す・通信の横取りを止める)
- PR をマージする(例外は 6. の記録だけの PR)
- 既存曲の譜面を作り直す・解析ファイルを作り直す(CLAUDE.md ⑩-2)
- 保存データの形を変える(CLAUDE.md ⑦)
- ワークフロー(yml)を増やす(CLAUDE.md ⑧)

## 運用の分担(2026-10-07 にユーザーと決めた)

| だれ | 役目 | しないこと |
| --- | --- | --- |
| **窓口の会話**(いま: 「モンヒロくん1号」`session_01MC7KZtt5oyrsS32Hc57TXv`) | 毎晩の呼び出し / 毎晩のセッションから届く要点を、ユーザーに分かる形で出す / ユーザーの判断(修正 PR のマージ・改善の提案えらび・担当の追加の依頼)を受けて実行する | 自分で遊ばない(会話がたまらないように) |
| **毎晩のセッション**(「モンヒロくんの毎日のプレイ(日付)」) | 手順 0〜8: 遊ぶ・調べる・小さな修正 PR・ボットの小さな直し・記録・要点を窓口へ送る | 修正 PR のマージ / 担当を新しく足すような大きな作り直し |
| **作り手の会話**(いま: 「モンヒロくん役割割当」`session_01911k2UUtVGudFqekCw9DB9`) | 新しい担当・遊び方を足す / ボットの大きな作り直し。足したら `HISTORY.md` に1〜2行書き、手順5の「担当ごとの結果」にも足す | 毎晩のプレイ・報告(窓口と毎晩のセッションの仕事) |

- ボットの直しの線引き: **その場で済む直し**(待ち方・押し方・見間違い・`KNOWN` への追加)は毎晩のセッションが直す。
  **担当を増やす・遊び方を変える**ものは、毎晩のセッションが要点に「作り手へ回したいこと」として書き、窓口がユーザーに確かめてから作り手へ頼む
- 作り手の会話が終わった・消えたあとは、窓口がその都度 `create_session` で作り手を立てて頼む(この表の「いま」を書き換える)

## 定期実行のしくみと引き継ぎ

2026-10-07 にユーザーと決めた形。スマホから定期実行の編集画面が開けず、定期実行のセッションにリポジトリを付けられなかった
(付いていないとプッシュが 403 になる)ため、次の2段にした。

1. 定期実行「モンヒロくんの毎晩の呼び出し」が、毎日 2:52 に**親の会話**を起こす
   (いまの親: `session_01MC7KZtt5oyrsS32Hc57TXv`)
2. 親の会話は `create_session`(`source_url` にこのリポジトリ)で**新しいセッション**を立て、この手順書のとおりに遊ばせる。
   親はそれ以上のことをしない(親の会話がたまらないように)。新しいセッションにはリポジトリが付くので、プッシュも PR も通る

前の日のことは、セッションではなく `docs/playbot/HISTORY.md` が覚えている。だから親の会話が長くなって古いやりとりが要約されても、
親の会話が消えても、毎日の作業そのものは困らない。

### 親の会話が消えた・別の会話へ移したいとき

新しい会話(このリポジトリを付けたもの)で「**モンヒロくんの定期実行を引き継いで**」と言う。受けた Claude は次を行う。

1. `list_triggers` で「モンヒロくんの毎晩の呼び出し」を探し、`delete_trigger` で消す(古い親へ飛び続けないように)
2. `create_trigger` で、同じ名前・`CRON_TZ=Asia/Tokyo 52 2 * * *`・その会話に向けた(`persistent_session_id` を付けない)
   呼び出しを作り直す。プロンプトは下の「呼び出しの文面」をそのまま使う
3. この節の「いまの親」と、`docs/playbot/HISTORY.md` の「決まったこと」を新しい会話の id に書き換える

### 呼び出しの文面

```
モンヒロくんの毎晩の呼び出しです。この会話では作業せず、新しいセッションを1つ立てて任せてください。
create_session を source_url=https://github.com/aknkakykhk-maker/monhero、permission_mode=auto、タイトル「モンヒロくんの毎日のプレイ(日付)」で呼び、
prompt には「リポジトリの tools/playbot/ROUTINE.md と CLAUDE.md を読み、手順 0〜8 のとおりに今日のぶんを行ってください。返答はすべて日本語で」と渡す。
立てたら、セッションの id を1行だけ返して終わる(結果を待たない・読み込まない)。
あとでそのセッションから要点が届いたら、ユーザーが朝に読みやすい形(担当ごとの結果・不具合とPR・改善の提案・決めてほしいこと)で日本語でまとめ、決めてほしいことがあれば選択式で聞く。
```
