# 助手画像 正本管理システム

助手画像の「古い画像の再利用・参照元の取り違え・修正前の再提出」を、注意ではなく仕組みで防ぐための台帳と道具一式。

## 構成

| ファイル | 役割 |
|---|---|
| `registry.json` | 全助手・全衣装・全表情の画像台帳 (自動生成)。パス・blob SHA (バージョン)・SHA-256・寸法・透過情報・正本宣言・承認状態・派生の鮮度を保持 |
| `build_registry.py` | GitHub 最新 main から台帳を再生成する。実ファイルをダウンロードして SHA-256 を実測し、blob SHA でキャッシュする |
| `approvals.json` | 承認状態の人手オーバーレイ。記録が無い組は `unknown` のまま — ビルダーは勝手に承認扱いにしない |
| `provenance.json` | 派生画像の参照元記録 + 引退した旧世代ハッシュ (`_retired`) |
| `landmarks.json` | 正本全身絵の顔ランドマーク実測。正本のハッシュと結び付いており、差し替えで自動的に無効化される |
| `framing.json` | セットごとの顔アイコン画角仕様 (承認済みアイコンの実測・あっくんの画角指示に基づくものだけ) |
| `verify.py` | 機械検証 (下記) |
| `make_face_icons.py` | 承認済み正本全身絵からの顔アイコン自動切り出し (再描画なし) |
| `make_sheet.py` | スマホ確認用の比較一覧シート生成 |

既存の `tools/image/assistant-art-catalog.json` (組ごとの正本宣言) と役割を分ける: あちらは「どの原本から作るか」、こちらは「個々のファイルのハッシュ・承認・鮮度」。台帳ビルダーはカタログ宣言を取り込んで作る。

## 運用ルール (スキルが強制する)

1. 作業開始時に最新 main で台帳を再生成する。過去の会話・キャッシュ・一時フォルダの画像を正本として使わない。
2. 生成・切り出しの前に、参照元の実ファイルの SHA-256 が台帳と一致することを検証する。一致しなければ開始しない。
3. 同じファイル名でもハッシュが異なれば別世代として扱う。
4. 正本が更新されたら、参照元記録と突き合わせて依存する派生 (立ち絵・顔アイコン等) が自動で `stale` になる。旧正本由来の派生を最新として提示・実装しない。
5. 顔アイコンは原則 AI 再描画せず、承認済み全身絵から自動切り出しする。
6. ユーザー確認は 1 枚ずつ求めない。基準全身絵の承認後は全表情の生成・自己検証・修正・アイコン生成まで連続で進め、最後に比較一覧シートで確認してもらう。修正は対象画像のみ。

## 検証の分担

機械検証 (`verify.py` が自動で判定):
- 参照元ハッシュの一致 / 鮮度 (stale 検出)
- 旧世代ハッシュとの一致 (旧画像の混入)
- 公開中ファイルと同一ハッシュ (旧ファイルの再提出)
- 重複画像、透過の有無・不透明率・四隅のアルファ
- 解像度・寸法規格、ファイル名・保存先の規則

目視検証 (AI/人が比較シートと拡大図で判定。機械では判定しない):
- 衣装・髪型・装飾の正本との一致、表情の正しさ
- 手・指・耳の数と破綻、頭や足先の欠損
- 透過の縁の品質 (最大級の拡大で全周)、画質劣化

## 顔検出について

自動顔検出 (YuNet / アニメ顔向けカスケード) を実測したが、この画風では誤検出・未検出が多く、そのままでは使えない。そのため切り出しは「登録済みランドマーク + 画角仕様」で決定的に行い、ランドマークは正本のハッシュと結び付けて管理する (正本が変われば再実測するまで生成を開始しない)。検出器の出力はランドマーク候補の提示にのみ使ってよい。
